## 2245A - Who Watches the Watchpig?

**Solution**

If a piggy faces left (L), any watchpig pair it belongs to must involve a piggy to its left facing right (R). Symmetric logic applies if it faces right.

Consider a piggy at index $i$ ($1 \le i \le k$). It cannot face $\mathtt{L}$ because there are at most $i - 1 \lt k$ piggies to its left, meaning it cannot form $k$ watchpig pairs. Thus, the leftmost $k$ piggies must all face $\mathtt{R}$. By the same reasoning, the rightmost $k$ piggies must all face $\mathtt{L}$.

Notice that this necessary condition is also sufficient:


- For any piggy $i$ in the prefix ($1 \le i \le k$), it forms exactly $k$ watchpig pairs with the rightmost $k$ piggies (which are guaranteed to face L).
- For any piggy $i$ in the suffix ($n - k + 1 \le i \le n$), it forms exactly $k$ watchpig pairs with the leftmost $k$ piggies (which are guaranteed to face R).
- For any piggy in the middle portion (if any), depending on its direction, it will form $k$ watchpig pairs with either the leftmost prefix or the rightmost suffix.

Therefore, if $2k \gt n$, the prefix and suffix overlap, and there is no solution. Otherwise, the optimal strategy is simply to force the leftmost $k$ piggies to face R and the rightmost $k$ piggies to face L, leaving the middle piggies completely untouched.

Overall complexity $O(n)$.


**Code**
```python
for _ in range(int(input())):
 n, k = map(int, input().split())
 s = input()
 if k * 2 > n:
 print(-1)
 continue
 ans = 0
 for i in range(k):
 ans += int(s[i] != 'R') + int(s[n - i - 1] != 'L')
 print(ans)
```

## 2245B - Delete and Concatenate
 
**Solution**

Let us first consider the base case where $c=0$. Observe that the final score is always the sum of some subset of elements from $a$. Let $m=\left \lceil \frac{n}{2} \right \rceil$. We claim that for any integer $k$ such that $m \le k \le n$, there exists a sequence of operations yielding a final score exactly equal to the sum of the $k$ largest elements in $a$.

Proof. We can demonstrate this by analyzing the following cases based on the remaining elements:

- $k \gt n-k$: Arbitrarily choose any of the largest $k$ elements and apply the first operation to remove it.
- $k=n-k$: There must exist at least one pair of adjacent elements where one belongs to the $k$ largest elements and the other does not. Select this pair and apply the second operation, which effectively absorbs the smaller element while retaining the larger one.
- $k \lt n-k$: Given our initial condition $k \ge \left \lceil \frac{n}{2} \right \rceil$, this scenario is mathematically impossible and will never occur.

Note that for the first two cases, $k$ remains greater than or equal to $n-k$ after an operation.

Thus, for $c=0$, if there are $p$ positive elements in $a$, the optimal strategy is simply to sum the largest $\max(m, p)$ elements.

Now, let us generalize to the case where $c \ge 0$. We can apply a baseline shift by defining a new array $a'$ such that $a'_i = a_i - c$. Under this transformation, applying the first operation yields a score of $a'_i = a_i - c$. Similarly, applying the second operation to adjacent elements yields $\max(a'_i, a'_j) = \max(a_i - c, a_j - c) = \max(a_i, a_j) - c$. This algebraic translation reduces the general case with cost $c$ to our previously solved base case with cost $0$.

The maximum possible final score can be computed by first transforming the array into $a'$, counting the number of positive elements $p'$ within it, and then simply returning the sum of the largest $\max(m, p')$ elements of $a'$. Overall complexity $O(n \log n)$.

 
**Code**
```python
for _ in range(int(input())):
    n, c = map(int, input().split())
    a = list(map(int, input().split()))
    a.sort()
    for i in range(n):
        a[i] -= c
    for i in range(n // 2):
        a[i] = max(a[i], 0)
    print(sum(a))
```

## 2245C - MEXOR

**Solution**

By definition, a permutation of length $n$ contains all integers from $0$ to $n-1$. Therefore, the MEX of the entire array is always exactly $n$. This means $f(n-1) = n$ is fixed for any valid permutation.

The problem requires $f(0) \oplus f(1) \oplus \dots \oplus f(n-1) = k$. Since $f(n-1) = n$, we can XOR $n$ on both sides to find the required XOR sum for the first $n-1$ prefixes: $$f(0) \oplus f(1) \oplus \dots \oplus f(n-2) = k \oplus n$$ Let $K' = k \oplus n$. Our goal simplifies to constructing a permutation such that the XOR sum of the MEX of all prefixes except the last one equals $K'$.

A powerful trick when dealing with prefix MEX is to control when $0$ appears. If we place $0$ toward the end of the permutation, every prefix before $0$ will be missing $0$, making their MEX exactly $0$. We only need to manipulate the few elements placed after $0$ to achieve the desired $K'$.

We can break the construction down into three cases based on the value of $K'$:

- $K' = 0$: we just place $0$ at the very end of the permutation.
- $K' \le n-1$: we can place $0$ at the second to last position, and $K'$ at the last position. The permutation looks like: $[\dots, \text{others}, \dots, 0, K']$. Here, $f(i)=0$ for all $i \lt n-2$, and $f(n-2)=K'$.
- $K' \gt n-1$: since the maximum possible MEX for any proper prefix is $n-1$, we cannot generate a single MEX value equal to $K'$. First, check whether it is even possible. If the highest set bit of $K'$ is strictly greater than the highest set bit of $n-1$, it is impossible to form $K'$ using any combination of values $\le n-1$. In this case, we output "NO".If it is possible, $K'$ and $n-1$ must have the same bit length. This means their XOR will cancel out the highest bit, strictly reducing the value. Let $v = (n-1) \oplus K'$. Because the highest bits cancel out, we are guaranteed that $0 \lt v \lt n-1$. We can construct the end of the permutation as: $[\dots, \text{others}, \dots, 0, v, n-1]$. Here, $f(i)=0$ for all $i \lt n-3$, $f(n-3)=v$, and $f(n-2)=n-1$.

Overall complexity $O(n)$.

```python
 print(*reversed(a))
```

## 2245D1 - Construct an Array (Easy Version)

Firstly, we shall prove a small lemma:

Lemma. If there exists a solution for the original problem, there exists one where all $|a_i|$ are distinct.

Proof. Consider any valid solution $a$. We build another array $a'$ as follows:

- If $a_i \ge 0$, then $a'_i=2n \cdot a_i + n + i$;
- If $a_i \lt 0$, then $a'_i = 2n \cdot a_i - i$.

It is not hard to verify that $a'$ is also a valid solution, and all $|a'_i|$ are distinct.

As such, we can safely replace the non-negative constraint with positive.

 Notice that we can deduce whether each element $a_i$ is negative or positive, since there definitely exists an $a_i+a_i$ restriction for every $i$.

Consider two elements $i$ and $j$ such that $a_i$ is positive and $a_j$ is negative. If $a_i+a_j$ is positive, we can conclude that $|a_i| \gt |a_j|$; otherwise, $|a_i| \lt |a_j|$.

Build a directed graph $G$ consisting of $n$ vertices. Add an edge from vertex $i$ to $j$ if $|a_i| \lt |a_j|$. Run topological sort on $G$. If no topological sorting exists, there must be a cycle in $G$, and we can conclude that there is no solution. Otherwise, let $t$ be any topological sorting. $|a_{t_i}|=i$ is a valid solution.

Overall complexity $O(m+n)=O(n^2)$.

 
**Code**
```cpp
#include <bits/stdc++.h>

void solve() {
    int n, m;
    std::cin >> n >> m;
    std::vector b(n, std::vector<int>(n));
    while (m--) {
        int o, i, j;
        std::cin >> o >> i >> j;
        i--;
        j--;
        b[i][j] = b[j][i] = o;
    }
    std::vector<std::vector<int>> g(n);
    for (int i = 0; i < n; i++) for (int j = 0; j < n; j++) {
        if (b[i][i] == 1 && b[j][j] == 2) {
            if (b[i][j] == 1) g[j].push_back(i);
            else g[i].push_back(j);
        }
    }
    std::vector<int> d(n), ans(n);
    for (int u = 0; u < n; u++) for (auto v : g[u]) d[v]++;
    int cnt = 0;
    std::queue<int> q;
    for (int u = 0; u < n; u++) if (!d[u]) q.push(u);
    while (!q.empty()) {
        int u = q.front();
        q.pop();
        if (b[u][u] == 1) ans[u] = ++cnt;
        else ans[u] = -(++cnt);
        for (auto v : g[u]) if (!--d[v]) q.push(v);
    }
    if (cnt == n) {
        for (int i = 0; i < n; i++) for (int j = i; j < n; j++) {
            if (b[i][j] == 1 && ans[i] + ans[j] < 0) return void(std::cout << "NO\n");
            if (b[i][j] == 2 && ans[i] + ans[j] >= 0) return void(std::cout << "NO\n");
        }
        std::cout << "YES\n";
        for (int i = 0; i < n; i++) std::cout << ans[i] << " \n"[i + 1 == n];
    } else {
        std::cout << "NO\n";
    }
}

int main() {
    std::ios::sync_with_stdio(0);
    std::cin.tie(0);

    int t;
    std::cin >> t;
    while (t--) solve();
}
```

## 2245D2 - Construct an Array (Hard Version)

Please read the editorial for D1 first.

The topological sorting approach in D1 relies on the information of whether each $a_i$ is positive or negative. However, it turns out that we do not need this information at all.

If there exists some $i$ such that $a_i + a_j \gt 0$ for all $j$, $a_i$ must be the largest element in $a$. We can simply assign $a_i$ a very large positive value and move on. The same logic applies if there exists some $i$ such that $a_i + a_j \lt 0$ for all $j$. After we process $a_i$, we can remove all restrictions involving $a_i$ and look for the new largest/smallest element.

This can be done in a topological sorting-like approach. Let $d_{1,i}$ be the number of restrictions involving $i$ and $o=1$. Let $d_{2,i}$ be defined similarly. In a classic topological sort, we push a vertex into the queue if its in-degree becomes zero. In this case, we push a vertex into the queue if either $d_{1,i}$ or $d_{2,i}$ becomes zero. Depending on which one reaches zero first, we can also conclude whether $a_i$ is positive or negative.

Overall complexity $O(n+m)$.


**Code**
```cpp
#include <bits/stdc++.h>

void solve() {
 int n, m;
 std::cin >> n >> m;
 std::vector d(2, std::vector<int>(n));
 std::vector<std::vector<std::pair<int, int>>> g(n);
 while (m--) {
 int o, i, j;
 std::cin >> o >> i >> j;
 o--;
 i--;
 j--;
 g[i].emplace_back(j, o);
 g[j].emplace_back(i, o);
 d[o][i]++;
 d[o][j]++;
 }
 std::queue<int> q;
 std::vector<bool> vis(n);
 for (int i = 0; i < n; i++) if (d[0][i] == 0 || d[1][i] == 0) q.push(i), vis[i] = true;
 std::vector<std::pair<int, int>> t;
 while (!q.empty()) {
 int u = q.front();
 q.pop();
 if (d[0][u] == 0) t.emplace_back(u, -1);
 else t.emplace_back(u, 1);
 for (auto [v, o] : g[u]) if (!--d[o][v] && !vis[v]) {
 vis[v] = true;
 q.push(v);
 }
 }
 if (t.size() < n) return void(std::cout << "NO\n");
 std::cout << "YES\n";
 std::vector<int> ans(n);
 std::reverse(t.begin(), t.end());
 for (int i = 0; i < n; i++) ans[t[i].first] = (i + 1) * t[i].second;
 for (int i = 0; i < n; i++) std::cout << ans[i] << " \n"[i + 1 == n];
}

int main() {
 std::ios::sync_with_stdio(0);
 std::cin.tie(0);

 int t;
 std::cin >> t;
 while (t--) solve();
}
```

## 2245E - Tom and Jerry
 
**Solution**

Let's analyze the game strictly after Tom's first move. Suppose Tom chooses an initial path $P_1$. We can conceptually root the tree at one of the endpoints of $P_1$.

When it is Jerry's turn, he must choose a path $P_2$ starting from some vertex $x \in P_1$. Because the edges of $P_1$ are now deleted, $x$ effectively becomes the root of an independent connected component in the remaining forest. To avoid traversing deleted edges, Jerry's path $P_2$ is restricted to traveling strictly downwards (from ancestor to descendant) into $x$'s subtrees.

Consequently, $P_2$ will also be a top-down path. By induction, every valid path chosen in all subsequent turns will strictly flow from an ancestor to a descendant. The game elegantly reduces to a top-down path-picking game.

Let $S$ be the set of vertices belonging to the path chosen in the immediately preceding turn. We claim that the game state is a winning state (N-state) if and only if at least one vertex in $S$ has an odd degree in the remaining forest; otherwise, it is a losing state (P-state) where all vertices in $S$ have an even degree.

We can rigorously prove this via combinatorial game theory:

- Base case: If a player has no valid moves, all vertices in $S$ must have a degree of $0$. Since $0$ is an even number and no vertex has an odd degree, the terminal state is strictly a losing state, which perfectly aligns with our definition.
- Losing State $\to$ Winning State: Suppose a player starts their turn in a losing state (all $v \in S$ have an even degree) and chooses a valid path $P$. By the rules of the game, the starting vertex $x$ of $P$ must belong to $S$. Because the path extends downwards, $x$ loses exactly $1$ outgoing edge. Since its initial degree was even, its new degree after deleting the edges of $P$ becomes odd. Because $x$ naturally belongs to the newly formed active set $S'$ (which comprises the vertices of $P$), the opponent is guaranteed to receive a state containing at least one odd-degree vertex.
- Winning State $\to$ Losing State: Suppose a player starts in a winning state. There exists at least one vertex $u \in S$ with an odd degree. The player can start the path at $u$ and walk downwards following this simple stopping rule:

 - If we arrive at a vertex with an even degree, we continue extending the path downwards. Because we just consumed one incoming edge and its initial degree was even (meaning it must be $\ge 2$), there is guaranteed to be at least one outgoing edge available to continue the walk.
 - If we arrive at a vertex with an odd degree, we stop and terminate the path there.
 Since the tree is finite and every leaf in a rooted forest has a degree of $1$ (which is odd), this top-down walk is strictly guaranteed to eventually hit an odd-degree vertex and terminate. Let's examine the degrees of the vertices in this chosen path $P$ after its edges are deleted: the starting vertex (odd) loses $1$ edge, becoming even; the terminating vertex (odd) loses $1$ edge, becoming even; and all intermediate vertices (even) lose exactly $2$ edges (one incoming, one outgoing), thus remaining even. Consequently, all vertices in the newly formed set $S'$ will have an even degree, successfully forcing the opponent into a losing state.

To guarantee a win, Tom (the first player) must ensure he hands Jerry a losing state right from the start. Therefore, Tom's initial path $P_1$ must satisfy the condition that all vertices in $P_1$ end up with an even degree after its edges are deleted.

Working backward to the original tree:

- The two endpoints of $P_1$ each lose $1$ edge, so they must initially have an odd degree.
- All intermediate vertices of $P_1$ each lose $2$ edges, so they must initially have an even degree.
 The number of such paths can be elegantly and efficiently calculated using a depth-first-search on the connected components of even-degree vertices.
Overall complexity $O(n)$.

 
**Code**
```cpp
#include <bits/stdc++.h>

void solve() {
    int n;
    std::cin >> n;
    std::vector<std::vector<int>> g(n);
    for (int i = 0; i < n - 1; i++) {
        int u, v;
        std::cin >> u >> v;
        u--;
        v--;
        g[u].push_back(v);
        g[v].push_back(u);
    }
    std::vector<bool> vis(n);
    long long ans = 0;
    int c = 0;
    auto dfs = [&](auto&& self, int u) -> void {
        vis[u] = true;
        for (auto v : g[u]) {
            if (g[v].size() & 1) ans += c++;
            else if (!vis[v]) self(self, v);
        }
    };
    for (int u = 0; u < n; u++) if (~g[u].size() & 1 && !vis[u]) {
        c = 0;
        dfs(dfs, u);
    }
    for (int u = 0; u < n; u++) for (auto v : g[u]) if (v > u) ans += g[u].size() & g[v].size() & 1;
    std::cout << ans << "\n";
}

int main() {
    std::ios::sync_with_stdio(0);
    std::cin.tie(0);

    int t;
    std::cin >> t;
    while (t--) solve();
}
```

## 2245F - Familiar?

**Solution**

A crucial observation is that for any permutation, its minimum element divides the monotonic stack process into two independent parts.

Consider a subsegment of the permutation and let $p_k$ be the minimum element in this subsegment. When $p_k$ is pushed into the stack, because it is the absolute minimum of the current range, it will pop all elements currently left in the stack that were pushed by the left part $[l, k-1]$. After this, $p_k$ will remain at the bottom of the stack and will never be popped by any element in the right part $[k+1, r]$.

This independence between the left and right sides (split by the minimum element) strongly inspires an range DP solution.

Let $f_{l,r,c}$ be the number of ways to choose $r - l + 1$ relative values to form a valid permutation for the interval $p[l..r]$, such that:

- All conditions $a_i$ for $i \in [l, r]$ are satisfied.
- Exactly $c$ elements remain in the stack after processing this interval (assuming the stack was empty before processing $p_l$).

Base case: for empty intervals, we leave $0$ elements in the stack: $f_{i,i-1,0} = 1$ for all $1 \le i \le n+1$.

Transition: Let $W(l, k)$ be the number of valid ways to form the left part $[l, k-1]$. Because $p_k$ is the minimum, it will pop all elements left by the left part. Thus, if $a_k \neq -1$, the left part must leave exactly $a_k$ elements. If $a_k = -1$, it can leave any number of elements. $$W(l, k) = \begin{cases} f_{l, k-1, a_k} & \text{if } a_k \neq -1 \\ \sum_{x} f_{l, k-1, x} & \text{if } a_k = -1 \end{cases}$$

The right part $[k+1, r]$ leaves $c-1$ elements in the stack, and $p_k$ itself contributes $1$ to the final stack size, totaling $c$. We also multiply by the number of ways to distribute the relative values to the left part: $$f_{l,r,c} = \sum_{k=l}^{r} \binom{r-l}{k-l} W(l, k) f_{k+1, r, c-1}$$

This transition takes $O(n^4)$ time: $O(n^2)$ states for $[l, r]$, $O(n)$ for $c$, and $O(n)$ to iterate $k$.

To optimize this, we introduce $g_{l,r}$, which represents the total number of valid ways to form the interval $[l, r]$ regardless of how many elements are left in the stack: $$g_{l,r} = \sum_{c} f_{l,r,c}$$

By substituting the transition of $f_{l,r,c}$ into the definition of $g_{l,r}$, we can elegantly push the summation over $c$ to the right side of the equation: $$g_{l,r} = \sum_{c} \sum_{k=l}^{r} \binom{r-l}{k-l} W(l, k) f_{k+1, r, c-1}$$ $$g_{l,r} = \sum_{k=l}^{r} \binom{r-l}{k-l} W(l, k) \left( \sum_{c} f_{k+1, r, c-1} \right)$$ $$g_{l,r} = \sum_{k=l}^{r} \binom{r-l}{k-l} W(l, k) g_{k+1, r}$$

Now, we can redefine $W(l, k)$ utilizing our new array $g$: $$W(l, k) = \begin{cases} f_{l, k-1, a_k} & \text{if } a_k \neq -1 \\ g_{l, k-1} & \text{if } a_k = -1 \end{cases}$$

For every $r$ such that $a_{r+1} \ne -1$, we only need to calculate $f_{l,r,c}$ up to $c = a_{r+1}$. For every $r$ such that $a_{r+1}=-1$, we only need to calculate $g_{l,r}$. Another observation is that during the monotonic stack process, each element pushed into the stack is popped at most once. This bounds the sum of $a$ to be at most $n$, which bounds the complexity to $O(n) \cdot O\left(\sum a\right) = O(n^2)$ states multiplied by $O(n)$ transitions per state. Overall complexity $O(n^3)$.

## 2245G - NPC Challenge
 
**Solution**

Notice that the set $S$ returned in any query is always an independent set. The solution relies heavily on properties of independent sets.

Consider two independent sets $A$ and $B$. If we query $A+B$, all elements in $A$, as well as all elements in $B$ that do not have any edges with vertices in $A$, will be in $S$. Thus, we can identify all vertices in $B$ that have at least one edge with any vertex in $A$ with cost $k=|A|+|B|$. Let this subset of $B$ be $f(A,B)$.

We design the following procedure, $\operatorname{find}(A,B)$, that finds all edges between two independent sets $A$ and $B$ such that $B=f(A,B)$.

Base case: $|A|=1$. All vertices in $B$ are connected to the only vertex in $A$.

Recursion: Split $A$ into two equally sized subsets $A_1$ and $A_2$. Let $B_1=f(A_1,B)$ and $B_2=f(A_2,B)$. We can recursively call $\operatorname{find}(A_1,B_1)$ and $\operatorname{find}(A_2,B_2)$. Note that if a vertex $u \in B$ is not connected to any vertex in $A_1$, it must be connected to some vertex in $A_2$. Thus, we can save some cost by using the equality $f(A_2,B)=f(A_2,B_1) \cup (B \setminus B_1)$.

With $\operatorname{find}$, we can design another procedure $\operatorname{dfs(T)}$, that finds all edges between vertices in $T$.

Base case: $|T| \le 1$. There are no edges between vertices in $T$.

Recursion: let $S$ be the subset returned by querying $T$. $S$ is an independent set. We recursively call $\operatorname{dfs}(T \setminus S)$ first. Since the induced graph of $T \setminus S$ is a forest, which is bipartite, we can partition $T \setminus S$ into two independent sets $W_1$ and $W_2$. Finally, we call $\operatorname{find}(S,W_1)$ and $\operatorname{find}(S,W_2)$ to find all crossing edges between $S$ and $T \setminus S$.

Some amortized analysis can be done to show that the above solution works in $O(n \log n)$. A detailed proof that the sum of $k$ is less than $30 \cdot n$ is given below. You may refer to the solution code.

Let the repeated dfs process define greedy color classes $C_1, C_2, \ldots, C_h$. The first dfs query accepts $C_1$, recurses on the rejected vertices, the next accepts $C_2$, and so on. This is exactly the usual first-fit greedy coloring in the fixed vertex order.

Let $$M = \sum_{v}(\operatorname{col}(v)-1).$$

For every vertex of greedy color $c$, it has earlier neighbors of all colors $1, \ldots, c-1$. Choose one such edge for each smaller color. These chosen oriented edges are all distinct, because an edge can only be chosen by its later endpoint. Since the hidden graph is a tree, $$M \le n - 1.$$

Therefore the total cost of the raw dfs queries is $$\sum_v \operatorname{col}(v) = n + M \le 2n - 1.$$

Now consider the initial work(b[i], p1) calls made after the recursive dfs(p2) returns. Across all levels, the A-side contribution is exactly $$\sum |p_2| = M \le n - 1.$$

The B-side contribution queries the current color class once or twice, depending on whether one or two bipartition sides of $p_2$ are nonempty. Since the color classes partition the vertices, this contributes at most $2n$. Hence $$K_{\text{initial work}} \le M + 2n \le 3n - 1.$$

It remains to bound all recursive find calls.

Consider one call find(A, B), where $|A| = m$, and let $e$ be the number of true tree edges between $A$ and $B$. Every vertex of $A$ has at least one neighbor in $B$, so $e \ge m$.

The recursive split tree of find has leaves $A$. Define $$H(m) = \sum_{\text{internal split nodes } U} |U|.$$

Equivalently, $H(m)$ is the sum of leaf depths in the balanced split tree. For this code's split, $$H(m) = m \lceil \log_2 m \rceil - \left(2^{\lceil \log_2 m \rceil} - m\right).$$

Because $m \le n - 1 \le 999$, $$\frac{H(m)}{m} \le \frac{H(999)}{999} = \frac{9965}{999}.$$

Now split the find query cost into A-parts and B-parts.

The A-parts contribute exactly $H(m)$.

For the B-parts, choose one incident "base" edge for every vertex of $A$. The base edges contribute at most $$H(m) + \frac{H(m)}{2} = \frac{3}{2}H(m),$$ because, at every split node $U$, the first B-query can see at most $|U|$ base-neighbor labels, and the second B-query can see at most the size of the left child, which is at most $|U|/2$.

There are $e - m$ extra edges beyond the one base edge per $A$-vertex. One extra edge can make a B-vertex appear along at most one root-to-leaf path in the split recursion: at most $10$ first-query occurrences and at most $10$ second-query occurrences, since $m \le 999$. So each extra edge adds at most $20$.

Thus one find call costs at most $$H(m) + \frac{3}{2}H(m) + 20(e - m) = \frac{5}{2}H(m) + 20(e - m).$$

Using $H(m)/m \le 9965/999$, $$\frac{5}{2}H(m) + 20(e - m) \le \frac{5}{2} \cdot \frac{9965}{999}m + 20(e - m).$$

Since $e \ge m$, and $$20 \le \frac{5}{2} \cdot \frac{9965}{999},$$ we get $$\text{cost of this find call} \le \frac{5}{2} \cdot \frac{9965}{999} \, e.$$

Every tree edge appears in exactly one such find call: if its endpoints have greedy colors $i \lt j$, it is processed when level $i$ handles edges between $C_i$ and the remaining vertices. Therefore $$K_{\text{find}} \le \frac{5}{2} \cdot \frac{9965}{999} \, (n - 1) \lt 24.938(n - 1).$$

Combining all three parts: $$K \le (2n - 1) + (3n - 1) + \frac{5}{2} \cdot \frac{9965}{999}(n - 1).$$

Therefore $$K \lt \left(5 + \frac{5}{2} \cdot \frac{9965}{999}\right)n = 29.937437\ldots \, n.$$

So a strict clean statement is $$\boxed{K \lt 29.938n}$$ and, in integer form, $$\boxed{K \lt 30n}$$

```cpp
std::vector<int> work(const std::vector<int>& a, const std::vector<int>& b) {
    if (a.empty() || b.empty()) return {};
    std::vector<int> s;
    for (auto v : a) s.push_back(v);
    for (auto v : b) s.push_back(v);
    std::string t = query(s);
    std::vector<int> r;
    for (int i = 0; i < b.size(); i++) if (t[i + a.size()] == '0') r.push_back(b[i]);
    return r;
}

void solve() {
    int n;
    std::cin >> n;
    std::vector<std::vector<int>> g(n);
    auto find = [&](auto&& self, std::vector<int> a, std::vector<int> b) -> void {
        if (a.empty() || b.empty()) return;
        if (a.size() == 1) {
            for (auto v : b) g[v].push_back(a[0]), g[a[0]].push_back(v);
            return;
        }
        int m = a.size() / 2;
        std::vector a1(a.begin(), a.begin() + m), a2(a.begin() + m, a.end());
        auto p1 = work(a1, b);
        std::set<int> vis(p1.begin(), p1.end());
        std::vector<int> nb, p2;
        for (auto v : b) {
            if (vis.count(v)) nb.push_back(v);
            else p2.push_back(v);
        }
        self(self, a1, p1);
        for (auto v : work(a2, nb)) p2.push_back(v);
        self(self, a2, p2);
    };
    auto dfs = [&](auto&& self, std::vector<int> a) -> void {
        if (a.size() <= 1) return;
        std::string t = query(a);
        std::vector<int> p1, p2;
        for (int i = 0; i < a.size(); i++) {
            if (t[i] == '0') p2.push_back(a[i]);
            else p1.push_back(a[i]);
        }
        self(self, p2);
        std::vector<int> col(n, -1);
        std::vector<std::vector<int>> b(2);
        for (auto w : p2) if (col[w] == -1) {
            std::queue<int> q;
            q.push(w);
            col[w] = 0;
            while (!q.empty()) {
                int u = q.front();
                q.pop();
                b[col[u]].push_back(u);
                for (auto v : g[u]) if (col[v] == -1) {
                    col[v] = col[u] ^ 1;
                    q.push(v);
                }
            }
        }
        for (int i = 0; i < 2; i++) {
            find(find, b[i], work(b[i], p1));
        }
    };
    std::vector<int> a(n);
    std::iota(a.begin(), a.end(), 0);
```
