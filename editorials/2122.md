## 2122A - Greedy Grid
**Solution**

If $n = 1$ or $m = 1$, there's only one down/right path, so it is trivially greedy and maximal.

If $n = m = 2$, any path must choose between two neighbors after the first step. Clearly, moving greedily always leads to a maximal path.

In all other cases, such a grid does exist. Assuming $n \leq m$, start with an $n \times m$ grid filled with ones, and modify the top-left $2 \times 3$ subgrid as follows: $$ \begin{bmatrix} 1 & 2 & 3 \\ 3 & 1 & 1 \end{bmatrix}. $$ It's easy to verify that in this grid, no greedy path achieves the maximum possible value.

## 2122B - Pile Shuffling
**Solution**

Let's start by finding a lower bound on the number of required operations.

For each pile, we determine the minimum number of elements that must be removed from the top:

- If $b_i \gt d_i$, we need to remove all the zeros above before we can remove the excess ones at the bottom. So, we must remove at least $a_i + b_i - d_i$ elements.
- Otherwise, if $a_i \gt c_i$, we need to remove at least $a_i - c_i$ zeros to reach the target number of zeros.

Summing these values over all piles gives us a clear lower bound on the total number of operations.

This lower bound is also achievable. For each element that needs to be removed, there always exists a pile where we can place it so that it never has to be moved again. Here's why:

- If we remove a one, it's because there are too many ones in its current pile. That means there must be another pile $i$ with fewer than $d_i$ ones, where we can place it beneath all existing elements.
- If we remove a zero, we can place it in any pile $i$ that currently has fewer than $c_i$ zeros above at most $d_i$ ones. If we place it in the highest position with at most $d_i$ ones below it, it will not need to be moved again.


**Bonus**

Solve the problem for multisets faster than $\mathcal{O}(n^3)$.

## 2122C - Manhattan Pairs
**Solution**

Let's begin by considering the 1D version of the problem.

In one dimension, the optimal strategy is to pair the smallest $\tfrac{n}{2}$ values with the largest $\tfrac{n}{2}$ values.

Now, let's move to the 2D case. The Manhattan distance is the independent sum of the contributions from the $x$-coordinates and the $y$-coordinates. Therefore, if we find a matching that is optimal independently for both the $x$- and $y$-coordinates, it will also be optimal in 2D.

To achieve this, partition the set of points in two different ways:

- Let $X_l$ and $X_r$ be the sets of points with the smallest and largest $\tfrac{n}{2}$ $x$-coordinates, respectively.
- Let $Y_l$ and $Y_r$ be the sets of points with the smallest and largest $\tfrac{n}{2}$ $y$-coordinates, respectively.

A pairing will be optimal in both dimensions if:

- each point in $X_l$ is paired with a point in $X_r$,
- each point in $Y_l$ is paired with a point in $Y_r$.

To satisfy both conditions simultaneously, we can pair:

- each point in $X_l \cap Y_l$ with a point in $X_r \cap Y_r$,
- each point in $X_l \cap Y_r$ with a point in $X_r \cap Y_l$.

Let $a$, $b$, $c$, $d$ denote the sizes of these four groups, respectively. Note that they are disjoint. Then, we have:

- $a + c = b + d$, because $|X_l| = |X_r|$,
- $a + d = b + c$, because $|Y_l| = |Y_r|$.
 Adding these equations up yields $a = b$ and $c = d$, so such a pairing is always possible.

## 2122D - Traffic Lights
**Solution**

Let's first construct a solution, then analyze its runtime.

Let $f(i, j)$ denote the minimum waiting time to reach vertex $i$ at time $j$. Initially, $f(1, 0) = 0$. There are two possible transitions:

- $f(i, j + 1) \leftarrow f(i, j) + 1$,
- $f(k, j + 1) \leftarrow f(i, j)$, where $k$ is the opposite vertex of the $(j \bmod \deg(i) + 1)$-th edge of $i$.

Let $x$ be the minimum total time required to move the token from vertex $1$ to vertex $n$. Then, the minimum waiting time is $f(n, x)$. Thus, it suffices to compute $f(i, j)$ for all $j \leq x$, which can be done in $\mathcal{O}(nx + m)$ time.

Observe that if there exists a path from vertex $1$ to vertex $n$, and the sum of the degrees of the vertices on this path is $d$, then $x \leq d$, as the worst case strategy implies waiting for the very last edge whenever advancing to a new node.

We will now show that there exists a path from vertex $1$ to vertex $n$ such that $d \leq 3n$.

Take any path that minimizes the number of edges from $1$ to $n$, that is, a shortest path. There do not exist edges between non-consecutive vertices on this path. Furthermore, there cannot exist a vertex outside this path that is adjacent to at least $4$ vertices on the path, since in that case the path could be shortened.

Let the number of vertices on the path be $k$. Then, the total sum of degrees is at most $2k + 3(n - k) = 3n - k$, which is at most $3n$, since $k \geq 2$.

Therefore, since $x \leq 3n$, the solution runs in $\mathcal{O}(n^2 + m)$ time.

## 2122E - Greedy Grid Counting
**Solution**

Let's examine the required condition for a single grid.

Let $a_i$ denote the values in the top row and $b_i$ the values in the bottom row. Define $c_i = a_{i+1} - b_i$, and let $s = a_1 + b_1 + b_2 + \dots + b_n$. Then, the value of a path that switches from the top row to the bottom row in the $i$-th column is $s + c_1 + c_2 + \dots + c_{i-1}$.

Let $p$ be the length of the longest prefix of $c$ such that all $c_i \geq 0$. The optimal greedy path is to follow this prefix and switch rows at column $p + 1$. Therefore, the condition holds if and only if the sum of this prefix is maximal among all prefixes. This is equivalent to requiring that every subarray of $c$ with left end equal to $p + 1$ has a non-positive sum.

How can we ensure this condition holds for all subgrids? We define a dynamic programming approach over the sequence $c_i$. Let $f(i, j)$ represent the number of ways to construct a valid prefix of length $i$ with cumulative sum $j$ since the most recent negative $c_i$. The key constraint is that $j$ must always remain $\leq 0$ (except within the initial prefix where all $c_i \geq 0$).

Since each negative $c_i$ resets the sum, and we always have $c_i \geq -k$, the cumulative sum $j$ lies within the range $[-k, 0]$. The transitions are straightforward: we iterate over the next element in the sequence $c_i$ and update $j$ based on whether $c_i$ is non-negative (accumulate) or negative (reset).

This yields an $\mathcal{O}(nk^2)$ solution.

## 2122F - Colorful Polygon
**Solution**

We begin by solving the problem for the case $n = 2$.

Through experimentation, we can discover that a polygon consisting of two adjacent line segments with $a + 1$ and $b + 1$ points respectively has exactly $\binom{a + b}{b}$ triangulations.


![](eimages/2122_1.png)

 Polygon with $\binom{6}{2} = 15$ triangulations.
We now generalize this construction to handle any product of binomial coefficients. The key insight is to connect these basic shapes in a manner that ensures their triangulations remain independent.

To achieve this, we extend the shorter side of the polygon to form a rectangle with additional points on two sides. This modification preserves the number of triangulations.


![](eimages/2122_2.png)


To connect multiple rectangles, we join them using triangular connectors, alternating the sides to which they are attached:


![](eimages/2122_3.png)


These connectors do not affect the total number of triangulations, as there is exactly one way to triangulate each connector.

Returning to the original problem, the most straightforward approach is to represent the required number of triangulations as a product of binomial coefficients: $$\binom{a_1 + \cdots + a_n}{a_1} \binom{a_2 + \cdots + a_n}{a_2} \cdots \binom{a_n}{a_n}.$$ However, this representation requires $\Theta(n \cdot s)$ vertices, where $s = a_1 + \cdots + a_n$, which exceeds the given constraint.

To reduce the vertex count, we employ a divide-and-conquer approach, analogous to polynomial multiplication with bounded degree sum.

We can interpret the multinomial coefficient as the number of ways to assign $s$ elements to $n$ distinct colors, where color $i$ appears exactly $a_i$ times. The construction procedure follows these steps:

- First, determine the positions where the first $\lfloor n/2 \rfloor$ colors will appear.
- Recursively construct representations for the first and second halves of the color set.

This divide-and-conquer strategy reduces the vertex count to $\Theta(s \log n)$, which satisfies the problem constraints.

## 2122G - Tree Parking
**Solution**

Let's solve the problem for a single tree.

A tree is valid if and only if no interval contains any endpoint from its subtree. This condition allows us to approach the problem using dynamic programming. After simplification, the answer for a single tree becomes $$ \frac{(2n)!}{2^n s_1 s_2 \cdots s_n}, $$ where $s_i$ is the size of the subtree rooted at vertex $i$. Therefore, calculating the sum of the answers reduces to computing the sum of $\tfrac{1}{s_1 s_2 \cdots s_n}$ across all labeled trees with $n$ vertices and $k$ leaves.

It is a well-known result that the number of topological sorts of a tree is $\tfrac{n!}{s_1 s_2 \cdots s_n}$. This means we only need to compute the total number of topological sorts of all trees with $n$ vertices and $k$ leaves, and then divide the result by $n!$ to obtain the desired sum.

Let us now fix a topological sort and count the number of trees consistent with it. This is equivalent to counting the number of trees where each parent $p_i \lt i$, and the tree has exactly $k$ leaves. This leads to the recurrence:

$$ f(n, k) = f(n - 1, k - 1) \cdot (n - k) + f(n - 1, k) \cdot k. $$

It turns out (as can be verified via OEIS or other sources) that $f(n, k) = A(n - 1, k - 1)$, where $A(n, k)$ is the Eulerian number counting permutations of length $n$ with exactly $k$ descents. Eulerian numbers can be computed efficiently [using inclusion-exclusion](<https://en.wikipedia.org/wiki/Eulerian_number#Definition>) in $\mathcal{O}(k \log n)$ time.

Taking everything into account, the final answer is $$ \frac{A(n - 1, k - 1) \cdot (2n)!}{n \cdot 2^n}. $$
