## 1170A - Three Integers Again

Idea: [vovuh](<https://codeforces.com/profile/vovuh>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)

**Tutorial**

We always can consider that the numbers in the input are $x = a + b$ and $y = b + c$. If $x \gt y$ let's swap them. Note, that $a + b + c = a + b + (y - b) = a + y$. That's why it's optimal to minimize value of $a$. So the value of $a$ can always be $1$. Then we can restore $b = x - a$, and $c = y - b$.


**Solution**
```kotlin
fun main() {
 val q = readLine()!!.toInt()
 repeat(q) {
 val (x, y) = readLine()!!.split(" ").map { it.toInt() }.sorted()
 println("1 ${x - 1} ${y - x + 1}")
 }
}
```

## 1170B - Bad Days

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)
 
**Tutorial**

Iterate over all elements in $a$ from $a_1$ to $a_n$ one by one. You can easily maintain two maximum values. If the current element is strictly less than the second maximum, increment the result. Here is the main part of the code:
```cpp
for (x in a) {
 if (m2 > x) {
 result++
 }
 when {
 x > m1 -> {
 m2 = m1
 m1 = x
 }
 x > m2 -> {
 m2 = x
 }
 }
}
```

 
**Solution**
```kotlin
fun main() {
    val n = readLine()!!.toInt()
    val a = readLine()!!.split(" ").map { it.toInt() }
    var m1 = 0
    var m2 = 0

        if (m2 > x) {
            c++
        }
        when {
            x > m1 -> {
                m2 = m1
                m1 = x
            }
            x > m2 -> {
                m2 = x
            }
        }
    }
```

## 1170C - Minus and Minus Give Plus

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)

**Tutorial**

Let's process $s$ and $t$ character by character from left to right in parallel. Let's use two indices $i$ and $j$: the index $i$ is for $s$ and the index $j$ is for $t$. Initially, $i=j=0$. If $s[i] == t[j]$ then you can simply increase both indices $i$ and $j$ ($i$++, $j$++). In the opposite case, the only allowed situation is $s[i] = s[i+1] = $ '-' and $t[j] = $ '+'. In this case, increase $i$ by $2$ and $j$ by one. Stop the process if at least one index ($i$ or $j$) reaches the end of the corresponding string. Return positive answer YES if and only if both $i$ and $j$ reach the ends of strings $s$ and $t$ ($i=len(s), j=len(t)$) at the same time.


**Solution**
```kotlin
fun main() {
 val k = readLine()!!.toInt()
 repeat(k) {
 val s = readLine()!!
 val t = readLine()!!
 println(if (solve(s, t)) "YES" else "NO")
 }
}

private fun solve(s: String, t: String): Boolean {
 var i = 0
 var j = 0
 while (i < s.length && j < t.length) {
 when (s[i]) {
 t[j] -> {}
 '+' -> return false
 else -> { // '-' -> '+'
 i++
 if (i >= s.length || s[i] != '-') return false
 }
 }
 i++
 j++
 }
 return i == s.length && j == t.length
}
```

## 1170D - Decoding of Integer Sequences

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)
 
**Tutorial**

The number of occurrences of '-1' is exactly $n$ (the number of sequences). Construct a linked list $l$ containing all the numbers from $0$ to $n-1$ (i.e. all the sequence indices) and $n$ empty sequences. Now process the input sequence, each time you take an element $b_i$ append it to the corresponding sequence. The index of the corresponding sequence is exactly the value of the current element in $l$ (use an iterator). If $b_i=-1$ then the corresponding sequence is over and just remove from $l$ the current element and move to the next (or to the first if there is no next element). If $b_i \ne -1$ then simply move to the next (or to the first if there is no next element).

 
**Solution**
```kotlin
import java.util.*

fun main() {
    val m = readLine()!!.toInt()
    val b = readLine()!!.split(" ").map { it.toInt() }
    val n = b.count { it == -1 }
    val a = Array(n) { ArrayList<Int>() }
    val ix = LinkedList<Int>((0 until n).toList())
    var iter = ix.iterator()
    for (x in b) {
        if (!iter.hasNext()) iter = ix.iterator()
        val i = iter.next()
        if (x == -1) {
            iter.remove()
        } else {
            a[i].add(x)
        }
    }
    println(n)
    println(a.joinToString("\n") {
        "${it.size} ${it.joinToString(" ")}"
    })
}
```

## 1170E - Sliding Doors

Idea: [adedalic](<https://codeforces.com/profile/adedalic>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)

**Tutorial**

Let's look at one query. It can be proven, that it's always optimal to fill free spaces between chosen cells greedily from left to right (or from right to left). The proof is based on the fact that placing doors as much as possible before the leftmost chosen cell doesn't harm us. After that, we can "cut" that prefix and solve the task recursively.

To calculate the maximum number of doors, that can be fit in the gap between two consecutive chosen cells, we can't just iterate, since we can make up to $O(n)$ operation per query. But we can use the binary search (while calculating the sum of widths by prefix sums). So, the complexity of one query is $O(c_k \log{n})$ and total complexity is $O(\sum{c_k} \log{n})$.


**Solution**
```kotlin
fun main() {
 val (n, m) = readInts()
 val a = readInts().toIntArray()
 val q = readInt()
 val b = IntArray(4 * a.size)

 fun buildTree(il: Int, ir: Int, p: Int): Int {
 val s = if (il == ir) {
 a[il]
 } else {
 val im = (il + ir) / 2
 buildTree(il, im, 2 * p + 1) + buildTree(im + 1, ir, 2 * p + 2)
 }
 b[p] = s
 return s
 }

 buildTree(0, n - 1, 0)
 val ans = List(q) {
 val w = readInts().drop(1) + (m + 1) // sentinel
 if (solveDoors(n, m, b, w)) "YES" else "NO"
 }.joinToString("\n")
 println(ans)
}

private fun solveDoors(n: Int, m: Int, b: IntArray, w: List<Int>): Boolean {
 var pp = 0
 var i = 0
 var rem = 0

 fun queryTree(il: Int, ir: Int, p: Int, i: Int): Int {
 if (il == i && rem >= b[p]) {
 rem -= b[p]
 return ir + 1
 }
 if (il == ir) return i
 val im = (il + ir) / 2
 if (i > im) return queryTree(im + 1, ir, 2 * p + 2, i)
 val j = queryTree(il, im,2 * p + 1, i)
 if (j <= im) return j
 return queryTree(im + 1, ir,2 * p + 2, im + 1)
 }

 for (cp in w) {
 rem = cp - pp - 1
 i = queryTree(0, n - 1, 0, i)
 if (i >= n) return true
 pp = cp
 }
 return false
}

private fun readInt() = readLine()!!.toInt()
private fun readInts() = readLine()!!.split(" ").map { it.toInt() }
```

## 1170F - Wheels

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>), [vovuh](<https://codeforces.com/profile/vovuh>), [pashka](<https://codeforces.com/profile/pashka>)

Solution: [Benq](<https://codeforces.com/profile/Benq>)
 
**Tutorial**

It is obvious that it is always better to try to equalize the subsegment of the sorted array. So let's sort the array and iterate over all $n-m+1$ of its subsegments.

Let $sum(l, r) = \sum\limits_{j=l}^{r} a_j$.

For the segment $[i; i + m - 1]$ we have to find the minimum number of moves needed to equalize this segment. In the best case (if $k=\infty$) it can be proven that the better way to equalize all elements is to move them to the middle element of the segment (or if $m$ is even then we can choose either the left middle or the right middle element). How to calculate answer for this case? Let $idx$ be the middle of the segment (in other words, $i + \lfloor\frac{m}{2}\rfloor$), $val$ be the middle element (in other words, $a_{idx}$) and $cnt$ be $idx - i + 1$. Then the number of moves we need is $res = (cnt \cdot val - sum(i, idx)) + (sum(idx + 1, i + m - 1) - (m - cnt) \cdot val)$. This formula gives the number of operations needed to equalize the whole segment to the value $val$. The left part of the formula increases the part to the left of $val$ and the rightmost part decreases the part to the right of $val$.

This is almost the complete solution! What should we do with $k$? Let's find the rightmost position $idx$ that belongs to the segment and we can increase all elements in segment $[i; idx]$ to the value $a_{idx}$. We can do it using binary search and prefix sums (or two pointers). Then consider two cases:

- $idx \lt i + \lfloor\frac{m}{2}\rfloor$;
- $idx \ge i + \lfloor\frac{m}{2}\rfloor$.

In the first case $idx$ does not change, $cnt = i + idx - 1$ and $val = a_{idx} + \lfloor\frac{k - (cnt \cdot a_{idx} - sum(i, idx))}{cnt}\rfloor$. Then we can substitute these variables to the formula calculating $res$ and update the answer with the result. What does this scary formula ($\lfloor\frac{k - (cnt \cdot a_{idx} - sum(i, idx))}{cnt}\rfloor$) mean? It means that we can increase all values on the segment $[i; idx]$ to the value $a_{idx}$ but there are some increasing opreations remain and we should use them. And because $idx$ is the rightmost such position, it means that we cannot increase all values to $a_{idx + 1}$ but we can increase the whole segment $[i; idx]$ by some value possible greater than $a_{idx}$ (and it will not increase the result for this segment).

In the second case $idx = i + \lfloor\frac{m}{2}\rfloor$, $cnt = idx - i + 1$ and $val = a_{idx}$, and we can substitute these variables into the formula calculating $res$ and update the answer with the result.

 
**Solution**
```kotlin
import java.util.*

fun next() = readLine()!!
fun nextInt() = next().toInt()
fun nextInts() = next().split(" ").map { it.toInt() }
fun nextLongs() = next().split(" ").map { it.toLong() }

fun solve() {
    val (n,m,k) = nextInts()
    var A = nextLongs()
    var a = arrayListOf<Long>()
    a.addAll(A)
    a.sort()
    var ans = (1e18).toLong()
    var ind = 0
    var above:Long = 0
    var below:Long = 0
    for (i in 0..m-1) above += a[i]-a[0]
    for (i in 0..n-m) {
        val des = i+(m-1)/2
        while (ind < des) { // try to get closer to median if possible
            if (below+(a[ind+1]-a[ind])*(ind+1-i) <= k) {
                below += (a[ind+1]-a[ind])*(ind+1-i)
                above -= (a[ind+1]-a[ind])*(i+m-1-ind) // ind+1 to i+m-1
                ind ++
            } else break
        }
        assert (k >= below)
        if (ind < des) {
            var oops: Long = (k-below)/(ind+1-i)
            ans = minOf(ans,below+above-(i+m-1-ind)*oops+(ind+1-i)*oops)
            assert(i+m-1-ind >= ind+1-i)
        } else ans = minOf(ans,above+below)
        if (i < n-m) {
            below -= a[ind]-a[i]
            above += a[i+m]-a[ind]
        }
    }
    print(ans)
}

fun main(args: Array<String>) {
    val t = 1
    for (i in 0..t-1) solve()
}
```

## 1170G - Graph Decomposition

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [elizarov](<https://codeforces.com/profile/elizarov>)

**Tutorial**

If there exists vertex with the odd degree then the answer is "NO", otherwise the answer is "YES". Let's find a way to constuct it.

Almost all we need is to run euler cycle finding for each component of the given graph. It can be done with the following code:
```cpp
dfs(v) {
 while (v.hasAdjacentVertices) {
 to = v.anyAdjacentVertex
 v.removeOneEdge(to)
 to.removeOneEdge(v)
 dfs(to)
 }
 path.push(v)
}
```

In the part when we pushes a new vertex into the path we should try to restore a new cycle. How do we check and do it? Let's maintain an array $used$: $used_v$ is true when the vertex $v$ is in $path$. When we try to add the vertex $v$ that already in $path$ ($used_v$ is true), let's extract the new simple cycle instead of adding this vertex. Let's pop out all vertices $u$ we pushed until the last vertex equals to $v$ (and don't forget to set $used_u$ to false). Otherwise let's add this vertex into the list and set $used_v$ to true.


**Solution**
```kotlin
fun main() {
 solveEuler()
}

class E(
 val y: Int,
 var c: Int = 0
)

class Edges {
 private val e = HashMap<Int, E>(2)
 private val c = ArrayList<E>(2)
 private var first = 0

 fun degree() = c.sumBy { it.c }

 fun add(y: Int) {
 val cur = e.getOrPut(y) { E(y) }
 if (cur.c == 0) c.add(cur)
 cur.c++
 }

 fun first() = c[first].y

 fun hasNext() = first < c.size

 fun rem(y: Int) {
 val cur = e.getValue(y)
 if (--cur.c == 0) {
 while (first < c.size && c[first].c == 0) first++
 }
 }
}

private fun solveEuler() {
 val (n, m) = readLine()!!.split(" ").map { it.toInt() }
 val g = Array(n) { Edges() }
 repeat(m) {
 val (x, y) = readLine()!!.split(" ").map { it.toInt() - 1 }
 g[x].add(y)
 g[y].add(x)
 }
 if (!g.all { it.degree() % 2 == 0 }) {
 println("NO")
 } else {
 val c = ArrayList<List<Int>>()
 var start = 0
 val v = IntArray(n) { -1 }
 while (true) {
 while (start < n && !g[start].hasNext()) start++
 if (start >= n) break
 val list = ArrayList<Int>()
 var x = start
 while (true) {
 v[x] = list.size
 list.add(x)
 val y = g[x].first()
 g[x].rem(y)
 g[y].rem(x)
 if (y == start) break
 if (v[y] >= 0) {
 val d = list.subList(v[y], list.size)
 c.add(d.toList())
 for (z in d) v[z] = -1
 d.clear()
 }
 x = y
 }
 c.add(list)
 for (z in list) v[z] = -1
 }
 println("YES")
 println(c.size)
 val ans = c.joinToString("\n") { list ->
 "${list.size + 1} ${list.joinToString(" ") { (it + 1).toString() }} ${list[0] + 1}"
 }
 println(ans)
 }
}
```

## 1170H - Longest Saw

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [pashka](<https://codeforces.com/profile/pashka>)
 
**Tutorial**

Let's sort the input array. In any saw, there are two types of elements: minimums and maximums. It is easy to see that you can always take a prefix of the sorted array as minimums, and a suffix of the sorted array as maximums.

Now the only problematic elements in a saw are such values $x$, that $x$ belongs to minimums and maximums at the same time. It is easy to see that $x$ is maximum among minimums and minimum among maximums at the same time. All such values $x$ should be non-adjacent (non-neighboring) in a saw. Actually, you can use a greedy approach to put all minimums and maximums: just sort all the minimums and put them from left to right in their positions, just sort all the maximums and put them from right to left in their positions. This method "minimizes" the chance to put two $x$ in the consecutive positions.

So the solution is as follows: you can use a binary search to find the answer. Consider $m$ is a required length of a saw. We need to check if it is possible to construct such a saw. If $m$ is even, take $m/2$ first values from the sorted array of all the elements, take $m/2$ last values from the sorted array of all the elements. Try to construct a saw: put minimums from left to right and maximums from right to left. Check if is it a saw after it. In case of odd $m$, you should take care of all the possible cases of a saw topology.

One can prove the greedy algorithm by considering a bipirtite graph (the first part of vertices are minimums, the second part vertices are maximums). Connect two vertices if the corresponding positions are neighboring. You should put all values $x$ in such a way, that they form an independent set of vertices. Its size can't exeed the size of maximum matching, which is exactly $m/2$ (rounded down) in this graph. It is easy to see that the greedy approach can put $m/2$ or less values $x$ in such a way they are independent. So greedy approach gives an optimal solution.

 
**Solution**
```kotlin
import java.io.BufferedReader
import java.io.IOException
import java.io.InputStreamReader
import java.io.PrintWriter
import java.util.*

/**
 * @author: pashka
 */

fun solve(a: IntArray): IntArray {
    val n = a.size
    var l = 0
    var r = a.size + 1
    var best = IntArray(0)
    while (r > l + 1) {
        var m = (l + r) / 2
        val c = IntArray(m)
        for (i in 0 until m) {
            if (i % 2 == 0) {
                c[i] = a[i / 2]
            } else {
                c[i] = a[n - m / 2 + i / 2]
            }
        }
        var ok = true
        for (i in 0 until m - 1) {
            if (c[i] == c[i + 1]) {
                ok = false
            }
        }
        if (!ok && m % 2 == 0) {
            for (i in 0 until m step 2) {
                val t = c[i]
                c[i] = c[i + 1]
                c[i + 1] = t
            }
            ok = true
            for (i in 0 until m - 1) {
                if (c[i] == c[i + 1]) {
                    ok = false
                }
            }
        }
        if (ok) {
            l = m
            best = c
        } else {
            r = m
        }
    }
    return best
}
```

## 1170I - Good Subsets

Idea: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

Solution: [pashka](<https://codeforces.com/profile/pashka>)

**Tutorial**

Let's consider components of connected segments separately and solve the problem for each of these components. The answer will be product of answers over all components. How to calculate the answer for some component?

Let $[lf; rg]$ be the whole segment covered by the component. Let's do the following dynamic programming: $dp_{pos}$ is the number of ways to choose the subset of segments to cover all points in segment $[lf; pos]$. The base of this dynamic programming is $dp_{lf - 1} = 1$, other values of $dp$ are zeros. Let's choose the order in which we will consider segments. It is very intuitively that we need to consider all segments in order of non-decreasing of their left border (because we calculate the dynamic programming from left to right).

What should we do with the current segment ($l_i, r_i$)? Let's understand how it can affect the final answer. There are two cases: it can extend the covered segment or not extend it.

If it extends the segment then we can do the following transition: $dp_{r_i} = dp_{r_i} + \sum\limits_{j=l_i-1}^{r_i - 1} dp_j$. What it means? It means that the union of the considered subsets of segments should ends in at least in $l_i - 1$ (otherwise the segment $[lf; rg]$ will not be fully covered), but not righter than $r_i - 1$ (otherwise the segment ($l_i, r_i$) will not extend the covered segment). So all subsets of segments that ends in $[l_i - 1; r_i - 1]$ are suitable for this case.

The other case is when the current segment does not extend the covered segment. In this case we can multiply by two all values of $dp$ from $r_i$ to $rg$ inclusive (set $dp_j := 2 dp_j$ for each $j \in [r_i; rg]$). Note that you should firstly multiply the value of $dp_{r_i}$ by two and then do the first transition.

The answer for the component is $dp_{rg}$. Don't forget about the modulo!

The first thing is that this solution is bugged. It considers only integer points of union, but we need to consider all points of union. How can we avoid it? Just multiply all coordinates by two!

And notes about implementation: the first note is that the solution above is quadratic. Why is it quadratic? Because we don't need any points except $l_i - 1, l_i, l_i + 1$ and $r_i - 1, r_i, r_i + 1$ for each segment. So there are $O(n)$ points we consider and each transition can be done in $O(n)$. But this solution can be improved to $O(n \log n)$ using the very standard segment tree with lazy propagation. All operations we need is to multiplying by two on segment, getting the sum on segment and addition in point. And the second note is: if you don't want to write implicit segment tree, don't forget to compress coordinates.


**Solution**
```kotlin
import java.io.BufferedReader
import java.io.IOException
import java.io.InputStreamReader
import java.io.PrintWriter
import java.util.*

/
 * @author: pashka
 */

val MOD = 998244353L

internal class SegmentTree(private val size: Int) {

 private val sum = LongArray(4 * size)
 private val add = LongArray(4 * size)
 private val mult = LongArray(4 * size)

 public fun add(l: Int, r: Int, c: Long) {
 add(0, 0, size, l, r, c)
 }

 private fun add(n: Int, ll: Int, rr: Int, l: Int, r: Int, c: Long) {
 push(n, ll, rr)
 if (ll >= l && rr <= r) {
 add[n] += c
 sum[n] += c * (rr - ll)
 add[n] %= MOD
 sum[n] %= MOD
 } else if (ll >= r || l >= rr) {
 return
 } else {
 val m = (ll + rr) / 2
 add(n * 2 + 1, ll, m, l, r, c)
 add(n * 2 + 2, m, rr, l, r, c)
 sum[n] = (sum[2 * n + 1] + sum[2 * n + 2]) % MOD
 }
 }

 public fun mult(l: Int, r: Int, c: Long) {
 mult(0, 0, size, l, r, c)
 }

 private fun mult(n: Int, ll: Int, rr: Int, l: Int, r: Int, c: Long) {
 push(n, ll, rr)
 if (ll >= l && rr <= r) {
 mult[n] *= c
 add[n] *= c
 sum[n] *= c
 mult[n] %= MOD
 add[n] %= MOD
 sum[n] %= MOD
 } else if (ll >= r || l >= rr) {
 return
 } else {
 val m = (ll + rr) / 2
 mult(n * 2 + 1, ll, m, l, r, c)
 mult(n * 2 + 2, m, rr, l, r, c)
 sum[n] = (sum[2 * n + 1] + sum[2 * n + 2]) % MOD
 }
 }

 private fun push(n: Int, ll: Int, rr: Int) {
 if (rr - ll > 1) {
 val m = ll + rr shr 1
 for (i in 1..2) {
 mult[2 * n + i] *= mult[n]
 add[2 * n + i] *= mult[n]
 sum[2 * n + i] *= mult[n]
 add[2 * n + i] += add[n]
 sum[2 * n + i] += add[n] * (if (i == 1) (m - ll) else (rr - m))
 mult[2 * n + i] %= MOD
 add[2 * n + i] %= MOD
 sum[2 * n + i] %= MOD
 }
 }
 add[n] = 0
 mult[n] = 1
 }

 public fun sum(l: Int, r: Int): Long {
 return sum(0, 0, size, l, r)
 }

 private fun sum(n: Int, ll: Int, rr: Int, l: Int, r: Int): Long {
 push(n, ll, rr)
 if (ll >= l && rr <= r) {
 return sum[n]
 } else if (ll >= r || l >= rr) {
 return 0
 } else {
 val m = (ll + rr) / 2
 return (sum(n * 2 + 1, ll, m, l, r) + sum(n * 2 + 2, m, rr, l, r)) % MOD
 }
 }
}

private fun solve() {
 val n = nextInt()
 val l = IntArray(n)
 val r = IntArray(n)
 for (i in 0 until n) {
 l[i] = nextInt()
 r[i] = nextInt()
 }
 var all = l + r
 all.sort()
 var m = 1
 for (i in 1 until all.size) {
 if (all[i] != all[m - 1]) {
 all[m] = all[i]
 m++
 }
 }
 all = all.copyOf(m)
 for (i in 0 until n) {
```
