## 1533A - Travel to Bertown

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

To solve this problem, we can use an approach similar to finding the maximum element in the array. Initialize the answer with $0$, then run a loop for $i$ from $1$ to $n$. In this loop, if $k$ belongs to the segment $[l_i, r_i]$, then the answer should be updated with the value $r_i - k + 1$.


**Solution (Neon)**
```kotlin
fun main() = repeat(readLine()!!.toInt()) {
 val (n, k) = readLine()!!.split(" ").map { it.toInt() }
 var ans = 0
 repeat(n) {
 val (l, r) = readLine()!!.split(" ").map { it.toInt() }
 if (l <= k) ans = maxOf(ans, r - k + 1)
 }
 println(ans)
}
```

## 1533B - Nearest Point Function

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [vovuh](<https://codeforces.com/profile/vovuh>)
 
**Tutorial**

Of course, we can't choose such $y$ that $y \lt x_1$, $y \gt x_n$ or $y = x_i$ for some $i$, because there will be exactly one nearest point in the array $x$. So, we need to choose such $y$ that $x_i \lt y \lt x_{i + 1}$ for some $i$ from $1$ to $n-1$. To make both points $x_i$ and $x_{i + 1}$ nearest to the point $y$, we need to choose $y = \frac{x_i + x_{i + 1}}{2}$. But this is not always possible, because if $x_i$ and $x_{i + 1}$ have different parities, the value $y$ will be non-integer. So, all we have to do in this problem is to check if there is some pair $x_i$ and $x_{i + 1}$ that they have the same parity. If there is such a pair, we can break the function, otherwise we can't. Choosing non-adjacent values in $x$ is wrong, though, because if we choose such $x_i$ and $x_j$ that $|j - i| \gt 1$ then there will be other points from $x$ that are nearest to the point $y = \frac{x_i + x_j}{2}$ (i.e. either $x_i$ or $x_j$ will not be the nearest point to $y$ in such a case).

 
**Solution (vovuh)**
```kotlin
fun main() {
    val t = readLine()!!.toInt()
    repeat(t) {
        val n = readLine()!!.toInt()
        val x = readLine()!!.split(" ").map { it.toInt() }
        var ans = false
        for (i in 1 until n) {
            if ((x[i] - x[i - 1]) % 2 == 0) {
                ans = true
            }
        }
        println(if (ans) "YES" else "NO")
    }
}
```

## 1533C - Sweets

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

You have to simulate the process described in the statement. Let's consider one of the many approaches to the solution.

Let's store a boolean array $used$, where sweets will be marked (a sweet $i$ is marked if $used[i]$ is true) if Anya has already eaten them. As long as there is at least one index $i$, such that $s_i = 1$ and $used_i = false$, we choose the next sweet that Anya will eat. To find the next sweet, it is enough to run a loop that will find the $k$-th position from the previous one among the remaining sweets (i. e., those sweets whose values in $used$ are $false$).


**Solution (Neon)**
```kotlin
fun main() = repeat(readLine()!!.toInt()) {
 val (n, k) = readLine()!!.split(" ").map { it.toInt() }
 val s = readLine()!!
 val used = BooleanArray(n) { false }
 var cnt = s.count({ it == '1'})
 var pos = 0
 while (cnt > 0) {
 used[pos] = true
 if (s[pos] == '1') --cnt
 if (cnt == 0) break
 var lft = k
 while (lft > 0) {
 pos = (pos + 1) % n
 if (!used[pos]) --lft;
 }
 }
 println(used.count({ it }))
}
```

To answer a query, it is enough to iterate over a character we delete from the string given in the query, and then check whether the resulting string is in the given set of strings (which should be stored in some associative data structure, for example, in a Set). ## 1533E - Chess Team Forming

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [awoo](<https://codeforces.com/profile/awoo>)

**Tutorial**

Let's begin with solving the task for a single option in any complexity that's better than trying all permutations.

Let the members of the opposing team be sorted in a non-decreasing order. Consider some answer — a permutation of members of Polycarp's team.

It's claimed that the members of Polycarp's team also being sorted in a non-decreasing order is one of the optimal answers. Consider a permutation that isn't sorted. Look at the first inversion. So there is some position $i$ such that $a_i \gt a_{i+1}$, $b_i \lt b_{i+1}$, the contribution to the answer is $max(b_i - a_i, b_{i+1} - a_{i+1})$. However, $b_i - a_i$ is not smaller than $b_i - a_{i+1}$ and $b_{i+1} - a_{i+1}$ is not smaller than $b_{i+1} - a_i$. Thus, swapping $a_i$ and $a_{i+1}$ won't make the answer any larger. Continue swapping inversions until none are left.

That allows us to produce a solution in $O(n)$ per query: sort the members of Polycarp's and the opposing teams beforehand, find where to insert the new member and calculate the maximum in linear time.

Now observe the resulting pairs. For some prefix of the pairs, the matched ones are $a_i$ and $b_i$ after the sorting. For some suffix, they move no more than one position and matches $a_i$ with $b_{i+1}$. And there's an extra pair that contains an option player.

Thus, it's possible to prepare the prefix maximums of $b_i - a_i$, the suffix maximums of $b_{i+1} - a_i$, search for the insertion point with a binary search in $O(\log n)$ and combine the resulting parts in $O(1)$.

Overall complexity: $O((n + m) \log n)$.


**Solution (awoo)**
```kotlin
fun main() {
	val n = readLine()!!.toInt()
	val a = readLine()!!.split(" ").map { it.toInt() }.toIntArray()
	val b = readLine()!!.split(" ").map { it.toInt() }.toIntArray()
	val m = readLine()!!.toInt()
	val c = readLine()!!.split(" ").map { it.toInt() }.toIntArray()
	a.sort()
	b.sort()
	val pr = IntArray(n + 1) { -2e9.toInt() }
	for (i in 0 until n) {
 pr[i + 1] = maxOf(pr[i], b[i] - a[i])
	}
	val su = IntArray(n + 1) { -2e9.toInt() }
	for (i in (n-1) downTo 0) {
 su[i] = maxOf(su[i + 1], b[i + 1] - a[i])
	}
	val ans = IntArray(m)
	for (i in 0 until m) {
 var pos = a.binarySearch(c[i])
 if (pos < 0) {
 pos = -pos - 1
 }
 ans[i] = maxOf(pr[pos], su[pos], b[pos] - c[i])
	}
	println(ans.joinToString(" "))
}
```

## 1533F - Binary String Partition

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

We will solve the problem for each value of $k$ separately.

Note that there is an optimal partition where all $t_i$ (except the last one) contain exactly $k$ zeros or ones. Using this fact, we can find in which position the next block $t_i$ will end. The current block $t_i$ should end before it contains at least $k+1$ zeros and at least $k+1$ ones. To quickly find this position, you can use a binary search with prefix sums, or save all the positions of zeros (ones) in a separate array. Such a solution will work for $O(m)$ or $O(m \log{n})$ (depending on whether binary search is used), where $m$ is the number of strings in the partition.

For each $k$, the value of $m$ does not exceed $\frac{n}{2k+1}$ (because there are at least $2k+1$ elements in each block). This means that the sum of $m$ for all $k$ does not exceed $\sum\limits_{k=1}^{n} \frac{n}{k}$, which is estimated as $O(n \log{n})$, which means that the entire solution works for $O(n \log{n})$ or $O(n \log^2{n})$.

 
**Solution (Neon)**
```kotlin
fun main() {
  val s = readLine()!!.map { (it - '0').toInt() }.toIntArray()
  val pos = Array(2) { c -> s.indices.filter { s[it] == c }.toIntArray() }
  val sum = Array(2) { c -> s.runningFold(0) { cur, x -> cur + if (x == c) 1 else 0 }.toIntArray() }
  println((1..s.size).map { k -> 
    generateSequence(0) { i ->
      IntArray(2) { c -> pos[c].getOrElse(sum[c][i] + k) { s.size } }.maxOrNull()!!
    }.indexOf(s.size)
  }.joinToString(" "))
}
```

## 1533G - Biome Map

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

Note that if the available biomes do not form a $4$-connected region (which can be checked with a simple DFS), then the answer is $-1$, because we will not be able to fulfill either the second rule or the third rule. Otherwise, the answer always exists.

Here is one of the possible constructions. Our map will have a size of $k \times k$. Such a matrix has $2k-1$ diagonals, so if we can find a sequence of biomes of length $2k-1$, such that each biome belongs to the sequence and the third rule is met for any two neighboring biomes in the sequence, then we can fill the matrix by diagonals (the $i$-th diagonal will be filled with the $i$-th biome in the sequence). Such a sequence can be obtained by using a DFS traversal, writing out vertices when entering and returning to them.


**Solution (Neon)**
```kotlin
fun main() = repeat(readLine()!!.toInt()) {
 val (n, m) = readLine()!!.split(" ").map { it.toInt() }
 val a = Array(n) { readLine()!!.split(" ").map { it.toInt() } }
 val used = BooleanArray(111) { false }
 val ord = ArrayList<Int>()

 val dx = intArrayOf(0, 1, 0, -1)
 val dy = intArrayOf(1, 0, -1, 0)

 fun dfs(x : Int, y : Int) {
 ord.add(a[x][y])
 used[a[x][y]] = true
 for (i in 0 until 4) {
 val nx = x + dx[i]
 val ny = y + dy[i]
 if (0 <= nx && nx < n && 0 <= ny && ny < m && a[nx][ny] != 0 && !used[a[nx][ny]]) {
 dfs(nx, ny)
 ord.add(a[x][y])
 }
 }
 }

 var k = 0

 for (x in 0 until n) {
 for (y in 0 until m) {
 if (a[x][y] != 0) {
 k += 1
 if (ord.isEmpty()) dfs(x, y)
 }
 }
 }

 if (ord.count() != 2 * k - 1) {
 return@repeat println(-1)
 }

 println("$k $k")
 for (x in 0 until k) {
 for (y in 0 until k) {
 print("${ord[x + y]} ")
 }
 println()
 }
}
```

## 1533H - Submatrices

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

Let's iterate through the subset of the first $5$ letters and count the number of submatrices that contain only letters from this subset. To do this, create a matrix $a$ of size $n \times m$, where $a_{i, j} = 1$ if $s_{i, j}$ belongs to the fixed subset, and $0$ otherwise. Now, you have to calculate the number of submatrices that consist only of $1$'s in this matrix.

This can be calculated as follows. Let's iterate over the row $i$, it will be the lower boundary of the submatrix. Denote $d_j$ as the maximum value such that all $a_{k, j} = 1$ for $k \in (i - d_j, i]$ (build an array of these values). Using this array, let's calculate $l_j$ — the closest position to the left where the value in the array $d$ is strictly less than $d_j$, and $r_j$ — the closest position to the right where the value in the array $d$ is not greater than $d_j$. Then the number of unit submatrices where $i$ is the lower bound is $\sum\limits_{j=1}^{m} (j - l_j) * (r_j - j) * d_j$.

Thus, we have counted all the answers for subsets of letters, but these values are not exactly what we need to print (for example, if the submatrix contained $2$ different letters, then it will be taken into account in subsets of $3$, $4$ and $5$ letters that include these $2$ letters), but this is easy to fix with an approach similar to inclusion-exclusion. The final complexity of the solution is $O (2^5nm)$.

 
**Solution (Neon)**
```kotlin
fun main() {
  val AL = 5
  val (n, m) = readLine()!!.split(" ").map { it.toInt() }
  val s = Array(n) { readLine()!! }
  val res = LongArray(1 shl AL) { mask ->
    val d = IntArray(m) { 0 }
    var sum = 0L
    for (i in 0 until n) {
      for (j in 0 until m) {
        val cur = (mask shr (s[i][j] - 'A')) and 1 
        d[j] = if (cur == 1) d[j] + 1 else 0
      }
      val l = IntArray(m) { -1 }
      val q = IntArray(m) { 0 }
      var ptr = -1
      for (j in 0 until m) {
        while (ptr >= 0 && d[q[ptr]] >= d[j]) ptr -= 1
        if (ptr >= 0) l[j] = q[ptr]
        ptr += 1
        q[ptr] = j
      }
      val r = IntArray(m) { m }
      ptr = -1
      for (j in m - 1 downTo 0) {
        while (ptr >= 0 && d[q[ptr]] > d[j]) ptr -= 1
        if (ptr >= 0) r[j] = q[ptr]
        ptr += 1
        q[ptr] = j
      }
      for (j in 0 until m) sum += (j - l[j]) * (r[j] - j) * d[j].toLong()
    }
    sum
  }
  
  for (i in 0 until AL) {
    for (mask in 1 until (1 shl AL)) {
      if (((mask shr i) and 1) == 0) res[mask or (1 shl i)] -= res[mask]
    }
  }
  
  val ans = LongArray(AL + 1) { 0 }
  for (mask in 1 until (1 shl AL)) ans[mask.countOneBits()] += res[mask]
  
  println(ans.drop(1).joinToString(" "))
}
```

## 1533I - Excursions

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

There is a linear solution to this problem (which I'll describe briefly at the end of this editorial), but our model solution is $O(n^4)$, that's why the constraints are that low. Guess I'm much less smarter than the top participants, I didn't see any linear solutions before the contest.

Okay, my solution uses minimum cost flows (though it can be formulated with matchings as well). Suppose that all tourists from sight $j$ in Engels go to sight $i$ in Saratov. It means that for every sight $v$ in Saratov such that $v \ne i$ and there's a bus route from $v$ to $j$, we can send all tourists from the sight $v$ to the sight $j$, and they won't return to the same sight where they started. Let's say that the sight $j$ in Engels "fixes" the sight $v$ in Saratov, if all tourists from sight $v$ go to sight $j$ and don't return to the sight $v$. Obviously, each sight $j$ in Engels can fix at most $d_j - 1$ sights in Saratov, where $d_j$ is the number of bus routes going to the sight $j$. The answer to the problem is the minimum possible total number of people in the sights of Saratov that are not "fixed".

Let's build a flow network as follows: each sight is represented by a vertex; for every sight $j$ in Engels, there is an arc from the source to the vertex representing it with a capacity of $d_j - 1$ and a cost of $0$, meaning that this sight can "fix" up to $d_j - 1$ sights in Saratov; for every sight $i$ in Saratov, there is an arc from the vertex representing it to the sink with a capacity of $1$ and a cost of $-k_i$ (meaning that if the $i$-th sight in Saratov is "fixed", the cost of the flow reduces by $k_i$); and for every bus route connecting sight $x_i$ in Saratov and sight $y_i$ in Engels, there is an arc from the vertex representing $y_i$ to the vertex representing $x_i$ with a capacity of $1$ and a cost of $0$, meaning that the sight $y_i$ can "fix" the sight $x_i$.

Finding the minimum cost flow in this network allows us to "fix" the sights with the maximum possible number of people, so the answer is $\sum_{i = 1}^{n} k_i + cost$, where $cost$ is the cost of the flow.

A brief description of linear solution: let's build a bipartite graph representing the sights and bus routes (sights are represented by vertices, bus routes — by edges) and solve the problem for each component of this graph separately. It can be shown that if some component contains a cycle, all tourists in this component can be directed so that nobody returns to the same vertex where they started; otherwise, if a component doesn't contain any cycles, it's sufficient to choose the vertex of the left part with minimum possible $k_i$ in this component, and the tourists from this vertex will be the only ones which return where they started (all other tourists can be directed so that they move towards this chosen vertex).


**Solution (Neon)**

```kotlin
import java.util.Queue
import java.util.LinkedList

fun main() {
 val (n1, n2, m) = readLine()!!.split(" ").map { it.toInt() }
 val S = n1 + n2
 val T = S + 1
 val V = T + 1

 data class Edge(val y : Int, val c : Int, var f : Int, val cost : Int)

 val e = ArrayList<Edge>()
 val g = Array(V) { ArrayList<Int>() }

 fun addEdge(x : Int, y : Int, c : Int, cost : Int) {
 g[x].add(e.size)
 e.add(Edge(y, c, 0, cost))
 g[y].add(e.size)
 e.add(Edge(x, 0, 0, -cost))
 }

 var sum = 0
 readLine()!!.split(" ").mapIndexed { i, value ->
 val k = value.toInt()
 addEdge(i, T, 1, -k)
 sum += k
 }

 val deg = IntArray(n2) { 0 }
 repeat(m) {
 val (x, y) = readLine()!!.split(" ").map { it.toInt() - 1 }
 addEdge(y + n1, x, 1, 0)
 deg[y] += 1
 }

 for (i in 0 until n2) {
 addEdge(S, i + n1, deg[i] - 1, 0)
 }

 var mincost = 0

 fun enlarge() : Boolean {
 val q: Queue<Int> = LinkedList<Int>()
 val inq = IntArray(V) { 0 }
 val d = IntArray(V) { 1e9.toInt() }
 val p = IntArray(V) { -1 }
 val pe = IntArray(V) { -1 }

 q.add(S)
 inq[S] = 1
 d[S] = 0

 while (!q.isEmpty()) {
 val k = q.poll()
 g[k].forEach { a ->
 val (to, c, f, w) = e[a]
 if (c - f != 0 && d[to] > d[k] + w) {
 d[to] = d[k] + w
 p[to] = k
 pe[to] = a
 if (inq[to] == 0) {
 q.add(to)
 inq[to] = 1
 }
 }
 }
 }

 if (p[T] == -1) return false

 var cur = T
 while (cur != S) {
 mincost += e[pe[cur]].cost
 e[pe[cur]].f += 1
 e[pe[cur] xor 1].f -= 1
 cur = p[cur]
 }

 return true
 }

 while (enlarge());

 println(sum + mincost)

}
```

## 1533J - Pawns

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Firstly, let's drop the constraint that white pawns can only be in empty cells. We will solve the problem assuming that white pawns can share cells with each other and/or black pawns without any special effects.

Let's analyze the sequence of black pawns captured by some white pawn. Suppose that some white pawn captures some black pawn $i$, and then — some other black pawn $j$. Then the following condition should hold: $x_j \gt x_i$ and $|y_j - y_i| = 1$. So, if we build a directed graph such that each vertex represents a black pawn, and there is an arc from vertex $i$ to vertex $j$ if $x_j \gt x_i$ and $|y_j - y_i| = 1$, then each sequence of pawns captured by some white pawn is represented by a path in this graph, and similarly, each path in this graph represents a possible sequence of captures of some white pawn. Since we need to capture all of the black pawns using the minimum possible number of white pawns, it means that we should cover the vertices of this graph using the minimum possible number of non-intersecting paths. Since this graph is a DAG, this problem can be solved with maximum matching (we'll describe the solution and analyze how can it be improved a bit later).

We dropped the constraint that no cell can contain more than one pawn, but in fact, it doesn't change the answer. The only problem which can arise from this constraint is that we have to move white pawns in some sequence, and it's not always possible to move some white pawn (it can be blocked). If we want to move some white pawn to a position with a black pawn, let's move the pawn that will capture that black pawn first (and force it to capture that black pawn). If we want to move some white pawn to a position with another white pawn, we can assume that these pawns are "swapped" — the remaining parts of their paths can be interchanged, and the blocking white pawn can continue the path of the pawn we were considering.

Okay, now let's go back to the problem about covering a DAG, which can be solved with maximum matching. We have to build a bipartite graph, where each vertex of the original DAG is represented by two vertices: one vertex in the left part, and one vertex in the right part (let's denote the vertex representing $x$ in the left part as $x^-$, and the vertex representing $x$ in the right part as $x^+$). Each arc $i \to j$ of the original DAG should be represented by an edge connecting $i^-$ with $j^+$. So, the maximum matching in this bipartite graph corresponds to the set of arcs belonging to the paths we use to cover the DAG; and the more arcs belong to the paths — the fewer paths we need to cover everything.

Unfortunately, even building this bipartite graph is too slow, let alone running Kuhn (or any other matching algorithm) in it. Let's try to find the maximum independent set in this bipartite graph without actually building it. We will divide this graph into two independent sections:

- the first section contains the vertices $i^-$ for the pawns $i$ on odd verticals, and the vertices $j^+$ for the pawns $j$ on even verticals;
- the second section contains the vertices $i^-$ for the pawns $i$ on even verticals, and the vertices $j^+$ for the pawns $j$ on odd verticals.

No edge connects the vertices from different sections, so we can find the maximum independent set in each section separately. The main idea that will allow us to do it in $O(n \log n)$ is the following one: if a vertex $i^-$ on some vertical belongs to the maximum independent set, all vertices above it on the same vertical should also belong to the maximum independent set. Similarly, if a vertex $j^+$ on some vertical belongs to the maximum independent set, then all vertices below it on the same vertical should belong to the maximum independent set as well. This allows us to solve the problem for one section using the following dynamic programming: $dp_{a,b}$ is the maximum possible number of vertices in the maximum independent set if we considered $a$ first verticals, and took $b$ top/bottom pawns on the last vertical into our independent set. It's quite easy to recalculate this dynamic programming for the next vertical using sweepline approach.

 
**Solution (Neon)**
```kotlin
fun main() {
  val N = 500043
  val n = readLine()!!.toInt()
  val pts = Array(N) { ArrayList<Int>() }
  repeat(n) {
    val (x, y) = readLine()!!.split(" ").map { it.toInt() }
    pts[y].add(x)
  }
  pts.forEach { it.sort() }
  
  data class Event(val y : Int, val t : Int, val value : Int)
  
  fun recalc(v1 : ArrayList<Pair<Int, Int>>, v2 : ArrayList<Int>, flag : Boolean) : ArrayList<Pair<Int, Int>> {
    val events = ArrayList<Event>()
    if (flag) {
      v1.forEach { events.add(Event(it.first, 0, it.second)) }
      v2.forEachIndexed { i, value -> events.add(Event(value, 1, i + 1)) }
      events.add(Event(0, 1, 0))
      events.sortWith(compareBy({ -it.y }, { it.t }, { it.value }))
```
