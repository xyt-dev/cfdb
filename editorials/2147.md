## 2147A - Shortest Increasing Path

This problem is about handling cases.

The main solution is to quickly realize that $x \lt y$ can be done in 2 moves and $x \gt y+1$ with $y \gt 1$ in 3. You can guess that other cases are impossible.

Using two moves, we can move to any ($x$,$y$) with $x \lt y$ by first moving $x$ and then $y$. Using 3 moves $0 \lt a \lt b \lt c$ we get to ($a+c$,$b$) as follows: first to ($a$,$0$), then to ($a$, $b$), and then to ( $a+c$, $b$). Without loss of generality we can subtract $1$ from $a$ and add $1$ to $c$ anytime so we can assume $a=1$ and hence we can reach ($x$, $y$) in $3$ moves if and only if $x \gt y+1$ and $y \gt 1$.

Now assume we can reach some ($x$, $y$) with $k \gt 3$ jumps. The last two jumps can be merged with the previous 2 jumps giving a solution with $k-2$ jumps. Hence any other case is impossible.

## 2147B - Multiple Construction

There are multiple ways to solve this problem. We believe the easiest one is based on the following construction:

[ n, n-1, n-2, ..., 3, 2, 1, n, 1, 2, 3, ..., n-2, n-1 ]

It's easy to see that both occurrences of $n$ are at a distance of $n$, and all the other values appear at a distance of twice their value. In other words, we place the two $n$'s at the first position and at the $(n+1)$-th position, then we use the second $n$ as a pivot to place numbers from $1$ to $n-1$ in order.

There exist other constructions as well. For example, for $n$ odd, we can use:

[ 1, n-2, n-4, ..., 3, n, 1, 3, 5, ..., n-2, n-1, n-3, ..., 2, n, 2, ..., n-3, n-1 ]

For $n$ even, the pattern is similar but we adjust the positions of $n-1$ and $n-2$ accordingly.

A greedy algorithm also works: we go from $n$ to $1$, and try to place each number in the leftmost possible position. Note that this greedy algorithm follows the same pattern as the first construction.

  ios::sync_with_stdio(false); cin.tie(nullptr);
 
  cin >> t;
  while (t--) {
    cin >> n;
    for (int i = n; i >= 1; i--) {
      cout << i << " ";
    }
    cout << n;
    for (int i = 1; i < n; i++) {
      cout << " " << i;
    }
    cout << "\n";
  }
}

## 2147C - Rabbits

The first observation is to notice that every substring "11" splits the problem into two subproblems since rabbits on opposite sides cannot interact with each other. For instance, in the string $0110$, the rabbits placed in positions $1$ and $4$ cannot interact with each other.

The second observation is that if we split the string in a way such that each subproblem does not contain two consecutive $1$'s, the string $101010 \dots 0101$ (no consecutive 0's) is solvable iff the number of 0's is even since we can match the rabbits in the following way $1R1L1R \dots R1L1$ (where $R$ means that we place a rabbit looking to the right and $L$ means that we place a rabbit looking to the left).

The last observation is that if we have two consecutive $0$'s, we can split the problem using them in a way that every subproblem looks like this alternating pattern ($101010 \dots 0101$) with an odd number of $0$'s. Thus, the only thing we need to look for is a substring with this alternating pattern that has an odd number of zeros.

We should also take care of boundary conditions. If the string starts or ends with a zero, we can ignore that position by placing the rabbit looking towards the border; these cases were present in the sample tests.

Alternatively, we can solve the problem using a dp that considers $dp_{i, L}$ = Is it possible to solve the prefix ${0, 1, \dots, i}$ placing the rabbit in position $i$ looking to the left, and $dp_{i, R}$ defined in the same way.

#include <bits/stdc++.h>
using namespace std;

void solve() {
	int n; cin >> n;
	string s; cin >> s;
	bool ok = true;
	bool curr = (s[0] == '1');
	int cnt = 0;
	for (int i = 0; i < n; i++) {
 if (s[i] == '0')
 cnt++;
 if (i == 0)
 continue;
 if (s[i] == s[i-1] && s[i] == '0')
 curr = false;
 if (s[i] == s[i-1] && s[i] == '1') {
 if (curr && cnt % 2 == 1)
 ok = false;
 curr = true;
 cnt = 0;
 }
	}

	if (curr && cnt % 2 == 1 && s[n-1] == '1')
 ok = false;

	cout << (ok ? "YES" : "NO") << "\n";
}

## 2147D - Game on Array

Let's separate odd and even numbers. One can intuitively see that it is bad to choose $x$ even since right after the other player can choose $x-1$ and get at least as many points as you did. This however is not true for odd numbers since after picking $x=1$ the opposite player cannot pick $x=0$.

Let the frequencies of the odd numbers (sorted) be $f_0 \geq f_1 \geq \ldots \geq f_k$. We claim that the difference in points between players will be $S = \sum_{i=0}^k (-1)^i f_i$. The following strategy gets at least $S$ points difference: if $k \gt 0$ choose $f_0$, otherwise choose any $x$. Now there are 3 cases.

- If player 2 chooses $f_i$ with odd $i$ you have by induction exactly $S$ points difference at the end.
- If player 2 chooses $f_i$ with even $i$ you can choose $f_{i-1}$ and by induction end up with $S - f_i+f_{i-1} \geq S$ difference at the end.
- If player 2 chooses an even $x$, copy and take $x-1$. Repeat until player 2 chooses an odd $x$. During this process you will have collected some (possibly 0) $f_i$'s and after that you will also get the alternating sum of the remaining $f_i$. Assume you remove one $f_i$ from $f$ to collect $f_i$ points. If $i$ is even, all $f_j$ signs for $j \gt i$ will be changed so you end up with $S + 2\sum_{j=i+1}^k(-1)^{j-(i-1)}f_j \geq S$. If $i$ is odd, all $f_j$ signs will be changed for $j\geq i$ so you end up with $S + 2\sum_{j=i}^k(-1)^{j-i}f_j \geq S$ which is at least $S$ in any case.
 This bound is also an upper bound since player 2 gets at least $-f_0 + \sum_{i=1}^k (-1)^{i-1} f_i = -S$ points using this same strategy.

## 2147E - Maximum OR Popcount

First of all, the answer is bounded by $31$ because the maximum number that can appear in the array is: $2 \cdot 10^{9}$ and $2^{30} \leq 2 \cdot 10^{9} \lt 2^{31}$ so the only bits that can be set on are bits $0$ through $30$, giving a maximum of $31$ bits on.

Following the idea given by the hints, we will show that the following greedy algorithm is optimal for obtaining $k$ more $1$s in the bitwise or.
```
let p be the position of the k-th least significant zero
for each bit from the p-th to the 0th:
  if it is not already set in the bitwise or:
    increase any number which is the closest
    to having that bit on to turn that bit on
```

We will prove this is optimal by contradiction. Suppose there is a better sequence of operations that uses the minimum number of operations possible and that isn't the same as the one obtained via the greedy algorithm. We'll call it the good sequence. Let's consider the bitwise or.

- It must have exactly the same number of bits on. Suppose not. The bitwise or can only increase by one with the operation, and therefore the good strategy must have passed through a state with fewer steps and the same number of bits on, which is impossible by the construction of the good strategy.
- It must have exactly the same bits on. Suppose not. Take any bit $x$ which is set to $1$ by the good strategy and isn't set to $1$ via the greedy strategy. Since the greedy strategy keeps bits set to $1$ always set to $1$, and since it turns on all bits from the $p$-th to the $0$-th, then we obtain: The good strategy sets a bit to $1$ that is left of the $k$-th one and that wasn't $1$ originally. Therefore, it must have increased some number to turn on that bit, but before turning on that bit, it must have passed through a state where all the lower bits than that $x$ are $1$ and all the upper ones are kept the same. Consider the strategy where we only perform the increments on that number up to that point. It is better than the good strategy but gets enough bits, which is also a contradiction.
- We can assume that the highest bit was obtained in the same way as the greedy solution. First of all, we can ignore all bits higher than the $p$-th one. Why is that? Because we will never increase a number from $2^{p+1}-1 \pmod{2^{p+1}}$ to $0 \pmod{2^{p+1}}$. We can show this with the same argument as in the previous point. Now, suppose in the good strategy we increment $a_i$ to turn on the $p$-th bit, but in the greedy strategy we increment $a_j$ instead. Then, increasing $a_j$ to the final value of $a_i$ in the good strategy and $a_i$ to the final value of $a_j$ in the good strategy (we can do that because we know $a_i \leq a_j$ thanks to the greedy algorithm) takes the same number of steps. From now on, we can assume that the good algorithm is the previous good algorithm after making that change.
- By induction, we can extend the argument to the rest of the bits. The full argument of the previous point applies.

Therefore, it turns out that the good strategy is as good as the greedy strategy, so there's a contradiction and the greedy algorithm is optimal.

Let $b = 31$, the number of bits we need to check.

We have to execute the greedy algorithm at most $b$ times, each time we iterate over $\mathcal{O}(b)$ bits and find the best element via a trivial $\mathcal{O}(n)$ search over the array.

Whenever we need to calculate the bitwise or of all elements we can do it simply by iterating for all elements, the complexity won't increase.

To get the answer, we can iterate over all possible answers and see if we have enough operations. We can even do binary search in $\mathcal{O}(q log (b))$.

The final time complexity is $\mathcal{O}(n b^2 + q log (b))$.

## 2147F - Exchange Queries

Let's look at the SCCs. Clearly we have a tournament graph as a subgraph, so SCCs are in a line (and from the right one you can go to the left ones). But for us to be not able to go from left to right, all the priorities on the left must be smaller than all the priorities on the right. So there is a cut between SCCs iff numbers [$1$, $x$] take the same set of positions in both priority permutations (and, therefore, numbers [$x + 1$, $n$] too).

Let's call this situation a cut in value $x$. If we have an item with priorities ($p_i$, $q_i$) (WLOG $p_i \leq q_i$), there can't be a cut in value $x$ for $p_i \leq x \lt q_i$. If we mark all the values where a cut cannot be, in all the remaining values there is a cut. So let's maintain a segment tree on values where in each position we will store how many times it is banned then each item gives a $+1$ on segment. Every swap is a change of two of the segments so we can update it by removing both old segments and adding both new segments. We are interested in positions of $0$s but all the values are non-negative, so $0$s are minimums (if they exist) so we can store a segment tree on minimum with add on segment tree to find strongly connected components.

Let the sizes of the SSCs be $s_1, s_2, ... s_k$. The answer to the problem is $n + \binom{n}{2} + \sum \binom{s_i}{2}$. We will enhance the segment tree to calculate this value. Maintain for every node the minimum value, the leftmost position of the minimum value, the rightmost position of the minimum value and $\sum_{i = 1}^t \binom{j_i - j_{i-1}}{2}$ where $j_0, j_1,...j_t$ are the positions of the minimum values. Now merging is straight-forward and the value at the root node gives the answer to the problem.

## 2147G - Modular Tetration

Suppose $a \gt 1$ and $\gcd(a,m) = 1$. Observe that the sequence $b$ is of the form $a^{a^N}$ for a very big $N$ after $n \gt 3$. So $b_n \equiv 1 \pmod m$ is equivalent to $a^N \equiv 0 \pmod {ord_m(a)}$. Since $N$ goes to infinity as $n$ increases, it is equivalent to the condition $\forall p| ord_m(a), p| a$ or $rad(ord_m(a))|a$. This implies that solutions are periodic: if $a$ is a solution, so is $a+m \cdot ord_m(a)$, hence $m \varphi(m)$ is a period. Fixing an $1\leq a \lt m$ try to find numbers of the form $a+ \lambda m$ such that $rad(ord_a(m))| a+\lambda m$. Since $gcd(a,m)=1$, as long as $\gcd(ord_a(m),m) = 1$ we have by CRT that there exists a unique $\lambda$ modulo $rad(ord_m(a))$ that satisfies that condition. Finally, grouping solutions by their order, the density can be written as follows: $$\frac{1}{m} \sum_{x | \varphi(m), \gcd(x,m)=1} \frac{cnt(x)}{rad(x)}$$ Where $cnt(x)$ is the number of values $a$ that have order exactly $x$. The sum is over divisors of $\varphi(m)$ since orders must divide it.

We are close to a $O(d(m))$ solution. The values of $cnt(x)$ are well known for odd prime power modulos: there are $\varphi(x)$ values $a$ with order exactly $x$ modulo $p_i^{\alpha_i}$ (and powers of $2$ do not matter since the order has to be coprime with $m$). Using that $ord_{xy}(a) = lcm(ord_x(a), ord_y(a))$ one can compute $cnt$ and have a $O(d(m))$ solution. This is however not enough to pass since there are $T = 10000$ tests.

So we had that the answer is $\frac{1}{m} \sum_{x | \varphi(m), \gcd(x,m)=1} \frac{cnt(x)}{rad(x)}$ Where $cnt$ is the number of values a that have order exactly $x$. Our goal is to fix $rad(x)$ and compute $\sum cnt(x)$ over $x$'s such that $rad(x) = k$. There might be an easier way to derive it but the following works: denoting $q_i$ the primes of $k$ and $q_i^{\beta_i}$ the exponents of $q_i$ in $\varphi(m)$, $$ \sum_{x|\varphi(m), rad(x) | k} cnt(x) = \sum_{d_1| q_1^{\beta_1}, \ldots , d_t | q_t^{\beta_t}} \prod \varphi(d_i) $$ $$= \prod_i \sum_{d | q_i^{\beta_i}} \varphi(d) $$ $$= \prod q_i^{\beta_i} $$ Möbius inversion (or inclusion exclusion) gives $$\sum_{x|\varphi(m), rad(x) = k} cnt(x) = \sum_{I \subset [t]} (-1)^{t-|I|}\prod_{i \in I}q_i^{\beta_i} = \prod (q_i^{\beta_i}-1)$$ So the answer can be written as $$\frac{1}{m} \sum_{I \subset [t]}\sum_{rad(x) = \prod q_i} \frac{\prod {(q_i^{\beta_i} -1)}}{\prod q_i }$$ Which can be factored as $\frac{1}{m} \prod (1 + \frac{q_i^{\beta_i}-1}{q_i})$, the product is over all prime factors $q_i^{\beta_i}$ of $\varphi(m)$ that are not of $m$. This formula can be computed in $O(\log m)$ by factoring $m$ and $\varphi(m)$.

## 2147I1 - Longest Increasing Path (Easy Version)

We like to motivate the solution in the following way. Consider the problem in 2D. One of the first things one might try is to put the points in an almost regular polygon (a polygon such that each edge is $\epsilon$-larger than the previous edge) and get a solution $n \approx m\log m$ by doing loops around the polygon skipping $i$ points per jump on the $i$-th loop. It gets about $\lfloor n/i \rfloor$ jumps on the $i$-th loop so about $m \log m$ in total.


![](eimages/2147_1.png)

 So the idea is to project the points into the $x$ axis in a way that each edge is also $\epsilon$-larger than the previous edge (or at least most of them). There are many ways to do that but one way is to choose some big integer distance $C$ and add first $\frac{m}{2}$ points from left to right where adjacent distances will be $C+1, C+2, C+3, \ldots C+\frac{m}{2}$ and then another $\frac{m}{2}$ points from right to left such that their distance from the previous added point is $C+\frac{m}{2} +1,C+\frac{m}{2} +2, \ldots , C+m$.
With this construction, we will do the following algorithm. Fix a step size $k = 0$. For each step size $k$ move from left to right skipping $k$ points each jump and then from right to left skipping $k$ points per jump until no jumps are possible. Then increase $k$ by $1$ and repeat. This gets at least $m\log m -3m$ jumps.

Proof for mlogm -3m bound (although in practice its like mlogm -1.5m)

For a fixed $k$, the previous step was $k-1$ so we are standing at one of the first $k-1$ points and we will keep jumping until we reach one of the last k positions. That is, $\lfloor \frac{\frac{m}{2}-k}{k} \rfloor = \lfloor \frac{m}{2k}\rfloor -1$ jumps worst case and $\lfloor \frac{m}{2k}\rfloor-0.5$ in average. Assume for a moment that we can turn from going right to going left without increasing k. Then each of those terms can be counted twice, giving $$\sum 2\lfloor \frac{m}{2i}\rfloor - 2m$$ Finally $2\lfloor \frac{x}{2}\rfloor \geq \lfloor x\rfloor-1$ (though half the time $2\lfloor\frac{x}{2}\rfloor=\lfloor x \rfloor$). So bound is $\sum \lfloor\frac{m}{k}\rfloor-3m \approx m \log m - 3m$ but in average $m \log m-1.5m$

Let's prove we can turn without having to increase $k$. Let the last few jumps before turn be the following picture.


![](eimages/2147_2.png)

 Black are jumps of step size $k$ (skipping $k$ points not drawn), red distance is the skip we want to perform and letters denote the actual real distance between each jump. So we need to prove $b \lt r \lt f$. First, $b \lt r$ is trivial. Let $t \lt k$ be the skip distance in points of the last black arc. $$f-e= \sum_k (D+k+i) - \sum_k(D+i) = k^2$$ $$d-c= tk$$ $$r= e+d-c = f-k^2 +tk^2 = f - k(k-t) \lt f$$ Hence we can turn back and keep jumping with the same length.
For $m = 15000$, $m\log m \approx 145000$ so this solves the easy version with some margin.

## 2147I2 - Longest Increasing Path (Hard Version)

First, consider the following construction that does about $2m$ jumps: Choose $t$ and place $t$ points in arithmetic progression (we call it a cluster), then two points in the middle (called standard pivots) and another t points in another cluster to the right. If you start from the rightmost point in the left cluster, you can keep jumping between clusters using one of the pivots points. In total you do $4t-2$ jumps. The following image is with $t = 3$.


![](eimages/2147_3.png)


If you are standing at some vertex of a cluster but it is not the rightmost one, you can use one extra point as auxiliary to then move to another point in the cluster in 2 moves. Call those points directional pivots.

Now, given two clusters of size $t$ far away enough, by adding two standard pivots and maybe a directional pivot we will do at least $4t-2$ jumps ($4t$ if directional pivot is used) by adding at most 3 extra points.

Now suppose we are given a construction with $m'$ different points and $g(m')$ jumps. Intuitively, we can convert every point into a cluster of $t$ points $\epsilon$-distance apart from each other and for every jump in the construction, add at most 3 new points to get extra $4t-2$ jumps. That is, we can use the construction to find another construction for $m = tm' +3g(m')$ that does $(4t-2)g(m')$ jumps.

In practice, recursively compute the solution for $m'$ and scale up all points by a large enough factor $C$ and build a cluster of $t \gt 1$ points near every point in the given construction. For every jump in the given construction, now we can add two standard pivots and (if needed) a directional pivot such that for every old jump now we do at least $4t-2$ jumps.

Now for a given $m$ we want to find the best ($t$, $m'$). To do this we can run a DP. Let $g[m]$ be the maximum number of jumps we currently can do with $m$ different points.

Iterate over $m'$ and then over $t$ updating $$g[tm'+3g[m']] \geq (4t-2)g[m']$$ This takes $O(m \log m)$ since it's the harmonic sum.

Apart from this, maintain for each $m$ the value $t$ that was used. Now, when given $m$, you can instantly find the best ($t$, $m'$) according to the DP, recursively compute the answer for $m'$ and apply the clustering construction we mentioned.

This gives about $200k$ jumps if applied naively with base cases for $2$, $3$. To get the $300k$ (AC), it is needed to precompute the best possible configurations for $m = 2,3,4, \ldots ,7$. It can be done in many smarter ways, but one way is to run a naive $O(m^3)$ DP on randomly generated points in [$0$, $50$] until it finds a good enough answer.
