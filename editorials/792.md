## 792B - Counting-out Rhyme

The task was just about implementing algorithm described in statement.

This is one of many possible ways of doing this. Firstly you should notice that doing *a*<sub>*i*</sub> iterations in *i*-th step is equal to doing *a*<sub>*i*</sub> *mod* (*n* - *i*) iterations (0-based numbering). That is less than *n*.

Now fill array of length *n* with ones and create pointer to current leader. Then on *i*-th step move pointer to the right (from cell *n* - 1 proceed to 0) till you encounter *a*<sub>*i*</sub> *mod* (*n* - *i*) ones. When finished, write 0 to this cell and move pointer to next cell which contains 1.

Overall complexity: *O*(*n*<sup>2</sup>).

## 792C - Divide by Three

Let's declare a function which takes number as a string and erases minimal number of digits in substring from 2-nd to last character to obtain beautiful number.

Note that if the answer for given string exists, then this function will erase no more than 2 digits. If the number is divisible by 3 then sum of its digits is also divisible by 3. So here are the only options for the function:

- Sum of digits is already equal to 0 modulo 3. Thus you don't have to erase any digits.
- There exists such a digit that equals sum modulo 3. Then you just have to erase this digit.
- All of the digits are neither divisible by 3, nor equal to sum modulo 3. So two of such digits will sum up to number, which equals sum modulo 3 ((2 + 2) *mod* 3 = 1, (1 + 1) *mod* 3 = 2).

Let positions of non-zero numbers be *a*<sub>1</sub>, *a*<sub>2</sub>, ..., *a*<sub>*k*</sub>. Then you can easily see that its enough to check only three function outputs: on substrings [*a*<sub>1</sub>..*n*], [*a*<sub>2</sub>..*n*] и [*a*<sub>3</sub>..*n*]. We imply that all digits to the left of the taken non-zero digit are erased. As we can erase no more than 2 digits, these options will cover all the cases.

If there exists no answer for any of substrings, than you need to check if the number contains 0 — it will be answer in that case. If there is no 0, then answer is  - 1.

Otherwise the answer is the function output of maximal length.

Overall complexity: *O*(*n*).

## 792D - Paths in a Complete Binary Tree

In this editorial *x* represents the number of vertex we are currently in.

Let *k* be the maximum integer number such that *x* is divisible by 2<sup>*k*</sup> (or the number of zeroes at the end of the binary representation of *x*). It is easy to prove that if *k* = 0, then *x* is a leaf; if *k* = 1, then both children of *x* are leaves, and so on. Even more, the difference between *x* and any of his children is exactly 2<sup>*k* - 1</sup>. So to traverse to the left child, we have to subtract 2<sup>*k* - 1</sup> from *x* (if *x* is not a leaf), and to traverse to the right child, we add 2<sup>*k* - 1</sup> to *x*.

How can we process traversions up? Let *y* be the number of the parent node. *y* has exactly *k* + 1 zeroes at the end of its binary representation, so to traverse from *y* to *x*, we need to either add or subtract 2<sup>*k*</sup> from *y*. And to traverse from *x* to *y* we also have to either subtract or add 2<sup>*k*</sup> to *x*. One of these operations will lead us to the number divisible by 2<sup>*k* + 1</sup> and not divisible by 2<sup>*k* + 2</sup>, and we need to choose this operation.
