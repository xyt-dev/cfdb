Note that $67$ is a prime number. Therefore, if you want a number of elements to have a product of $67$, at least one of them must be $67$. And if there is $67$ in the sequence $a$, you know that you can select that element to make $67$.

Therefore, you can simply check if $67$ appears in the sequence $a$.

Alternatively, you can run an algorithm similar to knapsack to get a solution in $\mathcal{O}(67n)$, but this is overkill compared to the intended solution.

**

Let us look at which elements can be rearranged freely:

- $a_1,a_2,a_4,a_8,\ldots$ can be rearranged freely;
- $a_3,a_6,a_{12},\ldots$ can be rearranged freely;
- $a_5,a_{10},\ldots$ can be rearranged freely;
- $a_7,a_{14},\ldots$ can be rearranged freely;
- $\ldots$

The lexicographically smallest achievable sequence would be found by sorting each of those subsequences one by one. You can achieve an $\mathcal{O}(n)$ solution by checking if each of the subsequences can be sorted into the elements required in those positions.

However, a solution under the given constraint does not have to be too complex. In fact, even if you sort each subsequence using bubble sort, the worst case time complexity would be $\mathcal{O}(n \log n)$. Remember that the longest one of these subsequences (containing $a_1$) has length $\left \lfloor \log_2 n \right \rfloor + 1$. Let's place squares with side length equal to subsequence length aligned to the $x$-axis. Then, these squares would easily fit in a rectangle of width $n$ and height $\left \lfloor \log_2 n \right \rfloor + 1$. Therefore, the sum of $k^2$ over all subsequence lengths $k$ follows $\mathcal{O}(n \log n)$ asymptotically.


![](eimages/2195_1.png)

 The proof for bubble sort working in $\mathcal{O}(n \log n)$ time on $n=15$
The problem is solved in $\mathcal{O}(n \log n)$ time.

 
**Code**
```cpp
#include<bits/stdc++.h>
using namespace std;
using ll=long long;

int main()
{
  cin.tie(0)->sync_with_stdio(0);
  int t;cin>>t;
  while(t--)
  {
    int n;cin>>n;
    vector<int>a(n+1);
    for(int i=1;i<=n;i++)
    {
      cin>>a[i];
    }
    for(int i=1;i<=n;i+=2)
    {
      for(int j=i;j<=n;j*=2)
      {
        for(int k=i*2;k<=n;k*=2)
        {
          if(a[k/2]>a[k])swap(a[k/2],a[k]);
        }
      }
    }
    if(is_sorted(begin(a),end(a)))cout<<"YES\n";
    else cout<<"NO\n";
  }
}
```

## 2195C - Dice Roll Sequence
**Rate the problem!**

Note how two integers $s$ and $t$ are on adjacent sides if $s \neq t$ and $s+t \neq 7$.

Now we introduce a simple observation derived from the dice itself:

- Theorem 1: For any two sides $S$ and $T$: there is a third side $U$ adjacent to both.

This can be shown in a case-work manner:

- If $S$ and $T$ are adjacent, $U$ is any side that shares a corner with $S$ and $T$.
- If $S=T$, $U$ is a side adjacent to $S$.
- If $S$ and $T$ are opposite to each other, any other side can be $U$.

Let's split the sequence $a$ into subsegments made of two opposite sides of the dice. For example, $[1,6,1,1,2,5,2,5,2,3,4,1,1]$ becomes $[1,6,1,1]+[2,5,2,5,2]+[3,4]+[1,1]$.

For each subsegment of $k$ indices, you need to change at least $\left \lfloor k/2 \right \rfloor$ indices to fix it. For example, $[1,6,1,1]$ can be turned into $[1,\color{red}{5},1,\color{red}{3}]$, and $[2,5,2,5,2]$ can be turned into $[2,\color{red}{4},2,\color{red}{4},2]$.

Then, there is always a way to use exactly $\left \lfloor k/2 \right \rfloor$ indices to remove all violations in this subsegment without making new violations. For odd $k$, changing the $\left \lfloor k/2 \right \rfloor$ indices greedily removes all violations in the subsegment without causing new violations. For even $k$, you can change all elements on odd indices. Now you will never use two adjacent indices at the same time, and each used index fixes violations with both of its adjacent elements.

Thus, after splitting the sequence, we have a lower bound which is always achievable, and the problem is solved in $\mathcal{O}(n)$ time.

Alternatively, there are DP solutions that work in $\mathcal{O}(n)$ time; feel free to use them if they are easier for you.


**Code**
```cpp
#include <bits/stdc++.h>
using namespace std;

typedef long long int ll;

void solve() {
 int n;
 cin >> n;
 vector<int> a(n);
 for (int i = 0; i < n; i++) cin >> a[i];

 int ans = 0;
 for (int i = 1; i < n; i++) {
 if (a[i] + a[i-1] == 7 or a[i] == a[i-1]) ans++, i++;
 }

 cout << ans;
}

int main() {
 ios::sync_with_stdio(0); cin.tie(0);
 ll tc = 1;
 cin >> tc;
 for (ll i = 1; i <= tc; i++) {
 solve();
 cout << '\n';
 }
}
```

**

Let's plot the graph for $y=f(x)=\sum_{i=1}^n a_i \cdot |i-x|$ and look at the slopes. How is the $a_i \cdot |i-x|$ term different from all of the other terms?

In the function $f(x)$, the only term that changes slope at $x=i$ is the $a_i \cdot |i-x|$ term. In other words, the slope difference near $x=i$ is related to $a_i$. Let's do some math with these slopes.

- The slope left to $x=i$ is $f(i)-f(i-1)$;
- The slope right to $x=i$ is $f(i+1)-f(i)$;
- We know that the slope changed by $2a_i$ near $x=i$;
- Therefore, $a_i = \frac{(f(i+1)-f(i))-(f(i)-f(i-1))}{2} = \frac{f(i+1)+f(i-1)-2f(i)}{2}$ when $1 \lt i \lt n$.

Now we know $a_2,a_3,\ldots,a_{n-1}$. How about $a_1$ and $a_n$? Let's define a new function as follows.

$$g(x)=a_1 \cdot |1-x| + a_n \cdot |n-x|$$

One value of $g(x)$ can be found in $\mathcal{O}(n)$ time by subtracting $n-2$ terms from $f(x)$.

Now note the following:

- $g(1) = (n-1) \cdot a_n$;
- $g(n) = (n-1) \cdot a_1$.

Therefore, $a_1$ and $a_n$ can be found from $g(1)$ and $g(n)$ in $\mathcal{O}(n)$ time.

 
**Code**
```cpp
#include<bits/stdc++.h>
using namespace std;
using ll=long long;
 
vector<ll>solve(ll n,vector<ll>f)
{
  vector<ll>vec(n);
  for(int i=1;i+1<n;i++)
  {
    if((f[i+1]+f[i-1]-2*f[i])%2!=0)return {};
    vec[i]=(f[i+1]+f[i-1]-2*f[i])/2;
    if(abs(vec[i])>1000)return {};
  }
  auto g=[&](ll j)
  {
    ll w=f[j];
    for(int i=1;i+1<n;i++)
    {
      w-=vec[i]*abs(i-j);
    }
    return w;
  };
  ll g1=g(0),gn=g(n-1);
  if(gn%(n-1)!=0)return {};
  if(g1%(n-1)!=0)return {};
  vec[0]=gn/(n-1);
  vec[n-1]=g1/(n-1);
  if(abs(vec[0])>1000||abs(vec[n-1])>1000)return {};
  return vec;
}

int main()
{
  int t;cin>>t;
  while(t--)
  {
    ll n;cin>>n;
    vector<ll>f(n);
    for(ll&i:f)cin>>i;
    auto a=solve(n,f);
    assert(a.size()==n);
    for(int i=0;i<n;i++)cout<<a[i]<<" \n"[i+1==n];
  }
}
```

## 2195E - Idiot First Search
**Rate the problem!**

- [ * * ](<https://codeforces.com/data/like?action=like>) Moderate

Can we recursively define Bob's path? Say, what happens when Bob moves to a vertex $v$ and then its subtree was empty? Then, he must traverse the entire subtree and then move up to the parent.

Note the following things:

- When he started on vertex $k$, its subtree was empty.
- When he traverses the entire empty subtree of $v$ and moves up to the parent, the subtree of $v$ becomes empty again.

Let's define $\mathtt{dp}_1[v]$ as the time to traverse the subtree of $v$ and move to the parent. Then $\mathtt{dp}_1$ can be computed using a simple "bottom-up" DP on tree. If $v$ is a leaf, then $\mathtt{dp}_1[v]=1$. Otherwise, it satisfies $\mathtt{dp}_1[v]=\mathtt{dp}_1[l_v]+\mathtt{dp}_1[r_v]+3$.

Now, Bob's path from vertex $v$ to vertex $0$ is as follows:

$$v \to \ldots \to v \to p(v) \to \ldots \to p(v) \to p(p(v)) \to \ldots p(p(v)) \to \ldots \to 0 $$

Therefore, Bob's path can be described by values of $\mathtt{dp}_1$ from vertex $v$ to vertex $0$.

Let's define $\mathtt{dp}_2[v]$ as the sum of $\mathtt{dp}_1$ over the path $v \to \ldots \to 1$. This can be computed using a "top-down" DP similarly to a prefix sum. Now the answer to vertex $v$ is equal to $\mathtt{dp}_2[v]$.

The problem is solved in $\mathcal{O}(n)$ time.


**Code**
```cpp
#include<bits/stdc++.h>
using namespace std;
using ll=long long;
const ll md=1000000007;

int main()
{
 int t;cin>>t;
 while(t--)
 {
 ll n;cin>>n;
 vector<ll>L(n),R(n);
 for(int i=0;i<n;i++)
 {
 cin>>L[i]>>R[i];
 L[i]--;R[i]--;
 }
 vector<ll>dp(n);
 auto dfs1=[&](auto dfs1,int x)->ll
 {
 if(L[x]==-1)return dp[x]=1;
 else return dp[x]=(dfs1(dfs1,L[x])+dfs1(dfs1,R[x])+3)%md;
 };
 dfs1(dfs1,0);
 auto dfs2=[&](auto dfs2,int x)->void
 {
 if(L[x]==-1)return;
 else
 {
 dp[L[x]]=(dp[L[x]]+dp[x])%md;
 dp[R[x]]=(dp[R[x]]+dp[x])%md;
 dfs2(dfs2,L[x]);
 dfs2(dfs2,R[x]);
 }
 };
 dfs2(dfs2,0);
 for(int i=0;i<n;i++)cout<<dp[i]<<" \n"[i+1==n];
 }
}
```

## 2195F - Parabola Independence
**Rate the problem!**

**

Let's consider a graph $G$ where $u\leftrightarrow v$ is an edge if and only if $f_u$ and $f_v$ are independent. Then, by the problem definition, an organized subset is a clique (complete subgraph) in the graph $G$. The issue is that the clique problem is famously known to be NP-complete. Can we use any other property to our advantage?

The given functions are continuous functions. That is, if $f_i(x) \neq f_j(x)$ for all $x \in \mathbb{R}$, then either of the following holds:

- $f_i(x) \gt f_j(x)$ for all $x \in \mathbb{R}$.
- $f_i(x) \lt f_j(x)$ for all $x \in \mathbb{R}$.

Let's denote that $u \prec v$ if $f_u(x) \lt f_v(x)$ for all $x \in \mathbb{R}$. We will consider the unique properties of this relation.

- The relation $\prec$ is transitive. That is, if $a \prec b$ and $b \prec c$, then $a \prec c$.
- If $u \prec v$, then trivially $v \prec u$ cannot be true.
- $u \prec u$ cannot hold for any $u$.

Such a relation is also called a [strict partial order](<https://en.wikipedia.org/wiki/Partially_ordered_set#Strict_partial_orders>) in mathematics.

Let's construct a directed graph $D$ where $u \to v$ is an edge if and only if $u \prec v$. All indices from an organized subset can be ordered by $\prec$, so organized subsets of size $k$ correspond to paths of $k$ vertices in $D$. Therefore, now we reduced the problem to a longest path problem in $D$.

Due to the properties of $\prec$, the graph $D$ cannot have cycles, meaning the graph $D$ is a directed acyclic graph (DAG). As we already know, the longest path problem on a DAG can be solved using DP.

Let's define two DP states. $\mathtt{dp}_l[v]$ is defined as the length (the number of vertices) of the longest path ending on $v$, and $\mathtt{dp}_r[v]$ is defined as the length of the longest path starting on $v$. Then the length of the longest path containing vertex $v$ is exactly $\mathtt{dp}_l[v]+\mathtt{dp}_r[v]-1$. We can compute both $\mathtt{dp}_r[v]$ and $\mathtt{dp}_r[v]$ in $\mathcal{O}(n^2)$ time, and the problem is solved.

 
**Code**
```cpp
#include<bits/stdc++.h>
using namespace std;
using ll=long long;
 
struct Quad{ll a,b,c;}; // ax^2+bx+c
 
// f(x) < g(x) for all x
bool comp(Quad f,Quad g)
{
  if(f.a>g.a)return false;
  else if(f.a==g.a)return f.b==g.b&&f.c<g.c;
  else
  {
    Quad Q{g.a-f.a,g.b-f.b,g.c-f.c};
    return Q.b*Q.b-4*Q.a*Q.c<0;
  }
}
 
int main()
{
  cin.tie(0)->sync_with_stdio(0);
  int t;cin>>t;
  while(t--)
  {
    int n;cin>>n;
    vector<Quad>vec(n);
    for(Quad&Q:vec)cin>>Q.a>>Q.b>>Q.c;
    vector<vector<int>>adj1(n),adj2(n);
    vector<int>id1(n),id2(n),dp1(n,1),dp2(n,1);
    for(int i=0;i<n;i++)
    {
      for(int j=0;j<n;j++)
      {
        if(comp(vec[i],vec[j]))
        {
          adj1[i].push_back(j);
          id1[j]++;
          adj2[j].push_back(i);
          id2[i]++;
        }
      }
    }
    queue<int>Q;
    for(int i=0;i<n;i++)if(id1[i]==0)Q.push(i);
    while(!Q.empty())
    {
      int a=Q.front();Q.pop();
      for(int i:adj1[a])
      {
        id1[i]--;dp1[i]=max(dp1[i],dp1[a]+1);
        if(id1[i]==0)Q.push(i);
      }
    }
    for(int i=0;i<n;i++)if(id2[i]==0)Q.push(i);
    while(!Q.empty())
    {
      int a=Q.front();Q.pop();
      for(int i:adj2[a])
      {
        id2[i]--;dp2[i]=max(dp2[i],dp2[a]+1);
        if(id2[i]==0)Q.push(i);
      }
    }
    for(int i=0;i<n;i++)cout<<dp1[i]+dp2[i]-1<<" \n"[i+1==n];
  }
}
```

## 2195G - Idiot First Search and Queries

We assume that you already read and understand the editorial of problem E.

What does $\mathtt{dp}_2$ tell you about, other than its definition? Specifically, what does it tell you about the structure of the path?

Let's assume a vertex $w$ that is an ancestor of vertex $v$. Then, the path defined by $\mathtt{dp}_2[w]$ is a suffix of the path defined by $\mathtt{dp}_2[v]$. Before reaching vertex $w$ for the first time, Bob has been traversing subtrees of descendants of $w$ (which never include $w$). Therefore, the first time Bob reaches an ancestor vertex $w$ from vertex $v$ can be simply written as $\mathtt{dp}_2[v]-\mathtt{dp}_2[w]$.

Let's say vertex $u$ is the lowest ancestor of $v$ such that $\mathtt{dp}_2[v]-\mathtt{dp}_2[u] \le k$. Then, we can say Bob was traversing the subtree of $u$ (including vertex $u$) after $k$ moves. Naively finding this vertex has a time complexity of $\mathcal{O}(n)$. Instead, using binary lifting, we can binary search directly on ancestors of $v$, finding vertex $u$ in $\mathcal{O}(\log n)$ time.

Now we have to find the vertex Bob is on after $k-(\mathtt{dp}_2[v]-\mathtt{dp}_2[u])$ moves from vertex $u$. This can be solved by preprocessing the Euler Tour order of the tree.

Let's record the path that Bob traverses after starting from vertex $1$. For the second example test case, it looks like the following:

$$1 \to 2 \to 1 \to 3 \to 4 \to 3 \to 5 \to 3 \to 1 \to 0$$

Then, any subtree traversal order appears contiguously in this record.

$$(1 \to (2) \to 1 \to (3 \to (4) \to 3 \to (5) \to 3) \to 1) \to 0$$

By also preprocessing the first index where vertex $v$ appears, we can find the $i$-th vertex in the subtree traversal of vertex $v$ in $\mathcal{O}(1)$ time. So we have solved the rest of the problem in $\mathcal{O}(1)$ time per query.

The problem is solved with time complexity $\mathcal{O}((n+q) \log n)$.

## 2195H - Codeforces Heuristic Contest 001
**Rate the problem!**

**

Is it possible to find a recurrence to reduce a problem into a smaller problem? Formally, can we find a construction for $n=k$ using a construction for some $n=k-c$?

The $2 \times 3$ rectangle has an interesting property that we can use. By placing two $(2 \times 3)$-s horizontally, you can get a $2 \times 6$ rectangle. Also, by placing three $(3 \times 2)$-s horizontally, you can get a $3 \times 6$ rectangle. By a corollary to the Frobenius coin problem, we can get a $k \times 6$ or $6 \times k$ rectangle for any $k \ge 2$ using these rectangles.

Now we can split a $3n \times 3n$ square into the following three rectangles:

- A $6 \times 3n$ rectangle;
- A $3(n-2) \times 6$ rectangle;
- A $3(n-2) \times 3(n-2)$ square.

The first two rectangles can be constructed as they are $6 \times k$ and $k \times 6$ rectangles. The third square is precisely the subproblem for $n-2$. Therefore, if there is a construction for $n=m-2$ having $3(m-2)^2-k$ triangles, we can also find a construction for $n=m$ having $3m^2-k$ triangles.

For even $n$, a $3n \times 3n$ square is easily tiled using $2 \times 3$ and $3 \times 2$ rectangles. For odd $n$, we know that we can use two triangles on $n=1$, and that gives us a construction with $3n^2-1$ triangles in the general case. Is that the maximum value? Can we do better for some $n$?

Yes, in fact, we can use $27$ triangles for $n=3$.


![](eimages/2195_2.png)


Therefore, we have shown that we can use $3n^2$ triangles for all $n \ge 2$. The $3n^2$ triangles can be constructed by implementing the aforementioned recursion with base condition $n \le 3$. Alternatively, it doesn't have to be implemented recursively; just keep the base condition in mind and it's easy to write an iterative construction. The problem has been solved in $\mathcal{O}(n^2)$ time.

As the $n=3$ case has only $27$ triangles, it is convenient to encode them in an array of strings with $27$ different characters and decode them at runtime.

 
**Code**
```cpp
#include<bits/stdc++.h>
using namespace std;
using ll=long long;
 
string base[9]=
{
"AABBCCDEE",
"ABFFCDDGE",
"HHFIJKLLG",
"MHIJJKKLG",
"MMINNOOPP",
"QRNSOTTUP",
"QRRSSTVUU",
"WQXXYVVZ_",
"WWXYYZZ__"
};
 
struct Point
{
  ll x,y;
  Point(ll xx,ll yy):x(xx),y(yy){}
};
 
ostream& operator<<(ostream&os,const Point& P)
{
  os<<P.x<<" "<<P.y;
  return os;
}
 
using Pgon=vector<Point>;
 
vector<Pgon>basis(string b[],int n)
{
  vector<Pgon>res;
  map<char,Pgon>mp;
  for(int i=0;i<n;i++)
  {
    for(int j=0;j<n;j++)
    {
      mp[b[i][j]].emplace_back(i+1,j+1);
    }
  }
  for(auto[c,v]:mp)res.push_back(v);
  return res;
}
 
void solve(int n)
{
  if(n==1)
  {
    cout<<"2\n";
    cout<<"1 1 1 2 2 1\n";
    cout<<"2 3 3 2 3 3\n";
  }
  else if(n%2==0)
  {
    cout<<3*n*n<<"\n";
    int cnt=0;
    for(int i=1;i<=3*n;i+=3)
    {
      for(int j=1;j<=3*n;j+=2)
      {
        cout<<Point(i,j)<<" "<<Point(i,j+1)<<" "<<Point(i+1,j)<<"\n";
        cout<<Point(i+1,j+1)<<" "<<Point(i+2,j+1)<<" "<<Point(i+2,j)<<"\n";
        cnt+=2;
      }
    }
    assert(cnt==3*n*n);
  }
  else
  {
    cout<<3*n*n<<"\n";
    int cnt=0;
    for(auto p:basis(base,9))
    {
      cout<<p[0]<<" "<<p[1]<<" "<<p[2]<<"\n";
      cnt++;
    }
    for(int i=1;i<=9;i+=3)
    {
      // 3*n-9=3*(n-3)=even
      for(int j=10;j<=3*n;j+=2)
      {
        cout<<Point(i,j)<<" "<<Point(i,j+1)<<" "<<Point(i+1,j)<<"\n";
        cout<<Point(i+1,j+1)<<" "<<Point(i+2,j)<<" "<<Point(i+2,j+1)<<"\n";
        cnt+=2;
      }
    }
    for(int i=10;i<=3*n;i+=2)
    {
      for(int j=1;j<=3*n;j+=3)
      {
        cout<<Point(i,j)<<" "<<Point(i,j+1)<<" "<<Point(i+1,j)<<"\n";
        cout<<Point(i+1,j+1)<<" "<<Point(i+1,j+2)<<" "<<Point(i,j+2)<<"\n";
        cnt+=2;
      }
    }
    assert(cnt==3*n*n);
  }
}
 
int main()
{
  cin.tie(0)->sync_with_stdio(0);
  int t;cin>>t;
  while(t--)
  {
    int n;cin>>n;
    solve(n);
  }
}
```
