## 2230A - Optimal Purchase

Idea: [fcspartakm](<https://codeforces.com/profile/fcspartakm>), preparation: [fcspartakm](<https://codeforces.com/profile/fcspartakm>)

**Tutorial**

Let us split the students into groups of $3$ people each (possibly, the last group will be smaller). Then we will have $c = \lfloor \frac{n}{3} \rfloor$ full groups, as well as one incomplete group of $d = n \bmod 3$ people.

For each group, we can choose whether to buy a group key. Moreover, if we buy a group key for some group, then it is beneficial to buy a group key for all groups of equal or larger size.

Thus, we have three different options:

- buy individual keys for everyone. Then the total cost will be $n \cdot a$;
- buy individual keys for all students in the incomplete group, and group keys for all full groups. Then the total cost will be $d \cdot a + c \cdot b$;
- buy one group key for each group. Then the total cost will be either $c \cdot b$ or $(c+1) \cdot b$ depending on whether an incomplete group exists. But in fact, in this option we can always assume that we spend $(c+1) \cdot b$: if the incomplete group does not exist (that is, $n \bmod 3 = 0$), the second option will be more profitable.

The minimum of these three numbers $(n \cdot a, d \cdot a + c \cdot b, (c+1) \cdot b)$ is the answer to the problem.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 n, a, b = map(int, input().split())
 c = n // 3
 d = n % 3
 print(min((c + 1) * b, c * b + d * a, n * a))
```

## 2230B - Digit String

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

First, let us remove all occurrences of the digit $4$, since they are divisible by $4$ by themselves.

According to the divisibility rule for $4$, a number is divisible by $4$ if the number formed by its last two digits is divisible by $4$. Therefore, it is enough to consider subsequences of length $1$ or $2$ consisting of digits $1$, $2$, and/or $3$. The only such subsequences that are divisible by $4$ are $12$ and $32$.

So, in order for the string to be beautiful, there must not be an even digit (since among even digits only $2$ remains) that comes after an odd digit. Then, to solve the problem, we can iterate over a prefix in which we take only even digits, and over the remaining suffix in which we take only odd digits. Among all variants, we choose the one that leaves as many digits as possible.

To make this solution work in $O(n)$ instead of $O(n^2)$, we need either to maintain the number of even digits in the prefix and odd digits in the suffix during the iteration, or to precompute these quantities in advance in the same way prefix sums are computed. Furthermore, you have to remove all occurrences of $4$ during the first step efficiently, without iterating on the string multiple times. For example, you can write out all characters, except for $4$'s, into a new string; or you can just ignore all occurrences of $4$ during the second step of the solution without actually removing them.

 
**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
    s = input()
    pref2 = 0
    suf = 0
    for x in s:
        if x == '1' or x == '3':
            suf += 1
    ans = pref2 + suf
    for x in s:
        if x == '2':
            pref2 += 1
        if x == '1' or x == '3':
            suf -= 1
        ans = max(ans, pref2 + suf)
    print(len(s) - ans) 
```

## 2230C - Arrange the Numbers in a Circle

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

First, let us prove that for each $i$, we take either all cards with number $i$, or none of them. Suppose we took some cards with number $i$, but not all of them. Let there be a card with number $i$ in the circle, and let its neighbors be $x$ and $y$. If we add one more card with number $i$ next to this card, then new triples of neighboring cards $(x, i, i)$ and $(i, i, y)$ will appear, but both of them satisfy the condition of the problem. Therefore, if we take at least one card with number $i$, we can take all of them.

Now let us consider unique cards, that is, cards with $c_i = 1$. Why are they special? Any triple containing card $i$ will contain it exactly once. Therefore, every triple involving this card must contain two equal cards different from $i$. In other words, both before card $i$ and after it, there must be two copies of the same card. We say that cards with number $j$ support a unique card $i$ if card $i$ is surrounded by four occurrences of card $j$.

If we take card $j$ and try to place unique cards between its occurrences as often as possible, then we should do it as follows: at least two cards $j$, a unique card, at least two cards $j$, a unique card, ..., at least two cards $j$. That is, if we need $k$ unique cards surrounded by cards with number $j$, the condition $c_j \ge 2k + 2$ must hold. This means that cards with number $j$ can support $(\lfloor \frac{c_j}{2} \rfloor - 1)$ unique cards.

For each $j$ with $c_j \ge 2$, we can compute the number of unique cards that can be supported by number $j$, and sum these values. This tells us how many unique cards we need to get rid of. It is never beneficial to get rid of cards that are not unique, because they do not need to be supported by cards with other numbers.

This almost gives us the solution, except for one case, which, fortunately, appeared in the examples from the statement: if there is only one number $j$ with $c_j \gt 1$, then cards with number $j$ can support more unique cards, because the first pair of cards with number $j$ can also serve as the last pair. In this case, we must use the formula $\lfloor \frac{c_j}{2} \rfloor$ to compute the number of unique cards.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 n = int(input())
 c = list(map(int, input().split()))

 s = sum(c)
 ones = 0
 slots = 0
 for x in c:
 if x == 1:
 ones += 1
 else:
 slots += x // 2 - 1
 if ones == n - 1:
 slots += 1
 wasted = max(0, ones - slots)
 if s - wasted < 3:
 print(0)
 else:
 print(s - wasted)
```

## 2230D - Good Schedule

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

Note that if the segment $[L, R]$ is good, then so is $[L, R - 1]$. Therefore, to solve the problem, we need to find the maximum $R$ for each $L$.

Let's fix some $L$ and look at the days when Alice and Bob watch the first episode (let's call them $x$ and $y$). If these days differ, then $R = \min(x, y) - 1$, as someone will spoil the episode on the following day. If $x = y$, then we should look at the positions of the nearest $2$, which come after $x$, and solve a similar problem for them. This continues until we find an episode shown on different days or until the episode is absent from both schedules. This leads us to use some dynamic programming.

Let's consider one of the possible solutions using dynamic programming. Let's iterate over the day number $L$ from $n$ to $1$ and maintain several arrays: $pa_x$ is the position of the next episode $x$ in Alice's schedule; $pb_x$ is the position of the next episode $x$ in Bob's schedule; and $dp_i$ is the day when the aforementioned algorithm stops if they watched the episode on day $i$. If $a_L = b_L$, we can calculate $dp_L$ as follows: if $pa_x = pb_x$, then $dp_L = dp_{pa_x}$, otherwise $dp_L = \min(pa_x, pb_x) - 1$, where $x = a_i + 1$ (i.e., the next episode they should watch).

The maximum $R$ for the current $L$ is $dp_{pa_1}$ if the positions of the nearest $1$ are the same, and $\min(pa_1, pb_1) - 1$ otherwise.

 
**Solution (Neon)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;

int main() {
    ios::sync_with_stdio(false); cin.tie(0);
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;
        vector<int> a(n), b(n);
        for (auto &x : a) cin >> x, --x;
        for (auto &x : b) cin >> x, --x;
        vector<int> pa(n + 1, n), pb(n + 1, n), dp(n + 1, n);
        long long ans = 0;
        for (int i = n - 1; i >= 0; --i) {
            pa[a[i]] = i;
            pb[b[i]] = i;
            if (a[i] == b[i]) {
                int x = a[i] + 1;
                if (pa[x] == pb[x]) {
                    dp[i] = dp[pa[x]];
                } else {
                    dp[i] = min(pa[x], pb[x]);
                }
            }
            if (pa[0] != pb[0]) {
                ans += min(pa[0], pb[0]) - i;
            } else {
                ans += dp[pa[0]] - i;
            }
        }
        cout << ans << '\n';
    }
}
```

## 2230E - Minimum Influence

Idea: [adedalic](<https://codeforces.com/profile/adedalic>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)

**Tutorial**

First, let's note a couple of useful properties of the function $I$:

- $I_p(i, j) \le p_i$, that is, the news contribution to the sum does not exceed its value.
- $I_c(i, j) \le c_i$ similarly.
- $p_x \le p_y \Rightarrow I_p(x, j) \le I_p(y, j)$, that is, the smaller $p_i$ is, the smaller its contribution to the sum is.
- $c_x \le c_y \Rightarrow I_c(x, j) \le I_c(y, j)$ similarly.

Next, let's look at the influence of news on a particular user $j$. Since the influence consists of two parts, each of which is described by a piecewise function with $3$ more parts, a naive approach would split all news into $9$ groups. However, let us examine all cases more closely and reduce them to five fairly simple ones.

First, let's look at all news items $i$ such that $p_i \lt tp_j$. For all of them, $I_p(i, j) = 0$, so it is enough to choose the news item with the minimum $I_c(i, j)$. But this is equivalent to choosing the news item with the minimum $c_i$.

Similarly, we can proceed with all news items $i$ such that $c_i \lt tc_j$. Among them, we are also interested only in the news item with the minimum $p_i$.

Second, let us look at all news items $i$ such that $p_i \ge tp_j + d_j$. For all of them, $I_p(i, j) = tp_j + d_j$, and similarly we are interested only in the news item with the smallest $I_c(i, j)$, that is, with the minimum $c_i$.

Similarly, among the news items with $c_i \ge tc_j + d_j$, we are interested in the news item with the minimum $p_i$.

Finally, we are left only with the news items $i$ such that both $tp_j \le p_i \lt tp_j + d_j$ and $tc_j \le c_i \lt tc_j + d_j$. For them, $I(i, j) = p_i + c_i$, so among them we simply need the news item with the minimum sum $p_i + c_i$. This can already be found using data structures such as a Segment Tree or a Sparse Table. But let us think a little more.

In fact, let us forget that $p_i$ and $c_i$ must lie in some intervals, and simply find the news item with the minimum sum $p_i + c_i$ among all news items. If our news item happens to be inside the required "rectangle", then everything is fine, because it is already the minimum possible one. If not, then its answer is still $I_p(i, j) + I_c(i, j) \le p_i + c_i$, which means that the minimum answer cannot be inside our rectangle.

Thus, for a given user $j$, all we need is:

- among all news items with $p_i \lt tp_j$, take the minimum $c_i$;
- among all news items with $c_i \lt tc_j$, take the minimum $p_i$;
- among all news items with $p_i \ge tp_j + d_j$, take the minimum $c_i$;
- among all news items with $c_i \ge tc_j + d_j$, take the minimum $p_i$;
- take the news item with the minimum $p_i + c_i$ among all news items.

Since all values do not exceed $A = 10^6$, we can precompute prefix and suffix minimums for all values from $0$ to $A$ in $O(n + A)$. Then we can obtain the required values in $O(1)$.

As a result, the time complexity of the solution is $O(n + m + A)$.


**Solution (adedalic)**
```python
import bisect
import sys
input = sys.stdin.readline

INF = int(1e9) + 7
A = int(1e6) + 3

n = int(input())
a = [list(map(int, input().split())) for i in range(2)]

minVal = [[INF] * A for i in range(2)]
pMin = [[INF] * A for i in range(2)]
sMin = [[INF] * A for i in range(2)]
for k in range(2):
 for i in range(n):
 minVal[k][a[k][i]] = min(minVal[k][a[k][i]], a[k ^ 1][i])

 for v in range(A - 1):
 pMin[k][v + 1] = min(pMin[k][v], minVal[k][v])

 for v in range(A - 2, -1, -1):
 sMin[k][v] = min(sMin[k][v + 1], minVal[k][v])

mid = 0
for i in range(n):
 if a[0][mid] + a[1][mid] > a[0][i] + a[1][i]:
 mid = i

m = int(input())
t = [list(map(int, input().split())) for i in range(3)]

def I(val, l, r):
 if val < l:
 return 0
 return min(val, r)

ans = []
for id in range(m):
 cur = I(a[0][mid], t[0][id], t[0][id] + t[2][id]) + I(a[1][mid], t[1][id], t[1][id] + t[2][id])
 for k in range(2):
 pos_l = t[k][id]
 pos_r = min(A - 1, t[k][id] + t[2][id])

 if pMin[k][pos_l] < INF:
 cur = min(cur, I(pMin[k][pos_l], t[k ^ 1][id], t[k ^ 1][id] + t[2][id]))
 if sMin[k][pos_r] < INF:
 cur = min(cur, pos_r + I(sMin[k][pos_r], t[k ^ 1][id], t[k ^ 1][id] + t[2][id]))
 ans.append(cur)

print("\n".join(map(str, ans)))
```

## 2230F - Game on Growing Tree

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

First, let us understand how to solve the problem on a fixed tree, and only then will we deal with queries that add new vertices.

Suppose we have chosen that Alice will start at vertex $v$. Then we can root the tree at this vertex and assume that Alice always moves downward in the tree. So, Alice's goal is to go as deep as possible from the root, and Bob's goal is to prevent Alice from doing so.

It is fairly obvious that after Alice's move, if the token is at vertex $u$, then Bob's best option is to block one of the children of $u$ by coloring it blue — this restricts Alice's possible moves more than if Bob blocked some vertex outside the subtree of $u$ or some vertex that is not a child of $u$.

Since Alice always moves downward, for each vertex we can compute a dynamic programming value $dp_u$ — the number of moves Alice can make if the token is currently at vertex $u$ and it is Bob's turn. After Bob's move, Alice will choose the unblocked child with the maximum DP value, so Bob's best strategy is always to block the child with the maximum DP value. Therefore, to compute the DP for vertex $u$, we can recursively process its children and then choose the two largest values among them — the largest one will be blocked by Bob, and Alice will move to the second largest one. Let the second-best son have DP value $dp_x$, then $dp_u = dp_x + 1$.

Thus, for a fixed root, we can compute the DP in $O(n)$. But Alice may choose the root herself on the first move. Trying every possible root and running the DP from scratch in $O(n)$ for each one is too slow; instead, we will use the rerooting technique.

Suppose we have computed the DP for the tree with some fixed root. We can recompute it for other roots by rerooting the tree at them. Rerooting works as follows: we will learn how to "reverse" a tree edge (swap parent and child for an arbitrary edge incident to the root), and then run a DFS from the root, which, when moving from the current vertex to a neighbor, will reverse the edge we traverse, and when returning, will reverse that edge back.

To reverse an edge, we need to handle the following situation: suppose the current root is $v$, and it has a neighbor $u$; we need to recompute the DP as if vertex $v$ were no longer the root and vertex $u$ became the root. We can handle this operation in $O(1)$ by performing the following two steps:

- recompute the DP for vertex $v$ as if vertex $u$ were no longer its child;
- recompute the DP for vertex $u$ as if vertex $v$ were now its child.

The second step is quite straightforward in $O(1)$: we want to update the second maximum taking into account that a new element is being added. But how do we perform the first step quickly? Recomputing the maximum (and the second maximum) when an element is removed is significantly harder than when an element is added.

We can use the fact that during rerooting, each vertex will always have at most one "forbidden" child. Therefore, if during the initial DP computation we store three maximum values among the children instead of two, we will always be able to recompute the second maximum from the children's DP values even if one of them is blocked.

This gives us a solution for a fixed tree in $O(n)$. Unfortunately, rerooting cannot be combined with queries that modify the tree. So it seems that we need a different solution — but in fact we don't; we can process the queries indirectly.

Let us estimate how large the answer can be. If for some starting vertex $v$ the DP value is $k$, then this means that it has at least two children with DP value at least $k-1$. Each of them, in turn, has at least two children with DP value at least $k-2$, and so on. This means that for a tree with $n$ vertices, the answer is $O(\log n)$ — and if we compute it more precisely, we can show that the answer does not exceed $17$.

Furthermore, when new vertices are added to the tree, the answer can only increase — this follows from the way we compute the tree DP (adding new elements cannot decrease the second maximum among the children).

This means that some initial segment of queries gives answer $1$, the next segment gives answer $2$, the next segment gives answer $3$, and so on. We can preprocess all queries and use binary search to find the boundaries of these segments. This gives a solution in $O(qk \log q)$, where $k$ is the number of segments; and we have already proved that the number of segments is $O(\log n)$. Therefore, our solution works in $O(q \log^2 q)$.

The asymptotics can be improved to $O(q \log q)$ if we slightly change the DP definition: for each vertex, we will compute a two-dimensional DP of the form $dp'_{v,i}$ — the minimum query index at which $i$ steps can be made from the subtree of vertex $v$. Unfortunately, this solution uses $O(q \log q)$ memory and in practice is not much faster than the previous one, and it is also noticeably harder to implement.

There are also online solutions that do not rely on preprocessing all queries in advance. We'll describe the idea of one such solution briefly: it is based on computing the DP not over vertices, but over directed edges (that is, over pairs $u, v$, where $u$ is the parent and $v$ is the child), and carefully updating this DP when new vertices are added; since the answer does not decrease when new vertices are added and does not exceed $O(\log q)$, for each edge the DP will be updated at most $O(\log q)$ times, and after each such update we can try to recompute the DP for "parent" edges (that is, those that can precede the current edge on a path).

 
**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int N = 200043;
const int K = 3;
const int LN = 20;

vector<int> g[N];
int p[N];
pair<int, int> dp_down[N][K];
int dp_up[N];
int q_index;
int ans[N];
int f[N];

void upd_down(int idx, pair<int, int> p)
{
    if(dp_down[idx][K - 1] < p)
    {
        dp_down[idx][K - 1] = p;
        int j = K - 1;
        while(j != 0)
        {
            if(dp_down[idx][j - 1] < dp_down[idx][j])
            {
                swap(dp_down[idx][j - 1], dp_down[idx][j]);
                j--;
            }
            else break;
        }
    }
}

void upd(pair<int, int>& p, int x)
{
    if(p.second < x) p.second = x;
    if(p.first < p.second) swap(p.first, p.second);
}

int get_cur(int x)
{
    pair<int, int> cur_ans = {0, 0};
    for(int i = 0; i < K; i++)
        if(dp_down[x][i].second != f[x])
            upd(cur_ans, dp_down[x][i].first);
    if(f[x] != -1)
        upd(cur_ans, dp_up[x]);
    return cur_ans.second + 1;        
}

int get_full(int x)
{
    pair<int, int> cur_ans = {0, 0};
    for(int i = 0; i < K; i++)
        upd(cur_ans, dp_down[x][i].first);
    upd(cur_ans, dp_up[x]);
    return cur_ans.second + 1;    
}

void dfs1(int x, int parent = -1)
{
    p[x] = parent;
    for(auto y : g[x])
    {
        if(y > q_index) continue;
        if(y != parent)
        {
            dfs1(y, x);
            upd_down(x, make_pair(get_cur(y), y));
        }
    }
}

void dfs2(int x)
{
    if(p[x] != -1)
        dp_up[x] = get_cur(p[x]);
    for(auto y : g[x])
    {
        if(y > q_index) continue;
        if(y != p[x])
        {
            f[x] = y;
            dfs2(y);
            f[x] = -1;
        }
    }
}

int get_ans(int x)
{
    q_index = x + 2;
    for(int i = 1; i <= q_index; i++)
    {
        dp_up[i] = 0;
        for(int j = 0; j < K; j++)
            dp_down[i][j] = {0, -1};
        p[i] = -1;
        f[i] = -1;
    }
    dfs1(1);
    dfs2(1);
    int ans = 1;
    for(int i = 1; i <= q_index; i++)
        ans = max(ans, get_full(i));
    return ans;
}

void rec(int l, int r, int L, int R)
{
    if(l >= r) return;
    if(L == R)
    {
        for(int i = l; i < r; i++)
            ans[i] = L;
        return;
    }
    int mid = (l + r) / 2;
    ans[mid] = get_ans(mid);
    rec(l, mid, L, ans[mid]);
    rec(mid + 1, r, ans[mid], R);
}

void solve()
{
    int q;
    cin >> q;
    for(int i = 0; i < q; i++)
    {
        int x;
        cin >> x;
        g[x].push_back(i + 2);
        g[i + 2].push_back(x);
    }
    rec(0, q, 1, LN);
    for(int i = 0; i < q; i++)
        cout << ans[i] << " ";
    cout << "\n";
}

int main()
{
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    int t = 1;
    for(int i = 0; i < t; i++)
        solve();
    return 0;
}
```
