**Problem A: Nash equilibrium**

## 1302A - Nash equilibrium

The solution itself is straightforward: for each row we mark all elements but the only maximal element (if exists) as not suitable for being the Nash equilibria, then do similarly for columns, then output the lexicographically minimal unmarked cell. The bug was reading $m$ and $n$ instead of $n$ and $m$ respectively, we hoped that the fact that the only two samples were square and a table filled with equal elements should be a hint for everyone who have made this mistake at least once in their life.


**Problem B: DAG**

## 1302B - DAG

To solve this problem one can update a bitset of all reachable vertices from every vertex $v$ in the topological sorted order and then calculate the sum of sqr(reachable[v].count()). The bug was, maybe, less obvious than in the previous problem, but still quite common (at least we thought so): instead of creating an edge $u\to v$ we created edges $v\to u$. Again, the first two samples contained a path and a set of isolated edges, while the third one has an incorrect answer.

However, bitset sometimes doesn't fit into memory, so one can, for example, calculate $n/64$ times for each vertex the number of reachable vertices with indices from $64k$ to $64(k+1) - 1$ and then sum up all the reachable counts.

**Problem E: Amazing bitset**

## 1302E - Amazing bitset

First of all, we claim that a bitset is amazing iff it has distinct elements. Indeed, if all its elements are equal, then we cannot do a single operation. Otherwise, if there are $a$ zero bits and $b$ one bits (wlog $a\leq b$), then we can do $(a - 1)$ operations to flip one 0-bit and one 1-bit per operation, and then flip all the remaining bits using the last operation.

So it can be seen that the probability for a bitset not to be amazing is $p^n + (1 - p)^n$. This can be calculated using fast exponentiation, and then subtracted from $1$.

The problem is that if we calculate both summands in ints, then their sum can exceed INT_MAX, because $1\,234\,567\,891 \gt 2^{30}$, so int overflow is the bug here.

**Problem H: Who needs suffix structures?**

## 1302H - Who needs suffix structures?

The problem name and the folder with open tests hint that the intended solution uses hashes. We already have the modulo from the statement. The rest is to obtain the base.

There is a bunch of tests where all queries compare the first segment of length $k$ with all other subsegments of length $k$ which end at a position divisible by $k$. One can manually (using an $O(nq)$ algorithm or a suffix structure) get all such pairs of substrings with a collision. Each of them gives us a constraint of form $P(base)\equiv 0\pmod{987\,898\,789}$ where $P$ is a polynomial. One can get a GCD of all such polynomials to obtain a polynomial having $base$ as its root.

GCD'ing such polynomials from the whole pack of open tests, one can obtain that $base$ is the root of the polynomial $x - 456\,545\,664$.


**Problem I: Deja vu**

## 1302I - Deja vu

The folder name in the open tests archive hints that this problem is about breaking hashing modulo $2^{64}$. One can also see this in the Thue-Morse open tests.

In the last but one test seeing $n = 128$ and $k = 64$ and an incorrect answer one can assume that the first and the last string give a collision. If you are not sure, you can decode the last input string considering it as a bit representation of some string:

>>> "".join(map(lambda x: chr(int(x, 2)), [s[i:i+8] for i in range(0, len(s), 8)]))

'if the answer is incorrect then maybe prefix =/= suffix, just a guess'

Subtracting the suffix polynomial from the prefix one we get a polynomial with coefficients from $\{-1, 0, 1\}$ and having base as the root modulo $2^{64}$. It is obvious that the base is odd. It turns out that its remainder modulo $4$ is uniquely determined. Using the remainder modulo $4$, its remainder modulo $8$ is also unique, and so on (the condition is that the free coefficient is nonzero, the total sum of coefficients is even and the total sum of coefficients of $x^1$, $x^3$, $x^5$, $\ldots$ is odd). Thus one can restore the base bit by bit.
