## 2144A - Cut the Array

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Of course, we can iterate through the positions $l$ and $r$, and then check if we get a valid cut. However, there is a simpler solution.

Let's try to rephrase the condition "either all numbers $s_1, s_2, s_3$ are different, or all numbers $s_1, s_2, s_3$ are the same". Since these are remainders when divided by $3$, their sum will be equal to $0$ modulo $3$:

- if they are all equal to $0$, $1$, or $2$, then their sum is divisible by $3$;
- otherwise, one of them is $0$, another is $1$, and the third is $2$, and their sum equals $3$.

On the other hand, if $s_1+s_2+s_3$ is equal to $0$ modulo $3$, then there are two possible cases:

- either $s_1 = s_2$, in which case $s_3$ will be equal to them (otherwise their sum would not be divisible by $3$);
- or $s_1 \ne s_2$, then $s_3 = 3 - s_1 - s_2$, and regardless of the values of $s_1$ and $s_2$, $s_3$ will differ from them.

Thus, if the sum of the array is not divisible by $3$, then there is no suitable cut; and if it is divisible by $3$, then any cut will be valid.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 n = int(input())
 a = list(map(int, input().split()))
 if sum(a) % 3 == 0:
 print("1 2")
 else:
 print("0 0")
```

## 2144B - Maximum Cost Permutation

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

First, let's understand how to calculate the cost of a permutation. I claim that the minimum subsegment that needs to be sorted is the one whose ends are the leftmost and rightmost elements that are not in their correct positions. On one hand, this segment cannot be shorter because these elements must be included in it. On the other hand, if we sort the subarray that includes all the elements that are not in their correct positions, the permutation will definitely become sorted in ascending order — all the elements outside this segment were already in their correct positions, and all the elements within the segment will be arranged in the correct order.

Now we need to create a permutation from the given array such that the minimum and maximum positions of the elements that are not in their correct positions are as far apart as possible. If there is only one $0$ in the array, there is only one way to turn it into a permutation, and we just need to check the answer for that case.

However, if there are multiple elements equal to $0$ in the array, there is always a way to place the missing elements such that at all positions where there were previously $0$s, there are elements that do not equal those positions. To do this, we can proceed as follows: first, we place the missing elements in such a way that as many elements as possible match their positions (if we are missing element $i$ and position $i$ in the array contains $0$, we place $i$ there; the remaining elements can be placed arbitrarily), and then we cyclically shift all the placed elements (that is, we place the first placed element in the second free position, the second in the third, and so on). This way, for every position of $0$, there will be an element which is not equal the position.

Therefore, if there is more than one zero in the given array, we can simply find the longest prefix and the longest suffix where all elements match their positions, assuming that zeros can always be replaced in such a way that they do not match their positions. The segment between this prefix and suffix will be the segment that needs to be sorted.

Time complexity of the solution is $O(n)$.

 
**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>
 
using namespace std;
 
void solve()
{
    int n;
    cin >> n;
    vector<int> p(n);
    vector<int> pos0;
    vector<int> used(n);
    for(int i = 0; i < n; i++)
    {
        cin >> p[i];
        --p[i];
        if(p[i] == -1)
            pos0.push_back(i);
        else
            used[p[i]] = 1;
    }
    if(pos0.size() == 1) 
    {
        int unused = 0;
        for(int i = 0; i < n; i++) if(used[i] == 0) unused = i;
        p[pos0[0]] = unused;
    }
    int l = 0, r = n - 1;
    while(l < n && p[l] == l) l++;
    while(r >= 0 && p[r] == r) r--;
    cout << max(0, r - l + 1) << "\n";
}
 
int main()
{
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    int t;
    cin >> t;
    for(int i = 0; i < t; i++)
        solve();
}
```

## 2144C - Non-Descending Arrays

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

First, let's understand how we can always obtain at least one subset. Let's keep the maximum elements from all pairs in one array, and the minimums in another (that is, if $a_i \gt b_i$, we swap them, so that $a$ will contain the minimums from each pair, and $b$ will contain the maximums).

We can prove that if there is at least one way to make both arrays sorted, then this way will definitely work. To do this, let's assume that we have reached a situation where one of the arrays is not sorted using this method:

- if in array $a$ we have a pair of elements $a_i \gt a_{i+1}$, then considering that $a_i \le b_i$, it follows that $b_i \gt a_{i+1}$. This means that whichever of the two elements $(a_i, b_i)$ we place before $a_{i+1}$, it will definitely be greater;
- if in array $b$ we have a pair of elements $b_i \gt b_{i+1}$, then considering that $a_{i+1} \le b_{i+1}$, it follows that $b_i \gt a_{i+1}$. This means that whichever of the two elements $(a_{i+1}, b_{i+1})$ we place after $b_i$, it will definitely be smaller.

Thus, if at least one good subset exists, we can always ensure that $a_i \le b_i$. Let's initially swap the elements in those pairs where $a_i \gt b_i$; the answer will not change (since the $2^n$ subsets of indices we are considering will yield the same results after such a transformation, just in a different order).

Now let's understand which pairs of elements we can swap while keeping the arrays sorted. For each pair of adjacent indices $(i, i+1)$, there are two possible situations:

- either $b_i \le a_{i+1}$, in which case any element at position $i$ will be less than or equal to any element at position $i+1$ (let's call this a type $1$ index pair);
- or $b_i \gt a_{i+1}$, in which case we must place $a_{i+1}$ after $a_i$ and $b_{i+1}$ after $b_i$. This means we should swap $a_i$ and $b_i$ if and only if we swap $a_{i+1}$ and $b_{i+1}$ (let's call this a type $2$ index pair).

Let's consider the "segments" of indices $i$ where every two adjacent indices form a type $2$ pair. Then if we choose what to do with any one index in this pair, it will automatically force us to choose an action for all other indices in this segment. However, different segments do not affect each other, as the indices at the boundary of two segments form a type $1$ pair.

Thus, the answer is $2^{m}$, where $m$ is the number of segments of type $2$ pairs. Each type $2$ pair "merges" two such segments, so we can calculate the answer as $2^{n-k}$, where $k$ is the number of such $i$ such that $b_i \gt a_{i+1}$ (after we have swapped $a_i$ and $b_i$ in pairs where $a_i \gt b_i$).


**Solution (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

const int MOD = 998244353;

int main() {
 int t;
 cin >> t;
 while (t--) {
 int n;
 cin >> n;
 vector<int> a(n), b(n);
 for (auto &x : a) cin >> x;
 for (auto &x : b) cin >> x;
 int ans = 1;
 for (int i = 0; i < n; ++i) {
 if (a[i] > b[i]) swap(a[i], b[i]);
 if (!i || a[i] >= b[i - 1]) ans = (ans * 2LL) % MOD;
 }
 cout << ans << '\n';
 }
}
```

## 2144D - Price Tags

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Let $A = \max{a_i}$. Firstly, if $x \gt A$ then the answer for $x$ will be the same as for $x - 1$, since for each $i$ value $\left\lceil \frac{a_i}{x} \right\rceil = \left\lceil \frac{a_i}{x - 1} \right\rceil = 1$. In other words, there is no need to check $x$-s bigger than $A$ (the corner case is when $A = 1$).

Suppose we fixed some value $x$. Each $\left\lceil \frac{a_i}{x} \right\rceil \le \left\lceil \frac{A}{x} \right\rceil$, so all resulting prices are bounded by $\left\lceil \frac{A}{x} \right\rceil$. So, if we somehow calculate the answer for $x$ in $O\left(\frac{A}{x}\right)$ time, we can achieve a pretty fast solution in total, since $\sum\limits_{x=1}^{A}{O\left(\frac{A}{x}\right)} = O(A \log{A})$.

So, how to calculate the answer for a fixed $x$? For the start, let's precalculate some statistics: let's calculate the array $\mathrm{cnt}$ where $\mathrm{cnt}[p]$ is the number of initial price tags equal to $p$. This array can be calculated once, since it doesn't change for different $x$.

Next, let's iterate over all $p$ from $1$ to $\left\lceil \frac{A}{x} \right\rceil$. What initial prices will result in $p$? It's prices in the segment $[(p - 1) \cdot x + 1, p \cdot x]$ and we can calculate their number (let's name it as $\mathrm{need}$) asking a sum on a segment in the array $\mathrm{cnt}$ that can be done in $O(1)$ using prefix sums.

Since there are exactly $\mathrm{cnt}[p]$ existing price tags, we'll need $\max(0, \mathrm{need} - \mathrm{cnt}[p])$ extra tags to print. In total, the resulting price $p$ will contribute to the total income exactly $p \cdot \mathrm{need} - y \cdot \max(0, \mathrm{need} - \mathrm{cnt}[p])$ coins.

As a result, we can calculate an income for each $x$ in $O\left(\frac{A}{x}\right)$ time that gives us the total complexity $O(n + A \log{A})$ per test.

 
**Solution (adedalic)**
```python
for _t in range(int(input())):
    n, y = map(int, input().split())
    a = list(map(int, input().split()))
    A = max(a) + 1
    cntTags = [0] * A
    for v in a:
        cntTags[v] += 1
    pSum = [0] * A
    for i in range(1, A):
        pSum[i] = pSum[i - 1] + cntTags[i]
    
    ans = -(10**18)
    if A == 2:
        print(n)
        continue
    for x in range(2, A):
        res = 0
        for price in range(1, A):
            l = x * (price - 1)
            r = min(A - 1, x * price)
            if l >= A:
                break
            cnt = pSum[r] - pSum[l]
            res += cnt * price
            res -= y * max(0, cnt - cntTags[price])
        ans = max(ans, res)
    print(ans)
```

## 2144E1 - Looking at Towers (easy version)

To begin with, let's calculaye $L(a)$ and $R(a)$; to do this, we can simply find all elements that are greater than all previous or next elements.

Now, let's look at the criteria that the subsequence must satisfy for the left view to equal $L(a)$ and the right view to equal $R(a)$. The maximum in this subsequence must be equal to the maximum in $a$, since the tower of maximum height will always be visible from both the left and the right. Let this maximum be $m$.

Let's fix the first and last occurrences of the maximum in the subsequence. Let these be the positions $i$ and $j$ in the original sequence ($a_i = a_j = m$; $i \le j$). Then, for this pair $i, j$, we need to add the product of these three numbers to the answer:

- the number of subsequences that have the left view equal to $L(a)$, end at position $i$, and do not have occurrences of $m$ before position $i$ (if the first occurrence of the maximum is before $i$, we will count it when considering another position of the first occurrence). We will call this $dpL_i$;
- the number of subsequences that have the right view equal $R(a)$, start at position $j$, and do not have occurrences of $m$ after position $j$ (if the last occurrence of the maximum is after $j$, we will count it when considering another position of the last occurrence). We will call this $dpR_j$;
- the number of ways to choose elements between $i$ and $j$. For each of them, it does not matter whether we include it in the subsequence or not, because it will be between two maxima, and thus will not affect the left/right view. Therefore, this number is equal to $2^x$, where $x$ is the number of elements between $i$ and $j$ (excluding the boundaries).

Let's learn to calculate the array $dpL$ (the $dpR$ can be calculated similarly by reversing the given sequence $a$ and $R(a)$, and then reversing the result after counting). Let $k$ be the size of $L(a)$. We will traverse the sequence $a$ from left to right and maintain an array $c$ of size $k$, where $c_i$ is equal to the number of subsequences whose left view matches the first $i$ elements of $L(a)$ (obviously, we are not interested in subsequences whose left view is not a prefix of $L(a)$). Initially, $c_0 = 1$, and all other elements are equal to $0$.

Let's see how this array $c$ changes when processing the element $a_i$. To do this, we need to understand what happens if we append the element $a_i$ to the sequence whose left view matches the first $j$ elements of $L(a)$. There are three cases:

- if $a_i$ is equal to the next element that should be in the left view (i.e., the $j$-th element of $L(a)$ in $0$-indexing), then we can obtain a subsequence whose prefix matches the prefix that is $1$ longer. Accordingly, we should add $c_j$ to $c_{j+1}$;
- if $a_i$ is greater than the $(j-1)$-th element of $L(a)$ but does not match the next element, we cannot append it to the subsequence because it would violate the left view;
- if $a_i$ is less than or equal to the $(j-1)$-th element of $L(a)$, we can either append it to the subsequence or skip it; this will not affect the left view. Accordingly, $c_j$ should be multiplied by $2$.

How do we obtain the array $dpL$ from this? Each time we encounter an element $a_i$ equal to the maximum, we need to count how many subsequences it can be appended to so that the left view matches $L(a)$ and the element itself is the first occurrence of the maximum. This is actually all subsequences whose left view matches $L(a)$ without the last element, so it is sufficient to assign $dpL_i = c_{k-1}$.

Thus, we will obtain a solution in $O(n^2)$, which is sufficient for the easy version of the problem.

[2144E2 - Looking at Towers (difficult version)](<https://codeforces.com/contest/2144/problem/E2>)

## 2144E2 - Looking at Towers (difficult version)

First, read the editorial for the easy version of the problem.

Let's understand which parts of the solution for the easy version work in $O(n^2)$ and figure out how to speed them up.

First, so far the arrays $dpL$ and $dpR$ are being computed too slowly. The main problem lies in maintaining the array $c$, because when processing one element $a_i$, we can change many elements of the array $c$ at once. However, all these elements are such that $c_j$ is the $j$-th element of the array $L(a)$ that is greater than or equal to $a_i$; therefore, it is always some suffix of the array $c$, which can be found using binary search. Additionally, all of them are multiplied by $2$. This means that to maintain the array $c$, we can use a segment tree with the following operations:

- double all elements in a segment;
- increase a certain element by a given value;
- get the value of a certain element.

This way, we can speed up the construction of the arrays $dpL$ and $dpR$ to $O(n \log n)$.

The second part of the solution that works in $O(n^2)$ is calculating the answer using $dpL$ and $dpR$. Recall that we need to iterate through all pairs of occurrences of the maximum $(i, j)$, where $i \le j$, and increase the answer by $dpL_i \cdot dpR_j \cdot 2^{\max(0, j-i-1)}$. This can be sped up to $O(n)$ as follows: when iterating through $j$, we will maintain the sum of all $dpL_i$ for $i \lt j$, multiplied by the required power of two; when moving from $j$ to $j+1$, it is sufficient to double this sum and add $dpL_j$ to it.

The remaining parts of the solution work in $O(n)$, so we will thus obtain a program that runs in $O(n \log n)$.


**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int MOD = 998244353;
const int N = 1000043;

int add(int x, int y)
{
 x += y;
 while(x >= MOD) x -= MOD;
 while(x < 0) x += MOD;
 return x;
}

int mul(int x, int y)
{
 return (x * 1ll * y) % MOD;
}

int binpow(int x, int y)
{
 int z = 1;
 while(y > 0)
 {
 if(y % 2 == 1) z = mul(z, x);
 x = mul(x, x);
 y /= 2;
 }
 return z;
}

vector<int> get(const vector<int>& a)
{
 int cur = -1;
 vector<int> res;
 for(auto x : a)
 if(x > cur)
 {
 res.push_back(x);
 cur = x;
 }
 return res;
}

struct SegTree
{
 vector<int> f;
 vector<int> t;
 int n;

 int getVal(int v, int pos)
 {
 return mul(t[pos], binpow(2, f[v]));
 }

 void push(int v)
 {
 if(f[v] != 0)
 {
 f[2 * v + 1] += f[v];
 f[2 * v + 2] += f[v];
 f[v] = 0;
 }
 }

 void resolve(int v, int pos)
 {
 if(f[v] != 0)
 {
 t[pos] = mul(t[pos], binpow(2, f[v]));
 f[v] = 0;
 }
 }

 int get(int v, int l, int r, int pos)
 {
 if(l == r - 1)
 return getVal(v, pos);
 else
 {
 push(v);
 int m = (l + r) / 2;
 if(pos < m)
 return get(v * 2 + 1, l, m, pos);
 else
 return get(v * 2 + 2, m, r, pos);
 }
 }

 int get(int pos)
 {
 return get(0, 0, n, pos);
 }

 void inc(int v, int l, int r, int pos, int val)
 {
 if(l == r - 1)
 {
 resolve(v, pos);
 t[pos] = add(t[pos], val);
 }
 else
 {
 push(v);
 int m = (l + r) / 2;
 if(pos < m)
 inc(v * 2 + 1, l, m, pos, val);
 else
 inc(v * 2 + 2, m, r, pos, val);
 }
 }

 void inc(int pos, int val)
 {
 return inc(0, 0, n, pos, val);
 }

 void mulBy2(int v, int l, int r, int L, int R)
 {
 if(L >= R) return;
 if(l == L && r == R)
 f[v]++;
 else
 {
 push(v);
 int m = (l + r) / 2;
 mulBy2(v * 2 + 1, l, m, L, min(R, m));
 mulBy2(v * 2 + 2, m, r, max(L, m), R);
 }
 }

 void mulBy2(int l, int r)
 {
 mulBy2(0, 0, n, l, r);
 }

 SegTree(int n = 0)
 {
 this->n = n;
 f.resize(4 * n);
 t.resize(n);
 }
};

vector<int> calc(const vector<int>& a, const vector<int>& b)
{
 int n = a.size();
 int m = b.size();
 SegTree tree(m + 1);
 tree.inc(0, 1);
 vector<int> res(n);
 int maxVal = b.back();
 for(int i = 0; i < n; i++)
 {
 int x = a[i];
 if(x > maxVal) continue;
 else
 {
 if (x == maxVal) res[i] = tree.get(m - 1);
 int lf = lower_bound(b.begin(), b.end(), x) - b.begin();
 tree.mulBy2(lf + 1, m + 1);
 if(b[lf] == x)
 {
 int cur = tree.get(lf);
 tree.inc(lf + 1, cur);
 }
 }
 }
 return res;
}

void solve()
{
 int n;
 cin >> n;
 vector<int> a(n);
 for(int i = 0; i < n; i++)
 cin >> a[i];
 auto left_view = get(a);
 reverse(a.begin(), a.end());
 auto right_view = get(a);
 reverse(a.begin(), a.end());

 auto dpL = calc(a, left_view);
 reverse(a.begin(), a.end());
 auto dpR = calc(a, right_view);
 reverse(a.begin(), a.end());
 reverse(dpR.begin(), dpR.end());

 int maxVal = *max_element(a.begin(), a.end());
 int ans = 0;
 int sumLeft = 0;
 for(int i = 0; i < n; i++)
 {
 if(a[i] > maxVal) continue;
 else
 {
 if(a[i] == maxVal) ans = add(ans, mul(add(sumLeft, dpL[i]), dpR[i]));
 sumLeft = mul(sumLeft, 2);
 if(a[i] == maxVal) sumLeft = add(sumLeft, dpL[i]);
 }
 }
 cout << ans << endl;
}

int main()
{
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 int t;
 cin >> t;
 for(int i = 0; i < t; i++) solve();
}
```

## 2144F - Bracket Groups

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

First, consider the $-1$ case. If one of the given bracket sequences is equal to "()", then it's definitely $-1$. Every regular bracket sequence has such substring. Turns out, otherwise, the answer always exists. Let's show this constructively and come up with an answer for any number of groups.

Consider a regular bracket sequence "()()()...()". Notice how it alternates brackets, so if a given bracket sequence has two of the same bracket next to each other, it can always be assigned to a group with that RBS. Otherwise, you can actually use a regular bracket sequence "((((...(())...))))". Since the remaining bracket sequences have alternating brackets and have length at least $3$ (or equal to ")("), they can always be assigned to a group with this RBS.

So we actually discovered that the answer is at most $2$ and have a construction to achieve that answer. Now, we only have to check if it's possible to fit all bracket sequences into one group.

Ideally, we'd like to take $\texttt{dp[i][bal]}$ — whether we can make a bracket sequence with length $i$ and balance $\mathit{bal}$ (and also, non-negative balance on every prefix), and adjust that to care about not having any substrings equal to any of the given strings.

Well, there is a tool for that, and it's called the Aho-Corasick automaton. This automaton is basically a trie with extra properties. So, we build a trie of the given bracket sequences and calculate suffix links (for each node of the trie, the link to the node that corresponds to its longest proper suffix that exists in the trie). Now we can make the node of the trie an additional state of the dp. So, $\texttt{dp[i][bal][v]}$ — whether we can make a bracket sequence with length $i$ and balance $\mathit{bal}$ such that the longest suffix of the current string that exists in the trie corresponds to the node $v$. Using the suffix links, we calculate the transitions of the automaton, so that we can know the node $v'$ we move to after we append either of the brackets to the string.

How to check if any of the strings from the set appear in our string as a substring then? Well, let's only make a transition in the dp if the string with an appended bracket doesn't have any of its suffixes equal to a string in the set. Consider the longest suffix of the current string that appears in the trie. Obviously, suffixes longer than that can't be equal to any of the strings in the set. However, even if the longest suffix isn't equal to the string in the set, one of the shorter suffixes might still be equal to some. To check for that, we can again use suffix links. Initially, mark every node that corresponds to a full string as a terminal node. After that, a node is unsafe if it's a terminal or it can reach a terminal while jumping via suffix links. Suffix links form a tree structure (since they always point to a node corresponding to a shorter string), so this can be precalculated with a single dfs/bfs.

Overall complexity: $O(nk)$ to build the AC automaton and $O(nk^3)$ for the dynamic programming (O($nk$) nodes in the trie and $O(k)$ for the length of the string and the current balance).

To be fair, the constraints allowed you to be very lazy with the AC automaton implementation. Like, you could collect all prefixes of all strings into a vector and sort that to give the prefixes some indices. To calculate if a string is bad, you could check if any of its suffixes appear in the set of full strings. To calculate the transitions, you could try appending a bracket to each suffix of the string and binary search to find the resulting string in the automaton.

The complexity of this makeshift automaton is probably $O(nk^3 \cdot \log nk)$.

 
**Solution 1 (awoo)**
```cpp
#include <bits/stdc++.h>
 
#define forn(i, n) for (int i = 0; i < int(n); i++)
 
using namespace std;
 
const string al = "()";
 
struct aho_corasick {
    static const int AL = 2;
 
    struct node {
        int nxt[AL], go[AL];
        int p, pch;
        int suf, ssuf;
        bool term;
        
        node() {
            memset(nxt, -1, sizeof(nxt));
            memset(go, -1, sizeof(go));
            suf = ssuf = -1;
            term = false;
        }
    };
 
    vector<node> nodes;
    vector<vector<int>> g;
    
    aho_corasick() {
        nodes.push_back(node());
    }
 
    void add(const string& s) {
        int v = 0;
        forn(i, s.size()) {
            int c = al.find(s[i]);
            if (nodes[v].nxt[c] == -1) {
                nodes.push_back(node());
                nodes[v].nxt[c] = nodes.size() - 1;
                nodes.back().p = v;
                nodes.back().pch = c;
            }
            v = nodes[v].nxt[c];
        }
        nodes[v].term = true;
    }
    
    int go(int v, int c) {
        if (nodes[v].go[c] != -1)
            return nodes[v].go[c];
        if (nodes[v].nxt[c] != -1)
            return nodes[v].go[c] = nodes[v].nxt[c];
        if (v == 0)
            return nodes[v].go[c] = 0;
        return nodes[v].go[c] = go(suf(v), c);
    }

        int s = suf(v);
        if (nodes[s].term)

    }

        }
```
