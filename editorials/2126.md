## 2126A - Only One Digit

Idea: [soullless](<https://codeforces.com/profile/soullless>)

**Tutorial**

Key idea The minimal valid $y$ is always a single digit. Simply find the smallest digit $d ∈ {0 … 9}$ that appears in the decimal representation of $x$; set $y = d$. Any multi-digit number would start with some digit already checked, so scanning beyond $9$ is pointless.

What to do

- Build the set of digits occurring in $x$.

- Iterate through digits   → $9$; the first one that belongs to the set is the answer.


**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
 int t;
 cin >> t;
 while(t--) {
 int x;
 cin >> x;
 int mn = 9;
 while(x > 0) {
 mn = min(mn, x % 10);
 x/=10;
 }
 cout << mn << endl;
 }
}
```

## 2126B - No Casino in the Mountains

Idea: [soullless](<https://codeforces.com/profile/soullless>)
 
**Tutorial**

Key observation

Inside one block of length len (all zeros) we must place patterns of $k$ good days (the hike) plus one mandatory rest day after each hike except the last. Thus each hike consumes $k + 1$ slots, except the final one, which does not need a trailing rest day.

Therefore, the maximum number of hikes in one block is

hikes_in_block = $\lfloor \frac {(len + 1)} {(k + 1)} \rfloor$

Intuition: add an imaginary rest day to the end of the block, then just cut the segment into chunks of size $k + 1$.

 
**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
  int t;
  cin >> t;
  while(t--) {
    int n,k;
    cin >> n >> k;
    int a[n + 1];
    for(int i = 1;i <= n;i++) cin >> a[i];
    int ans = 0;
    int cnt = 0;
    for(int i = 1;i <= n;i++) {
      if(a[i] == 1) {
        ans+=(cnt + 1)/(k + 1);
        cnt = 0;
        continue;
      }
      else {
        cnt++;
      }
    }
    ans+=(cnt + 1)/(k + 1);
    cout << ans << endl;
  }
}
```

## 2126C - I Will Definitely Make It

Idea: [soullless](<https://codeforces.com/profile/soullless>)

**Tutorial**

Key idea While you stand on a tower of height $h$, you must depart no later than time $h − 1$ (water hits level $h$ at that instant). Therefore, if you arrive at height $h$ at global time $t$, you have a slack of

$slack = h − 1 − t$

A move to a taller tower $H$ costs $H − h$ seconds. Feasibility condition:

t$ + (H − h) \leq h − 1$ ⇔ $t + (H − h) \lt h$ Greedy path (monotone-ascending) Any detour to a lower tower only wastes time and shrinks slack, so an optimal route is strictly non-decreasing in height. Thus:

1. Collect all tower heights, mark your start height $h_0$.

2. Sort the heights ascending.

3. Starting with $time = 0$, $cur = h_0$, walk through every height $H \gt cur$ in order:

- $time += H − cur$ (teleport duration)

- if $time ≥ cur$ ⇒ drowned ⇒ answer NO

- else $cur = H$ and continue.

4. If the loop finishes (or you began on the highest tower), output YES

Correctness sketch For each step we enforce $time \lt cur$, exactly the survival requirement for the tower we are leaving. Because total time accumulated along an ascending chain equals the direct height difference $(H_{max} − h_0)$, any other path cannot finish earlier. Hence the greedy check is both necessary and sufficient.


**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
 int t;
 cin >> t;
 while(t--) {
 int n,p;
 cin >> n >> p;
 int a[n + 1];
 for(int i = 1;i <= n;i++) cin >> a[i];
 int cur = a[p];
 int dist = a[p];
 sort(a + 1,a + n + 1);
 bool ans = true;
 for(int i = 1;i <= n;i++) {
 if(a[i] < cur) continue;
 if(a[i] &mdash; cur > dist) {
 ans = false;
 }
 cur = a[i];
 }
 if(ans) cout << "YES" << endl;
 else cout << "NO" << endl;
 }
}
```

## 2126D - This Is the Last Time

Idea: [soullless](<https://codeforces.com/profile/soullless>)
 
**Tutorial**

Core insight The process is monotone non-decreasing: coins never drop after a visit ($real_i ≥ l_i$). Hence we can repeatedly grab any casino whose interval currently covers $c$; doing so can only enlarge the set of playable casinos.

To obtain the best final value, whenever multiple casinos are currently available, choose the one with the largest $real_i --- it$ gives the greatest immediate boost and cannot harm future options.

Greedy algorithm with a heap

1. Sort casinos by $l_i$ asc.

2. Maintain an index ptr over the sorted list and a max-heap (priority queue) keyed by $real_i$.

3. Let $cur = k$.

4. Loop

- Push into the heap every casino with $l_i ≤ cur$ (advance ptr while that holds).

- Pop from the heap until you find one with $cur ≤ r_i$ (still covers current coins).

- If none exists ⇒ no more moves, stop.

- Otherwise set cur = $real_i$ and continue.

5. Output cur.

Because each casino enters the heap once and leaves once, the complexity is $O(n log n)$ per test case, $O(n)$ memory

Correctness sketch Choice of maximal $real_i$: suppose we pick a smaller real. The larger one remains playable now (it covers cur) and yields $a ≥ increase$, so delaying it cannot enlarge the reachable set; taking it immediately is never worse.

The heap loop simulates exactly the greedy sequence above, terminating only when no playable casino remains — then cur is provably maximal.

 
**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
int main() {
  int t;
  cin >> t;
  while(t--) {
    int n,k;
    cin >> n >> k;
    pair <int,pair <int,int> > p[n + 1];
    for(int i = 1;i <= n;i++) cin >> p[i].first >> p[ыi].second.first >> p[i].second.second;
    sort(p + 1,p + n + 1);
    int cur = k;
    for(int i = 1;i <= n;i++) {
      if(p[i].first > cur) break;
      cur = max(cur,p[i].second.second);
    }
    cout << cur << endl;
  }
}
```

## 2126E - G-C-D, Unlucky!

Idea: [Away_in_the_heavens](<https://codeforces.com/profile/Away_in_the_heavens>)

**Tutorial**

Problem. We are given two integer arrays $p[1 … n]$ and $s[1 … n]$. They are alleged to be the prefix-GCDs and suffix-GCDs of some hidden array $a[1 … n]$:

 $p_i$ = $gcd(a_1,...,a_i)$, $s_i$ = $gcd(a_i,...,a_n)$.

Decide whether such an array a exists.

Step 1. Immediate divisibility checks. For any prefix GCD chain one always has $p_i$ | $p_{i - 1}$ (moving right never introduces new prime factors). Likewise, for the suffix chain $s_i | s_{i+1}$. So we must have

 $p_{i-1}$ mod $p_i = 0$ for every $i ≥ 2$, $s_{i+1}$ mod $s_i = 0$ for every $i ≤ n − 1$.

Both chains describe the GCD of the entire array when they meet in the middle, therefore $p_n$ must equal $s_1$. Denote that common value by $g$. If any of these conditions fails, the answer is immediately "NO".

Step 2. Factor $g$ out. Write $P_i = \frac {p_i} {g} $ and $S_i = \frac {s_i} {g}$. From now on we only reason about the reduced chains $P$ and $S$; $g$ can be multiplied back into every $a_i$ at the end.

Step 3. What must hold at a single position $i$. Suppose we already know $gcd(a_1,…,a_{i-1}) = p_{i-1}$ and $gcd(a_{i+1},…,a_n) = s_{i+1}$. We must choose a positive integer $A$ such that

$gcd(p_{i-1}, A) = p_i$ and $gcd(A, s_{i+1}) = s_i$.

Divide by g everywhere and let

 $x = \frac {p_{i-1}} {p_i}$ (an integer $≥ 1$), $y = \frac {s_{i+1}} {s_i} $ (also $≥ 1$).

The two equations become

 $gcd(x, \frac {A} {g}) = 1$ and $gcd(\frac {A}{g}, y) = 1$, $P_i$ divides $\frac {A}{g}$, $S_i$ divides $\frac {A} {g}$.

Set $\frac {A}{g} = u$. We need a $u$ that is a common multiple of $P_i$ and $S_i$ and is simultaneously coprime to both $x$ and $y$.

Key arithmetic facts: $P_i$ and $x$ are always coprime, because $x = \frac {P_{i-1}} {P_i}$ and no prime can divide both a number and its own quotient. Symmetrically, $S_i$ and $y$ are coprime.

Therefore $u = P_i * S_i$ works iff

$gcd(x, S_i) = 1$ and $gcd(y, P_i) = 1$.

These two gcd tests are both necessary and sufficient; if they pass we can put $a_i = g * P_i * S_i$.

Step 4. Global algorithm.

1. Verify the divisibility chains and $p_n = s_1$; if something fails, print NO.

2. For every $i = 2…n$ check $gcd((\frac {p_{i-1}}{p_i}), S_i) = 1$.

3. For every $i = n-1…1$ check $gcd((\frac {s_{i+1}}{s_i}), P_i) = 1$. (All divisions are exact by the chain property.)

4. If every test passes, print YES; otherwise NO.

Step 5. Complexity. Each gcd call is logarithmic in the values involved; we make $O(n)$ such calls and a constant number of simple passes over the arrays, so the total running time per test case is $O(n log maxvalue)$ with $O(1)$ extra memory.

If the algorithm answers YES, one explicit witness array is $a_i = g * P_i * S_i$.


**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
main() {
 int t;
 cin >> t;
 while (t--) {
 int n;
 cin >> n;
 long long a[n + 1];
 for (int i = 1; i <= n; i++) {
 cin >> a[i];
 }
 long long b[n + 1];
 for (int i = 1; i <= n; i++) {
 cin >> b[i];
 }
 long long ans[n + 1];
 for (int i = n; i >= 1; i--) {
 ans[i] = lcm(a[i], b[i]);
 }
 bool ch = 1;
 if(ans[1] != a[1]) ch = 0;
 if(ans[n] != b[n]) ch = 0;
 for (int i = 2; i <= n; i++) {
 if (__gcd(a[i &mdash; 1], ans[i]) != a[i]) {
 ch = 0;
 }
 }
 for (int i = n &mdash; 1; i >= 1; i--) {
 if (__gcd(b[i + 1], ans[i]) != b[i]) {
 ch = 0;
 }
 }
 if (ch) {
 cout << "YES" << "\n";
 } else {
 cout << "NO" << "\n";
 }
 }
}
```

## 2126F - 1-1-1, Free Tree!

Idea: [soullless](<https://codeforces.com/profile/soullless>)
 
**Tutorial**

Root the tree at vertex $1$. During one $DFS$ store, for every vertex $v$, its parent $par_v$ and the weight $cost_v$ of the edge $(par_v, v)$. While visiting a child $u$ of $v$, also add $cost_u$ to a dictionary $mem_{v_{colour}}$ under key $a_u$; thus $mem_{v_c}$ is the total weight of edges from $v$ to children that currently have colour $c$. The $DFS$ finishes in $O(n)$.

Compute the initial answer $ans --- the sum of costs of edges whose endpoints have different colours$. Walk over all vertices $v ≠ 1$ and, if $a_v$ differs from $a_{par_v}$, add $cost_v$ to $ans$. This is $O(n)$.

A query gives a vertex $v$ and a new colour $x$. Let $old = a_v$. First handle the edges from $v$ to its children. All those edges whose children had colour old were previously free; after the repaint they become paid, so add mem_{v_{old}} to $ans$. Conversely, the edges counted in $mem_{v_x}$ were previously paid and now become free, so subtract $mem_{v_x}$ from $ans$.

Next handle the edge $(par_v, v)$ if $v$ is not the root. Its weight $w = cost_v$ was included in ans exactly when old differed from the parent's colour; if so, subtract $w$. After the repaint the edge must be included exactly when $x$ differs from the parent's colour; if so, add $w$. After that update the parent's dictionary: decrease $mem_{par_{v_{old}}}$ by $w$ and increase $mem_{par_{v_x}}$ by $w$.

Write $a_v = x$ and output the new $ans$. Every dictionary access is an $O(log deg_v)$ map operation, so each query costs $O(log n)$ in the worst case. Overall complexity for one test case is $O((n + q) log n)$ time and $O(n)$ memory, which fits easily in the limits.

 
**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int B = 2e5 + 100;
int n;
int col[B];
long long costt = 0;
vector <pair <int,int> > reb[B];
bool was[B];
map <int,long long> cnt[B];
int pred[B];
long long zn[B];
void dfs(int v) {
  was[v] = true;
  for(auto u:reb[v]) {
    if(was[u.first]) {
      pred[v] = u.first;
      continue;
    }
    if(col[v] != col[u.first]) costt+=u.second;
    dfs(u.first);
    zn[u.first] = u.second;
    cnt[v][col[u.first]]+=zn[u.first];
  }
}
void update(int v,int x) {
  if(v != 1) {
    cnt[pred[v]][col[v]]-=zn[v];
    if(col[pred[v]] == col[v]) costt+=zn[v];
    cnt[pred[v]][x]+=zn[v];
    if(col[pred[v]] == x) costt-=zn[v];
  }
  else {
      
  }
  costt+=cnt[v][col[v]];
  costt-=cnt[v][x];
  col[v] = x;
}
void clr() {
  for(int i = 1;i <= n;i++) {
    reb[i].clear();
    was[i] = false;
    cnt[i].clear();
    zn[i] = 0;
  }
  costt = 0;
}
int main() {
  int t;
  cin >> t;
  while(t--) {
    int q;
    cin >> n >> q;
    for(int i = 1; i <= n; i++) cin >> col[i];
    for(int i = 1; i < n; i++) {
      int u, v, c;
      cin >> u >> v >> c;
      reb[v].push_back({u,c});
      reb[u].push_back({v,c});
    }
    dfs(1);
    while(q--) {
      int pos,x;
      cin >> pos >> x;
      update(pos,x);
      cout << costt << "\n";
    }
    clr();
  }
}
```

[2126G1 - Big Wins! (easy version)](<https://codeforces.com/contest/2126/problem/G1>)

**Tutorial**

## 2126G1 - Big Wins! (easy version)

The array values do not exceed $100$, so the median we are hunting for can be any integer $m$ from $1$ to $100$.

For a fixed $m$ mark every position $j$ by

$b_j = +1$ if $a_j ≥ m$

$b_j = −1$ otherwise.

For any subarray its median is at least $m$ ⇔ the majority of its elements are $≥ m$ ⇔ the sum of the $b$'s on that segment is positive. Let $pref_k$ = $\sum_{i = 1}^{k} b[i]$. Then a subarray $(l, r]$ has positive sum iff $pref_r  \gt  pref_l$.

For the same fixed $m$ we would like to know, for every position $j$, whether there is a positive - sum subarray that contains $j$. That is true whenever $\min_{0≤l \lt j} pref_l  \lt  pref_j$   or   $pref_{j - 1}  \lt  \max_{j≤r≤n} pref_r$. Pre-compute left-side prefix minima $prefmn_j = \min_(pref_{0\leq x \leq j})$ and right-side suffix maxima $ suffmx_j = \max_(pref_{j \leq x \leq n})$ in two linear passes.

If either inequality holds, index $j$ can lie in some subarray whose median is $≥ m$. We are free to take that same $j$ as the minimum of the chosen subarray, giving value $a_j$. Hence, for that $j$ we can realise the gap $m − a_j$. Among all indices that satisfy the test keep the largest difference.

Repeat the whole procedure for $m = 1…100$ and output the global maximum. Every round over $m$ costs $O(n)$: build $b[ ]$, prefix sums, prefix minima, suffix maxima, then scan once more. Total work $O(100n) ≤ 2 · 10⁷$ for $n ≤ 2 · 10⁵$, which fits easily. Memory is $O(n)$.


**Solution**
```cpp
#include <bits/stdc++.h>
using namespace std;
const int B = 2e5 + 100;

int main() {
 int t;
 cin >> t;
 while(t--) {
 int n;
 cin >> n;
 int a[n + 1];
 for(int i = 1;i <= n;i++) cin >> a[i];
 int ans = 0;
 for(int i = 1;i <= 100;i++) {
 int b[n + 1] = {};
 for(int j = 1;j <= n;j++) {
 if(a[j] >= i) b[j] = 1;
 else b[j] = -1;
 }
 int pref[n + 1] = {};
 for(int j = 1; j <= n; j++) {
 pref[j] = pref[j - 1] + b[j];
 }
 int prefmn[n + 2] = {},suffmx[n + 1] = {};
 prefmn[0] = 0,suffmx[n] = pref[n];
 for(int j = 1; j <= n; j++) {
 prefmn[j] = min(prefmn[j - 1],pref[j]);
 }
 for(int j = n - 1; j >= 1; j--) {
 suffmx[j] = max(suffmx[j + 1],pref[j]);
 }
 for(int j = 1; j <= n; j++) {
 if(prefmn[j - 1] <= pref[j] || pref[j - 1] <= suffmx[j]) {
 ans = max(ans,i - a[j]);
 }
 }
 }
 cout << ans << endl;
 }
}
```

[2126G2 - Big Wins! (hard version)](<https://codeforces.com/contest/2126/problem/G2>)

Idea: [soullless](<https://codeforces.com/profile/soullless>)
 
**Tutorial**

## 2126G2 - Big Wins! (hard version)

Goal: maximise  $median(subarray) − minimum(subarray)$. Treat the minimum as the "left pointer" $mn$ that we increase from $1$ up to max $a_i$. For every fixed $mn$ we try to push a second pointer $med$ (the candidate median) as high as possible while some subarray exists whose minimum is exactly $mn$ and whose median is at least $med$. The answer is the largest difference $med − mn$ reached during this sweep.

Fix a value $mn$. Any subarray whose minimum equals $mn$ must contain at least one position $u$ with $a_u = mn$, and the whole subarray must lie inside the maximal span where that $u$ is the strict minimum. Those spans are computed once by the usual monotone stack: $l_u =$ first index to the left that has $value \lt  a[u] + 1$, $r_u = $first index to the right that has $value \lt  a_u - 1$.

For a potential median $M$ define an array $sign_i$ = $+1$ if $a_i ≥ M$, $−1$ otherwise. Inside any interval its median is $≥ M$ exactly when the total sum of sign over that interval is positive (at least half the elements are high). Therefore, for a particular position $u$ to serve as the minimum we need

$maxSuffix(l_u, u−1) + sign_u + maxPrefix(u+1, r_u) ≥ 0$.

Here $maxSuffix$ and $maxPrefix$ are, respectively, the largest suffix sum ending at $u−1$ and the largest prefix sum starting at $u+1$, measured in the sign array.

All max-prefix / max-suffix / total-sum queries can be answered in $O(log n)$ with a segment-tree that stores at each node ($ans, bestPrefix, bestSuffix, totalSum$). Merging two children follows the standard Kadane-style formulas.

Algorithm loop. Initialise the segment tree with $sign ≡ +1$, so total sum everywhere is positive; set $med = 1$. For $med←1$ we must exclude from the tree every position whose value is $ \lt  med$, by updating that point to $−1$. Now iterate $mn$ from $1$ upward:

 - for every index $u$ with $a_u = mn$ evaluate the inequality above.

 - while the inequality is satisfied for all such indices, increment $med$ by $1$ and for every position whose value just became $ \lt  med$ perform one point-update to $−1$ in the segment tree.

 - when the test fails for some $u$, stop raising med.

 - record $ans = max(ans, med − mn)$.

Because med only increases and never exceeds $n$, the total number of tree updates is $O(n)$ and every update / query costs $O(log n)$, so the whole run is $O(n log n)$. Memory is $O(n)$.

Why correct. For each mn the inner while moves med upward greedily until the moment no subarray with minimum mn can keep the $median ≥ med$; thus the last valid value of $med$ realises the true maximum for this $mn$. The outer sweep examines every possible minimum, hence the largest gap ever recorded is the global optimum.
