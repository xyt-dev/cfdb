## 2222A - A Wonderful Contest

Author: [Lyz09](<https://codeforces.com/profile/Lyz09>)

**Hint 1**

**Tutorial**

First, consider the case where $k=1$. We find that this condition holds if and only if there exists $a_i=100$. Assuming $a_d=100$, then letting $x_d=k$ and the remaining $x_i=0$ satisfies the condition $k\in [0,100]$.

Furthermore, we find that when $k \gt 100$, letting $x_d=((k-1)\bmod 100)+1$ and having $\lfloor \frac{k-1}{100}\rfloor$ of the remaining $x_i$ as $a_i$ and $n-1-\lfloor \frac{k-1}{100}\rfloor$ as $0$ constructs the corresponding solution.

In summary, the necessary and sufficient condition for any $k$ to satisfy the problem's conditions is that there exists at least one $a_i$ such that $a_i=100$.

## 2222B - Artistic Balance Tree

Author: [lizhous](<https://codeforces.com/profile/lizhous>)
 
**Hint 1**

Consider for a given $p$, which elements can be placed at $p$ with one reversal operation.

 
**Tutorial**

Note that when reversing a segment of odd length, the parity of the indices remains unchanged. It can be shown that through a single reversal operation, we can move any element from a position with the same parity as $x_i$ to the target position $x_i$.

Using a greedy approach, we aim to mark the largest numbers first and avoid marking negative numbers when possible. Our strategy is: – If the maximum value in the group of positions with the same parity as $x_i$ is greater than $0$, or if no marks have been made in that group yet, we mark that maximum value. – Otherwise, we mark the largest value from any previously marked position in the same group.

We can solve this by separating the elements by parity and applying any sorting algorithm to process the groups.

 
**Implementation**

## 2222C - Median Partition

**Hint 1**

**Hint 2**

**Tutorial**

Consider how to determine whether the median of an interval equals $x$. Let the count of values less than $x$ be $a$, the count of values equal to $x$ be $b$, and the count of values greater than $x$ be $c$. We then require: $a+b \gt c$ and $b+c \gt a$.

Note that the median of all intervals is the same as the median of the original sequence. The proof can consider that if they are equal to another integer $y$, assuming it is divided into $k$ segments, the number of $ \lt y$ as $a_1,a_2,a_3,...,a_k$ and the number of $=y$ as $b_1,b_2,b_3,...,b_k$ must be greater than $c_1,c_2,c_3,...c_k$ when summed. Similarly, the entire sequence also satisfies this condition, $b+c \gt a$.

Therefore, we only need to design $f_i$ to represent the maximum number of segments into which the first $i$ numbers can be divided, transitioning from all $j \lt i$ where the median of $[j+1, i]$ is the original median.

## 2222D - Permutation Construction

Author: [Lyz09](<https://codeforces.com/profile/Lyz09>)
 
**Hint 1**

Try to perform a prefix sum on $a$.

 
**Hint 2**

Consider what the upper bound of the answer is.

 
**Tutorial**

First, let $b_i=\sum_{j=1}^{i-1} a_j$. Then the value of the inversion $(i,j)$ can be expressed as $b_j-b_i$.

Consider maximizing the beauty of the permutation $p$. The ideal situation is that for all $(i,j)$ where $b_j \gt b_i$ and $i \lt j$, $p_i \gt p_j$ is satisfied, and for all $(i,j)$ where $b_j \lt b_i$ and $i \lt j$, $p_i \lt p_j$ is satisfied.

We find that even when $i \lt j$ is not guaranteed, the magnitude relationship between $p_i$ and $p_j$ is the opposite of the magnitude relationship between $b_i$ and $b_j$. Therefore, we can sort all $i$ in descending order by $b_i$ and set $p_i=x$ for the $x$-th $i$, which exactly meets all the above requirements.

This entire process uses only sorting and has a time complexity of $O(n\log n)$.

Author: [Lyz09](<https://codeforces.com/profile/Lyz09>)

**Hint 1**

Try to use $0$ and $2^n-1$ in the solution.


**Tutorial**

First, consider the value of $a$. Since $a$ might conflict with a later $f(x)$, making it impossible to determine the value of $f(x)$, we want $a$ to be as different as possible from being equal to a later $f(x)$. Let's assume $a=0$, so that it will definitely not be equal to $f(x)$ when $k=2$.

Next, consider inserting an $f(x)$ into $S$. We find that if we assume $x=0$, we can easily distinguish between the cases when $k=1$ and $k=2$, $k=3$. Therefore, after inserting $f(0)$ into $S$, we can discuss the cases separately:

- If $|S|=1$, it means $f(0)=0$, then $k=1$, and $c=f(2^n-1)$. Since $c \gt 0$, we know that $f(2^n-1) \neq 0$.
- If $|S|=2$, it means $f(0) \neq 0$, then $k = 2$ or $k = 3$, and $c = f(0)$.

How do we find the value of $f(x)$? We only need to know the specific elements in $S$ before inserting $f(x)$, and then perform a binary search on the value $z$ of $f(x)$ after inserting $f(x)$. If the number of elements in $S$ that are $\geq z$ is different from the number of elements in $S$ that are $\geq z$ before inserting $f(x)$, then $f(x) \geq z$; otherwise, $f(x) \lt z$. The number of queries required to find $f(x)$ by binary search is $\log_2 2^n = n$.

For case 2 above, we still need to determine whether $k=2$ or $k=3$. Observation shows that when $c\neq 2^n-1$, $0$, $c$, $2^n-1 | c$, and $(2^n-1)\oplus c$ are all different. Therefore, we can directly insert $f(2^n-1)$ to distinguish between the cases of $k=2$ and $k=3$.

Here, we don't need to know the specific value of $f(2^n-1)$, only whether the value of $f(2^n-1)$ is $2^n-1$, so only one query operation is needed.

For the case of $c=2^n-1$, we only need to determine whether the value of $f(1)$ is $2^n-1$.

When $k=1$, a total of $1+1+n=n+2$ interactions are required.

When $k=2$ or $k=3$, a total of $1+n+1+1=n+3$ interactions are required.

## 2222F - Building Tree

Author: [hzy_____](<https://codeforces.com/profile/hzy_____>) Preparation: [Rebex](<https://codeforces.com/profile/Rebex>)
 
**Hint 1**

Under what circumstances can an edge with cost $w$ be added between vertex $u$ and vertex $v$ in a new graph?

 
**Hint 2**

Consider divide and conquer.

 
**Tutorial**

Note that in the new graph, an edge with weight $w$ exists between two points if and only if, after adding edges with weights in $[0,w-1]$ and $[w+1,\infty]$ to the original graph, these two points become connected.

Sort the edges of the original graph and apply a divide-and-conquer approach by edge weight. Suppose the current interval is $[l,r]$:

- Let $mid=\lfloor\frac{l+r}{2}\rfloor$;
- Add edges with weights in $[mid+1,r]$ to the original graph;
- Recursively process $[l,mid]$;
- Undo the edges added in the previous steps, add edges with weights in $[l,mid]$, and recursively process the interval $[mid+1,r]$;
- Undo the edges added in step 4.

This process of adding and removing edges can be maintained using a reversible union-find data structure. It is not difficult to see that, for any two points $(u,v)$, the $\text{mex}$ of the weights of the edges added when they are first connected during this process is minimized.

Then, consider Kruskal's algorithm: each time two connected components $S$ and $T$ are merged in the original graph, arbitrarily take one point $x$ from $S$ and one point $y$ from $T$ in the new graph, and attempt to add an edge $(x,y,w)$ to the minimum spanning tree of the new graph, where $w$ is the $\text{mex}$ of the weights of the edges currently added in the original graph.

Any point from the new graph can be chosen because the points in the connected component are already connected in the new graph at this stage, and $w$ can be easily maintained during the divide-and-conquer process.

Thus, the problem is solved. The time complexity is $O(n\log^2 n)$ (assuming all parameters are of the same order). Since one $\log$ factor comes from the reversible union-find, the algorithm runs quite efficiently.

 
**Implementation**
```cpp
#include <iostream>
#include <algorithm>
#include <cstdio>
#include <vector>

using namespace std;

const int S=300005;

int n,m,k;
vector<pair<int,int> > vec[S];
int fa[S],hei[S],pt[S],fa2[S];
int top,*pot[S*3],val[S*3];
long long ans;

int fnd(int x){return fa[x]==x?x:fnd(fa[x]);}
int fnd2(int x){return fa2[x]==x?x:fa2[x]=fnd2(fa2[x]);}

inline void push(int &x){pot[++top]=&x,val[top]=x;}
inline void pop(){*pot[top]=val[top],top--;}

inline void merge(int x,int y,int w)
{
    int rx=fnd(x),ry=fnd(y);
    if(rx==ry) return;
    int px=pt[rx],py=pt[ry];
    if(px!=0&&py!=0)
    {
        int rx=fnd2(px),ry=fnd2(py);
        if(rx!=ry) ans+=w,fa2[rx]=fa2[ry];
    }
    if(hei[rx]>hei[ry]) swap(rx,ry);
    push(hei[ry]),hei[ry]=max(hei[ry],hei[rx]+1);
    push(pt[ry]),pt[ry]=max(pt[ry],pt[rx]);
    push(fa[rx]),fa[rx]=ry;
}

void doit(int l,int r,int w)
{
    if(l==r) return;
    int tp=top;
    int mid=l+r>>1;
    for(int i=r;i>=mid+1;i--)
        for(auto t:vec[i]) merge(t.first,t.second,w);
    doit(l,mid,w);
    while(top>tp) pop();
    for(int i=l;i<=mid;i++)
    {
        if(!vec[i].empty()&&w==i) w++;
        for(auto t:vec[i]) merge(t.first,t.second,w);
    }
    doit(mid+1,r,w);
    while(top>tp) pop();
}

inline void slove()
{
    cin>>n>>m>>k;
    for(int i=0;i<=m;i++) vec[i].clear();
    for(int i=1,x,y,w;i<=m;i++) cin>>x>>y>>w,vec[w].emplace_back(x,y);
    vector<int> tmp;
    for(int i=1,x;i<=k;i++) cin>>x,tmp.push_back(x);
    sort(tmp.begin(),tmp.end());
    tmp.erase(unique(tmp.begin(),tmp.end()),tmp.end());
    k=tmp.size();
    for(int i=1;i<=n;i++) pt[i]=0;
    for(int i=0;i<k;i++) pt[tmp[i]]=i+1;
    for(int i=1;i<=n;i++) fa[i]=i,hei[i]=1;
    for(int i=1;i<=k;i++) fa2[i]=i;
    ans=0;
    doit(0,m,0);
    for(int i=1;i<=k;i++) if(fnd2(i)!=fnd2(1)) return cout<<"-1\n",void();
    cout<<ans<<'\n';
}

int main()
{
    ios::sync_with_stdio(false),cin.tie(0),cout.tie(0);
    int T;
    cin>>T;
    while(T-->0) slove();
    return 0;
}
```

## 2222G - Statistics on Tree

Author: [Lyz09](<https://codeforces.com/profile/Lyz09>) Developer: [Z-301](<https://codeforces.com/profile/Z-301>)

**Hint 1**

What is the value of a path that passes through the centroid of a tree?


**Hint 2**

What is the value of a path that does not pass through the centroid of a tree?


**Hint 3**

This is a convolution problem. Enumerate only the terms in the polynomial with non-zero coefficients and prove that the time complexity is correct.


**Tutorial**

We consider rooting the tree at any of its centroids. Then, we enumerate the LCA of the paths (denoted as $o$).

For a path $(x, y)$ where $\mathrm{LCA}(x, y) = o$ (where $x \ne o$ and $y \ne o$), its value is clearly $\max(a_x, a_y, n - b_x - b_y)$. Here:

- $a_u$ represents the maximum size of the components (other than the one containing $o$) when the edges along the path $(u, o)$ are removed.
- $b_u$ represents the size of the component containing $u$ after removing $o$ from the tree.

By definition, we have $a_u \le b_u$.

The maximum value among $a_x$, $a_y$, and $n - b_x - b_y$ determines the path's value. We analyze each case separately.


- Handling $a_x$ or $a_y$ as Maximum: If $a_x$ is the maximum, then $a_x \ge n - b_x - b_y$. Since $b_x \ge a_x$, this implies $2b_x + b_y \ge n$. Thus, either $b_x \ge \frac{n}{3}$ or $b_y \ge \frac{n}{3}$. After removing $o$, the sum of the sizes of the remaining connected components is $n - 1$. Hence, there are at most two connected components with size $\ge \frac{n}{3}$. Assume without loss of generality that $x$ lies in a connected component of size $\ge \frac{n}{3}$. We enumerate the components in the tree after removing $o$. For each pair of connected components $(X, Y)$, we sort the values of $a_*$ within each component. For each $y \in Y$, if $n - b_x - b_y \lt a_y$, we use binary search to count the number of $x \in X$ where $a_x \le a_y$ and add this to the answer. For $x \in X$ where $a_x \gt \max(a_y, n - b_x - b_y)$, we increment a counter $c_x$ (maintained via difference arrays). Finally, we add the contributions from $c_x$ to the answer. The condition $a_x$ or $a_y$ being the maximum only holds when $o$ is the root. Otherwise, $n - b_x - b_y \ge \frac{n}{2}$, which implies $a_x + a_y \le b_x + b_y \le \frac{n}{2}$. Thus, each node is processed $O(1)$ times, leading to an $O(n \log n)$ time complexity for this part.
- Handling $n - b_x - b_y$ as Maximum: This case resembles a convolution, which is complex. Instead of considering $a_x$ and $a_y$, we first assume $n - b_x - b_y$ is the maximum and later correct the answer during handling $a_x$ or $a_y$ as maximum when $o$ is the root. Treating this as a polynomial, the highest-degree term is $O(sz_o)$, where $sz_o$ is the size of the subtree rooted at $o$. Direct polynomial multiplication would lead to $O(n^2 \log n)$ time, but we exploit sparsity properties to optimize. Proof of $O(n \log n)$ Time:

 - For each $o$, let the largest child subtree be the "heavy" subtree and the others be "light".
 - Contribution between heavy and light subtrees costs $O(deg_o)$ complexity per node, where $deg_o$ is the degree of $o$, totaling $O(n)$.
 - For light subtrees, the number of distinct sizes is $O(\sqrt{sm_o})$, where $sm_o$ is the sum of light subtree sizes. So the convolution costs $O(sm_o)$ complexity, and according to DSU on tree, the sum of $sm_o$ is $O(n \log n)$.


We can simply add contributions when either $x=o$ or $y=o$. So the overall time complexity is $O(n \log n)$.

## 2222H - Counting Sort?

Author: [CutieSmileHaruka](<https://codeforces.com/profile/CutieSmileHaruka>)
 
**Hint 1**

You are given an array $a$. How to count the number of arrays $b$ that satisfy $f(b) = a$ and $ \forall 1 \le i \le n, b_i \le r_i $.?

 
**Hint 2**

You are given an array $a$. How to count the number of arrays $b$ that satisfy $f(f(b)) = a$ and $ \forall 1 \le i \le n, b_i \le r_i $.?

 
**Hint 3**

How many arrays $a$ satisfy there exists an array $b$ such that $f(f(b)) = a$?

 
**Hint 4**

[The partition numbers](<https://oeis.org/A000041>).

 
**Tutorial**

After connecting all arrays $ a $ to $ f(a) $ with directed edges, we obtain a directed pseudoforest (a collection of directed trees where each tree has a single cycle at its root). Specifically, the array $ a = [0, 0, 0, \dots, 0] $ forms an isolated node, while $ a = [1, 0, 0, \dots, 0] $ serves as the root for all other nodes. Here, $ g(a) $ corresponds to the depth of $ a $ in its tree plus one.

Directly characterizing $ g $ is quite challenging, so we resort to a more brute-force approach. We observe that after removing two layers of leaves, the number of remaining nodes in the tree becomes manageable. Specifically, we focus on counting the number of arrays $ a $ such that there exists a array $b$ that satisfies $ f(f(b)) = a $.

It turns out that this constraint is equivalent to $ \sum_{i=1}^n i \times a_i \le n $. Let $ P(n) $ denote the number of integer partitions of $ n $. Then, the number of such arrays $ a $ is $ \sum_{i=0}^n P(i) $. For $ n = 50 $, this count is at most $ 1.3 \times 10^6 $.

We first preprocess all such arrays $ a $ along with their depths. Then, for each $ a $, we compute the number of arrays $ b $ satisfying $ f(f(b)) = a $ and $ \forall 1 \le i \le n, b_i \le r_i $. Except for the case where $ a = [1, 0, 0, \dots, 0] $, we have $ g(b) = g(a) + 2 $. We accumulate these counts into the final answer and handle the special cases where $ g(*) \le 3 $ separately.

Next, we discuss how to compute these counts. First, for a given $ a $, we determine the number of arrays $ b $ such that $ f(b) = a $ and $ \forall 1 \le i \le n, b_i \le r_i $. This can be done by filling the array $ b $ from the largest value to the smallest, with the coefficients being products of several binomial coefficients.

We incorporate this process into a dynamic programming (DP) approach. Let $ dp_{i, a} $ denote the number of valid arrays $ b $ where we have already determined $ f(b)_i, f(b)_{i+1}, \dots, f(b)_n $, and $ f(f(b)) = a $. The DP can be updated in $ \mathcal{O}(n) $ time per state by enumerating the possible values of $ f(b)_i $. Thus, for a given $ a $, the total number of valid arrays $ b $ is $ dp_{1, a} $.

The overall time complexity is $ \mathcal{O}(n^2 \sum_{i=0}^n P(i)) $. In practice, the number of possible transitions is only about $ 2.5 \times 10^8 $, which is significantly smaller than this upper bound, making the solution feasible.
