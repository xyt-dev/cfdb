## 1571A - Sequence of Comparisons

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

If $s$ consists only of characters =, then $a_1 = a_n$.

If $s$ consists only of characters < and =, then $a_1 \lt a_n$.

If $s$ consists only of characters > and =, then $a_1 \gt a_n$.

Otherwise, it is impossible to uniquely determine the relationship between $a_1$ and $a_n$. For example, this can be checked on the strings <> and ><.


**Solution (Neon)**
```kotlin
fun main() = repeat(readLine()!!.toInt()) {
 val s = readLine()!!
 val l = s.count({ it == '<' })
 val g = s.count({ it == '>' })
 if (l > 0 && g > 0) println("?")
 else if (l > 0) println("<");
 else if (g > 0) println(">");
 else println("=");
}
```

## 1571B - Epic Novel

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

Note that since each day Alex either reads the same volume or the next one, then for $x$ days he can't read more than $x$ volumes, or (in other words) for any day $i$ and $j$ ($i \lt j$) $v_j - v_i \le j - i$.

Now, let's iterate over all possible variants for $v_b$. It's obvious that $v_a \le v_b \le v_c$. So we need to check:

- it is possible that Alex was reading volume $v_a$ at day $a$ and volume $v_b$ at day $b$;
- it is possible that Alex was reading volume $v_b$ at day $b$ and volume $v_c$ at day $c$.

To check the first case, it's enough to check that $v_b - v_a \le b - a$. Analogically, to check the second case, we check that $v_c - v_b \le c - b$.

As a result, all we need to do is find any $v_b$ from $v_a$ to $v_c$ where $v_b - v_a \le b - a$ and $v_c - v_b \le c - b$.

 
**Solution (adedalic)**
```kotlin
fun main() {
    repeat(readLine()!!.toInt()) {
        val n = readLine()!!.toInt()
        val (d1, v1) = readLine()!!.split(' ').map { it.toInt() }
        val (d3, v3) = readLine()!!.split(' ').map { it.toInt() }
        val d2 = readLine()!!.toInt()

        fun isPossible(d1: Int, v1: Int, d2: Int, v2: Int) = (v2 - v1) <= (d2 - d1)

        for (v2 in v1..v3) {
            if (isPossible(d1, v1, d2, v1) && isPossible(d2, v2, d3, v3)) {
                println(v2)
                break
            }
        }
    }
}
```

## 1571C - Rhyme

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)

**Tutorial**

Let $\mathit{limit}_i$ be the maximum value $k$ such that the $i$-th pair rhymes regardless of must it or must not. It's easy to calculate $\mathit{limit}_i$ as the length of the longest equal suffix of $s_i$ and $t_i$.

Now, if we know that the $i$-th pair must rhyme, then any possible $k$ should not exceed $\mathit{limit}_i$. But if the $i$-th pair must not rhyme, then any possible $k$ should be strictly greater than $\mathit{limit}_i$.

In other words, all possible $k$-s form a segment between minimum possible $k$ and maximum possible $k$. So, we can calculate minimum possible $k$ (named $l$) as $\max(\mathit{limit}_i) + 1$ among all $i$ with $r_i = 0$ and maximum possible $k$ (named $r$) as $\min(\mathit{limit}_i)$ among all $i$ with $r_i = 1$.

As a result there will be $\max(0, r - l + 1)$ possible $k$ from $l$ to $r$.


**Solution (adedalic)**
```kotlin
fun main() {
 repeat(readLine()!!.toInt()) {
 val n = readLine()!!.toInt()
 var l = 0
 var r = 4e5.toInt()
 for (i in 1..n) {
 val pairs = readLine()!!.split(' ')
 val limit = pairs[0].commonSuffixWith(pairs[1]).length
 if (pairs[2] == "0")
 l = maxOf(l, limit + 1)
 else
 r = minOf(r, limit)
 }
 println(maxOf(0, r - l + 1))
 if (r - l + 1 > 0)
 println((l..r).joinToString(" "))
 }
}
```

## 1571D - Sweepstake

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

Let's iterate over all possible pairs (winner, looser), calculate our place and take a maximum among all of them.

Suppose, $\mathit{cntPairs}_{w, l}$ be the number of spectators who chose pair winner $w$ and looser $l$, $\mathit{cntFirst}_w$ be the number of spectators who chose $w$ as winner, and $\mathit{cntLast}_l$ be the number of spectators who chose $l$ as looser.

Then, for a fixed pair (winner $w$ and looser $l$) it's possible to calculate both $c_2$ and $c_1$ in the following way: $c_2 = \mathit{cntPairs}_{w, l}$ and $c_1 = \mathit{cntFirst}_w + \mathit{cntLast}_l - 2 \mathit{cntPairs}_{w, l}$ (because, both $\mathit{cntFirst}_w$ and $\mathit{cntLast}_l$ contain spectators who guessed $2$ results). After that, baced on the number of our right answers, we can calculate our rank: is it $1$, $c_2 + 1$ or $c_2 + c_1 + 1$.

But there is one simplification: it can be proved that we can always iterate only over pairs $(w, l)$ where we guessed $0$ right answers. In this case our rank will always be $c_2 + c_1 + 1$ $=$ $\mathit{cntFirst}_w + \mathit{cntLast}_l - \mathit{cntPairs}_{w, l} + 1$ (union of all spectators who answered right at least once).

 
**Solution (adedalic)**
```kotlin
fun main() {
    val (n, m) = readLine()!!.split(' ').map { it.toInt() }
    val cntPairs = Array(n) { IntArray(n) { 0 } }
    val cntFirst = IntArray(n) { 0 }
    val cntLast = IntArray(n) { 0 }

    val firstPair = readLine()!!.split(' ').map { it.toInt() - 1 }
    for (i in 2..m) {
        val (f, l) = readLine()!!.split(' ').map { it.toInt() - 1 }
        cntPairs[f][l]++
        cntFirst[f]++
        cntLast[l]++
    }

    fun I(a: Boolean) = if (a) 1 else 0

    var worstPlace = 0
    for (w in 0 until n) {
        for (l in 0 until n) {
            if (w == l)
                continue
            val yourScore = I(w == firstPair[0]) + I(l == firstPair[1])
            var place = 1
            if (yourScore < 2)
                place += cntPairs[w][l]
            if (yourScore < 1)
                place += cntFirst[w] + cntLast[l] - 2 * cntPairs[w][l]
            worstPlace = maxOf(worstPlace, place)
        }
    }
    println(worstPlace)
}
```

## 1571E - Fix the String

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

Firstly, let's notice that there are only two correct bracket sequences of length $4$: (()) and ()().

Let's look at the neighboring ones (i.e., there are no other ones between them) in the string $a$. Let their positions be $i$ and $j$ ($j \lt i$). Let's consider what restrictions they put on each other:

- if $i - j = 1$, then there is no answer, because it is impossible to choose a pair of correct bracket sequences that the last $3$ characters of one coincide with the first $3$ characters of the other;
- if $i - j = 2$, then the only option when the last $2$ characters of one coincide with the $2$ characters of the other is two sequences of the form ()().
- if $i - j = 3$, then there is no answer, because it is impossible to choose a pair of correct bracket sequences that the last character of one coincides with the first character of the other;
- otherwise, they do not put any restrictions on each other.

Thus, for all $i$ that $a_i = 1$, we know what the correct bracket sequence should be the substring $s[i;i+3]$. If both sequences are suitable, then you have to choose the one that changes the minimum number of positions.

## 1571F - Kotlinforces

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Notice that it doesn't make sense to not put the competitions with $t=1$ not next to each other or start them from day $1$.

So the problem is to place competitions with $t=2$ over the remaining $m - cnt_1$ days.

Any competition with $t=2$ takes up either consecutive odd days or consecutive even days. We can count the number of remaining odd and even days.

The issue is to decide for each competition which of these two it should take up. So we want the total length of the competitions in the odd days to not exceed $\mathit{cnt}_{odd}$ and the total length of the competitions in the even days to not exceed $\mathit{cnt}_{even}$.

If the total length of the competitions exceeds $\mathit{cnt}_{odd} + \mathit{cnt}_{even}$, then there is no way for sure. Otherwise, you can fill up the odd days as much as possible and leave the remaining competitions for the even days.

That can be done with a $dp_{i,j}$ — is it possible to fill $j$ odd days with some subset of the first $i$ competitions. You should get AC with $O(nm)$ memory, but it's possible to make it $O(m)$.

Overall complexity: $O(nm)$.

 
**Solution (pashka)**
```kotlin
@file:Suppress("CanBeVal")
 
import java.io.BufferedReader
import java.io.InputStreamReader
import java.io.OutputStreamWriter
import java.io.PrintWriter
import java.util.*
 
private fun solve() {
    var (n, m) = readInts()
    var k = intarr(n)
    var t = intarr(n)
    for (i in k.indices) {
        var (kk, tt) = readInts()
        k[i] = kk
        t[i] = tt
    }
    var s1 = 0
    var s2 = 0
    var d = intarr(m + 1, -1)
    d[0] = 0
    for (i in k.indices) {
        if (t[i] == 2) {
            s1 += k[i]
            for (j in m downTo 0) {
                if (d[j] != -1 && j + k[i] <= m && d[j + k[i]] == -1) {
                    d[j + k[i]] = i
                }
            }
        } else {
            s2 += k[i]
        }
    }
    for (i in 0..m) {
        if (d[i] == -1) continue
        if (maxOf(i * 2 - 1, (s1 - i) * 2) + s2 > m) continue
        var c = BooleanArray(n)
        var x = i
        while (x > 0) {
            c[d[x]] = true
            x -= k[d[x]]
        }
        var res = intarr(n)
        var kk = 1
        for (i in 0 until n) {
            if (t[i] == 2 && c[i]) {
                res[i] = kk
                kk += k[i] * 2
            }
        }
        kk = 2
        for (i in 0 until n) {
            if (t[i] == 2 && !c[i]) {
                res[i] = kk
                kk += k[i] * 2
            }
        }
        kk = m + 1
        for (i in 0 until n) {
            if (t[i] == 1) {
                kk -= k[i]
                res[i] = kk
            }
        }
        println(res)
        return
    }
    println(-1)
}
```

## 1571G - A Battle Against a Dragon

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [awoo](<https://codeforces.com/profile/awoo>)

**Tutorial**

Obviously, the problem requires some sort of dynamic programming.

Consider the simplest one. $dp_{i,j}$ is the maximum total damage dealt by the first $i$ warriors if there are $j$ barricades after the move of the $i$-th warrior. The transitions are exactly the same as they are written in the statement.

That solution works in $O(nm)$ which is too slow. Let's analyze the behavior of the transitions on the dp table. The transition that destroys a barricade moves the value in some cell $(i,j)$ to $(i+1,j-1)$. The transition, that does nothing, moves it to $(i+1,j)$. The important thing to notice is that only the attack transition changes the value before updating the other state.

Thus, the idea is to write the dp in such a way that useless states produced by the first two transitions aren't stored explicitly and only collected by the attack transitions.

Let's restate the dp. $dp_{i,k}$ is the total damage dealt by the first $i$ warriors if the $i$-th warrior used his $k$-th attack. Notice that the fact that the attack was possible helps to identify the current number of barricades. To update such a dp we should iterate over both the previous warrior to attack and the attack he used.

Let the previous warrior be $j (j \lt i)$, his attack was when there were $x$ barricades and the attack of the $i$-th warrior was when there were $y$ barricades. If $x \lt y$, then there was no way for the $i$-th warrior to use his attack. At the same time, if $x - y \ge i - j$, then the warriors between the $j$-th and the $i$-th one have no way to destroy enough barricades. Otherwise, there is a way to assign either of the two moves to them in such a way that exactly $y$ barricades are left. Thus, $y \le x \le (i - j) + y$ should hold for the transition to be possible.

Picture a set of possible states, which can update $dp_{i,k}$, on the table. It looks like a triangle starting from $(i-1,y)$ and going vertically to the top and diagonally to the top-right.

That screams data structures, and we are finally approaching them.

I propose the following way to calculate the dp. Sort the attacks of all warriors altogether, first, in the decreasing order of the number of barricades and, second, in the increasing order of the warrior index.

Store a BIT such that its $i$-th position contains the maximum value of dp over the $i$-th diagonal (going from top-right to bottom-left). Now you can forget that the query area is a triangle and query on the entire prefix of the diagonals. The values in the required area are calculated already, and the values outside of it that get captured by the query are not calculated yet (due to being to the left of the triangle).

The answer is the maximum value stored in the entire BIT at the end.

Overall complexity: $O((\sum \limits_{i=1}^n k_i) \cdot \log(n + m))$.


**Solution (awoo)**
```kotlin
class Attack(val a: Int, val b: Int, val i: Int)

fun main() {
	val (n, m) = readLine()!!.split(" ").map { it.toInt() }
	val ev = ArrayList<Attack>()

	for (i in 0 until n) {
 val k = readLine()!!.toInt()
 val a = readLine()!!.split(" ").map { it.toInt() }
 val b = readLine()!!.split(" ").map { it.toInt() }
 for (j in 0 until k) {
 ev.add(Attack(a[j], b[j], i))
 }
	}
	ev.sortWith(compareBy({ -it.b }, { it.i }))

	val INF = 1e18.toLong()
	val mx = m + n + 1
	val f = LongArray(mx) { -INF }

	fun update(pos: Int, x: Long) {
 var i = pos
 while (i < mx) {
 f[i] = maxOf(f[i], x)
 i = i or (i + 1)
 }
	}

	fun query(pos: Int) : Long {
 var res = -INF
 var i = pos
 while (i >= 0) {
 res = maxOf(res, f[i])
 i = (i and (i + 1)) - 1
 }
 return res
	}

	update(m - 1, 0L)
	for (it in ev) {
 val dp = query(it.i + it.b - 1) + it.a
 update(it.i + it.b, dp)
	}
	println(query(mx - 1))
}
```

## 1571H - Laser Beams

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

We will treat the level as a planar graph, where the segments of the rays and the level border denote the edges, and their intersection points denote the vertices. The main idea of the solution is to use Euler's Formula for planar graphs: for a connected planar graph, $f = e - v + 2$, where $e$ is the number of edges, $v$ is the number of vertices, and $f$ is the number of regions into which the graph divides the plane. The number of parts of the level is exactly $f - 1$ (since Euler's Formula treats the exterior as an additional region), and we will use the linearity of expectation to evaluate the expected value of the answer: $E(ans) = E(e) - E(v) + 1$.

Calculating $E(v)$ is easy. Firstly, let's generate all the intersection points between the rays and/or the borders in $O(n^2)$. Then, for each intersection point, calculate the probability of it being a part of the planar graph — which is the probability that at least one of the possible lines that pass through this point actually exists. For each of the four possible lines that can pass through the point, we can calculate the probability that it exists — and this allows us to easily calculate $E(v)$.

There are many different ways to find $E(e)$, but, in my opinion, the easiest one is to calculate the expected sum of degrees of all vertices (and the sum of degrees is exactly $2e$). For each vertex, if it is not the last vertex on some line, and this line exists, there is an edge to the next vertex on this line. Similarly, if it is not the first vertex on some line, and this line exists, there is an edge to the previous vertex on this line. So calculating the expected degree of a vertex is actually summing up the probabilities of existence of each line passing through it such that this vertex is not the first on that line, and adding the same values for the lines such that this vertex is not the last on that line (possibly counting the same line twice).

All that's left is to use the Euler's Formula to calculate $E(f)$.

## 1571I - Physical Examination

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [awoo](<https://codeforces.com/profile/awoo>)

**Tutorial**

Think of the function that can tell if it's possible to start at minute $x$ and visit all doctors by the rules in the statement. This is solvable in $O(n \log n)$. That's a very common greedy, where you basically take the doctor who closes the earliest among the open ones and put him in the next minute.

If there exists a way to visit everyone, this solution will find it (and vice verse, the proof is left as an exercise for the reader).

Otherwise, there are two options for when it can fail. First, there might be no doctors to visit at some minute. Second, there might be two or more doctors that close at the same minute and weren't visited prior to it.

It's claimed that the function that returns $-1$ for the fail of the first type, $0$ for a valid start and $1$ for the fail of the second type, is monotonous.

Thus, we can perform a binary search on it to obtain a solution in $O(n \log n \log \mathit{MAX})$.

The idea of the proof is the following.

Consider a fail of the first type. What happens if you move $x$ one to the left? There was a prefix of doctors who got visited at $x$, $x+1$ and so on. Then there was a minute with no doctors. Since that minute is free, no doctor other than from this prefix is open. If there are $y$ doctors in it, then they have to fill up $y+1$ minutes, which is impossible. Adding a minute to the left and possibly removing one from the right still leave it at least $y+1$. Thus, it's still a fail of the first type.

Now consider a fail of the second type. What happens if you move $x$ one to the right? Minute $x+n$ is added and minute $x$ is removed. However, even if minute $x$ wasn't removed, an extra minute on the right doesn't help in any way. The minute on the left can only cause more collisions between doctors. Thus, it's still a fail of the second type.

Beware that some $x$ might be a fail of both types if the answer doesn't exist.


**Solution (awoo)**

```kotlin
import java.util.*

fun main() = repeat(readLine()!!.toInt()) {

	val ord = Array(n, { i -> i })
	ord.sortWith({x : Int, y: Int -> L[x] - L[y]})

	val ans = IntArray(n)

	fun check(m: Int, fl: Boolean): Int {
 val cur = PriorityQueue<Int>(compareBy { R[it] })
 var j = 0
 var res = 0

 while (j < n && L[ord[j]] <= t) {
 cur.add(ord[j])
 ++j;
 }
 if (cur.isEmpty()) {
 res = 1
 break
 }
 if (R[cur.peek()] < t) {
 res = -1
 break
 }
 if (fl) ans[t - m] = cur.peek() + 1
 cur.poll()
 }
 return res;
	}

	var l = 1
	var r = 1e9.toInt()
	var res = -1
	while (l <= r) {
 val m = (l + r) / 2
 val tmp = check(m, false)
 if (tmp == 0) {
 res = m
 break
 }
 if (tmp == -1) {
 r = m - 1
 }
 else {
 l = m + 1
 }
	}

	if (res != -1) {
 check(res, true)
 println(ans.joinToString(" "))
	}
```

## 1571J - Two Railroads

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Firstly, the problem asks us to find maximum flow in some special network. Instead of the maximum flow, we will try to find the minimum cut for each query.

Recall that an $s$-$t$-cut in a flow network is a partition of its vertices into two sets, $S$ and $T$, such that $s \in S$, $t \in T$, and the total capacity of all arcs leading from a vertex in $S$ to a vertex in $T$ is the value of the cut. The maximum flow from $s$ to $t$ is equal to the minimum $s$-$t$-cut.

Let's analyze the properties of the cut in this network. For simplicity, I will denote the $i$-th Main station as the vertex $v_i$, and the $i$-th Auxiliary station as the vertex $u_i$.

First of all, if we have a cut where $v_i \in S$ and $v_{i-1} \in T$, this cut is not a minimum one. If $u_{i - 1} \in S$, then we can add $v_{i-1}$ into $S$ and remove it from $T$, so the value of the cut will decrease at least by $a_{i-1}$. If $u_i \notin S$, we can remove $v_i$ from $S$ and decrease the value of the cut at least by $c_i$. If both $u_i$ and $v_i$ belong to $S$, and both $u_{i-1}$ and $v_{i-1}$ belong to $T$, we can just remove both $u_i$ and $v_i$ from $S$, and the value of the cut won't increase. So, it means that we can search for a cut where some prefix of vertices on the Main road belongs to $S$. Similarly, some prefix of vertices on the Auxiliary road will belong to $S$.

Now there are four cases how the cut can go. They are described in the following pictures:


![](eimages/1571_1.png)



![](eimages/1571_2.png)

 Let's analyze these cases one by one. For simplicity, denote $p_i = \sum\limits_{j=1}^{i} c_j$.

- Case 1: if the last $v$-vertex in $S$ is $v_x$, then the value of the cut is $a_x + c_l + c_{l+1} + \dots + c_{x-1} + c_x$, which can be rewritten as $a_x + p_x - p_{l-1}$. The minimum value can be calculated with a RMQ query of the value $a_x + p_x$ on the segment $[l, r - 1]$, since $p_{l-1}$ is constant.
- Case 2: if the last $v$-vertex in $S$ is $v_x$, then the value of the cut is $a_x + c_{x+1} + c_{x+2} + \dots + c_r$, which can be rewritten as $a_x + p_r - p_x$. The minimum value can be calculated with a RMQ query of the value $a_x - p_x$ on the segment $[l, r - 1]$, since $p_r$ is constant.
- Case 3: if the last $v$-vertex in $S$ is $v_x$, and the last $u$-vertex in $S$ is $u_y$, the value of the cut is $a_x + b_y + c_{y+1} + c_{y+2} + \dots + c_x = a_x + p_x - b_y - p_y$. We need to look deeper into this case, there's no clear way to solve this right now.
- Case 4: similar to Case 3, if we can solve that case, we'll solve Case 4.

Let's analyze the Case 3 more thoroughly. We have to minimize the value of $a_x + p_x - b_y - p_y$ under the constraints $l \le y \le x \le r$. Instead of this, let's lift one of the constraints; let's say that $y$ can be less than $l$. Then we can easily calculate the minimum value of $a_x + p_x - b_y - p_y$: for every $x$, precalculate the minimum $b_y + p_y$ to the left of it and "match" them; then just use RMQ on the precalculated values.

But doesn't the fact that we have lifted one of the constraints make our solution wrong? In fact, it doesn't. Suppose the answer to the Case 3 is "illegal" because the value of $y$ we found is less than $l$. Let's take a look at the picture of this case and the Case 2:


![](eimages/1571_3.png)


In fact, if Case 3 yields us an illegal solution, it will be overwritten by the solution of Case 2 since an illegal cut for the Case 3 can be transformed into a legal cut for Case 2 (and the value of the cut will only decrease). Similarly, illegal solutions of Case 4 (where we'll lift the constraint $y \le r$) can be fixed by Case 1.

So, we can answer each query with just four RMQ queries, and our solution runs in, for example, $O(n + q \log n)$ if we use a segment tree to process RMQ queries.

```kotlin
private class SegmentTree(private val size: Int) {
 
    class Item(val a: Long) {
        fun add(item: Item): Item {
            return if (a < item.a) this else item
        }
    }
 
    val NEUTRAL = Item(Long.MAX_VALUE)
 
    private val a: Array<Item>
 
    operator fun set(i: Int, v: Item) {
        set(0, 0, size, i, v)
    }
 
    private operator fun set(n: Int, l: Int, r: Int, i: Int, v: Item) {
        if (r == l + 1) {
            a[n] = a[n].add(v)
        } else {
            val m = (l + r) / 2
            if (i < m) {
                set(n * 2 + 1, l, m, i, v)
            } else {
                set(n * 2 + 2, m, r, i, v)
            }
            a[n] = a[n * 2 + 1].add(a[n * 2 + 2])
        }
    }
 
    fun sum(l: Int, r: Int): Item {
        return sum(0, 0, size, l, r)
    }

            a[n]

            sum(n * 2 + 1, ll, m, l, r).add(sum(n * 2 + 2, m, rr, l, r))
        }
    }
```
