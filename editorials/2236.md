## 2236A - Games on the Train

Idea: [arsen1y](<https://codeforces.com/profile/arsen1y>)

**Tutorial**

Let the maximum element be $mx$ and the minimum element be $mn$. Note that $1 \le x_i \le k$. After increasing the heights, the new height of the maximum will be at least $mx + 1$, and the new height of the minimum will be at most $mn + k$.

After the changes, all heights must become equal, so the new maximum must be equal to the new minimum. Therefore, the game can be finished if $k$ satisfies $mn + k \ge mx + 1$, that is, $k \ge mx - mn + 1$.

It can be shown that it is always possible to make all heights equal with $k = mx - mn + 1$, so this is the answer.


**Solution (arsen1y)**
```cpp
#include <bits/stdc++.h>
#define int long long

using namespace std;

const int INF = (int) 1e18;

int32_t main() {
 std::ios::sync_with_stdio(false);
 cin.tie(NULL);
 cout.tie(NULL);

 int _;
 cin >> _;

 while (_--) {
 int n;
 cin >> n;

 vector <int> a(n);
 int mx = -INF;
 int mn = INF;
 for (int i = 0; i < n; ++i) {
 cin >> a[i];
 mx = max(mx, a[i]);
 mn = min(mn, a[i]);
 }

 cout << mx - mn + 1 << "\n";
```

## 2236B - Tatar TV Show

Idea: [eyfxrby](<https://codeforces.com/profile/eyfxrby>)
 
**Hint**

Try to find a property that does not change during operations.

 
**Tutorial**

Let us repeatedly find the leftmost $1$ in the string and apply the operation to it, as long as it is not among the last $k$ characters. Since each operation only removes a $1$ from the prefix of length $n - k$, in the end we will obtain either a string of all zeros or a string in which all $1$s are located within the last $k$ positions.

Let us prove that in the second case there is no sequence of operations that can turn the string into all zeros. Observe that the operations do not change the parity of the number of ones among positions with the same $i \bmod k$:

- $00 \rightarrow 11$: $+2$ ones;
- $01 \rightarrow 10$: $+0$ ones;
- $10 \rightarrow 01$: $+0$ ones;
- $11 \rightarrow 00$: $-2$ ones.

Since all ones are located within the last $k$ positions, their indices have distinct values of $i \bmod k$, and thus it is impossible to make their total number equal to zero.

Alternatively, one could simply count the number of ones for each value of $i \bmod k$ and check their parity.

 
**Solution (eyfxrby)**
```cpp
#include <bits/stdc++.h>
using namespace std;
 
int main() {
    int t;
    cin >> t;
    while (t--) {
        int n, k; cin >> n >> k;
        string s; cin >> s;
        vector<int> cnt(k, 0);
        for (int i = 0; i < n; i++) cnt[i % k] += s[i] - '0';
        bool ok = true;
        for (int r = 0; r < k; r++) {
            if (cnt[r] % 2) {
                ok = false;
                break;
            }
        }
        cout << (ok ? "YES" : "NO") << '\n';
    }
}
```

## 2236C - Omsk Programmers

Idea: [arsen1y](<https://codeforces.com/profile/arsen1y>)

**Hint**

It can be shown that it is advantageous to do only divisions first, and then only additions.


**Tutorial**

First, we describe an algorithm that finds the optimal answer, and then we prove that it is indeed optimal.

The algorithm is as follows: suppose the current state is described by a pair of numbers $(p, q)$. Without loss of generality, assume $p \leq q$, and let $cnt$ be the number of divisions already performed. We try to update the answer with the value $q - p + cnt$. If the numbers are equal, we stop. Otherwise, we repeat the process with the pair $(p, q / x)$.

Now let us prove its correctness. The key idea of the algorithm is that it is optimal to perform all integer divisions first, and only then make the numbers equal using operations of adding $+1$. Suppose this is not true. Then at some point we applied $+1$ to a number $p$, and then applied $/= x$. Consider two cases:

$ \lfloor \frac{p}{x} \rfloor = \lfloor \frac{p + 1}{x} \rfloor $.

In this case, the $+1$ operation had no effect at all, so it could have been skipped, reducing the total number of operations.

$ \lfloor \frac{p}{x} \rfloor + 1 = \lfloor \frac{p + 1}{x} \rfloor $.

In this case, we can swap the order of operations: first apply $/= x$, and then apply $+1$. The result and the number of operations remain the same, while the desired property holds.

Thus, the lemma is proven, which establishes the correctness of the algorithm.

The time complexity of the solution is $O(\log_x(a) + \log_x(b))$ per test case.


**Solution (arsen1y)**
```cpp
#include <bits/stdc++.h>
#define int long long

using namespace std;

const int INF = (int) 1e18;

int32_t main() {
 int _;
 cin >> _;

 while (_--) {
 int a, b, x;
 cin >> a >> b >> x;

 int ans = INF;
 int i = 0;
 while (a != b) {
 if (b > a) {
 swap(a, b);
 }

 ans = min(ans, abs(a - b) + i);
 a /= x;
 i++;
 }

 ans = min(ans, i);

 cout << ans << "\n";
 }

 return 0;
}
```

## 2236D - Brand New Tatar TV Show

Idea: [dvb1r](<https://codeforces.com/profile/dvb1r>)
 
**Hint 1**

What happens if Arseny chooses the maximum of the array as his first move?
 
**Answer**

If the count of maximum is odd, then Dabir wins, otherwise Egor wins.

 
**Hint 2**

Try to look at the second maximum.

 
**Tutorial**

Observe the following: if the players start taking the maximum element from the array, they will keep taking it until all its occurrences are exhausted.

Based on this observation, consider the following algorithm:

Let the current maximum in the array be $mx$, and let its count be $cnt$. If $cnt$ is even, then Arseniy can take $mx$ on the first move. Then, by parity, Egor will win, so the answer is YES.

Otherwise, if the difference between the maximum and the second maximum in the array is not greater than $k$, then Arseniy can take the second maximum on the first move. After that, Egor will take the maximum and win by parity. The answer is YES.

If there is no second maximum in the array (i.e., all remaining elements are equal), then the answer is NO.

Otherwise, we can remove all occurrences of the maximum from the array and continue the algorithm on the modified array.

Now consider when the answer is NO. This happens if the difference between every pair of consecutive distinct values is greater than $k$, and the count of each value is odd. In these cases, no valid move sequence can help, and Egor will lose regardless of the play.

In all other cases, Arseniy can choose the first move so that Egor wins.

The overall time complexity is $O(n \cdot \log n)$ due to sorting and compressing the array.

 
**Solution (dvb1r)**
```cpp
#include <bits/stdc++.h>

using namespace std;
void solve();

int main() {
    int t; cin >> t;
    while (t--) solve();
    return 0;
}

void solve() {
    int n, k; cin >> n >> k;
    vector<int> A(n);
    for (auto& x : A) cin >> x;
    sort(A.begin(), A.end());
    vector<pair<int, int>> a = {{A[0], 1}};
    for (int i = 1; i < n; ++i) {
        if (A[i] == A[i - 1]) a.back().second++;
        else a.emplace_back(A[i], 1);
    }

    while (a.size() > 0) {
        n = a.size();
        if (a[n - 1].second % 2 == 0) {
            cout << "YES\n";
            return;
        }
        if (n == 1) {
            cout << "NO\n";
            return;
        }
        if (a[n - 1].first - a[n - 2].first <= k) {
            cout << "YES\n";
            return;
        }
        a.pop_back();
    }
}
```

## 2236E - Friendly Gifts

Idea: [arsen1y](<https://codeforces.com/profile/arsen1y>)

**Hint 1**

The cut segments of the array do not need to be checked for non-intersection.


**Hint 2**

Try to save information about all the good segments, and only then find the answer.


**Tutorial**

First, note an important observation: since good arrays must remain good after concatenation, the chosen subsegments of the array must not overlap.

The condition for a segment to be a good array is actually equivalent to the following: all numbers on the segment are distinct and $max - min = r - l$. Therefore, we can iterate over all subsegments of the array, and if a segment is good, store this information in a separate array: $good_{min, max} = 1$ (meaning that there exists a good segment with these $min$ and $max$). This can be implemented in $O(n^2)$ time.

Next, iterate over the answer from $\lfloor \frac{n}{2} \rfloor$ down to $0$, and consider the segment of values that will correspond to the concatenation of two subsegments of the array. To check feasibility, we need to verify that both segments exist, i.e., that $good_{l, l + ans - 1}$ and $good_{l + ans, l + 2 \cdot ans - 1}$ hold. If such a segment exists for the current value of $ans$, we output it and stop; otherwise, we continue.

The overall time complexity of the solution is $O(n^2)$.


**Solution (dvb1r)**
```cpp
#include <bits/stdc++.h>

using namespace std;
void solve();

int main() {
 int t = 1; cin >> t;
 while (t--) solve();
 return 0;
}

void solve() {
 int n; cin >> n;
 vector<int> a(n);
 for (auto& x : a) cin >> x, --x;
 vector<vector<bool>> able(n, vector<bool>(n));
 for (int i = 0; i < n; ++i) {
 vector<int> us(n);
 int mn = a[i], mx = a[i];
 for (int j = i; j < n; ++j) {
 if (us[a[j]]) break;
 us[a[j]] = 1;
 mn = min(mn, a[j]), mx = max(mx, a[j]);
 if (mx - mn == j - i) able[mn][mx] = 1;
 }
 }

 for (int ans = n; ans > 0; --ans) {
 for (int i = 0; i + 2 * ans <= n; ++i) {
 if (able[i][i + ans - 1] && able[i + ans][i + 2 * ans - 1]) {
 cout << ans << '\n';
 return;
 }
 }
 }
 cout << "0\n";
}
```

## 2236F1 - Elections in Saransk (easy version)

First, observe that for an array $p = [p_1, p_2, \ldots, p_n]$ to satisfy $\mathrm{lcm}(p_1, p_2, \ldots, p_n) = p_1 \cdot p_2 \cdot \ldots \cdot p_n,$ it is necessary and sufficient that $\gcd(p_i, p_j) = 1$ for all pairs $i \ne j$, i.e., all elements are pairwise coprime.

Now fix a prime number $\texttt{prime}$. Let $v_{\texttt{prime}}(x)$ denote the exponent of $\texttt{prime}$ in the prime factorization of $x$ (that is, the largest power $k$ such that $\texttt{prime}^k \mid x$).

Since all $p_i$ must be pairwise coprime, for each fixed prime $\texttt{prime}$, at most one element of the array $p$ can be divisible by $\texttt{prime}$.

Let us count the number of ways to assign this prime $\texttt{prime}$ across the array $p$. For each index $i$, the value $p_i$ must divide $a_i$, so the exponent of $\texttt{prime}$ in $p_i$ can be any integer from $0$ to $v_{\texttt{prime}}(a_i)$.

Thus, there are two types of choices: either the prime $\texttt{prime}$ does not appear in any $p_i$ (all exponents are $0$), or we choose exactly one index $i$, and assign to $p_i$ a positive exponent from $1$ to $v_{\texttt{prime}}(a_i)$.

Therefore, the total number of ways to handle this prime is: $1 + \sum_{i=1}^n v_{\texttt{prime}}(a_i)$, where: the $1$ corresponds to the case when the prime is not used at all, and each $v_{\texttt{prime}}(a_i)$ corresponds to choosing index $i$ and one of its possible positive exponents.

Finally, since different primes are independent, we multiply the number of ways over all primes that appear in at least one $a_i$. The final answer is: $\prod_{\texttt{pr}: \ \exists i,\ \texttt{pr} \mid a_i} \left(1 + \sum_{i=1}^n v_{\texttt{pr}}(a_i)\right)$.

## 2236F2 - Elections in Saransk (hard version)

Let us again fix a prime number $pr$ and consider the condition for it separately.

For the array $p = [p_1, p_2, \ldots, p_n]$ to satisfy $x \cdot \mathrm{lcm}(p_1, p_2, \ldots, p_n) = p_1 \cdot p_2 \cdot \ldots \cdot p_n$, for each prime $pr$ the following must hold: $\max(v_{pr}(p_i)) + v_{pr}(x) = \sum_{i=1}^n v_{pr}(p_i)$. Therefore, $v_{pr}(x) = \sum_{i=1}^n v_{pr}(p_i) - \max(v_{pr}(p_i))$.

Here $v_{pr}(x)$ denotes the exponent of the prime $pr$ in the prime factorization of $x$.

We precompute all values $v_{pr}(a_i)$ for $a_i \le 5 \cdot 10^5$ in $O(\log a_i)$ per number by using a sieve of Eratosthenes to find the smallest prime divisor.

Now consider two cases for each prime $pr$. As in the easy version, the final answer is the product of contributions over all primes.

1. If $pr$ does not divide $x$ (i.e., $v_{pr}(x) = 0$), then the condition simplifies to $\sum_{i=1}^n v_{pr}(p_i) = \max(v_{pr}(p_i))$, which means that at most one $p_i$ can have a positive exponent of $pr$. This is exactly the same as in the easy version, so the contribution is $1 + \sum_{i=1}^n v_{pr}(a_i)$.

2. If $pr$ divides $x$ (i.e., $v_{pr}(x) = vp \gt 0$), we solve the subproblem using dynamic programming.

Define $dp[i][mx][s]$ as the number of ways to choose values for the first $i$ elements such that:

- the current maximum exponent is $mx = \max(v_{pr}(p_1), \ldots, v_{pr}(p_i))$,
- the sum of exponents is $s = \sum_{j=1}^i v_{pr}(p_j)$.
 Here $0 \le v_{pr}(p_i) \le v_{pr}(a_i)$.
The answer for this prime is: $\sum dp[n][mx][vp + mx]$, over all $mx$ such that $1 \le vp + mx \le S$, where $S = \sum_{i=1}^n v_{pr}(a_i)$.

Note that in practice $vp + mx \le \min(S, 36)$, since $v_{pr}(a_i) \le 18$.

Transitions:

- If the chosen exponent $e$ does not increase the maximum (i.e., $e \le mx$): $dp[i][mx][s] += dp[i-1][mx][s - e]$.
- If the chosen exponent becomes a new maximum (i.e., $e \gt old_mx$, so $mx = e$): $dp[i][mx][s] += dp[i-1][old_mx][s - mx]$.

Initial state: $ dp[0][0][0] = 1. $

The complexity of this solution is: $ O(A \cdot \log(a_i)^3 \cdot n), $ where $A$ is the number of distinct prime divisors of $x$ (and $A \le 7$).

Note that in both transitions we can eliminate one loop with prefix sum:

- in the first transition — over $e$,
- in the second transition — over $old_mx$.

This improves the complexity to: $O(A \cdot \log(a_i)^2 \cdot n)$.

## 2236G - Criterion in Burlandia

Idea: [dvb1r](<https://codeforces.com/profile/dvb1r>)

**Hint 1**

In fact, the XOR of non-negative numbers is always less or equal their sum, and you can think about why.


**Hint 2**

Using the fact that the XOR of a set of numbers is equal to the sum of those numbers, how many non-zero numbers can there be in this set?

**Answer**

No more than $log(A)$, since each bit must occur at most once.


**Hint 3**

For each vertex, pre-calculate the closest ancestor on the vertical path that violates the good segment condition.


**Hint 4**

Reduce the problem to a path of length at most $2 * log(A)$, and calculate the rest using the pre-calculation from hint 3.


**Tutorial**

Let us first analyze the condition. For non-negative integers, the XOR is always less than or equal to their sum. Therefore, since a good segment requires the XOR to be at least the sum, it must be that XOR equals the sum.

This equality holds if and only if each bit appears at most once across all numbers in the segment. Hence, the segment can contain at most $log(A)$ non-zero elements.

First, for each vertex $v$, let us find the closest ancestor $bad_v$ such that on the path from $v$ to $bad_v$, there exists a bit that appears at least twice (i.e., the condition of a good segment is violated).

Now consider how to answer a query for a path between vertices $u$ and $v$. Assume the path is not purely vertical (the vertical case is handled similarly). Let $t$ be their LCA. We want to separately count:

- segments lying entirely on the path from $u$ to $t$,
- segments lying entirely on the path from $t$ to $v$,
- segments that pass through $t$.
 However, if we simply sum values of the form $d_x - d_{bad_x}$ along the path from $u$ to $t$, we may overcount, because for some vertices $x$, the corresponding $bad_x$ may lie above $t$.
To handle this, recall that any valid segment contains at most $log(A)$ non-zero elements. Therefore, we can move $t$ down by $log(A) + \varepsilon$ non-zero elements in both directions (towards $u$ and towards $v$). This can be done using level ancestor (LA) queries on a compressed tree.

The resulting middle path has length at most $2 \cdot log(A)$ and can be processed naively:

- either in $O(log(A)^2)$ by brute force,
- or in $O(log(A))$ using a two-pointer technique.
 The remaining parts of the path can be processed by summing values $d_x - d_{bad_x}$, for example using binary lifting.
The overall complexity of the solution is: $O(n \cdot (log(n) + log(A)))$ or $O(n \cdot (log(n) + log(A)^2))$, depending on the implementation.

The official solution uses the two-pointer approach.

```cpp
#include <bits/stdc++.h>

using namespace std;
using ll = long long;
void solve();

 int t = 1;

struct Graph {
 vector<int> tin, tout, d;
 vector<vector<pair<int, ll>>> up;

 int timer;

 void dfs(int v, const vector<vector<int>>& g, const vector<int>& arr, int p = -1) {
 tin[v] = timer++;
 up[0][v] = {p, arr[v]};
 for (int l = 1; l < 20; ++l) {
 if (up[l - 1][v].first == -1) {
 up[l][v] = {-1, 0};
 continue;
 }
 up[l][v].first = up[l - 1][up[l - 1][v].first].first;
 up[l][v].second = up[l - 1][up[l - 1][v].first].second + up[l - 1][v].second;
 }
 for (int u : g[v]) {
 if (u == p) continue;
 d[u] = d[v] + 1;
 dfs(u, g, arr, v);
 }
 tout[v] = timer;
 }

 Graph(const vector<vector<int>>& g, const vector<int>& a) : tin(g.size()), tout(g.size()), d(g.size()), up(20, vector<pair<int, ll>>(g.size())) {
 timer = 0;
 dfs(0, g, a);
 }

 bool anc(int p, int v) {
 return tin[p] <= tin[v] && tout[p] >= tout[v];
 }

 int getLenVertical(int u, int v) {
 if (!anc(u, v)) swap(u, v);
 assert(anc(u, v));
 return d[v] - d[u] - 1;
 }

 pair<int, ll> LA(int v, int k) {
 if (k <= 0) return {v, 0};
 ll sum = 0;
 for (int i = 0; i < 20; ++i) {
 if (k >> i & 1) sum += up[i][v].second, v = up[i][v].first;
 }
 return {v, sum};
 }

 int LCA(int u, int v) {
 if (anc(u, v)) return u;
 for (int l = 19; l >= 0; --l) {
 if (up[l][u].first == -1 || anc(up[l][u].first, v)) continue;
 u = up[l][u].first;
 }
 return up[0][u].first;
 }

 bool lower(int a, int b) {
 return tin[a] < tin[b];
 }
};

ll sum(int r) { return r * 1ll * (r + 1) / 2; }

ll sumSeg(int l, int r) {
 return sum(r) - sum(l - 1);
}

void solve() {
 int n, q; cin >> n >> q;
 vector<int> a(n);
 for (int i = 0; i < n; ++i) cin >> a[i];
 vector<vector<int>> g(n);
 for (int i = 1; i < n; ++i) {
 int u, v; cin >> u >> v;
 --u, --v;
 g[u].emplace_back(v);
 g[v].emplace_back(u);
 }
 vector<int> parent(n), d(n);
 auto dfs = [&](auto& self, int v, int p = -1) -> void {
 parent[v] = p;
 for (int u : g[v]) {
 if (u == p) continue;
 d[u] = d[v] + 1;
 self(self, u, v);
 }
 };
 dfs(dfs, 0);

 vector<int> compressed_parent = parent;
 vector<vector<int>> cG(n);
 for (int v = 0; v < n; ++v) {
 vector<int> path;
 while (compressed_parent[v] > 0 && a[compressed_parent[v]] == 0) {
 path.emplace_back(compressed_parent[v]);
 compressed_parent[v] = compressed_parent[compressed_parent[v]];
 }
 for (auto& x : path) compressed_parent[x] = compressed_parent[v];
 if (a[v] == 0 || !v) continue;
 cG[compressed_parent[v]].emplace_back(v);
 }

 vector<int> next_collision(n), sum_collision(n);
 for (int v = 0; v < n; ++v) {
 if (!a[v]) continue;
 next_collision[v] = v;
 int xr = a[v], sm = a[v];
 while (xr == sm && next_collision[v] > -1) {
 next_collision[v] = compressed_parent[next_collision[v]];
 if (next_collision[v] == -1) break;
 xr ^= a[next_collision[v]];
 sm += a[next_collision[v]];
 }
 }

 for (int v = 0; v < n; ++v) {
 if (!a[v]) {
 if (!v) next_collision[v] = -1;
 else next_collision[v] = next_collision[compressed_parent[v]];
 }
 sum_collision[v] = d[v];
 if (next_collision[v] > -1) sum_collision[v] -= d[next_collision[v]];
 else sum_collision[v]++;
 }

 Graph def(g, sum_collision);
 Graph compressed(cG, sum_collision);

 while (q--) {
 int u, v; cin >> u >> v;
 --u, --v;
 if (def.lower(v, u)) swap(u, v);
 int z = def.LCA(u, v);

 int cv = (a[v] || !v ? v : compressed_parent[v]), cu = (a[u] || !u ? u : compressed_parent[u]), cz = (a[z] || !z ? z : compressed_parent[z]);

 ll ans = 0;

 vector<int> L, R, Lspaces = {0}, Rspaces = {0};

 if (compressed.d[cv] > compressed.d[cz] + 23) {
 int unt = compressed.LA(cv, compressed.d[cv] - (compressed.d[cz] + 23)).first;
 auto [to, sm] = def.LA(v, d[v] - d[unt]);
 ans += sm, v = to;
 }

 if (compressed.d[cu] > compressed.d[cz] + 23) {
 int unt = compressed.LA(cu, compressed.d[cu] - (compressed.d[cz] + 23)).first;
 auto [to, sm] = def.LA(u, d[u] - d[unt]);
 ans += sm, u = to;
 }

 while (u != z) {
 int to = compressed_parent[u];
 if (def.anc(to, z)) to = z;
 L.emplace_back(u);
 Lspaces.emplace_back(def.getLenVertical(u, to));
 u = to;
 }
 while (v != z) {
 int to = compressed_parent[v];
 if (def.anc(to, z)) to = z;
 R.emplace_back(v);
 Rspaces.emplace_back(def.getLenVertical(v, to));
 v = to;
 }
 L.emplace_back(z);
 std::reverse(R.begin(), R.end());
 std::reverse(Rspaces.begin(), Rspaces.end());
 for (auto& x : R) L.emplace_back(x);
 for (auto& x : Rspaces) Lspaces.emplace_back(x);
 int j = 0, xr = 0, sum = 0;
 ll cnt = 0;
 for (int i = 0; i < L.size(); ++i) {
 while (j < L.size() && xr == sum) {
 xr ^= a[L[j]], sum += a[L[j]];
 cnt += Lspaces[j] + 1;
 j++;
 }
 if (xr != sum) cnt--;
 ans += sumSeg(cnt - Lspaces[i], cnt);
 if (xr != sum) cnt++;
 xr ^= a[L[i]], sum -= a[L[i]];
 cnt -= Lspaces[i] + 1;
 }
 cout << ans << '\n';
 }
}
```
