## 2233A - AI Project Development

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

Let us consider both options and choose the minimum:

- If Nikita does not use AI, then code is written at a rate of $(x + y)$ lines per hour, so the total number of hours is $\left\lceil\frac{n}{(x + y)}\right\rceil$;
- If Nikita uses AI, then during the first $z$ hours Maxim will write $x \cdot z$ lines and there will remain $n - x \cdot z$ lines to write, after which the total speed will be $(x + 10 \cdot y)$ lines per hour, so the total number of hours will be $z + \max(0, \left\lceil\frac{n - x \cdot z}{(x + 10 \cdot y)}\right\rceil)$.

This solution works in $O(1)$.

## 2233C - Cost of a Bracket Sequence

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Solution $O(n^2)$:

The length of the maximum regular bracket subsequence (RBS) in the string depends on the maximum number of non-overlapping pairs of the following form: the bracket "$\texttt{(}$" is to the left of "$\texttt{)}$".

Each such pair contributes $2$ to the cost. Therefore, instead of minimizing the cost, we can minimize the number of such pairs. In the end, the cost will simply be twice as large.

Notice the following: to decrease the number of such pairs, it is beneficial to remove either the leftmost opening bracket or the rightmost closing bracket. Let us show this.

Suppose we have found the maximum number of pairs, and the leftmost opening bracket at position $i$ does not belong to any of the pairs. Consider one of the pairs $(j, k)$. Its opening bracket $j$ is to the right of the leftmost opening bracket $i \lt j$, which means that instead of the pair $(j, k)$, we can take the pair $(i, k)$. Therefore, there is no point in removing any opening bracket other than the leftmost one in order to decrease the maximum number of pairs.

Analogous reasoning can be applied to the rightmost closing bracket.

This observation allows us to write a simple solution in $O(n^2)$.

Let us iterate over the number $x$ — how many opening brackets on the prefix we remove. Then, on the suffix, we remove no more than $(k - x)$ closing brackets. The maximum subsequence that is an RBS in the string can be found in $O(n)$ using a simple greedy algorithm.

Solution $O(n)$:

For a faster solution, we need a not entirely trivial observation: the maximum number of pairs of the form where the bracket "$\texttt{(}$" is to the left of "$\texttt{)}$" is:

$$ \min_{i = 0}^{n} \,\,\,\texttt{pref_open}_{i} + \texttt{suff_close}_{i} $$

Let us prove this observation.

Denote the maximum number of pairs as $\texttt{pairs}$, and the minimum value of $\texttt{pref_open}_{i} + \texttt{suff_close}_{i}$ for some $i$ as $\min f$. Also denote

$$ \texttt{balance}_{i} = \texttt{pref_open}_{i} - \texttt{pref_close}_{i} $$

Then

$$ \texttt{suff_close}_{i} = \texttt{total_close} - \texttt{pref_close}_{i} $$

Therefore,

$$ \texttt{pref_open}_{i} + \texttt{suff_close}_{i} = \texttt{pref_open}_{i} + \texttt{total_close} - \texttt{pref_close}_{i} \\ = \texttt{total_close} + \texttt{balance}_{i} $$

Hence,

$$ \min f = \texttt{total_close} + \min_i \texttt{balance}_{i} $$

Now let us look at the greedy algorithm for finding the maximum number of pairs. We go from left to right: if we see "$\texttt{(}$", we put it into the reserve, and if we see "$\texttt{)}$" and there is an opening bracket in the reserve, then we form a pair.

A closing bracket remains unmatched only if, at the moment it is processed, there were more closing brackets than opening brackets before it. The total number of such unmatched closing brackets is equal to

$$ -\min_i \texttt{balance}_{i} $$

There are $\texttt{total_close}$ closing brackets in total, so the number of closing brackets that entered pairs is equal to

$$ \texttt{total_close} - (-\min_i \texttt{balance}_{i}) = \texttt{total_close} + \min_i \texttt{balance}_{i} $$

Each such closing bracket corresponds to exactly one pair, therefore

$$ \texttt{pairs} = \texttt{total_close} + \min_i \texttt{balance}_{i} = \min f $$

The observation is proven. $\blacksquare$

Therefore, in the solution, we find the corresponding cut $i$ that minimizes $\texttt{pref_open}_{i} + \texttt{suff_close}_{i}$, and remove $\le k$ arbitrary symbols from the set {opening brackets to the left of $i$ + closing brackets to the right of $i$}. Using prefix sums, this can be done in $O(n)$.

				cur_k--;
			}

				bal++;
			}
		}

			ans = cur_ans;
		}

## 2233D - Goods on the Shelf

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)
 
**Tutorial**

Note that the exact value of $a_i$ does not matter: for any two goods, we only need to know whether they are equal or different. Therefore, we perform coordinate compression, that is, replace all $a_i$ with $b_i$ in such a way that for any two positions $i, j$, if $a_i = a_j$, then $b_i = b_j$, and also $\max b_i \lt n$.

How can we check whether the shelf is arranged correctly? This can be done with two pointers. Below is a code fragment for clarity:
```cpp
bool check(vector<int>& b) {
 int n = b.size();
 vector<int> used(n);
 for (int i = 0; i < n; ) {
 int j = i;
 while (i < n && b[i] == b[j]) {
 i++;
 }
 if (used[b[j]]) {
 return false;
 }
 used[b[j]] = true;
 }
 return true;
}
```

In the code, the array $\texttt{used}$ helps determine whether a block of such elements has already appeared before. Instead of $\texttt{used}$, we will store an array $\texttt{cnt}$, where $\texttt{cnt}_i$ is the number of blocks of value $i$ in array $b$. For a correctly arranged shelf, the condition $\max \texttt{cnt}_i \le 1$ must hold.

How can this help us?

Consider a correctly arranged shelf and perform one swap. Then, for any value, the number of its blocks after the swap can become at most $3$.

Indeed, if we moved one element from the middle of a block, that block could split into two parts, and the moved element itself could form one more block somewhere else. Therefore, at most $3$ blocks can appear.

Since the operation of swapping is reversible, we get an important consequence: if a correctly arranged shelf can be obtained from the current array with one swap, then in the current array no value can appear in more than $3$ blocks.

Let us find a value $x$ in array $b$ for which the number of blocks is greater than $1$. If for this value the number of blocks is greater than $3$, then we immediately output "NO".

It can be shown that if such an element $x$ is found, then in a successful swap one of the positions must contain value $x$. Otherwise, the positions of all elements equal to $x$ would not change, and therefore several blocks of value $x$ would remain several blocks.

Moreover, for each block of value $x$, there is no point in choosing a position from the middle of the block. If we swap an element from the middle of a block with some other element, that block will only split into two parts. Therefore, it is enough to consider only the ends of each block of value $x$ as candidates.

There are at most $3 \cdot 2 = 6$ such candidates, because there are at most $3$ blocks of value $x$.

The next observation is that there are also only a few candidates for the second index of the swap. To merge the blocks of value $x$, the second index must be located near one of the blocks of value $x$, that is, immediately to the left or immediately to the right of some block. Otherwise, we will not be able to make all elements equal to $x$ into one contiguous block.

There are also at most $6$ such candidates.

Thus, it is enough to try a constant number of swaps: one index is chosen among the ends of the blocks of value $x$, and the second among the positions adjacent to these blocks. After each swap, we check whether the shelf is arranged correctly. We know how to do this in $O(n)$.

In implementation, we can simply put all positions of the form $l - 1$, $l$, $r$, $r + 1$ for each block $[l, r]$ of value $x$ into one candidate list and try all pairs from this list. Since there are at most $3$ blocks, there are at most $12$ candidates, so the number of swaps to check is constant.

Overall, the solution works in $O(n \log n)$ due to coordinate compression.

## 2233E2 - Permutation Transmission (Difficult Version)

The main observation for solving the problem is that, for any permutation, the strings must be in nondecreasing order of the number of ones.

Let us prove this statement. Let $\texttt{cnt}_{k}$ denote the number of ones in the $k$-th bit among the numbers $1, 2, \ldots, n$. It is convenient to add the number $0$ as well. This changes nothing, because it adds a zero column. So we will prove the statement for the set of numbers $0, 1, 2, \ldots, n$.

We will prove that $\texttt{cnt}_{k} \ge \texttt{cnt}_{k + 1}$ for any $k$.

Consider only bits $k$ and $k + 1$. Split the numbers into blocks of length $2^{k + 2}$. Inside each full block, these two bits look like this by quarters:

- $Q_{0}$: $00$
- $Q_{1}$: $01$
- $Q_{2}$: $10$
- $Q_{3}$: $11$

where each quarter has length $2^{k}$.

In each full block:

- in bit $k$, the ones are in quarters $Q_{1}$ and $Q_{3}$, and their total count is $2^{k} + 2^{k} = 2^{k + 1}$;
- in bit $k + 1$, the ones are in quarters $Q_{2}$ and $Q_{3}$, and their total count is $2^{k} + 2^{k} = 2^{k + 1}$.

So full blocks contribute equally.

Only the last incomplete block remains. In it, the number of ones in each bit grows as follows:

- in $Q_{0}$, no ones are added to either bit;
- in $Q_{1}$, ones are added only to bit $k$;
- in $Q_{2}$, ones are added only to bit $k + 1$, but bit $k$ has already gained an advantage in $Q_{1}$;
- in $Q_{3}$, ones are added to both bits simultaneously.

Therefore, for any incomplete block, the number of ones in bit $k$ is at least the number of ones in bit $k + 1$.

Hence, $\texttt{cnt}_{k} \ge \texttt{cnt}_{k + 1}$. $\blacksquare$

The next useful observation is that if $\texttt{cnt}_{k} = \texttt{cnt}_{k + 1}$, then bits $k$ and $k + 1$ can be swapped and the set of numbers $0, 1, 2, \ldots, n$ does not change.

To prove this, we use the same idea and again consider blocks of length $2^{k + 2}$. Swapping bits $k$ and $k + 1$ inside a block does the following:

- $Q_{0}$ remains $Q_{0}$;
- $Q_{1}$ becomes $Q_{2}$;
- $Q_{2}$ becomes $Q_{1}$;
- $Q_{3}$ remains $Q_{3}$.

So inside a block, this is just a swap of the two middle quarters.

If $\texttt{cnt}_{k} = \texttt{cnt}_{k + 1}$, then from the reasoning above the last incomplete block must end either in $Q_{0}$ or in $Q_{3}$. In either case, the last block is invariant under swapping the middle quarters:

- if the last block ends in $Q_{0}$, then $Q_{1}$ and $Q_{2}$ do not exist;
- if the last block ends in $Q_{3}$, then $Q_{1}$ and $Q_{2}$ are complete, and swapping them changes nothing.

Therefore, swapping bits $k$ and $k + 1$ for which $\texttt{cnt}_{k} = \texttt{cnt}_{k + 1}$ does not change the set $0, 1, 2, \ldots, n$. $\blacksquare$

After proving these facts, the solution becomes very simple. Sort all strings by non-increasing number of ones and check that in this order they form a permutation of the numbers $1, 2, \ldots, n$; if not, the answer is $0$.

Then compute the array $c_i$ — the number of strings containing exactly $i$ ones. The answer is:

$$ \prod_i c_i! $$

## 2233F - Shortest GCD Paths

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

We cannot build the graph directly and search for the shortest path in it, because $n$ can be very large. Instead, let us look for useful properties of such a graph.

Notice that for any vertices $u, v$ and any natural number $x$, we have $w(u \cdot x, v \cdot x) = w(u, v)$, because both the maximum and the gcd are multiplied by the same value $x$.

As a consequence, we may assume that $a$ and $b$ can be divided by $\gcd(a, b)$. That is, if $g = \gcd(a, b)$, then the shortest path between $a' = \frac{a}{g}$ and $b' = \frac{b}{g}$ has the same length as the shortest path between $a$ and $b$.

Let us prove this carefully. Our proof will consist of two parts:

- from a shortest path for ($a'$, $b'$), we can obtain a path of the same length for ($a$, $b$);
- from a shortest path for ($a$, $b$), we can obtain a path of no greater length for ($a'$, $b'$).

The first part follows easily from our property: take all vertices on the shortest path for ($a'$, $b'$) and multiply them by $g$. The weight of every edge on this path remains unchanged.

Now let us prove the second part. Define the operation $f(x, y)$ for a natural number $x$ and a positive prime number $y$ as follows:

$$ f(x, y) = \begin{cases} x & \quad \text{if } x \text{ is not divisible by } y \\ \frac{x}{y} & \quad \text{if } x \text{ is divisible by } y \end{cases} $$

We claim that this operation does not increase the weight of an edge if applied to both endpoints of the edge. That is, for any vertices $u, v$ and any positive prime $x$, we have $w(u, v) \ge w(f(u, x), f(v, x))$:

- if $x$ divides both endpoints of the edge, then both $\max$ and $\gcd$ are divided by $x$, so the weight does not change;
- if $x$ divides neither endpoint, then nothing changes;
- if $x$ divides exactly one endpoint, then $\max$ does not increase, while $\gcd$ does not decrease, so the weight does not increase.

Also define the operation $f'(x, y)$ for natural numbers $x$, $y$ as follows:

$$ f'(x, y) = f(f(\ldots f(f(x, p_1), p_2) \ldots), p_k) $$

for such $p_{i}$ that $\displaystyle\prod_{i = 1}^{k} p_{i} = y$. In other words, $f'(x, y)$ removes from $x$ the prime factors that are present in $y$.

Now let us apply the operation $f'$ to every vertex $v$ of the shortest path for ($a$, $b$), that is, replace every vertex $v$ with $f'(v, g)$. If two neighboring vertices become equal after this replacement, simply remove one of them from the path.

We obtain a path for ($\frac{a}{g}$, $\frac{b}{g}$) whose length has not increased, and this is exactly a path for ($a'$, $b'$).

Thus, we have proved that:

- the shortest path for ($a$, $b$) is no longer than the shortest path for ($a'$, $b'$);
- the shortest path for ($a'$, $b'$) is no longer than the shortest path for ($a$, $b$).

Therefore, the lengths of the shortest paths for ($a$, $b$) and ($a'$, $b'$) are equal. $\blacksquare$

From now on, we will assume that $a$ and $b$ are coprime.

The next observation is that the shortest path will use only vertices that are divisors of $a \cdot b$. Indeed, if some intermediate vertices on the path are divisible by some factor that is not present in $a \cdot b$, then for each such vertex $v$, replace it with $\gcd(v, a \cdot b)$. This replacement does not increase the weight of any edge: we are only removing extra prime factors from the endpoints of edges. Therefore, there exists an optimal path in which all vertices are divisors of $a \cdot b$.

Taking all observations above into account, we can view a transition along some edge as an operation that removes some factor $d_{a}$ from $a$ and adds some factor $d_{b}$ from $b$, where these factors are coprime. The cost of such an operation is $\max(d_{a}, d_{b})$. Let us show why this is true.

Suppose the current vertex has the form $\frac{a}{d_a} \cdot d_b$. If we additionally remove a factor $p$ from $a$ and add a factor $q$ from $b$, then the new vertex is $\frac{a}{d_a \cdot p} \cdot d_b \cdot q$. The two vertices share the common part $\frac{a}{d_a \cdot p} \cdot d_b$, so the weight of the edge is equal to $\max(p, q)$.

Let us write the following dynamic programming solution: let $\texttt{dp}[d_{a}][d_{b}]$ denote the minimum total cost of operations needed to remove the factor $d_{a}$ from $a$ and add the factor $d_{b}$ from $b$. The answer will be $\texttt{dp}[a][b]$. The transitions are quite simple: for each state ($d_{a}, d_{b}$), iterate over $p$ (it will be a divisor of $\frac{a}{d_{a}}$) and iterate over $q$ (it will be a divisor of $\frac{b}{d_{b}}$), and then transition to the state $\texttt{dp}[d_{a} \cdot p][d_{b} \cdot q]$.

Why does this work fast? Let $\tau(x)$ be the number of divisors of $x$. Then the number of states is $\tau(a) \cdot \tau(b)$, and the number of transitions is:

$$ \displaystyle\sum_{d_{a} | a} \sum_{d_{b} | b} \tau(\frac{a}{d_{a}}) \cdot \tau(\frac{b}{d_{b}}) = \displaystyle\sum_{d_{a} | a} \sum_{d_{b} | b} \tau(d_{a}) \cdot \tau(d_{b}) $$

This can be transformed into:

$$ \displaystyle\sum_{d_{a} | a} \tau(d_{a}) \cdot \sum_{d_{b} | b} \tau(d_{b}) $$

$\tau(x)$ is an arithmetic function with the important property $\tau(x \cdot y) = \tau(x) \cdot \tau(y)$ if $\gcd(x, y) = 1$, so from the expression

$$ \displaystyle\sum_{d_{a} | a} \tau(d_{a}) $$

we can move to the expression

$$ \displaystyle\prod_{p_{i}} \sum_{e = 0}^{k_{i}} \tau(p_{i}^{e}) $$

for such $p_{i}$ that $a = p_{0}^{k_{0}} \cdot p_{1}^{k_{1}} \cdot \ldots$, where $p_{i}$ is some prime number from the prime factorization of $a$.

It is known that $\tau(p^e) = e + 1$, where $p$ is prime.

Therefore:

$$ \displaystyle\prod_{p_{i}} \sum_{e = 0}^{k_{i}} \tau(p_{i}^{e}) = \displaystyle\prod_{p_{i}} \frac{(k_{i} + 1) \cdot (k_{i} + 2)}{2} $$

Since $a$ and $b$ are coprime, the number of transitions is:

$$ \displaystyle\sum_{d_{a} | a} \tau(d_{a}) \cdot \sum_{d_{b} | b} \tau(d_{b}) = \displaystyle\prod_{p_{i}} \frac{(k_{i} + 1) \cdot (k_{i} + 2)}{2} $$

where $p_{i}$ is a prime number in the factorization of $a \cdot b$, and $k_{i}$ is its corresponding exponent.

By the constraints of the problem, $a, b \le 10^{9}$, hence $a \cdot b \le 10^{18}$. The maximum value of this function for numbers up to $10^{18}$ can be found by brute-forcing possible sets of exponents in the factorization, similarly to how [highly composite numbers](<https://gist.github.com/dario2994/fb4713f252ca86c1254d>) are found. Coincidentally, the maximum value of the function is attained at the same number $897612484786617600$, which has the maximum number of divisors ($103680$). The number of transitions for this number is approximately $1.6 \cdot 10^{8}$. Thus, with a careful implementation, this easily fits within the time limit.

P.S.

The most attentive readers may have noticed an inaccuracy in the proof of the validity of dividing $a$ and $b$ by $g$: when multiplying by $g$, some vertex of the path for ($a'$, $b'$) could become greater than $n$. However, this will not happen, because our solution is able to construct a path such that every intermediate vertex is no greater than $\max(a', b')$.

//#define int long long

const int INF = 1000000007;

void solve(){
	int n, a, b;
	cin >> n >> a >> b;

	int g = gcd(a, b);
	a /= g;
	b /= g;

	vector<int> d1, d2;
	for (int i = 1; i * i <= a; i++){
 if (a % i == 0){
 d1.push_back(i);
 if (i * i != a){
 d1.push_back(a / i);
 }
 }
	}

	for (int i = 1; i * i <= b; i++){
 if (b % i == 0){
 d2.push_back(i);
 if (i * i != b){
 d2.push_back(b / i);
 }
 }
	}

	sort(d1.begin(), d1.end());
	sort(d2.begin(), d2.end());

	int sz1 = d1.size();
	int sz2 = d2.size();

	vector<vector<int>> to_d1(sz1, vector<int> (sz1, -1));
	for (int i = 0; i < sz1; i++){
 int u = 0;
 for (int j = i; j >= 0; j--){
 while(u < i && d1[i] > d1[u] * d1[j]){
 u++;
 }
 if (d1[i] % d1[j] == 0 && d1[i] / d1[j] == d1[u]){
 to_d1[i][j] = u;
 }
 }
	}

	vector<vector<int>> to_d2(sz2, vector<int> (sz2, -1));
	for (int i = 0; i < sz2; i++){
 int u = 0;
 for (int j = i; j >= 0; j--){
 while(u < i && d2[i] > d2[u] * d2[j]){
 u++;
 }
 if (d2[i] % d2[j] == 0 && d2[i] / d2[j] == d2[u]){
 to_d2[i][j] = u;
 }
 }
	}

	vector<vector<int>> dels_d1(sz1);
	for (int i = 0; i < sz1; i++){
 for (int j = 0; j <= i; j++){
 if (d1[i] % d1[j] == 0){
 dels_d1[i].emplace_back(j);
 }
 }
	}

	vector<vector<int>> dels_d2(sz2);
	for (int i = 0; i < sz2; i++){
 for (int j = 0; j <= i; j++){
 if (d2[i] % d2[j] == 0){
 dels_d2[i].emplace_back(j);
 }
 }
	}

	vector<vector<int>> dp(sz1, vector<int> (sz2, -1));

	auto go = [&](auto&& self, int x, int y) -> int{
 if (dp[x][y] != -1){
 return dp[x][y];
 }
 if (x == 0 && y == 0){
 return 0;
 }
 dp[x][y] = INF;

 for (int dx : dels_d1[x]){
 for (int dy : dels_d2[y]){
 if (dx == 0 && dy == 0){
 continue;
 }
 dp[x][y] = min(dp[x][y], max(d1[dx], d2[dy]) + self(self, to_d1[x][dx], to_d2[y][dy]));
 }
 }
 return dp[x][y];
	};

	cout << go(go, sz1 - 1, sz2 - 1) << '\n';
}
