## 2112A - Race

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Suppose $x \lt y$, then there are $3$ cases of relative positions of $a$, $x$ and $y$:

- if $a \lt x \lt y$, Bob can start at $x$ and win no matter where the prize is;
- if $x \lt a \lt y$, Bob cannot choose a starting position that guarantees victory: if he starts to the left of $a$, then $y$ is closer to Alice, but if he starts to the right of $a$, then $x$ is closer to Alice;
- if $x \lt y \lt a$, Bob can start at $y$ and win no matter where the prize is.


**Solution (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
 int t;
 cin >> t;
 while (t--) {
 int a, x, y;
 cin >> a >> x >> y;
 cout << ((a < x) == (a < y) ? "YES" : "NO") << '\n';
 }
}
```

## 2112B - Shrinking Array

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

First, let's check if the given array $a$ is already beautiful. If it is, then the answer is obviously $0$. Otherwise, it means that $|a_i - a_{i + 1}| \ge 2$ for all $i$, and we need to perform at least one operation.

Next, note that if there is at least one local extremum in the array, i. e. there exists a position $i$ such that $a_{i - 1} \lt a_i \gt a_{i + 1}$ (or $a_{i - 1} \gt a_i \lt a_{i + 1}$), and without loss of generality, $a_{i - 1} \le a_{i + 1}$, then we can, in one operation, transform the pair $(a_{i - 1}, a_i)$ into the number $x = a_{i + 1}$ and make the array beautiful.

In other words, the array $\dots, a_{i - 2}, a_{i - 1}, a_i, a_{i + 1}, \dots$ will become $\dots, a_{i - 2}, a_{i + 1}, a_{i + 1}, \dots$. (For a local minimum, we act symmetrically).

On the other hand, when there is no local extremum in the array, it means that the array is sorted in either ascending or descending order. In this case, we can observe that there is no solution, as replacing $\dots, a_{i - 1}, a_i, a_{i + 1}, a_{i + 2}, \dots$ with $\dots, a_{i - 1}, x, a_{i + 1}, \dots$ cannot decrease the distance between the elements at any step, since $|a_{i - 1} - x| \ge |a_{i - 1} - a_i|$ and $|x - a_{i + 2}| \ge |a_{i + 1} - a_{i + 2}|$.

Thus, the solution to the problem is as follows: if the array is beautiful, then the answer is $0$; otherwise, if the array is sorted in any order, then the answer is $-1$; otherwise, the answer is $1$. All of this can be checked in $O(n)$.

 
**Solution (adedalic)**
```cpp
#include<bits/stdc++.h>

using namespace std;

void solve() {
	int n;
	cin >> n;
	vector<int> a(n);
	for (int i = 0; i < n; i++)
		cin >> a[i];
	
	for (int i = 1; i < n; i++) {
		if (abs(a[i - 1] - a[i]) <= 1) {
			cout << 0 << endl;
			return;
		}
	}
	for (int i = 1; i + 1 < n; i++) {
		if (a[i - 1] < a[i] && a[i] > a[i + 1]) {
			cout << 1 << endl;
			return;
		}
		if (a[i - 1] > a[i] && a[i] < a[i + 1]) {
			cout << 1 << endl;
			return;
		}
	}
	cout << -1 << endl;
}

int main() {
#ifdef _DEBUG
	freopen("input.txt", "r", stdin);
	int tt = clock();
#endif
	int t;
	cin >> t;
	while (t--) {
		solve();
	}
	return 0;
}
```

## 2112C - Coloring Game

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Let the three elements chosen by Alice be $a_x, a_y, a_z$, where $x \lt y \lt z$.

Let's understand Bob's strategy. When Alice has already colored the elements she has chosen, Bob has two options: either to choose the greatest element of the array ($a_n)$, or to choose the greatest red element ($a_z$). The first option increases the sum of blue elements by $a_n$. The second option increases it by $a_z$ and decreases the sum of red elements by $a_z$. So, the difference between the sum of red and blue elements will be changed by $\max(2 \cdot a_z, a_n)$.

In order for Alice to win, the following condition must be met: $a_x + a_y + a_z \gt \max(2 \cdot a_z, a_n)$. We can iterate on all three elements she chooses and check this condition, but it is too slow.

Instead, we can iterate on the elements $y$ and $z$, and since the array is sorted, $a_x \lt a_{x+1}$. This allows us to find the minimum valid $x$ with binary search (and all elements between it and $y$ will also be valid), resulting in a solution with complexity $O(n^2 \log n)$. You can improve it to $O(n^2)$ by using two pointers instead of binary search, but this was not necessary.


**Solution (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
 int t;
 cin >> t;
 while (t--) {
 int n;
 cin >> n;
 vector<int> a(n);
 for (auto& x : a) cin >> x;
 long long ans = 0;
 for (int i = 0; i < n; ++i) {
 for (int j = 0; j < i; ++j) {
 int x = max(a[n - 1], 2 * a[i]) - a[i] - a[j];
 int k = upper_bound(a.begin(), a.begin() + j, x) - a.begin();
 ans += j - k;
 }
 }
 cout << ans << '\n';
 }
}
```

## 2112D - Reachability and Tree

Idea: [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

First, note that for each edge $\{u, v\}$, when choosing its direction, exactly one pair will be good: either $(u, v)$ or $(v, u)$. This means there will always be at least $n - 1$ good pairs. Therefore, we need one more good pair, or in other words, we need one more path in the tree.

On the other hand, the only good paths of length $1$ can only be the edges of the original tree. Thus, an additional good path $(u, v)$ will have a length of at least $2$. However, if this path is longer than two, then its "sub-paths" will also be good, and the total number of paths will exceed $n$.

Thus, in our graph, there should only be paths consisting of a single edge and exactly one path of length $2$ of the form $u \to r \to v$. Next, note that if there is at least one more edge $\{r, t\}$ coming out of $r$, then regardless of how we choose its direction, we will have another path: either $u \to r \to t$ or $t \to r \to v$. This means that the degree of vertex $r$ must be exactly $2$.

Therefore, if there is no vertex of degree $2$ in the given tree, then there is definitely no solution.

It turns out that this condition is sufficient. We can construct the answer as follows:

- Let the vertex of degree two be $r$. Direct the edges $u \to r$ and $r \to v$.
- From vertex $u$, there is one outgoing arc: let's direct all other edges $\{u, t_i\}$ from $u$, i.e., create arcs $u \to t_i$.
- Into vertex $v$, there is one incoming arc: let's direct all other edges $\{v, s_i\}$ into $v$, i.e., create arcs $s_i \to v$.
- We will process the neighbors $s_i$ and $t_i$ recursively using rules $2$ and $3$.

As a result of this procedure, we can see that we have not created any other paths of length two, since we cannot extend any path $(x, y)$ of length one, as edges only exit from $x$ and only enter into $y$.

 
**Solution (adedalic)**
```cpp
#include<bits/stdc++.h>

using namespace std;

#define fore(i, l, r) for(int i = int(l); i < int(r); i++)
#define sz(a) int((a).size())

const int N = int(2e5) + 5;

int n;
vector<int> g[N];

inline bool read() {
	if(!(cin >> n))
		return false;
	fore (i, 0, n)
		g[i].clear();
	
	fore (i, 0, n - 1) {
		int u, v;
		cin >> u >> v;
		u--, v--;
		g[u].push_back(v);
		g[v].push_back(u);
	}
	return true;
}

vector<int> used;
vector<pair<int, int>> ans;

void dfs(int v, bool in) {
	used[v] = 1;
	for (int to : g[v]) {
		if (used[to])
			continue;
		if (in)
			ans.emplace_back(to, v);
		else
			ans.emplace_back(v, to);
		dfs(to, !in);
	}
}

inline void solve() {
	int r = 0;
	while (r < n && sz(g[r]) != 2)
		r++;
	if (r >= n) {
		cout << "NO\n";
		return;
	}

	used.assign(n, 0);
	ans.clear();

	ans.emplace_back(r, g[r][0]);
	ans.emplace_back(g[r][1], r);
	used[r] = 1;

	dfs(g[r][0], true);
	dfs(g[r][1], false);

	cout << "YES\n";
	sort(ans.begin(), ans.end());
	for (auto [u, v] : ans)
		cout << u + 1 << " " << v + 1 << '\n';
}

int main() {
#ifdef _DEBUG
	freopen("input.txt", "r", stdin);
	int tt = clock();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0), cout.tie(0);
	cout << fixed << setprecision(15);
	
	int t; cin >> t;
	while (t--)  {
		read();
		solve();
		
#ifdef _DEBUG
		cerr << "TIME = " << clock() - tt << endl;
		tt = clock();
#endif
	}
	return 0;
}
```

## 2112E - Tree Colorings

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Note that if a vertex is not green, its entire subtree must be colored the same color: for example, if the vertex is blue and it has a green or yellow descendant, the root is unreachable from that descendant without passing through that blue vertex. At the same time, the green vertices do not impose any additional constraints.

Using this observation, let's explore how to solve the inverse problem to the original one (namely, given a tree, count the number of beautiful colorings) using dynamic programming. Let $cnt_v$ be the number of ways to color the subtree rooted at vertex $v$, provided that $v$ itself is green. Since $v$ is green, each of its child vertices can be colored in any color. If a child $u$ is green, there are $cnt_u$ ways to color its subtree. If $u$ is blue or yellow, there is only one way to color its subtree. Therefore, the total number of colorings for $u$ is $cnt_u + 2$. Since each child subtree can be colored independently, $cnt_v = (cnt_{u_1} + 2)(cnt_{u_2} + 2) \cdots (cnt_{u_k} + 2)$, where $u_1, u_2, \dots, u_k$ are the children of $v$.

Notice that the formula above shows the number of colorings for a tree depends solely on the number of colorings of its child subtrees. Therefore, we can solve the original problem using the following dynamic programming approach: let $dp_m$ be the minimum number of vertices in a tree with exactly $m$ beautiful colorings. To calculate this, we can use the fact that the number of colorings of a tree is the product of colorings of its child subtrees. Let's iterate over the number of colorings of the last subtree (let's denote it $x$), then $dp_m$ is the minimum among $dp_{\frac{m}{x}} + dp_{x - 2}$ for all values of $x$. Note that $x$ must be a divisor of $m$. Therefore, to speed up the solution, we can iterate through either $x$ up to $\sqrt{m}$ or $\frac{m}{x}$ up to $\sqrt{m}$.

This approach yields a solution with time complexity $O(M\sqrt{M})$, where $M$ is the maximum number of colorings we need to consider. This is enough to get AC, but we can speed this up to $O(M \log M)$ as follows: for every integer $x$ from $1$ to $M$, let's prepare the list of its divisors. We can iterate on the divisor $d$ and append it to the lists of divisors for integers $2d, 3d, 4d, \dots$. The integer $d$ will be processed in $O(\frac{M}{d})$, so in total, we achieve a complexity of $\sum\limits_{d=1}^{M} \frac{M}{d}$, which is $O(M \log M)$ because it is the harmonic sum (multiplied by $M)$.


**Solution in M sqrt M (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

const int M = 5e5;
const int INF = 1e9;

int main() {
 vector<int> dp(M + 1, INF);
 dp[1] = 1;
 for (int m = 2; m <= M; ++m) {
 for (int i = 1; i * i <= m; ++i) {
 if (m % i != 0) continue;
 if (m / i > 2) dp[m] = min(dp[m], dp[i] + dp[m / i - 2]);
 if (i > 2) dp[m] = min(dp[m], dp[m / i] + dp[i - 2]);
 }
 }

 int q;
 cin >> q;
 while (q--) {
 int m;
 cin >> m;
 cout << (dp[m] == INF ? -1 : dp[m]) << '\n';
 }
}
```

 
**Solution in M log M (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int N = 500043;

vector<int> divisors[N];

int dp[N], dp2[N];

int calc(int x);

int calc2(int x)
{
    if(dp2[x] != -1) return dp2[x];
    if(x == 1) return dp2[x] = 0;
    dp2[x] = calc(x);
    for(auto y : divisors[x]) dp2[x] = min(dp2[x], calc(y) + calc2(x / y));
    return dp2[x];
}

int calc(int x)
{
    if(dp[x] != -1) return dp[x];
    if(x == 1) return dp[x] = 0;
    if(x == 3) return dp[x] = 1;
    return dp[x] = calc2(x - 2) + 1;
}                       

int main()
{
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    for(int i = 2; i < N; i++)
        for(int j = i * 2; j < N; j += i)
            divisors[j].push_back(i);
    for(int i = 0; i < N; i++) dp[i] = dp2[i] = -1;

    int t;
    cin >> t;
    for(int i = 0; i < t; i++)
    {
        int x;
        cin >> x;
        if(x % 2 == 0) cout << -1 << endl;
        else cout << calc(x + 2) << endl;
    }
    return 0;
}
```

## 2112F - Variables and Operations

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The first step of the solution is analyzing the operations we perform. Do they look similar to something well-known? If you're familiar with graph algorithms, you should recognize that this operation is actually edge relaxation from shortest path algorithms like Ford-Bellman and Dijkstra: when we relax an edge going from vertex $u$ to vertex $v$, we update the distance to vertex $v$ (which is $d_v$) as the value of $\min(d_v, d_i + w)$, where $w$ is the weight of the edge. So, if we treat the values of the variables as distances to some vertices, then the operation $(x_i, y_i, z_i)$ is actually relaxing the edge from $y_i$ to $x_i$ with weight $z_i$.

So, this is actually a graph problem. Every variable is represented by a vertex; every vertex has some initial distance to it (equal to $a_i$), and the operations we perform are relaxing all edges exactly once in some order. The operation $(x_i, y_i, z_i)$ is represented by a directed edge from $y_i$ to $x_i$ with weight $z_i$.

The weights of the edges are non-negative, so, from Dijkstra's algorithm we can deduce that there always exists an order of relaxation that results in correct shortest paths to all vertices (because Dijkstra's algorithm tries to relax each edge exactly once). However, from Ford-Bellman algorithm, we can deduce that wrong relaxation order might lead to wrong shortest paths to some vertices, since Ford-Bellman requires $n-1$ relaxation phases in the worst case.

So, the sequence of initial values $a_1, a_2, \dots, a_n$ (which are the initial distances to the corresponding vertices) is $i$-unstable if and only if there exists a relaxation order which results in the shortest path to the vertex $i$ calculated incorrectly. If the shortest path to it consists of $0$ or $1$ edges, it will always be found, since there is no incorrect order that doesn't consider this path. However, if all shortest paths to vertex $i$ consist of at least $2$ edges, we can always relax the edges going into the vertex $i$ first, and then all other edges, and this order won't consider any of the shortest paths. This means that the sequence of initial values is $i$-unstable if and only if every shortest path to the vertex $i$ consists of at least $2$ edges.

Let's show how to check if a sequence is $i$-unstable first; then, we'll get back to the original problem where we need to transform the sequence into $i$-unstable by decreasing elements. Let $d_{i,j}$ be the distance from $i$ to $j$, and $e_{i,j}$ be the distance from $i$ to $j$ considering only paths consisting of $0$ or $1$ edge (or $+\infty$ if such paths do not exist). The shortest path to the vertex $i$ is $\min_{j=1}^{n} d_{j,i} + a_j$, and the shortest path consisting of at most one edge is $\min_{j=1}^{n} e_{j,i} + a_j$. If the first value is strictly less than the second value, then all shortest paths to $i$ consist of at least $2$ edges, and the sequence is $i$-unstable.

Now let's try to calculate the minimum number of operations to make the sequence $i$-unstable. The main observation we need here is that we should apply all operations to the same value $a_j$, because we need to decrease $\min_{j=1}^{n} d_{j,i} + a_j$ and it is as small as the smallest of $d_{j,i} + a_j$. Suppose we want to make the sequence $i$-unstable by decreasing the variable $j$, how many actions do we need? If $d_{j,i} = e_{j,i}$, it is impossible, since we cannot make $d_{j,i} + a_j$ less than $e_{j,i} + a_j$. Otherwise, $d_{j,i} + a_j$ is always less than $e_{j,i} + a_j$, and we need to make it less than $e_{k,i} + a_k$ for all vertices $k$. We can precalculate the minimum value of $e_{k,i} + a_k$ for the vertex $i$, and this will allow us to compute how many operations we need to apply to $j$ to make the sequence $i$-unstable in $O(1)$.

If we build the matrix of distances for the graph once and reuse it in every query, we can get a solution working in $O(n^3 + m)$ preprocessing and $O(n^2)$ per query.


**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int N = 543;
const long long INF64 = (long long)(1e18);

long long e[N][N];
long long d[N][N];
int n, m;

int main()
{
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 cin >> n >> m;
 for(int i = 0; i < n; i++)
 for(int j = 0; j < n; j++)
 if(i != j) e[i][j] = INF64;
 for(int i = 0; i < m; i++)
 {
 int x, y, w;
 cin >> x >> y >> w;
 --x;
 --y;
 swap(x, y);
 e[x][y] = min(e[x][y], (long long)w);
 }
 for(int i = 0; i < n; i++)
 for(int j = 0; j < n; j++)
 d[i][j] = e[i][j];
 for(int k = 0; k < n; k++)
 for(int i = 0; i < n; i++)
 for(int j = 0; j < n; j++)
 d[i][j] = min(d[i][j], d[i][k] + d[k][j]);

 int q;
 cin >> q;
 for(int i = 0; i < q; i++)
 {
 long long op;
 cin >> op;
 vector<long long> a(n);
 for(int j = 0; j < n; j++) cin >> a[j];
 vector<long long> min_dist = a;
 vector<long long> min_one_edge = a;
 for(int j = 0; j < n; j++)
 for(int k = 0; k < n; k++)
 {
 min_dist[k] = min(min_dist[k], a[j] + d[j][k]);
 min_one_edge[k] = min(min_one_edge[k], a[j] + e[j][k]);
 }
 vector<long long> min_op(n, INF64);
 for(int j = 0; j < n; j++)
 for(int k = 0; k < n; k++)
 {
 if(d[j][k] < e[j][k]) min_op[k] = min(min_op[k], (d[j][k] + a[j]) - (min_one_edge[k] - 1));
 }
 for(int j = 0; j < n; j++)
 {
 if(min_op[j] <= op) cout << 1;
 else cout << 0;
 }
 cout << endl;
 }

 return 0;
}
```
