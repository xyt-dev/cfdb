## 863B - Kayaking

Firstly let's learn how to split persons in pairs as if there are no single kayaks. Let there be people with weights *a*, *b*, *c* and *d* (*a* ≤ *b* ≤ *c* ≤ *d*). Obviously, the lowest instability you can achieve is *max*(*b* - *a*, *d* - *c*). Swapping any two elements will only make the result greater. This greedy strategy can be used to distribute all the seats.

Now you need to check every pair of persons to seat in single kayaks and calculate total instability for the rest. The answer will be the minimun instabily over all pairs.

Overall complexity: *O*(*n*<sup>3</sup>).

## 863D - Yet Another Array Queries Problem

One can guess from the constraits that complexity of the algorithm should be either *O*(*nm* + *q*) or *O*(*qm*). And there is a solution with the second one.

Let's try to solve the reversed problem — answer what position will some number be at after all the queries. Check the impact of some query on position *pos*. Let the query be on some segment [*l*, *r*]. If *pos* is outside this segment then you can skip it. Otherwise reverse will swap *a*<sub>*pos*</sub> and *a*<sub>*r* - (*pos* - *l*)</sub>, shift will swap *a*<sub>*pos*</sub> and *a*<sub>*pos* - 1</sub> (if *pos* = *l* then it will be *r* instead of (*pos* - 1)).

This task can be translated to the given one just by reversing the query list.

Overall complexity: *O*(*qm*).

## 863E - Turn Off The TV

Firstly let's compress the moments of time. Note that storing only *l* and *r* isn't enough (consider pairs ([1, 2], [3, 4]) and ([1, 2], [4, 5])), you also should take (*l* - 1).

Now moments of time are up to 6·10<sup>5</sup>. For every moment calculate the number of segments to cover it (make *cnt*<sub>*l*</sub> +  = 1 and *cnt*<sub>*r* + 1</sub> -  = 1 for each segment and take prefix sums over this array). Then let *pref*<sub>*i*</sub> be the number of moments of time covered by only one segment on some prefix up to *i*-th moment.

And finally if for some segment [*l*, *r*] from the input *pref*<sub>*r*</sub> - *pref*<sub>*l* - 1</sub> is 0 then you can safely delete this segment.

## 863F - Almost Permutation

This problem can be solved with mincost maxflow approach.

Let's construct a following network:

- Construct a vertex for every number from 1 to *n*. For each of these vertices add *n* directed edges from the source to this vertex, the capacity of each edge will be 1, and the costs will be 1, 3, 5, ..., 2*n* - 1 (so pushing *k* flow from the source to the vertex will cost exactly *k*<sup>2</sup>);
- Also construct a vertex for every index of the array. For each number make add a directed edge with capacity 1 and cost 0 to every position in the array such that this number can be put into this position, and for every index make a directed edge from the vertex constructed for this index to the sink with capacity 1 and cost 0.

Minimum cost maximum flow in this network will construct a suitable array with minimum cost, so the answer to the problem is minimum cost of maximum flow in the network.
