## 2203A - Towers of Boxes

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The main idea of this problem is to calculate how many boxes can be in one tower. Suppose we want to build a tower of $k$ boxes; then if we consider the very bottom box, there will be $k-1$ boxes on top of it, and their total weight is $m(k-1)$. This means that the constraint $d \ge m(k-1)$ must hold, and then the maximum possible $k$ is equal to $\lfloor \frac{d}{m} \rfloor + 1$. If there should be no more than $k$ boxes in the tower, then the minimum number of towers is $\lceil \frac{n}{k} \rceil$.

When it is necessary to compute a quotient with rounding down or up, it is not recommended to use floating-point numbers and functions like ceil, as this can cause precision issues. For integer division with rounding down, all programming languages have standard operators; if rounding up is needed, you can use the relation $\lceil \frac{x}{y} \rceil = \lfloor \frac{x+y-1}{y} \rfloor$.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 n, m, d = map(int, input().split())
 k = 1 + d // m
 print((n + k - 1) // k)
```

## 2203B - Beautiful Numbers

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Note that $F(x) \lt x$ for $x \ge 10$, and $F(x) = x$ otherwise. Therefore, a number is beautiful only if $F(x) \le 9$.

Consider a number represented by the sequence of digits $a_1, a_2, \dots, a_n$. For each position, we can calculate how much the sum of digits can be reduced by changing that position (let's call it $d_i$ for the $i$-th position). We can set $0$ in every position except the first one (since leading zeros are not allowed). Therefore, $d_i = a_i$ for $i \gt 1$ and $d_1 = a_1 - 1$.

To minimize the number of moves, we can sort the array $d$ in non-ascending order. Then, find the minimum $k$ such that the sum of all digits minus the sum of the first $k$ elements of $d$ is at most $9$ (i. e. $\displaystyle\sum\limits_{i=1}^{n} a_i - \displaystyle\sum\limits_{j=1}^{k} d_j \le 9$). This value of $k$ is the answer to the problem.

 
**Solution (Neon)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
int main() {
	int t;
	cin >> t;
	while (t--) {
		string s;
		cin >> s;
		int sum = 0;
		vector<int> a;
		for (int i = 0; i < int(s.size()); ++i) {
			int x = s[i] - '0';
			sum += x;
			a.push_back(x - (i == 0));
		}
		sort(a.begin(), a.end());
		int ans = 0;
		while (sum > 9) {
			sum -= a.back();
			a.pop_back();
			++ans;
		}
		cout << ans << '\n';
	}
}
```

## 2203C - Test Generator

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

Let's remove the condition on the minimum possible $n$ and try to solve the problem where we simply need to answer whether such an array $a$ exists or not.

Consider an example for $s = 147$ and $m = 57$.

Let's write our number $s$ in binary representation:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{1}, \color{red}{0}, \color{green}{0}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{1}, \color{green}{1}]$$

Here, we color the bits green that are allowed by the condition (i.e., these are the set bits of $m$), and the other bits are colored red. If there were no red set bits in the binary representation of $s$, we would be guaranteed to be able to create the array $a$. But what should we do if that is not the case?

Let's transition from the binary representation of $s$ to an array $c$, such that $\sum c_{i} \cdot 2^{i} = s$. This is necessary so that we can perform the following operation for $i \gt 0$:

- subtract one from $c_{i}$ and then add two to $c_{i - 1}$.

For such an operation, the sum of $c$ does not change, and we can use it to eliminate red set bits:

Let's perform the operation with $i = 7$:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{2}, \color{green}{0}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{1}, \color{green}{1}]$$

Now, let's perform the operation with $i = 6$:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{1}, \color{green}{2}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{1}, \color{green}{1}]$$

Next, let's perform the operation with $i = 6$ again:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{4}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{1}, \color{green}{1}]$$

Now, let's perform the operation with $i = 1$:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{4}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{3}]$$

After removing the red set bits, we can construct the array $a$ as follows:

We will form the numbers $a_{i}$ one by one. For the next $a_{i}$, we will go through $c$ and if $c_{j}$ is greater than $0$, we will subtract one from $c_{j}$ and add $2^{j}$ to $a_{i}$ (i.e., we will set the $j$-th bit to one).

For our example:

$a_{0} = 2^{5} + 2^{4} + 2^{0} = 49$ and after this:

$$c = [\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{3}, \color{green}{0}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{2}]$$

$a_{1} = 2^{5} + 2^{0} = 33$ and after this:

$$c = [\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{2}, \color{green}{0}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{1}]$$

$a_{2} = 2^{5} + 2^{0} = 33$ and after this:

$$c = [\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{1}, \color{green}{0}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{0}]$$

$a_{3} = 2^{5} = 32$ and after this:

$$c = [\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{0}, \color{green}{0}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{0}]$$

It is clear that this method generates a valid array $a$. We also note that the number of elements in the resulting array is $n = \max c_{j}$.

We have learned to construct $a$, but when will we not be able to construct it? It is easy to see that this happens when some bit of $s$ is a red set bit and there is no green bit lower down, for example:

$$s = [\color{red}{0}, \ldots, \color{red}{0}, \color{red}{1}, \color{red}{0}, \color{green}{0}, \color{green}{1}, \color{green}{0}, \color{red}{0}, \color{red}{1}, \color{red}{1}]$$

Okay, we have learned to solve the simplified problem. Now let's return to the original problem, meaning we will restore the condition on the minimum $n$.

Simply removing the red set bits is now insufficient, as we would like to minimize $\max c_{j}$. For our example, the minimum $\max c_{j}$ is $3$, since after we have removed all the red set bits, we can apply the operation at $i = 5$:

$$[\color{red}{0}, \ldots, \color{red}{0}, \color{red}{0}, \color{red}{0}, \color{green}{3}, \color{green}{3}, \color{green}{0}, \color{red}{0}, \color{red}{0}, \color{green}{3}]$$

Let's try to apply binary search! This can be done since the monotonicity condition holds (if we can create a suitable $a$ from $n$ elements, we can also create a suitable $a$ from $n + 1$ elements, for example by adding $a_{n} = 0$).

Now we have a plan for the solution:

We will iterate over $n$ using binary search. In the checking function for $n = mid$, we will go through the bits from the most significant to the least significant and form the array $c$, with the constraint that $c_{i} \le mid$.

This works quite quickly, as the binary search performs $O(\log s)$ checks and each check operates in $O(\log s)$ (since we go through the bits, and the number of bits is $\log s$).

Asymptotic complexity: $O(t \cdot \log^2 s)$

Bonus: Think about how to solve the problem in $O(t \cdot \log s)$


**Solution (FelixArg)**

```cpp
#include<bits/stdc++.h>

 f <<= 1;
 if (((x >> i) & 1) == 1){
 f++;
 }
 if (((a >> i) & 1) == 1){
 f -= min(lim, f);
 }
	}
	return (f == 0);
}

 if (get(x, a, m)){
 r = m - 1;
 }
 else{
 l = m + 1;
 }
	}

	cout << l << '\n';
}
```

## 2203D - Divisibility Game

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)
 
**Tutorial**

We will divide the numbers from the array $b$ into three classes:

- Numbers that can only be removed by Alice (they are divisible by every number in the array $a$), we will call them Alice's numbers;
- Numbers that can only be removed by Bob (none of the numbers in the array $a$ divide them evenly), we will call them Bob's numbers;
- Numbers that can be removed by both Alice and Bob, we will call them common numbers.

It is easy to guess that the optimal strategy for each player will be to first remove the common numbers and only then remove their own.

The main difficulty of the problem is to learn how to quickly determine to which class each number from $b$ belongs.

Let's take an arbitrary number from $b$ and denote it as $y$. We will try to check whether it is Bob's number or Alice's number; if it is neither, then it is a common number.

Let's look at all the divisors of the number $y$. For $y$ to be Alice's number, the array $a$ must consist only of its divisors, that is:

$$\displaystyle\sum_{d|y} \text{cnt}[d] = n$$

where $\text{cnt}[d]$ denotes the number of occurrences of the number $d$ in the array $a$.

Similarly, for $y$ to be Bob's number, there should not be any of its divisors in the array $a$:

$$\displaystyle\sum_{d|y} \text{cnt}[d] = 0$$

Now we can already write a solution that finds all the divisors of the number and directly checks these two conditions. However, this is slow and works in $O(\sqrt{(n + m)} \cdot m)$.

Instead of checking each number from $b$ separately, let's try to calculate an array $c$ such that:

$$c_{i} = \displaystyle\sum_{d|i} \text{cnt}[d]$$

How can we do this? With a simple nested loop:
```cpp
for(int i = 1; i <= n + m; i++){
 for (int j = 1; i * j <= n + m; j++){
 c[i * j] += cnt[i];
 }
}
```

In this loop, we iterate over the number $i$ and add $\text{cnt}[i]$ to all numbers that are divisible by it. After that, using the array $c$, we can check the class of a number in $O(1)$.

This works faster than iterating over all divisors of each number. Let's estimate the number of operations of these nested loops: for $i = 1$, the inner loop will make $n + m$ iterations; for $i = 2$: $\frac{n + m}{2}$; for $i = 3$: $\frac{n + m}{3}$, and so on. Thus, the total number of operations is:

$$\displaystyle\sum_{i = 1}^{n + m} \frac{n + m}{i} = (n + m) \cdot \displaystyle\sum_{i = 1}^{n + m} \frac{1}{i}$$

The last factor is the [harmonic series](<https://en.wikipedia.org/wiki/Harmonic_series_(mathematics)>). It is known that asymptotically it is equal to $\ln (n + m) + \gamma$, where $\gamma$ is a constant, so the number of operations of the nested loops, and thus the entire problem, is solved in $O((n + m) \cdot \log (n + m))$.

 
**Solution (FelixArg)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
int main() {
	ios_base::sync_with_stdio(0);
	cin.tie(0);
	cout.tie(0);
	
	int t;
	cin >> t;
	
	for (int test = 0; test < t; test++){
    	int n, m;
    	cin >> n >> m;
    
    	vector<int> a(n), b(m);
    	for (int i = 0; i < n; i++){
    		cin >> a[i];
    	}
    	for (int i = 0; i < m; i++){
    		cin >> b[i];
    	}
    
    	int max_a = n + m + 1;
    
    	vector<int> cnt_b(max_a, 0), cnt_a(max_a, 0);
    
    	for (int i = 0; i < n; i++){
    		cnt_a[a[i]]++;
    	}
    
    	for (int i = 0; i < m; i++){
    		cnt_b[b[i]]++;
    	}
    
    	vector<int> cnt_del(max_a, 0);
    
    	int f = 0, s = 0, com = 0;
    
    	for (int i = 1; i < max_a; i++){
    		for (int j = i; j < max_a; j += i){
    			cnt_del[j] += cnt_a[i];
    		}
    	}
    
    	for (int i = 1; i < max_a; i++){
    		if (cnt_b[i] == 0){
    			continue;
    		}
    
    		if (cnt_del[i] == 0){
    			s += cnt_b[i];
    		}
    		else if (cnt_del[i] == n){
    			f += cnt_b[i];
    		}
    	}
    
    	com = m - f - s;
    
    	bool turn = 0;
    	string win = "";
    
    	while(1){
    		if (turn == 0){
    			if (com > 0){
    				com--;
    			}
    			else if (f > 0){
    				f--;
    			}
    			else{
    				win = "Bob";
    				break;
    			}
    		}
    		else{
    			if (com > 0){
    				com--;
    			}
    			else if (s > 0){
    				s--;
    			}
    			else{
    				win = "Alice";
    				break;
    			}
    		}
    		turn = !turn;
    	}
    
    	cout << win << '\n';
	}
 
    return 0; 
}
```

## 2203E - Probabilistic Card Game

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Since the third card is chosen uniformly at random, the expected value is equal to the sum of the scores that Bob will receive for each of the cards, divided by $i-2$, where $i$ is the index of the round. Therefore, it is sufficient for us to minimize or maximize the sum. For output, multiply the sum by the inverse element of $i-2$, which can be found using Fermat's little theorem.

Let Alice choose some card $a$. Which card is most optimal for Bob to choose? Let's show that it's a card nearest to $a$ by value (either on the lesser or greater side). We can represent the cards as points on a number line. Suppose Bob chooses a card $b \gt a$, i. e., to the right of Alice's card. Then for all cards to the left of $a$, he will definitely receive a score of $0$. If there is at least one card $b'$ between $a$ and $b$, then it is surely better for Bob to take it. Indeed, all cards between $b'$ and $b$ previously gave a score of $0$, but now they will give a positive score. All cards to the right of $b$ will give an even greater score. Therefore, the sum will increase.

We define two functions $\mathit{cost}_l(a)$ and $\mathit{cost}_r(a)$, which return the total score of the nearest card to the left of $a$ and the nearest card to the right of $a$, respectively. Then Alice wants to choose a card $a$ that minimizes the value of $\max(\mathit{cost}_l(a), \mathit{cost}_r(a))$.

Let's consider the function $\mathit{cost}_l$. Note that this function is monotonically increasing. As the value of card $a$ increases, the value of the nearest card to the left also increases, and the distance from it to the other cards on the left also grows. Similarly, the function $\mathit{cost}_r$ is monotonically decreasing.

Now, let's look at the graph of the function $\max(\mathit{cost}_l(a), \mathit{cost}_r(a))$. This function monotonically decreases until the intersection point of the functions $\mathit{cost}_l(a)$ and $\mathit{cost}_r(a)$, and then it monotonically increases. Thus, the minimum of this function is found at the intersection. Since the functions are discrete, the answer can be either the largest point for which $\mathit{cost}_l(a) \lt \mathit{cost}_r(a)$ or the next one after it (the smallest point for which $\mathit{cost}_l(a) \ge \mathit{cost}_r(a)$).

These candidates can be found using binary search. If we learn to quickly compute $\mathit{cost}_l(a)$ and $\mathit{cost}_r(a)$, then by comparing them, we can understand from which side the intersection occurs.

The first problem: with each round, cards are added in arbitrary order, and we need to perform binary search on them. That is, we need to be able to quickly look up the $k$-th largest card, as well as the previous and next cards from it. The jury's solution uses ordered_set from pbds for this, but any data structure that can answer $k$-th order statistic queries can be used.

Now, let's learn to quickly compute $\mathit{cost}_l(a)$. Suppose we have found the nearest card to the left $b$. Let $b$ be the $k$-th card in increasing order. Then we need to compute $\sum\limits_{i=1}^{k} (b - \mathit{card}_i)$. We can break this down into two sums. $\sum\limits_{i=1}^{k} b = k \cdot b$. The sum $\sum\limits_{i=1}^{k} -\mathit{card}_i$ can be maintained using a data structure like a Fenwick tree or a segment tree. $\mathit{cost}_r(a)$ is computed similarly. It will be convenient to use coordinate compression beforehand: renumerate the points in increasing order as $0, 1, 2, \dots$ and update the value at the renumerated index in the data structure.

Overall complexity: $O(m \log^2 m)$.

Instead of binary search, we can also use sqrt decomposition on the renumbered cards. In each block of size $\sqrt{m}$, we can maintain the rightmost card that's already added, the sum of the card values, and their count. The previous and next cards can be maintained in a doubly linked list.

Then the intersection point of the functions can be found iteratively in $O(\sqrt{m})$. We check the rightmost card of the block: if it lies to the left of the intersection, we move to the next block; otherwise, we go one card at a time until we reach the intersection.

Overall complexity: $O(m\sqrt{m})$.


**Solution 1 (awoo)**
```cpp
#include <bits/stdc++.h>
#include "ext/pb_ds/assoc_container.hpp"
using namespace __gnu_pbds;

#define forn(i, n) for (int i = 0; i < int(n); i++)

using namespace std;

const int MOD = 998244353;

int mul(int a, int b){
	return a * 1ll * b % MOD;
}

int binpow(int a, int b){
	int res = 1;
	while (b){
 if (b & 1)
 res = mul(res, a);
 a = mul(a, a);
 b >>= 1;
	}
	return res;
}

template <typename T> using ordered_set = tree<T, null_type, less<T>, rb_tree_tag, tree_order_statistics_node_update>;

int main() {
	cin.tie(0);
	ios::sync_with_stdio(false);
	int m;
	cin >> m;
	vector<long long> a(m);
	forn(i, m) cin >> a[i];
	auto xs = a;
	sort(xs.begin(), xs.end());
	for (auto& x : a) x = lower_bound(xs.begin(), xs.end(), x) - xs.begin();

	vector<long long> f(m);

	auto upd = [&](int x, long long val){
 for (int i = x; i < int(f.size()); i |= i + 1)
 f[i] += val;
	};
	auto get = [&](int x){
 long long sum = 0;
 for (int i = x; i >= 0; i = (i & (i + 1)) - 1)
 sum += f[i];
 return sum;
	};

	long long sum = 0;
	ordered_set<int> cur;
	for (int x : a){
 cur.insert(x);
 int n = cur.size();
 sum += xs[x];
 upd(x, xs[x]);

 if (n < 3) continue;

 auto getL = [&](int pos, auto it){
 if (it == cur.begin()) return 0ll;
 return xs[*prev(it)] * 1ll * pos - get(*it - 1);
 };

 auto getR = [&](int pos, auto it){
 if (next(it) == cur.end()) return 0ll;
 return (sum - get(*it)) - xs[*next(it)] * 1ll * (n - pos - 1);
 };

 int l = 0, r = n - 1;
 int pos = n;
 while (l <= r){
 int m = (l + r) / 2;
 auto it = cur.find_by_order(m);
 if (getL(m, it) >= getR(m, it)){
 pos = m;
 r = m - 1;
 }
 else{
 l = m + 1;
 }
 }

 long long ans = 1e18;
 forn(_, 2){
 if (0 <= pos && pos < n){
 auto it = cur.find_by_order(pos);
 ans = min(ans, max(getL(pos, it), getR(pos, it)));
 }
 --pos;
 }

 cout << mul(ans % MOD, binpow(n - 2, MOD - 2)) << '\n';
	}
	return 0;
}
```

**Solution 2 (awoo)**
```cpp
#include <bits/stdc++.h>
 
#define forn(i, n) for (int i = 0; i < int(n); i++)
 
using namespace std;
 
const long long INF64 = 1e18;
const int MOD = 998244353;
 
int mul(int a, int b){
	return a * 1ll * b % MOD;
}
 
int binpow(int a, int b){
	int res = 1;
	while (b){
		if (b & 1)
			res = mul(res, a);
		a = mul(a, a);
		b >>= 1;
	}
	return res;
}
 
int main() {
	cin.tie(0);
	ios::sync_with_stdio(false);
	int m;
	cin >> m;
	vector<long long> a(m);
	int n = m + 2;
	forn(i, m) cin >> a[i];
 
	int p = sqrt(n) + 3;
	auto xs = a;
	xs.push_back(0);
	sort(xs.begin(), xs.end());
	xs.push_back(xs.back() + 1);
	vector<int> cntbl(n), rgh(n, -1);
	rgh[0] = 0;
	rgh[(n - 1) / p] = n - 1;
	vector<long long> sumbl(n);
	vector<int> cll(n, 0), clr(n, n - 1);
 
	set<int> on({0, n - 1});
	int cnt = 0;
	long long sum = 0;
	forn(i, m){
		int x = lower_bound(xs.begin(), xs.end(), a[i]) - xs.begin();
		int bl = x / p;
 
		++cntbl[bl];
		sumbl[bl] += xs[x];
		rgh[bl] = max(rgh[bl], x);
		sum += xs[x];
		++cnt;
 
		auto it = on.lower_bound(x);
		clr[x] = *it;
		cll[x] = *prev(it);
		clr[*prev(it)] = cll[*it] = x;
		on.insert(x);
 
		if (cnt < 3) continue;
 
		int lst = clr[0];
		int cntl = 0;
		long long suml = 0;
 
		auto getL = [&](int x){ return xs[cll[x]] * 1ll * cntl - suml; };
		auto getR = [&](int x){ return (sum - suml - xs[x]) - xs[clr[x]] * 1ll * (cnt - cntl - 1); };
		auto check = [&](int x){
			if (x == 0) return true;
			if (x == n - 1) return false;
			return getL(x) < getR(x);
		};
 
		while (lst < n - 1){
			int bl = lst / p;
			assert(rgh[bl] != -1);
			if (!check(rgh[bl])) break;
			cntl += cntbl[bl];
			suml += sumbl[bl];
			lst = clr[rgh[bl]];
		}
 
		while (lst < n - 1){
			if (!check(lst)) break;
			++cntl;
			suml += xs[lst];
			lst = clr[lst];
		}
 
		x = lst;
		long long ans = 1e18;
		if (x != n - 1)
			ans = min(ans, max(getL(x), getR(x)));
		assert(x != 0);
		x = cll[x];
		if (x != 0){
			--cntl;
			suml -= xs[x];
			ans = min(ans, max(getL(x), getR(x)));
		}
 
		cout << mul(ans % MOD, binpow(cnt - 2, MOD - 2)) << '\n';
	}
	return 0;
}
```

## 2203F - Binary Search with One Swap

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Let's call the integer $\lfloor \frac{l + r}{2} \rfloor$ the center of the segment $[l, r]$. We say that the center of the segment controls every integer in the segment.

Consider the binary tree that defines the binary search process. The root controls $c = \lfloor \frac{1+n}{2} \rfloor$ the whole segment $[1, n]$, the left child of the root controls its left part — the segment $[1, c-1]$, the right child of the root controls its right part — the segment $[c+1, n]$, and so on.

Suppose we are swapping $a_i$ with $a_j$. Let $k$ be the LCA of $i$ and $j$ in this tree. If an integer $x$ is not controlled by $k$, then searching for the integer $x$ will not go to $k$ or its subtree; so, every integer outside of $k$'s subtree will be successfully found.

This allows us to use the following approach: iterate on $k$ (the LCA of $i$ and $j$), and consider only the subtree of $k$ as integers which might not be found. For this fixed $k$, we are going to build an array $[p_0, p_1, \dots, p_{f(k)}]$, where $f(k)$ is the size of the segment that $k$ controls, and $p_x$ is the number of pairs $(i, j)$ such that their LCA is $k$ and swapping them makes exactly $x$ elements impossible to find.

If $k$ is the LCA of $i$ and $j$, then there are three possible cases for the location of $i$ and $j$:

- $i$ is in the left subtree, $j = k$;
- $i = k$, $j$ is in the right subtree;
- $i$ is in the left subtree, $j$ is in the right subtree.

We will consider the first and the third case; the second case is symmetric to the first one and can be solved in the same way.

Case $1$: let's say that we swap $k$ with $i$, and $i$ belongs to the left subtree of $k$. Which integers won't be found? I claim that these are all integers from $i+1$ to $k$: we will go to the right subtree of $k$ while searching for them (since the vertex $k$ now has value $i$), but they are all in the left subtree. For all integers less than $i$ or greater than $k$, nothing will change, and for $i$ itself, it will be found as soon as we arrive to the vertex $k$. So, the number of integers we won't find if we swap $k$ with $i$ is exactly $k-i$.

Case $3$: let's say that we swap $i$ with $j$, $i$ belongs to the left subtree of $k$, and $j$ belongs to the right subtree of $k$. Let $g(i)$ be the number of integers in the left subtree of $k$ which won't be found if we replace $i$ with some integer greater than $k$, and $h(j)$ be the number of integers in the right subtree of $k$ which won't be found if we replace $j$ with some integer less than $k$. I claim that $g(i)$ is equal to the size of the right subtree of $i$, plus one: obviously, $i$ won't be found; but also, when we arrive at the subtree which $i$ controlled, we have to go to the right if we are looking for some integer from the right subtree, but we will go to the left instead. Similarly, $h(j)$ is equal to the size of the left subtree of $j$, plus one.

This allows us to calculate all of the values of $g(i)$ and $h(j)$ in $O(n)$, but how do we "merge" them? This looks like a FFT problem, but FFT is too slow. Instead, let's analyze the possible values of $g(i)$ and $h(j)$. I claim that there are only $O(\log n)$ different values of $g(i)$ and $h(j)$, because there are $\log_2 n$ layers in our tree and the sizes of subtrees in each layer differ at most by $1$. So, we can simply build two frequency maps which, for every $g(i)$ and $h(j)$, store the number of vertices having this value of $g(i)$ or $h(j)$ in the subtree, and merge them naively. The sizes of these maps are at most $\log n$, so processing every $k$ works in $O(f(k) \log \log n + \log^2 n)$.

And our final optimization will be as follows: if two vertices which we choose as LCAs of $i$ and $j$ have the same subtree sizes, then the search in their subtrees behaves exactly the same. So we don't need to calculate everything for each possible vertex $k$; instead, for every $f(k)$, let's count the number of vertices having this $f(k)$, calculate the answers for that value of $f(k)$, and multiply them. There are only $O(\log n)$ different values of $f(k)$, and their sum is $O(n)$, so now our solution works in $O(n \log \log n + \log^3 n)$.
