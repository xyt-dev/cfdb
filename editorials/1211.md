## 1211A - Three Problems
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

Just choose any three indices with different values and print them in order of increasing values. You can do it in a billion ways. One of the is to use map data structure (from elements to indices): while reading the data assign value $i$ for the key $a_i$ (use an ordered map, for example, TreeMap). If the size of the map less than $3$, print -1. Overwise print values (i.e. correspondent values) for the first three elements of the map.

Here is the example of a solution in Kotlin:
```kotlin
fun main() {
 val n = readLine()!!.toInt()
 val r = readLine()!!.split(" ").map { it.toInt() }
 .withIndex()
 .distinctBy { it.value }
 .sortedBy { it.value }
 .map { it.index + 1 }
 if (r.size < 3) {
 println("-1 -1 -1")
 } else {
 println("${r[0]} ${r[1]} ${r[2]}")
 }
}
```

## 1211B - Traveling Around the Golden Ring of Berland
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

The first solution is to find $w = \max a_i-1$. We need to make $w$ whole cycles plus some partial cycle. The last addend (partial cycle) is the index of the last occurrence of $\max a_i$.

Let's iterate through all possible $a_i$ and consider the length of the minimal path to make exactly $a_i$ selfie in the city $i$ in total (just do not consider other $a_j$ for other cities). If is exactly $i + (a_i - 1) \cdot n$ (or $0$ if $a_i=0$). The answer is the maximum value among all of them.

Here is the example of a solution in Kotlin:
```kotlin
fun main() {
 val n = readLine()!!.toLong()
 val a = readLine()!!.split(" ").map { it.toInt() }
 var ans = 0L
 for ((i, k) in a.withIndex()) {
 if (k == 0) continue
 var visits = (i + 1).toLong()
 if (k > 0) visits += (k - 1) * n
 if (visits > ans) ans = visits
 }
 println(ans)
}
```

## 1211C - Ice Cream
Problem writers: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>), [geranazavr555](<https://codeforces.com/profile/geranazavr555>)

**Tutorial**

If $a_1+a_2+\dots+a_n \gt k$ or $b_1+b_2+\dots+b_n \lt k$ then the answer is $-1$. Otherwise, let's initialize the answer $res=a_1 \cdot c_1 + a_2 \cdot c_2 + \dots + a_n \cdot c_n$, the number of extra portions to buy is $rem=k-(a_1+a_2+\dots+a_n)$.

Now we have an option in each day to buy at most $b_i-a_i$ portions with price $c_i$. Let's sort all such options and apply them in a greedy way until there are $rem$ extra portions that have been bought.

Here is the example of a solution in Kotlin:
```kotlin
import kotlin.math.*

fun main() {
 val (n, k) = readLine()!!.split(" ").map { it.toInt() }
 val a = IntArray(n)
 val b = IntArray(n)
 val c = IntArray(n)
 for (i in 0 until n) {
 val l = readLine()!!.split(" ").map { it.toInt() }
 a[i] = l[0]
 b[i] = l[1]
 c[i] = l[2]
 }
 println(solveIceCream(a, b, c, n, k))
}

private fun solveIceCream(a: IntArray, b: IntArray, c: IntArray, n: Int, k: Int): Long {
 val sa = a.fold(0L, Long::plus)
 val sb = b.fold(0L, Long::plus)
 if (sa > k || sb < k) return -1
 var res = a.foldIndexed(0L) { i, acc, av -> acc + av.toLong() * c[i] }
 val e = c.mapIndexed { i, cv -> Extra(cv, b[i] - a[i]) }.sortedBy { it.c }
 var rem = k - sa
 var idx = 0
 while (rem > 0) {
 val take = min(rem, e[idx].q.toLong())
 rem -= take
 res += e[idx].c * take
 idx++
 }
 return res
}

data class Extra(val c: Int, val q: Int)
```

## 1211D - Teams
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

Consider that $a \lt b$. If you have a chain of ratings $rr_1, rr_2, \dots, rr_t$ such that $rr_{i+1} = rr_i \cdot k$ for each $1 \le i \lt t$ and $cc_i$ is number of players with the rating equals $rr_i$, then you can compose teams in a greedy way from left to right. This is true, since if you move a composed team along the chain to the left, then only improve the situation.

In the opposite case $a \ge b$ you should compose teams greedy from right to left.

So for each rating compute the number of players in a map (say, $rm$). After it iterate through all the keys (possible ratings) in increasing order if $a \lt b$ or in decreasing order if $a \ge b$. Each time try compose as many teams as you can using two ratings $r$ and $r \cdot k$ (i.e. increase the answer by $\min(rm[r] / a, rm[r \cdot k] / b)$).

Here is the example of a solution in Kotlin:
```kotlin
import kotlin.math.*

fun main() {
 val (n, a, b, k) = readLine()!!.split(" ").map { it.toInt() }
 val rm = readLine()!!.split(" ").map { it.toInt() }
 .groupingBy { it }.eachCount()
 .mapValues { Left(it.value) }
 val rl = rm.keys.sorted()
 .let { if (a >= b) it else it.reversed() }
 var ans = 0
 for (r in rl) {
 val p = rm.getValue(r)
 if (p.cnt < a) continue
 val q = rm[r * k] ?: continue
 if (q.cnt < b) continue
 val t = min(p.cnt / a, q.cnt / b)
 ans += t
 p.cnt -= a * t
 q.cnt -= b * t
 }
 println(ans)
}

data class Left(var cnt: Int)
```

## 1211E - Double Permutation Inc.
Problem writers: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>), [geranazavr555](<https://codeforces.com/profile/geranazavr555>)

**Tutorial**

One can solve the problem with binary search by the length of a permutation. If the length is $len$ then:

- just ignore all elements greater than $len$ (paint the with blue);
- the expected number of unpainted elements is $2 \cdot len$: two $1$'s, two $2$'s and so on;
- split the into two permutations with a greedy approach and check that they are equal.

If it is impossible to process any item above, it means that there is no solution with the length of a permutation that equals $len$.

There is an alternative solution without any binary search. You can greedily construct both permutations in order: add into them elements that equal $1$, add into them elements that equal $2$ and so on. Before the step $i$ you should check that there are exactly two occurrences of $i$ in the given array. After each step you should check that the current two permutations are equal. You can easily check it if you maintain them as ordered maps and each time you insert new elements at the same positions (the code below checks that next elements after the inserted are the same).

Here is the example of a solution in Kotlin:
```kotlin
import java.lang.StringBuilder
import java.util.*

fun main() {
 val n = readLine()!!.toInt()
 val a = readLine()!!.split(" ").map { it.toInt() }
 val d = a.withIndex().groupBy { it.value }
 val s = StringBuilder(n).apply { repeat(n) { append('B') } }
 val pr = TreeMap<Int, Int>()
 val pg = TreeMap<Int, Int>()
 for (i in 1..n) {
 val list = d[i] ?: break
 if (list.size != 2) break
 val rn = pr.insert(list[0])
 val gn = pg.insert(list[1])
 if (rn != gn) break
 s[list[0].index] = 'R'
 s[list[1].index] = 'G'
 }
 println(s)
}

private fun TreeMap<Int, Int>.insert(iv: IndexedValue<Int>): Int? {
 val next = tailMap(iv.index).values.firstOrNull()
 put(iv.index, iv.value)
 return next
}
```

## 1211F - kotlinkotlinkotlinkotlin...
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

Note that in the word kotlin all letters are different. At first glance, it seems that this problem can be solved greedily, each time putting a word that can continue the required sequence. In fact, it is not. Look at the following test:
```
3
kotlinkotli
nkotlinkotli
nkotlin
```

Obviously, you should start with kotlinkotli. But the next word must be nkotlinkotli but not nkotlin (despite the fact that both options correctly continue the sequence).

We need a graph approach to solve the problem. Let's build a graph with exactly $6$ vertices. Each given word is an oriented edge in this graph. If a word starts with the $j$-th letter of the word kotlin and has the length $l$ then it connects vertices $j$ and $(j+l) \mod 6$.

For example, the word kotlinkotli is the edge $(0, 5)$, nkotlinkotli is $(5, 5)$ and nkotlin is $(5, 0)$.

Now you need to find a path containing all edges exactly once which starts at $0$ and ends at $0$. It called Eulerian Cycle and it can be found in linear time with easy algorithm (Fleury's algorithm). You can read the details by the link [https://en.wikipedia.org/wiki/Eulerian_path](<https://en.wikipedia.org/wiki/Eulerian_path>).

Here is the example of a solution in Kotlin:
```kotlin
fun main() {
 val n = readLine()!!.toInt()
 val w = List(n) { readLine()!! }
 val k = "kotlin"
 val g = k.withIndex().associateBy({ it.value }) { it.index }
 val gf = IntArray(k.length) { -1 }
 val gn = IntArray(n)
 val gv = IntArray(n)
 for ((i, s) in w.withIndex()) {
 val p = g.getValue(s.first())
 val q = (g.getValue(s.last()) + 1) % k.length
 gv[i] = q
 gn[i] = gf[p]
 gf[p] = i
 }
 val ans = IntArray(n)
 var cnt = 0
 val vStack = IntArray(n + 1)
 val eStack = IntArray(n + 1)
 var sp = 0
 while (true) {
 val p = vStack[sp]
 if (gf[p] < 0) {
 if (sp <= 0) break
 ans[cnt++] = eStack[sp–]
 continue
 }
 val j = gf[p]
 val q = gv[j]
 gf[p] = gn[j]
 sp++
 vStack[sp] = q
 eStack[sp] = j
 }
 check(cnt == n)
 ans.reverse()
 println(ans.joinToString(" ") { (it + 1).toString() })
}
```

## 1211G - King's Path
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

It is easy to see that if for a leaf $u$ holds $c_u=d_u$, then the leaf $u$ is redundant (you can exclude it from any valid path). So while there is at least one such leaf in the tree, just erase any of them.

After it, the resulting tree should degenerate to be a path (or print No). Just test the path if it is valid with two possible directions.

## 1211H - Road Repair in Treeland
Problem writer: [MikeMirzayanov](<https://codeforces.com/profile/MikeMirzayanov>)

**Tutorial**

Let's do a binary by answer. For each candidate $c$ you should check if it is possible to color edges in such a way that:

- at most two colors are incident to any vertex,
- the usage of the most frequent color is at most $c$.

Let's use a dynamic programming approach to check it. Build a recursive function to check if it possible to color subtree in the required way it the edge to the parent is included in a subtree (if such edge exists). In case of positive answer also return the minimal number of usages of color $c'$ (where $c'$ is a color of the edge to the parent).

Formally, $d[u]$ is:

- $-1$ if it is impossible to color subtree rooted in $u$ in the required way, the edge to the parent of $u$ (if any) is included in the subtree;
- $f$ if such coloring exists and $f$ is the minimal number of usages of the color in which the edge to the parent of $u$ is colored (of $f$ is just any number in case of root, i.e. no parent).

Now to calculate $f[u]$ you need to solve an instance of a knapsack problem: find such subset of children which should be colored same a the parent edge that the sum $d[v_1] + d[v_2] + \dots + d[v_k] + 1$ is less or equal than $c$, where $x=v_1, v_2, \dots, v_k$ are chosen children vertices. You should erase $+1$ addend for the case $u$ is the root. Among all such cases, you need to find a subset of children with the greatest value $x$ less or equal than $c$. It is exactly a knapsack problem.

As the total degree of all vertices in a tree is $O(n)$, the total complexity of the algorithm is $O(n^2)$ for fixed $c$ and $O(n^2 \log n)$ for the whole solution (remember about a binary search).

## 1211I - Unusual Graph
Problem writer: [300iq](<https://codeforces.com/profile/300iq>)

**Tutorial**

Key lemma

- If two vertices have the same set of adjacent vertices, we can set them equal numbers.

Because if two vertices with the same adjacent vertices have different numbers, we can change any one of them to the other, and it is easy to see that all constraints will be satisfied.

So, we can merge all vertices with the equal adjacency list into one vertex, and reduce the problem to following:

New problem

- Set different integers $0 \leq a_v \leq 15$ to vertices of the graph with $n \leq 16$ vertices, to satisfy the same condition as in the original problem.

Solution 1 (Found by participants)

- You can use brute force with some prunings, and it will work fast enough. It can be proved that it will work fast enough. For example, it is quite clear that it will work fast enough if the number of edges is big because you can set $0,1,2,4,8$ arbitrary to vertex and its neighbors, and you will have $\leq 11$ remaining values to place, so it is quite clear that it is $\leq 11!$, and with further case analysis you can prove that it is way much faster.

Solution 2 (Intendend)

Now we can see that there are $\leq 2^{16}$ possible graphs, up to isomorphism.

So we can fix the set of values of vertices, and check that the given graph and the current graph are isomorphic.

Isomorphism problem

- You need to check that two graphs with $n \leq 16$ are isomorphic, note that these graphs are not arbitrary, so you can use some hacky way to check isomorphism.

Well, indeed, some hash-functions will work here! For example, you can fix some vertex as root, and calculate some hash of the graph with different coefficients of vertices, according to is it root or not. Also, you may fix more vertices, not only one root.

Any naive hash-function will reduce the number of candidate graphs to $\leq 300$.

For them, you can check with some smart, but slower to calculate hash-functions, as written earlier.

Bonus (maybe unsolvable?)

- Solve for $0 \leq a_v \leq 31$.
