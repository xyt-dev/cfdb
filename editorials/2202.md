## 2202A - Parkour Design
Notice how these three paths end up on the same coordinate:

- $(0,0) \to (2,1) \to (6,0)$
- $(0,0) \to (3,0) \to (6,0)$
- $(0,0) \to (4-1) \to (6,0)$

Because of this, using both $(+2,+1)$ and $(+4,-1)$ types of moves is meaningless because they can be substituted into two $(+3,0)$ moves. Now we can simply align the $y$ coordinate using only one type of move, and then check if the given coordinate is reachable by checking the $x$ coordinate.

Alternatively, one can show that the answer is YES if $(x,y)$ satisfies the following two conditions:

- $x+y \equiv 0 \pmod 3$
- $-\frac{x}{4} \le y \le \frac{x}{2}$

The proof is left as a practice for the reader.

## 2202B - ABAB Construction
Notice that the states $T=\mathtt{abab}\ldots\mathtt{abab}$ and $T=\mathtt{baba}\ldots \mathtt{baba}$ (with the same length) are equivalent by reflection (you can simply use the opposite operation for the rest of the iteration).

Initially, if $n$ is odd, you can only append a to $S$. Therefore, $S_1$ needs to be a if $n$ is odd. The rest of the string is equivalent to when $n$ is even, so WLOG we will assume that $n$ is even.

When $T=\mathtt{abab}\ldots\mathtt{abab}$, you can't use the same letter twice in a row because the first and last letters of $T$ will be the same on the next iteration. Therefore, when you look at the letters of $S$ in groups of $2$, they should be either ab or ba.

Therefore, the string $S$ generated by the algorithm must satisfy the following conditions:

- $S_1$ is a if $n$ is odd;
- $S_{2i} \neq S_{2i+1}$ if $n$ is odd;
- $S_{2i-1} \neq S_{2i}$ if $n$ is even.

The '?'-s in the input don't make a difference in the solution after this observation. The problem is solved in $\mathcal{O}(n)$ time.

## 2201A1 - Lost Civilization (Easy Version)

There are two solutions to the easy version. They both utilize one observation:

- Each element of the initial sequence corresponds to a subsegment of the returned sequence.

The two solutions are as follows:

- Solution 1: Process in the order of left to right.

Let's check for each element if it must be a new subsegment or should be merged into the previous subsegment. Let's say the first element of the previous subsegment was $x$, and the last element was $y$. We definitely know that $x \le y$. Let's think of it in a case-by-case analysis:

- If $a_i \le x$, then nothing in the previous subsegment could add $a_i$. This must be a new subsegment.
- If $a_i = y+1$, then you can construct $a_i$ from the last element. This can be merged into the previous subsegment.
- If $x+1 \le a_i \le y$, then we can perform until $a_i-1$ is found in the previous subsegment, add $a_i$, then perform the rest of the operations. This can be merged into the previous subsegment.
- If $y+1 \lt a_i$, then nothing could add $a_i$. Note that the maximum value of the previous subsegment does not matter. This is because adding $a_i$ and then inserting smaller values right before it is impossible.

Therefore, $a_i$ can be merged into the previous subsegment if and only if $x+1 \le a_i \le y+1$.

Greedily merging according to this rule yields the optimal initial sequence in $\mathcal{O}(n)$ time.

- Solution 2: Process in the order of right to left.

Let's maintain a stack of elements. For each earlier element $a_i$ we see, we will eliminate all occurrences of $a_i+1$ on top of the stack. Afterwards, we push $a_i$ to the top of the stack.

This can be seen as performing the operations in reverse order, and thus this algorithm only gets sequences that can construct the given sequence.

The stack after this algorithm finishes (from top to bottom) gives you the optimal initial sequence. The algorithm has time complexity $\mathcal{O}(n)$.

Let's use the stack solution, while we will observe something from both solutions.

- The stack solution maintains the shortest sequence for all suffixes.
- The prefix solution maintains the shortest sequence for all prefixes.

Note how both algorithms performed iterations in an online manner. That being said, by the proof of the prefix solution, we know that a prefix of the shortest constructing sequence is a shortest constructing sequence for some prefix. In other words, when we use the stack solution, the stack contains the shortest constructing sequences for all prefixes of this suffix (which are subsegments of the sequence!).

Therefore, let's record at which index each element in the stack gets added. Then we can record the contribution of each element, and find the sum of all prefixes in $\mathcal{O}(1)$ at any moment. As we found the sum of all prefixes for every suffix, we have effectively found the sum of all subsegments in $\mathcal{O}(n)$ time.

## 2201B - Recollect Numbers
The value $k$ can't be less than $n$ because each pair needs to be flipped at least once, and can't be greater than $2n$ because each pair will be flipped in at most two operations. What is the actual maximum number of operations?

Let's simulate the algorithm to look at how the number of operations is computed. We classify elements into "unseen" and "seen"; for each value the first occurrence is "unseen" ('u') and the second occurrence is "seen' ('s').

The number of operations accumulated in the algorithm is as follows:

- If the next element is seen ('s'), then a pair is flipped and $1$ operation is accumulated for $1$ index.
- Otherwise, the next element is unseen ('u?').

 - If the following element is seen ('us'), there are two cases:

 - If the element was the same as the previously flipped element, this pair is already flipped and $1$ operation is accumulated for $2$ indices.
 - If the element was different from the previously flipped element, you need to flip again and $2$ operations are accumulated for $2$ indices.

 - If the following element is unseen ('uu'), nothing is flipped yet and $1$ operation is accumulated for $2$ indices.


Which case would waste the most number of operations? It's certainly either 's' or 'us' when two elements are different. But 's' cases make the other operations use less on average, because the unseen card of the pair should have appeared from either 'us' or 'uu'. If we record correct operations as $1$ flip for that pair and wasted operations as $0.5$ flips for both pairs, the real contribution is as follows:

- 's': $1$ flip for this pair;
- 'us' (same value): $1$ flip for this pair;
- 'us' (different value): $0.5$ flips for the unseen, $1.5$ flips for the seen;
- 'uu': $0.5$ flips for both pairs.

Therefore, we can see that using the 's' case can only allow $1.5$ flips for this pair, while the 'us' (different value) case allows $2$ flips for this pair.

Let's try using as many 'us' cases as possible. The first consideration would be $\mathtt{ususus}\ldots\mathtt{ususus}$, but this makes every case have the same value and only uses $n$ operations in total. The respective sequence would be $1,1,2,2,\ldots,n,n$.

Instead, if we use $\mathtt{uuusus}\ldots\mathtt{ususss}$, then we can achieve $2n-1$ operations. One respective sequence would be as follows:

- $1,2,3,1,4,2,5,3,\ldots,n,n-2,n-1,n$

As we have shown that not every pair can get $2$ flips as contribution, we can see that $2n-1$ is the maximum possible number of operations.

Now to construct every possible $k$ for the given $n$, we concatenate the $k=n$ case and the $k=2n-1$ case. By concatenating the construction for $(x,2x-1)$ and the construction for $(n-x,n-x)$, we achieve a construction for $(n,n+x-1)$. By setting $x=k-n+1$, we can construct every possible value of $k$.

The problem is solved in $\mathcal{O}(n)$ time.

## 2201C - Rigged Bracket Sequence
Thanks to [reirugan](<https://codeforces.com/profile/reirugan>) for writing the model solution without bugs!



Let's observe how the prefix sums (when '(' and ')' are substituted with $+1$ and $-1$) change when you shift a subsequence.

Let's say $S$ was $\mathtt{()(()())}$ and we shifted the subsequence $S_2 S_4 S_7$. The prefix sums before and after the shift are as follows:

- Before ($\mathtt{()(()())}$): $[0,1,0,1,2,1,2,1,0]$
- After ($\mathtt{(\color{red}{)}(\color{red}{)})(\color{red}{(})}$): $[0,1,0,1,0,-1,0,1,0]$

How did the number of brackets in the first five indices change? Let's look at them side by side:

$$\mathtt{\underline{(\color{blue}{)}(\color{blue}{(})}(\color{blue}{)})} \\ \mathtt{\underline{(\color{red}{)}(\color{red}{)})}(\color{red}{(})}$$

We can observe that $S_7$ got moved into the prefix as $S_2$, and $S_4$ moved out from the prefix as $S_7$. Generalizing this, we get the following:

- If a prefix either doesn't include any index or includes all indices of the subsequence, then the number of brackets doesn't change.
- If a prefix only partially includes the indices of the subsequence, then the number of brackets changes:

 - The last chosen element within the prefix moves out of the prefix.
 - The last chosen element of the subsequence moves into the prefix.


If the last chosen element of the subsequence was a '(', this always keeps the string regular. If it was a ')', it might make the string not regular because a '(' moving out and a ')' moving in means that the prefix sum changes by $-2$.

Let's maintain a DP defined as $\mathtt{DP}_i = (\text{number of non-trivial subsequences in prefix containing index }i)$, where non-trivial means that the subsequence ends with a ')'. Then, $\mathtt{DP}_j$ affects $\mathtt{DP}_i$ ($j \lt i$) if either:

- $S_j$ was ')';
- or the prefix sums between $j$ and $i$ never dropped below $2$.

One can implement this DP in time complexity $\mathcal{O}(n^2)$ trivially, and by using prefix sums on DP values, it is possible to optimize condition $2$ (by binary search or two pointers) to make the DP run in $\mathcal{O}(n)$ or $\mathcal{O}(n \log n)$ time.

Now the final answer can be computed as follows:

- If $S_k$ was '(', then add $2^{k-1}$ to the answer.
- If $S_k$ was ')', then add the corresponding value of $\mathtt{DP}$ to the answer.

The problem is solved in time complexity $\mathcal{O}(n)$ or $\mathcal{O}(n \log n)$.

## 2201D - Binary Not Search and Queries
Let's observe how it is possible to compute $k_\max$:

For every two indices $i \lt j$ such that $a_i=a_j$, we know that $(i,i+1,j-i)$ is an element in $S(a)$. From this we claim:

- $k_\max$ is the maximum value of $|i-j|$ such that $a_i=a_j$.

Let's say this maximum value is $d$, and then suppose there is a good tuple such that $k \gt d$. In that case, $a_i$ must appear in the part unique to the left segment, but cannot appear in the part unique to the right segment. This is a contradiction. Therefore, $k_\max=d$.

Let's see how we can count $f(a)$ and also maintain it over updates. For each distinct value in $a$, we can simply find one (and not more than one) candidate of $k_\max$. If we maintain all such candidates in a set, it takes only $\mathcal{O}(\log n)$ time to add and remove candidates. Finding the removed/added candidates of $k_\max$ can be done by maintaining a set of indices for each distinct value; there are $n$ elements throughout $n$ distinct values, so this also takes only $\mathcal{O}(\log n)$ time to maintain.

How can we maintain $f(a)$ then? Observe that if $(i,i+1,k_\max),(i+1,i+2,k_\max),\ldots,(i+x-1,i+x,k_\max)$ are all found from candidates of $k_\max$ that we know, then any $(p,q,k_\max)$ where $i \le p \lt q \le i+x$ are also elements of $S(a)$. Therefore, if we know these "chains" of tuples then we can count $f(a)$ by sums of $\binom{x}{2}$-s. Now we maintain these chains as intervals. For example, $(i,i+1,k_\max),(i+1,i+2,k_\max),\ldots,(i+x-1,i+x,k_\max)$ becomes interval $[i,i+x-1]$. Now these can be maintained in a set of intervals; adding a tuple becomes inserting the interval $[i,i]$ and removing a tuple becomes removing the interval $[i,i]$.

That was about maintaining $f(a)$ for one $k_\max$. However, our complexity does not change even if we maintain it for all $k_\max$. Because there's just at most one candidate tuple for each distinct value, there's still only $\mathcal{O}(n)$ intervals maintained at any moment, and the time complexity didn't suffer.

Now we can maintain all of this and then simply take the value of $f(a)$ from the set with the actual current value of $k_\max$.

The time complexity is $\mathcal{O}((n+q) \log n)$.

## 2201E - ABBA Counting
Thanks to [satyam343](<https://codeforces.com/profile/satyam343>) which suggested a modification of an easier problem, which later turned into this problem!



To solve the problem, first observe the following:

- $S$ can be factored into $A+B+B+A$ if and only if the first half is a cyclic rotation of the second half.

Let's count the strings that can be the second half with respect to the first half. Think of rotation; if you rotated the first half by $k$ indices and then found $x$ coinciding '?'s without any 'a' coinciding with a 'b', then we can say that there are $2^x$ second halves that match when rotated $k$ times. We can consider adding this up.

But this counting has a flaw. Let's think of "abaababaabaa". The second half "baabaa" must have been counted twice on $k=0$ and $k=3$! Therefore, we must find a way to deal with this overcounting issue. For this, we consider the minimal period of the first half.

For each divisor $d$ of $n/2$, we want to count minimal periods of length $d$. We can collapse the first and second halves of the string into two length-$d$ strings. Then, similarly to when we overcounted, we can count for each rotation from $k=0,1,\ldots,d-1$. Then, strings with minimal period length $d$ are counted in divisor $d$ exactly once. The unfortunate part is that our "abaababaabaa" is still counted twice in $d=6$.

But that's fine! Thankfully, if the minimal period length is $d$ for some period, then we know that it's overcounted $2$ times for $2d$, $3$ times for $3d$, and $x$ times for $xd$. Therefore, we can perform an "inclusion-exclusion" kind of elimination; for $d_1 \lt d_2$ and $d_1 \mid d_2$, we subtract $(d_2/d_1)$ times the answer for $d_1$ from the answer for $d_2$. Then we actually have the correct count for each minimal period length, and adding them up gives us the answer.

Counting fast for one period length is considered (relatively) standard practice. Formally, you can reverse the second half and find a cyclic "convolution" with the first half. That is, we modify $\sum_{i+j=k} a_i \cdot b_j$ into $\sum_{i-j=k} a_i \cdot b_j = \sum_{i=j+k} a_i \cdot b_j$. By FFT, we can count for a divisor $d$ in $d \log d$ time.

As we took $\mathcal{O}(n+d \log d)$ time while counting for divisor $d$, the total time complexity is $\mathcal{O}(n \, d (n/2) + \sum d \log d)$. It can be shown that $\sum d$ is actually of order $\mathcal{O}(n \log \log n)$, and therefore our time complexity boils down to $\mathcal{O}(n \, d (n/2) + n \log n \log \log n)$.

## 2201F2 - Monotone Monochrome Matrices (Hard Version)

For the Easy subtask, you may observe the following reduction of the problem.

- If there is no violation between two rows $i$ and $j$, it holds true that either row is a submask of the other.

This is because if there is a black column in row $i$ that is not in $j$, and a black column in row $j$ that is not in $i$, this is both equivalent to a violation in the problem and a violation to both $M_i \subseteq M_j$ and $M_j \subseteq M_i$.

Let's try to sort the rows and count the adjacent violations. If you maintain the rows sorted, then the number of adjacent violations can be maintained by looking at adjacent elements in a std::set.

The issue is on how to sort rows. For this, we can see that if $M_1 \subseteq M_2 \subseteq \ldots \subseteq M_n$, then $|M_1| \le |M_2| \le \ldots \le |M_n|$. Therefore, if the answer is YES, then sorting by cardinality is equivalent to sorting so that subsets come before supersets.

By dealing with adjacent violations using bitsets, one can achieve a time complexity of $\mathcal{O}((n+q)(\frac{n}{w}+\log n))$.

The difference between Easy and Medium is not very intuitive. The biggest issue of Easy is that it uses $\mathcal{O}(\frac{n^2}{w})$ memory. There are various facts one can use to resolve this and hopefully achieve $\mathcal{O}(q \sqrt {q})$ time complexity:

- There are only $\mathcal{O}(\sqrt q)$ different cardinalities at any moment.
- If the answer is YES, then either the number of active rows or the number of active columns is $\mathcal{O}(\sqrt {q})$.
- If there are two different contents of rows with the same cardinality, the answer is NO.

Each of these facts lead to a different solution that optimizes the solution. For example, we can use the second observation, and find the final moment $k$ such that either the number of rows or the number of columns was at most $\sqrt{k}$. Then, any moment after this the answer is NO, and we can solve up to this moment only using the active rows/columns of the smaller side. As the smaller side has cardinality $\mathcal{O}(\sqrt{q})$, one can achieve a time complexity of $\mathcal{O}(q \sqrt{q})$ or $\mathcal{O}(\frac{q\sqrt{q}}{w})$.

In order to achieve a solution to the Hard subtask, we would want to drastically change our approach, because large bitmasks are fundamentally hard to manage anyways.

Here is an observation that solves the problem:

- If you push the $1$-s forcefully into one direction (think of gravity), then it's equivalent to sorting if and only if the answer is YES.

Proving equivalence is not easy, but the general idea of the proof is:

- If the answer is YES, then the algorithm to simulate gravity always pulls supersets into subsets, so it becomes equivalent to selection sort.
- If the answer is NO, then any sorting order yields a floating $1$, whereas gravity doesn't allow a floating $1$.

It is now quite easy to maintain a sorted order (respective to cardinality) and the orientation due to gravity at the same time, because we have done the former by std::set (Note that we don't have to use a std::set, and can simply swap two indices each time) and the latter is just placing cells at the rightmost possible column.

Then, by either comparing the column cardinalities, or simply hashing both matrices, we can bookkeep equivalence of sorting and gravity in $\mathcal{O}(1)$ time. By the time complexity to maintain the sorted order, the total time complexity is $\mathcal{O}((n+q)\log n)$.
