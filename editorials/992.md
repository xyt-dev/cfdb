Solution II

Let *p*<sub>*i*</sub> be the prefix sums of *a*. We're gonna introduce *f*<sub>*i*</sub> = *p*<sub>*i*</sub> - 2·*a*<sub>*i*</sub> and reformulate the queries using these new terms.

- Imagine we wanna change the value at *j* to *val*. Let δ = *val* - *a*<sub>*j*</sub>. Then *f*<sub>*j*</sub> will decrease by δ whereas *f*<sub>*i* > *j*</sub> will increase by δ.
- Imagine we wanna find the answer. Then it's sufficient to find any *i* satisfying *f*<sub>*i*</sub> = 0.

Split *f* into blocks of size *M*. Each block will be comprised of pairs (*f*<sub>*i*</sub>, *i*) sorted by *f*. At the same time we will maintain *overhead* array responsible for lazy additions to blocks. How does this help?

- Let *b* = *j* / *M*. The goal is to find the position of *j*, decrease its value and increase values for all *i* > *j* within this block. It can be done in a smart way in *O*(*M*) (actually, this can be represented as merging sorted vectors). You should also take care of the tail, i.e add δ to *overhead*<sub>*j* > *b*</sub> in *O*(*n* / *M*) time.
- We're asked to find such *i* that *f*<sub>*i*</sub> + *overhead*<sub>*j* / *M*</sub> = 0. All blocks are sorted, thus we can simply apply binary search in

It's easy to see that each group contains no more than two candidates for answer (since their sum is guaranteed to be greater than any of the remaining ones). This observation leads to an easy solution in
