## 2182A - New Year String

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The main observation you need to solve this problem is that an occurrence of 2025 can be turned into 2026 using only one operation. So, if the given string does not meet any of the conditions from the statement, you need only one operation to create an occurrence of 2026 (since $s$ contains 2025 if it is not a New Year string already).

Thus, the answer to the problem is either $0$ or $1$. To check if the string meets at least one of the conditions (which is exactly the case when the answer is zero), you can use built-in tools to search for an occurrence of a substring, like string::find in C++ or in in Python.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 n = int(input())
 s = input()
 if '2025' in s and not '2026' in s:
 print(1)
 else:
 print(0)
```

## 2182B - New Year Cake

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

The sizes of the cake layers grow exponentially: each subsequent layer is twice the size of the previous one. This means that the answer to the problem is not very large — it does not exceed $\log_2{\max(a, b)}$, which under the problem constraints is no more than $20$. This allows us to write a solution with runtime proportional to the answer.

For example, we can write a loop that maintains the current total size of the "even" and "odd" layers (by "even", we mean the top layer and all layers of the same type with it, and by "odd", we mean all the other layers). During each iteration, we can increase one of these total sizes by the current power of two and check that we have enough chocolate for the current sizes of the layers (depending on the implementation, two cases may be required here, as the top layer can be covered with chocolate of any type). As soon as we run out of chocolate, we can break the loop — in the next iteration, another layer will be added, and if we did not have enough chocolate for $k$ layers, we will not have enough for $(k+1)$ layers either.

Another solution is to iterate over the number of layers in the cake and check if there is enough chocolate for a cake of that many layers. Although this solution is slower, it is still fast enough for the problem constraints.

 
**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
    a, b = map(int, input().split())
    if a < b:
        a, b = b, a
    x, y = 0, 0
    ans = 0
    cur = 1
    while True:
        x, y = y + cur, x
        if x <= a and y <= b:
            ans += 1
            cur *= 2
        else:
            break
    print(ans)
```

## 2182C - Production of Snowmen

Idea: [Roms](<https://codeforces.com/profile/Roms>)

**Tutorial**

A straightforward solution that checks all triples runs in $O(n^4)$, which is too slow. Let's try to speed it up.

We can improve the complexity to $O(n^3)$ by checking only $n^2$ triples instead of $n^3$ triples. We will only check triples where $j = 1$. How can we account for triples where $j \ne 1$ in the answer? In fact, each of those triples will already be considered with $j = 1$: the triple $(i, j, k)$ is equivalent to the triple $(i - (j - 1), 1, k - (j - 1))$ — using them will yield the same snowmen, just in a different order. This allows us to only consider triples where $j = 1$, and then multiply the answer by $n$.

Unfortunately, this is still too slow. To achieve an even faster solution, we can notice that in the combination $(i, j, k)$, the value of $i$ can conflict with the value of $j$ (if for some snowman with such values the head is not smaller than the body), the value of $j$ can conflict with the value of $k$ (if for some snowman with such values the body is not smaller than the legs), however, the values of $i$ and $k$ do not impose restrictions on each other. Therefore, instead of checking triples $(i, j, k)$, we can find the number of suitable values for $i$ and suitable values for $k$ for a given value of $j$, and then multiply these two numbers.

Thus, the solution consists of the following steps:

- count how many values of $i$ are available for $j = 1$;
- count how many values of $k$ are available for $j = 1$;
- multiply these two numbers to get the number of suitable triples $(i, j, k)$ for $j = 1$;
- multiply the answer by $n$ to account for the fact that the parameter $j$ does not necessarily have to be equal to $1$.

This solution already works in $O(n^2)$, which is fast enough given the problem constraints.


**Solution (BledDest)**
```python
def good(x, y, n, k):
 ans = True
 for i in range(n):
 if x[i] <= y[(i + k) % n]:
 ans = False
 return ans

t = int(input())
for _ in range(t):
 n = int(input())
 a = list(map(int, input().split()))
 b = list(map(int, input().split()))
 c = list(map(int, input().split()))
 k1, k2 = 0, 0
 for i in range(n):
 if good(b, a, n, i):
 k1 += 1
 if good(c, b, n, i):
 k2 += 1
 print(k1 * k2 * n)
```

## 2182D - Christmas Tree Decoration

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Note that it is optimal for each person to hang decorations first from their own box, and only when it becomes empty, they should start hanging decorations from the $0$-th box.

Each person will hang at least $k = \lfloor\frac{s}{n}\rfloor$ decorations, where $s = \sum\limits_{i=0}^{n} a_i$ is the total number of decorations. Let $b_0, b_1, \dots, b_n$  represent the remaining number of decorations after $k$ full rounds. If $b_0 \lt 0$ (indicating someone did not have enough decorations for $k$ rounds) or if there is an $i \gt 0$ such that $b_i \gt 1$ (meaning there is a person who cannot hang all their decorations), then fair permutations are impossible.

During the last round, $s \bmod n$ decorations remain. Let $z$ denote the number of people with empty boxes, and $x = z - b_0$ be the number of people who will not hang decorations during this round. If $x \lt 0$, there are too many decorations in the $0$-th box, and $z$ people cannot hang them all. In this case, there are no fair permutations either. Otherwise, the number of fair permutations can be calculated using simple combinatorial formula: $\binom{z}{x} x! (n - x)!$. This involves selecting $x$ people out of $z$ who will not hang decorations (placing them at the end of the permutation) and arranging their order, as well as ordering the remaining $(n-x)$ people who will hang the decorations.

 
**Solution (Neon)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
const int N = 55;
const int MOD = 998244353;
 
int mul(int x, int y) {
  return x * 1LL * y % MOD;
}
 
int binpow(int x, int y) {
  int z = 1;
  while (y > 0) {
    if (y & 1) z = mul(z, x);
    x = mul(x, x);
    y >>= 1;
  }
  return z;
}
 
int main() {
  vector<int> f(N, 1);
  for (int i = 1; i < N; ++i)
    f[i] = (f[i - 1] * 1LL * i) % MOD;
 
  int t;
  cin >> t;
  while (t--) {
    int n;
    cin >> n;
    vector<int> a(n + 1);
    for (int &x : a) cin >> x;
    int k = accumulate(a.begin(), a.end(), 0) / n;
    int z = 0, bad = 0;
    for (int i = 1; i <= n; ++i) {
      int x = min(a[i], k);
      a[i] -= x;
      a[0] -= k - x;
      z += a[i] == 0;
      bad |= a[i] > 1 || a[0] < 0;
    }
    bad |= a[0] > z;
    int ans = bad ? 0 : f[z];
    if (!bad) {
      ans = mul(ans, f[n - z + a[0]]);
      ans = mul(ans, binpow(f[a[0]], MOD - 2));
    }
    cout << ans << '\n';
  }
}
```

## 2182E - New Year's Gifts

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Let's reformulate the problem a bit: we'll immediately spend $\sum\limits_{i=1}^{n}$ coins on gifts for each friend. Now, we can make the $i$-th friend happy if we use some box $j$ with a beauty $a_j \ge x_i$ or if we pay extra $z_i - y_i$ coins.

Let's say we put some gifts in boxes, and now we want to pay extra for some gifts. Obviously, to do this, we will sort the remaining friends in ascending order of the values of $z_i - y_i$ and take some prefix of friends. From here, we can see that for the box $j$, we want to put a gift $i$ such that $x_i \le a_j$, and $z_i - y_i$ is as big as possible, so that you have to pay less extra for the remaining gifts.

Therefore, we can solve the problem using the following greedy algorithm: let's go through the beauty $j$ from $1$ to $m$ and maintain a set (sorted by value $z_i - y_i$) of unpacked gifts with $x_i \le j$. Then for a box with beauty $j$, we can take a gift from the set with the maximum value of $z_i - y_i$. After such a pass, it is impossible to match any box with any gift, which means we will have to pay extra for several gifts (the cheapest ones) that are left in the set, as long as the value of $k$ allows it.


**Solution (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

void solve() {
 int n, m;
 long long k;
 cin >> n >> m >> k;
 vector<vector<int>> ev(m);
 for (int i = 0; i < m; ++i) {
 int x; cin >> x;
 ev[x - 1].push_back(-1);
 }
 for (int i = 0; i < n; ++i) {
 int x, y, z;
 cin >> x >> y >> z;
 ev[x - 1].push_back(z - y);
 k -= y;
 }
 int ans = 0;
 multiset<int> s;
 for (int i = 0; i < m; ++i) {
 reverse(ev[i].begin(), ev[i].end());
 for (int x : ev[i]) {
 if (x == -1) {
 if (!s.empty()) {
 s.erase(--s.end());
 ++ans;
 }
 } else {
 s.insert(x);
 }
 }
 }
 while (!s.empty() && *s.begin() <= k) {
 k -= *s.begin();
 s.erase(s.begin());
 ++ans;
 }
 cout << ans << '\n';
}

int main() {
 ios::sync_with_stdio(false); cin.tie(0);
 int t;
 cin >> t;
 while (t--) solve();
}
```

## 2182F2 - Christmas Reindeer (hard version)

In this editorial, we wiil refer to a deer with strength $2^i$ as a deer of type $i$ for convenience.

The first observation needed to solve the problem is as follows: if we replace a deer of type $i$, which contributes a non-zero amount to the carrying capacity, with any number of deer of lower types, the total carrying capacity will decrease. We will prove this: suppose there were $k$ other deer before this one in sorted order, and it is the last deer of type $i$. Then its contribution is $\frac{2^i}{2^k}$. If we replace it with any number of deer of lower types, the contribution of the strongest of these deers will be at most $\frac{2^{i-1}}{2^k}$, the contribution of the next one will be at most $\frac{2^{i-1}}{2^{k+1}}$, the contribution of the next one will be at most $\frac{2^{i-1}}{2^{k+2}}$, and so on. If we sum the maximum possible contributions of all subsequent deer, we get $(\frac{2^i}{2^k} - 1)$, which is less than the contribution of the deer of type $i$. Let's remember this observation; we will need it soon.

Now let's try to understand how to achieve a carrying capacity of exactly $x$, ensuring that there are no deers with zero contribution. This will help us later understand when the carrying capacity is at least $x$.

Consider the highest non-zero bit of $x$; let this be the bit corresponding to $2^i$. Also, consider the strongest deer in the group; let its type be $j$:

- If $j \lt i$, then we cannot achieve a total carrying capacity of $2^i$ with deer of types $j$ and lower, so the total carrying capacity will definitely be less than $x$;
- If $j \gt i$, then the deer of type $j$ definitely provides a carrying capacity strictly greater than $x$;
- If $j = i$, then we can subtract $2^i$ from $x$, remember that we had one deer of type $i$, and move to the next bit.

For the next bit (let's say it corresponds to $2^{i'}$), the situation is the same, but since the contribution of the next deer is half as much, instead of comparing with $i'$, we need to compare with $(i'+1)$. For the bit after that (let's say it corresponds to $2^{i"}$), we need to compare with $(i"+2)$, and so on. Note that since $i'+1 \le i$, each subsequent deer will definitely not be stronger than the previous one.

Thus, we can determine how many deer of each type are needed so that the total carrying capacity is exactly $x$, and no deer contributes zero. Let's say we obtained an array $[r_0, r_1, r_2, \dots, r_{60}]$, where $r_i$ is the required number of deer of type $i$.

Now, let's understand how to check that the carrying capacity of a group of deer, where there are $[k_0, k_1, k_2, \dots, k_{60}]$ deer of types $0, 1, 2, \dots, 60$, is at least $x$. We find the last position where $r_i \ne k_i$ (if there is none, then the carrying capacity equals $x$). If in this position $r_i \gt k_i$, then we are lacking a deer of this type, and the carrying capacity is less than $x$. If $r_i \lt k_i$, then this "extra" deer covers the remaining carrying capacity, and the carrying capacity of the group is at least $x$.

Now we can solve the problem. We will maintain an array $[f_0, f_1, \dots, f_{60}]$, where $f_i$ is the number of deer of type $i$. Queries of the first and second types are handled trivially. To process a query of the third type, let's iterate over how many of the last elements in the arrays $r$ (the required number of deer of each type) and $k$ (the number of deer of each type in the group we are building) match. Let's say $r_i \ne k_i$, but all subsequent values match; we will count the number of ways to assemble a group of deer such that the array $k$ satisfies this condition:

- for deer of all types $j \gt i$, we definitely know their counts, so the number of ways to choose them is $\prod\limits_{j=i+1}^{60} {{f_j}\choose{r_j}}$;
- for deer of all types $j \lt i$, we are fine with any number, so the number of ways to choose them is $2^{f_0 + f_1 + \dots + f_{i-1}}$;
- for deers of type $i$, their count must be more than $r_i$, so the number of ways to choose them is $\sum\limits_{j=r_i+1}^{f_i} {{f_i}\choose{j}}$.

The first and second values can be recalculated in $O(1)$ for each $i$. But what about the third value? Let's use the fact that $\sum\limits_{k=0}^{n} {{n}\choose{k}} = 2^n$, and transform it as follows (assuming $r_i \le f_i$):

$$\sum\limits_{j=r_i+1}^{f_i} {{f_i}\choose{j}} = 2^{f_i} - \sum\limits_{j=0}^{r_i} {{f_i}\choose{j}}$$

This value can now be computed in $O(r_i)$, and since the sum $r_i$ does not exceed the number of bits in $x$, we can process the query in $O(\log x)$. Don't forget that the arrays $r$ and $k$ may not necessarily differ, so we also need to add the number of ways to choose a group of deer with the specified array of counts (but this is calculated trivially).

 
**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>
 
using namespace std;
 
const int MOD = 998244353;
const int LOGN = 61;
 
int add(int x, int y)
{
    x += y;
    if(x >= MOD) x -= MOD;
    if(x < 0) x += MOD;
    return x;
}
 
int sub(int x, int y)
{
    return add(x, -y);
}
 
int mul(int x, int y)
{
    return (x * 1ll * y) % MOD;
}   
 
int binpow(int x, int y)
{
    int z = 1;
    while(y > 0)
    {
        if(y % 2 == 1) z = mul(z, x);
        x = mul(x, x);
        y /= 2;
    }
    return z;
}                   
 
vector<int> get_required(long long x)
{
    vector<int> ans(LOGN);
    int cnt = 0;
    for(int i = LOGN - 1; i >= 0; i--)
    {
        if((x >> i) & 1)
        {
            ans[i + cnt]++;
            cnt++;
        }
    }
    return ans;
}
 
void solve()
{
    int n, m;
    cin >> n >> m;        
    vector<int> freq(LOGN);
    for(int i = 0; i < n; i++)
    {
        int x;
        cin >> x;
        freq[x]++;
    }
    
    int max_n = n + m + 111;
 
    vector<int> fact(max_n, 1);
    for(int i = 1; i < max_n; i++)
        fact[i] = mul(fact[i - 1], i);
    vector<int> inv_fact(max_n);
    for(int i = 0; i < max_n; i++)
        inv_fact[i] = binpow(fact[i], MOD - 2);
    vector<int> pow2(max_n, 1);
    for(int i = 1; i < max_n; i++)
        pow2[i] = mul(pow2[i - 1], 2);
 
    auto choose = [&](int x, int y)
    {           
        if(x < y || x < 0 || y < 0) return 0;
        return mul(fact[x], mul(inv_fact[y], inv_fact[x - y]));
    };
 
    auto sum_greater = [&](int x, int y)
    {
        if(y >= x) return 0;
        int ans = pow2[x];
        for(int i = 0; i <= y; i++)
            ans = sub(ans, choose(x, i));
        return ans;
    };
 
    for(int i = 0; i < m; i++)
    {
        int t;
        long long x;
        cin >> t >> x;
        if(t == 1)
            freq[x]++;
        else if(t == 2)
            freq[x]--;
        else
        {
            auto req = get_required(x);
            int ans = 0;
            int cur = 1;
            int cnt_less = 0;
            for(int i = 0; i < LOGN; i++) cnt_less += freq[i];
            for(int i = LOGN - 1; i >= 0; i--)
            {
                cnt_less -= freq[i];
                ans = add(ans, mul(cur, mul(sum_greater(freq[i], req[i]), pow2[cnt_less])));
                cur = mul(cur, choose(freq[i], req[i]));
            }
            ans = add(ans, cur);
            cout << ans << "\n";
        }
    }
}
 
int main()
{
    ios_base::sync_with_stdio(0);
    cin.tie(0);    
    int t = 1;
    //cin >> t;
    for(int i = 0; i < t; i++) solve();
}
```

## 2182G - Short Garland

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The procedure in the problem statement describes a depth-first search, where a vertex is written down upon entry. Accordingly, the choice we are allowed to make is the order of traversing the children of each vertex.

Let's think about the condition that the distance must not exceed $k$. It follows that when we have traversed all vertices in the subtree of one child of vertex $v$, and there are still other unvisited children, the last visited vertex in the subtree must be at a distance of no more than $k-1$ from $v$.

Let's try to fit this into dynamic programming. Let $\mathit{dp}[v][k]$ store the number of ways to traverse the subtree of vertex $v$ such that the last visited vertex is at a distance exactly $k$ from $v$. This dynamic programming can be computed as follows. Fix the last visited child of the vertex and the depth of the last vertex in its subtree. Then, the other children can be visited in any order, as long as the condition that the depth does not exceed $k-1$ is satisfied. That is, for each child, we need to sum $\mathit{dp}[u][t]$ for all $t \lt k$, multiply the obtained sums, and multiply by the factorial of the number of remaining children to fix their order.

In fact, in such dynamic programming, it is often more convenient to store not the dp array itself, but its prefix sum directly. Thus, we can say that $\mathit{dp}[v][k]$ will store the number of ways to traverse the subtree of vertex $v$ such that the last visited vertex is at a distance no more than $k$ from $v$. Then, for recalculation, it is enough to take the value $\mathit{dp}[u][k-1]$. Thus, the transitions in the dynamic programming look as follows: $\mathit{dp}[v][t+1] = \sum\limits_{u \in g_v}\mathit{dp}[u][t] \cdot (|g_v|-1)! \cdot \mathit{prod}_u$, where $\mathit{prod}_u = \prod\limits_{w \in g_v; w \neq u}\mathit{dp}[w][k-1]$.

We have obtained a polynomial solution to the problem, but so far it is too slow. Since the depth (the second state of the dynamic programming) is of the order of $O(n)$, the complexity in the most optimal implementation will be $O(n^2)$.

The first difficulty is obtaining the product $\mathit{dp}[u][k-1]$ for all children of $v$, except for the current one. Of course, we can precompute the product for all children and then divide by the value for the current child to remove its contribution to the product. The modulo in the problem is prime, so dividing is not too difficult; however, there is a problem with zero values. When multiplying by zero, all information about the other factors is lost, and it cannot be retrieved. There are two popular ways to solve this problem. The first solution is to compute the product on the prefix and on the suffix of the children. To obtain the product without one factor, we multiply the prefix up to it and the suffix after it. The second solution is to compute the product without zeros and also keep track of the number of zeros. If there are at least two zeros, the product will always be zero, regardless of which factor we remove. With one zero, we can carefully consider whether we are removing a zero or a non-zero value.

Now, regarding the optimization of the dynamic programming itself. It is quite natural to try to optimize it using small-to-large. The contributions of the children, except for the heaviest one, are calculated in the same way. For them, we can iterate through all depths and add them with the corresponding coefficients. To avoid adding the contribution of the heaviest child, we can multiply the values of its dynamic programming by a correct coefficient and make this an initial dp for the vertex $v$.

Unfortunately, we cannot afford to iterate over all values for the heaviest child. Let's perform the multiplication lazily instead. In addition to the dynamic programming array, we will also store two values: $\mathit{ml}$ — what to multiply all elements of the array by and $\mathit{ad}$ — what to add to them. Then, the heaviest child can be recalculated by multiplying both $\mathit{ml}$ and $\mathit{ad}$ by the necessary coefficient.

To add values for the other children, we need to divide them by $\mathit{ml}$ in advance. This means that $\mathit{ml}$ should not be zero, which could potentially happen when recalculating the heaviest child. Let's solve this problem. If we need to multiply $\mathit{ml}$ by zero, we can set all values of dp to zero with a loop and only leave as many values as there are in the second largest child. Then the heaviest child is still the heaviest, but the complexity of small-to-large is preserved.

The value of $\mathit{ad}$ is needed for adding the other children. Since we maintain the prefix sum of the dynamic programming, we need to update all dp values for $v$ for each child. That would break the small-to-large complexity if performed directly. However, all values beyond the depth of the child change by the same value. Therefore, we can lazily add this number to the variable $\mathit{ad}$.

This variation of small-to-large, where the number of dynamic programming values is limited by the height of the vertex, works in $O(n)$. In my implementation, the asymptotic complexity turned out to be $O(n \log A)$ because it is necessary to compute the inverse element for $\mathit{ml}$ at each vertex.


**Solution (awoo)**

 return dp[max(0, int(dp.size()) - k - 1)];

 }

 pr[i + 1] = mul(pr[i], val[i]);
 su[val.size() - i - 1] = mul(su[val.size() - i], val[val.size() - i - 1]);
 }

 int cur = mul(fact[g[v].size() - 1], mul(pr[i], su[i + 1]));
 if (cur == 0){
 int mx = 1;
 for (int u : g[v]) mx = max(mx, int(dp[u].dp.size()));
 dp[v].dp.assign(mx, 0);
 dp[v].ml = 1, dp[v].ad = 0;
 }
 else{
 dp[v].ml = mul(dp[v].ml, cur);
 dp[v].ad = mul(dp[v].ad, cur);
 }
 }

 int rev = binpow(dp[v].ml, MOD - 2);
 forn(i, g[v].size()){
 int u = g[v][i];
 if (u == bst) continue;
