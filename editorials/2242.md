## 2242A - Bigrams

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Each bigram can consist either of two identical letters (type $1$) or of two different letters (type $2$). So let us understand when it is possible to build a string with two identical bigrams from the given cards, depending on their type.

For two bigrams of type $1$, at first glance we need $4$ identical symbols, two for each bigram. However, if we place $3$ identical symbols next to each other, the middle one will belong to both bigrams at once. Therefore, for two identical bigrams of type $1$, it is enough that at least one of the $c_i$ is greater than $2$. If each type has at most $2$ cards, then it is impossible to make two identical bigrams of type $1$.

If we want to obtain two identical bigrams of type $2$, then they cannot overlap. Therefore, we need $2$ cards with two different letters. So there must exist two indices $i$ and $j$ such that $c_i \ge 2$, $c_j \ge 2$, and $i \ne j$.

To check these conditions conveniently, we can sort the array $c$ in non-increasing order; then we only need to look at $c_1$ and $c_2$ (if it exists). Alternatively, we can check that the maximum in the array is at most $2$, and the number of occurrences of the number $2$ is at most $1$.


**Solution (BledDest)**
```python
t = int(input())
for i in range(t):
 k = int(input())
 a = list(map(int, input().split()))
 if max(a) > 2 or a.count(2) > 1:
 print('YES')
 else:
 print('NO')
```

## 2242B - Predominant Frequency Division

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)
 
**Tutorial**

Let the cut positions be $x$ and $y$. Then the array is split into three non-empty parts:

$$ [1 \dots x], \quad [x + 1 \dots y], \quad [y + 1 \dots n], $$

where $1 \le x \lt y \le n - 1$.

Let us consider the conditions for each part.

For the first part, the number of elements greater than $1$ must not exceed half of its length. Since the array elements are only $1$, $2$, and $3$, this is equivalent to the condition $ \#1 \ge \#2 + \#3$.

Let us assign a weight to each element:

$$ w_1(a_i) = \begin{cases} +1, & a_i = 1,\\ -1, & a_i = 2 \text{ or } a_i = 3. \end{cases} $$

Then the first part is good if and only if the sum of the weights $w_1$ on it is non-negative.

For the second part, the number of elements greater than $2$ must not exceed half of its length. That is, the number of threes must not exceed the number of ones and twos: $\#1 + \#2 \ge \#3$.

Similarly, define the weights:

$$ w_2(a_i) = \begin{cases} +1, & a_i = 1 \text{ or } a_i = 2,\\ -1, & a_i = 3. \end{cases} $$

The second part is good if and only if the sum of the weights $w_2$ on it is non-negative.

For the third part, the condition is always satisfied, because there are no elements greater than $3$ in the array. Therefore, the third part only needs to be non-empty.

Now let us compute prefix sums:

$$ pref_1[i] = \sum_{k=1}^{i} w_1(a_k), $$

$$ pref_2[i] = \sum_{k=1}^{i} w_2(a_k). $$

Then the first segment $[1 \dots x]$ is good if:

$$ pref_1[x] \ge 0. $$

The second segment $[x+1 \dots y]$ is good if:

$$ pref_2[y] - pref_2[x] \ge 0. $$

That is:

$$ pref_2[x] \le pref_2[y]. $$

So, for each possible $y$, we need to know whether there exists an $x \lt y$ such that:

$$ pref_1[x] \ge 0 $$

and

$$ pref_2[x] \le pref_2[y]. $$

We will scan $y$ from left to right. Before checking the current $y$, we add position $x = y - 1$ to consideration if the first part $[1 \dots x]$ is good. Among all such suitable $x$, we store the minimum value of $pref_2[x]$.

If at some moment

$$ \min (pref_2[x]) \le pref_2[y], $$

then suitable cuts exist.

For each test case, we compute the prefix sums once and then make one pass over the array.

The total complexity is $O(n)$.

 
**Solution (FelixArg)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;

const int INF = 1'000'000'007;
 
void solve() {
	int n;
	cin >> n;
	vector<int> a(n);
	for (int i = 0; i < n; i++){
		cin >> a[i];
	}

	vector<int> pref1(n + 1);
	vector<int> pref2(n + 1);
	for (int i = 0; i < n; i++){
		pref1[i + 1] = pref1[i] + (a[i] == 1 ? 1 : -1);
		pref2[i + 1] = pref2[i] + (a[i] == 3 ? -1 : 1);
	}

	int mn = INF;
	for (int i = 1; i < n; i++){
		if (pref2[i] - mn >= 0){
			cout << "YES\n";
			return;
		}
		if (pref1[i] >= 0){
			mn = min(mn, pref2[i]);
		}
	}

	cout << "NO\n";
}

 
signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);
 
	int tests = 1;
	cin >> tests;
	while(tests--){
		solve();
	}
 
#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
		chrono::high_resolution_clock::now()
			- _clock_start).count() << "ms." << endl;
#endif
	return 0;
```

## 2242C - Unstable Elements

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Consider blocks of equal numbers in the given array. Each operation either decreases or increases the size of every block by $1$ (let these be operations of type A and B, respectively). At first glance, this means that the operations are inverses of each other, but this is not quite true.

Indeed, if we first increase the size of all blocks and then decrease it, nothing changes. But if we do these actions in the opposite order, something may change: if some block is completely destroyed, it will not come back after performing operations of type B. Therefore, the sequence of operations can be viewed as follows: first we perform operations of type A some number of times, and then — operations of type B.

Suppose we want to perform some number of operations of type A, say $x$, and then check whether it is possible to make the array size equal to $k$ using operations of type B. Blocks whose sizes are less than or equal to $x$ are completely destroyed, and blocks whose sizes are greater than $x$ decrease by exactly $x$ (note that since the array is sorted, when a block is destroyed, its neighbors never merge into one block). Let the total size of the destroyed blocks be $d$, and let the number of remaining blocks be $q$. Then after performing $x$ operations of type A, the number of remaining elements will be $n - d - x \cdot q$, and each next operation of type B will increase this number by $q$.

So, we can obtain an array of size $k$ by starting with exactly $x$ operations of type A if and only if the following two conditions hold: $n - d - x \cdot q \le k$ and $(k - (n - d - x \cdot q)) \bmod q = 0$. But we are interested in the number of different arrays of size $k$ that we can obtain. Some of these ways will produce the same arrays, so we need to somehow avoid counting duplicates.

Fortunately, there is a simple way to solve this problem. Two arrays of the same length obtained by such sequences of operations will be equal if and only if we remove the same blocks as a result of operations of type A (this follows from the fact that the size of each remaining block changes by the same amount, so the size of the resulting array and the set of remaining blocks uniquely determine the number of elements in each block). Therefore, let us ignore those $x$ for which $(x+1)$ would remove the same blocks (because these two numbers of operations of type A will ultimately give the same set of blocks, and if both conditions $n - d - x \cdot q \le k$ and $(k - (n - d - x \cdot q)) \bmod q = 0$ hold for $x$, then they also hold for $(x+1)$). In other words, we will check only those $x$ for which there exists at least one block of size exactly $(x+1)$ — when $x$ increases, this block will be removed. This way we eliminate duplicate counting of the same arrays.

Depending on the implementation of this solution, the complexity will be either $O(n \log n)$ or $O(n)$.


**Solution (BledDest)**
```cpp
#include <bits/stdc++.h>

using namespace std;

void solve()
{
 int n, k;
 cin >> n >> k;

 vector<int> a(n);
 for (int i = 0; i < n; i++)
 {
 cin >> a[i];
 }

 vector<int> lens;

 int cur = 1;
 for (int i = 1; i < n; i++)
 if (a[i] != a[i - 1])
 {
 lens.push_back(cur);
 cur = 1;
 }
 else cur++;
 lens.push_back(cur);
 sort(lens.begin(), lens.end());

 int m = (int)lens.size();
 int d = 0;

 int ans = 0;
 int i = 0;
 while(i < m)
 {
 int len = lens[i];
 int x = len - 1;
 int q = m - i;
 int curLen = n - d - x * q;
 if (curLen <= k && (k - curLen) % q == 0)
 ans++;

 int j = i;
 while (j < m && lens[j] == len)
 j++;
 d += (j - i) * lens[i];
 i = j;
 }

 cout << ans << '\n';
}

int main()
{
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 int t;
 cin >> t;
 for(int i = 0; i < t; i++)
 solve();
 return 0;
}
```

## 2242D - Two Digit Strings

Idea: [Roms](<https://codeforces.com/profile/Roms>)
 
**Tutorial**

This problem has many different solutions. In my opinion, the most elegant one is to consider prefix sums modulo $10$.

Let us build two arrays $ps$ (of size $n+1$) and $pt$ (of size $m+1$), such that $ps_i$ is the sum of the first $i$ digits of the string $s$ modulo $10$ (similarly, $pt$ is defined for the string $t$). For example, for $57246$ this array will be $[0, 5, 2, 4, 8, 4]$.

Let us see how the operations described in the statement affect these arrays. Merging elements $i$ and $(i+1)$ means that we remove the sum that includes element $i$ but does not include element $(i+1)$ — that is, one arbitrary element is removed from the prefix sums array (except for the border elements).

In addition, there is a one-to-one correspondence between prefix sums arrays and strings: we defined how to build the prefix sums array from a string; similarly, we can define how to build a string from a valid prefix sums array (starting with $0$): each element of the string is the difference of two neighboring prefix sums modulo $10$. This means that the strings are equal if and only if their prefix sums are equal, and we need to make the prefix sums equal in the minimum number of operations.

Now the problem has turned into the following: two arrays are given, and in one operation we can delete one element from one of the arrays (except for the border elements). We need to make them equal, leaving as many elements as possible.

If the last element of $ps$ differs from the last element of $pt$, then there is no answer (the same is true for the starting elements, but we know for sure that they are both $0$). Otherwise, an answer exists (we can always delete all elements except the border ones). Let us keep as many undeleted elements as possible; for this, we can find the longest common subsequence (LCS) of these two arrays (formally, we want to find the longest common subsequence of the arrays without the border elements, but it can be proved that they always simply increase the answer by $2$ regardless of the other elements).

How do we find the LCS of two arrays? This is a well-known problem that can be solved with dynamic programming of the form $dp_{i,j}$ — the LCS of the first $i$ elements of the first array and the first $j$ elements of the second array. This DP has three types of transitions:

- skip an element in the first array ($dp_{i,j} \rightarrow dp_{i+1,j}$);
- skip an element in the second array ($dp_{i,j} \rightarrow dp_{i,j+1}$);
- if the current elements in the arrays are equal, take them into the answer ($dp_{i,j} \rightarrow dp_{i+1,j+1}$, the DP value increases by $1$).

Thus, we obtain a solution in $O(|s| \cdot |t|)$.

 
**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int MOD = 998244353;

void upd(int& x, int y)
{
    if(x < y) x = y;
}

void solve()
{
    string s, t;
    cin >> s >> t;
    int n = s.size();
    int m = t.size();
    vector<int> ps(n + 1), pt(m + 1);
    for(int i = 0; i < n; i++)
        ps[i + 1] = (ps[i] + (s[i] - '0')) % 10;
    for(int i = 0; i < m; i++)
        pt[i + 1] = (pt[i] + (t[i] - '0')) % 10;
    n++;
    m++;
    if(ps.back() != pt.back())
    {
        cout << -1 << "\n";
        return;
    }

    vector<vector<int>> dp(n + 1, vector<int>(m + 1));
    for(int i = 0; i <= n; i++)
        for(int j = 0; j <= m; j++)
        {
            if(i < n) upd(dp[i + 1][j], dp[i][j]);
            if(j < m) upd(dp[i][j + 1], dp[i][j]);
            if(i < n && j < m && ps[i] == pt[j]) upd(dp[i + 1][j + 1], dp[i][j] + 1);
        }
    cout << dp[n][m] - 1 << "\n";
}

int main()
{
    int t;
    cin >> t;
    for(int i = 0; i < t; i++)
        solve();
    return 0;
}
```

## 2242E - Product of Closures

Idea: [adedalic](<https://codeforces.com/profile/adedalic>)

**Tutorial**

Let $k = \lfloor \log_{2}{r} \rfloor$. Then $2^k$ is the largest power of two not exceeding $r$. We consider several cases.

Case 1: $l \ge 2^k$. In this case, all possible integers have length $k_1 = k + 1$ in binary form, which means that all their closures $C(x)$ have a period of $k_1$. Consequently, all products also have a period of $k_1$. Therefore, we can "ignore" the infinite length of the closures and simply find a pair of numbers with the minimal bitwise AND.

To do this, we find the most significant bit (MSB) where $l$ and $r$ differ. Let its index be $d$ (0-indexing, counting from the least significant bit). We can then take $x = l$, and set $y$ to be the number obtained from $l$ by flipping the $d$-th bit and zeroing all other bits. Formally, $y = l - (l \bmod 2^d) + 2^d$. It is easy to show that $l \lt y \le r$. This pair gives the minimal AND because all lower $d+1$ bits are zeroed out.

Case 2: $2^{k - 1} \lt l \lt 2^k$. In this case, it is optimal to take the pair $x = l$ and $y = 2^k$.

Case 3: $l \le 2^{k - 1}$. In this case, it is optimal to take the pair $x = 2^{k - 1}$ and $y = 2^k$.

For the proof of Cases 2 and 3, we introduce further notation. Let $s^c$ denote the string $s$ repeated $c$ times, and let $s^*$ denote an infinite repetition.

Consider two integers $x$ and $y$ with lengths $a$ and $b$, respectively. Since the first symbols of both $x$ and $y$ are $1$, these ones will meet every $\text{lcm}(a, b)$ steps, guaranteeing a '1' in the product of closures. This means that the minimum possible product must have the form $(1\underbrace{0 \ldots 0}_{\mathrm{lcm}(a, b) - 1})^*$ or $(1(0)^{\mathrm{lcm}(a, b) - 1})^*$.

Note that such a string can indeed be achieved by choosing $x = 2^{a-1}$ and $y = 2^{b-1}$.

Next, let's look at the segment of integers $[1, r]$. The lengths of all integers in this segment lie within the interval $[1, k_1]$, meaning that the maximum possible $\text{lcm}$ we can achieve is $\mathrm{lcm}(k_1 - 1, k_1) = (k_1 - 1) \cdot k_1$. Thus, if $l \le 2^{k - 1}$, the pair $x = 2^{k - 1}$ and $y = 2^k$ is guaranteed to yield the minimum possible answer.

However, if $2^{k - 1} \lt l \lt 2^k$, all numbers will be of length $k_1$ or $k_1 - 1$. First, we observe that the pair $x = 2^{k} - 1$ and $y = 2^k$ yields an answer no worse than any pair where $x \ge 2^k$. Indeed, the AND of two numbers of length $k_1$ is no less than $(1(0)^k)$, meaning the resulting product will be no less than $(1(0)^{k})^*$.

Meanwhile, $C(2^{k} - 1) \mathop{\&} C(2^k)$ exactly equals $(1(0)^{k})^*$. Thus, it is never advantageous to choose two numbers of length $k_1$.

Note that choosing two numbers of length $k_1 - 1$ is also not optimal because replacing one of them with $2^k$ results in a strictly smaller answer.

What remains is to look at the product of closures of a number $x$ of length $k_1 - 1$ and a number $y$ of length $k_1$. First, taking $y = 2^k$ is always advantageous because all possible bits in it are zeros.

Second, let's see which bits from the closure $C(x) = (x_0 x_1 \dots x_{k-1})^*$ correspond to a '1' in $C(2^k)$: the ones in it will be located at positions $0$, $k_1$, $2k_1$, $3k_1$, etc.

However:

- at position $0$ in $C(x)$ is $x_0$;
- at position $k_1$ in $C(x)$ is $x_1$;
- at position $2k_1$ in $C(x)$ is $x_2$;
- at position $3k_1$ in $C(x)$ is $x_3$;
- and so on.

Thus, $C(x) \mathop{\&} C(2^k)$ simply equals $C(x)$, where a block of $k$ zeros has been inserted between every pair of digits. Formally, we get $(x_0 (0)^{k} x_1 (0)^{k} x_2 (0)^{k} \dots x_{k-1} (0)^{k})^*$.

In other words, the smaller $x$ is, the smaller the product. Therefore, it is most advantageous to take $x = l$ (and $y = 2^k$).

## 2242F - Summer Vacation

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)
 
**Tutorial**

Let $F_k$ be the answer (that is, the number of dollars Monocarp will have left) for a suffix of length $k$.

Notice that during the computation of the answer, the number of dollars Monocarp has never becomes greater than $2n$. Indeed, if the current value is at least $a_i$, then it will decrease. Otherwise, we add $a_i$, so the new value will be less than $2a_i \le 2n$.

We will process the array from right to left and maintain the answer for the already processed suffix. Let $\texttt{dp}[j]$ denote the number of dollars after processing the current suffix if the number of dollars before it starts (the starting amount of dollars) was $j$.

Initially, the suffix is empty, so

$$ \texttt{dp}[j] = j $$

Now add a new element $x$ on the left. Let the new array be $\texttt{new}\_\texttt{dp}$. If the number of dollars before element $x$ is $j$, then after processing $x$ it becomes:

$$ j + x, \quad \text{if } j \lt x, $$

and

$$ j - x, \quad \text{if } j \ge x. $$

Therefore,

$$ \texttt{new}\_\texttt{dp}[j] = \begin{cases} \texttt{dp}[j + x], & j \lt x, \\ \texttt{dp}[j - x], & j \ge x. \end{cases} $$

So the new array $\texttt{dp}$ is obtained from the old one in a very simple way:

$$ \texttt{new}\_\texttt{dp} =

\texttt{dp}[x \ldots 2x - 1] + \texttt{dp}[0 \ldots 2n - x]. $$

For example, if

$$ \texttt{dp} = [\color{green}{4}, \color{green}{3}, \color{green}{4}, \color{green}{5}, \color{green}{6}, \color{green}{7}, \color{green}{8}, \color{green}{3}, \color{blue}{4}, \color{blue}{5}, \color{blue}{0}, \color{blue}{1}, \color{orange}{2}, \color{orange}{3}, \color{orange}{4}, \color{orange}{5}, \color{red}{6}, \color{red}{7}, \color{red}{8}, \color{red}{9}] $$

and $x = 8$, then the new array will be

$$ [\color{blue}{4}, \color{blue}{5}, \color{blue}{0}, \color{blue}{1}, \color{orange}{2}, \color{orange}{3}, \color{orange}{4}, \color{orange}{5}, \color{green}{4}, \color{green}{3}, \color{green}{4}, \color{green}{5}, \color{green}{6}, \color{green}{7}, \color{green}{8}, \color{green}{3}, \color{blue}{4}, \color{blue}{5}, \color{blue}{0}, \color{blue}{1}]. $$

After adding another element on the left, the answer for the current suffix is $\texttt{dp}[0]$, because the initial number of dollars is $0$.

It remains to learn how to quickly perform the operation

$$ \texttt{dp} \leftarrow \texttt{dp}[x \ldots 2x - 1] + \texttt{dp}[0 \ldots 2n - x]. $$

For this, we can store the array $\texttt{dp}$ in a persistent implicit treap. Then we can obtain the required subarrays in $O(\log n)$ using split operations and concatenate them using merge.

Since for each array element we perform a constant number of split/merge operations, the total complexity is $O(n \log n)$ in time and memory.

Advice on coding a persistent treap:

- we sometimes need to merge different versions of the same treap, so the nodes can be duplicated. This means you cannot store the node priorities explicitly, because treap requires them to be pairwise distinct. Instead of priorities, you should use subtree sizes, and when merging a tree $l$ of size $sz_l$ with a tree $r$ of size $sz_r$, the root of $l$ should become the root of the result with probability $\frac{sz_l}{sz_l + sz_r}$;
- after each operation, only $O(n)$ nodes are needed, since we only need a treap of size $O(n)$, but we have many unreachable nodes from previous operations. You should clear and rebuild the treap from scratch every several thousand operations to reduce memory consumption.

 
**Solution (FelixArg)**
```cpp
#include <bits/stdc++.h>

using namespace std;

mt19937_64 rng(chrono::high_resolution_clock::now().time_since_epoch().count());

const int MX = 200000;
const int REBUILD_EVERY = 5000;

struct item {
    int value, cnt;
    int l, r;

    item(): value(0), cnt(0), l(0), r(0) {}
    item(int x): value(x), cnt(1), l(0), r(0) {}
};

vector<item> treap(1);

int copy(int v) {
    treap.push_back(treap[v]);
    return int(treap.size()) - 1;
}

int cnt(int v) {
    return v ? treap[v].cnt : 0;
}

void upd_cnt(int v) {
    if (v) {
        treap[v].cnt = cnt(treap[v].l) + cnt(treap[v].r) + 1;
    }
}

int merge(int l, int r) {
    if (!l || !r) {
        return l ? l : r;
    }

    int rang = rng() % (cnt(l) + cnt(r));

    if (rang < cnt(l)) {
        int res = copy(l);
        treap[res].r = merge(treap[res].r, r);
        upd_cnt(res);
        return res;
    } else {
        int res = copy(r);
        treap[res].l = merge(l, treap[res].l);
        upd_cnt(res);
        return res;
    }
}

int find_first(int v) {
    if (!treap[v].l) {
        return treap[v].value;
    } else {
        return find_first(treap[v].l);
    }
}

void dfs(int v) {
    if (!v) {
        return;
    }

    if (treap[v].l) {
        dfs(treap[v].l);
    }

    cout << treap[v].value << ' ';

    if (treap[v].r) {
        dfs(treap[v].r);
    }
}

pair<int, int> split(int t, int key, int add = 0) {
    if (!t) {
        return make_pair(0, 0);
    }

    t = copy(t);

    int cur_key = add + cnt(treap[t].l);

    if (key <= cur_key) {
        auto [l, r] = split(treap[t].l, key, add);
        treap[t].l = r;
        r = t;
        upd_cnt(t);
        return {l, r};
    } else {
        auto [l, r] = split(treap[t].r, key, add + 1 + cnt(treap[t].l));
        treap[t].r = l;
        l = t;
        upd_cnt(t);
        return {l, r};
    }
}

int change(int x, int it) {
    auto [l, r] = split(it, x, 0);
    auto [rl, rr] = split(r, x, 0);
    auto [l1, r1] = split(it, MX - x, 0);
    return merge(rl, l1);
}

void collect_values(int v, vector<int>& values) {
    if (!v) {
        return;
    }

    collect_values(treap[v].l, values);
    values.push_back(treap[v].value);
    collect_values(treap[v].r, values);
}

int build_balanced(const vector<int>& values, int l, int r) {
    if (l >= r) {
        return 0;
    }

    int m = (l + r) / 2;

    treap.emplace_back(values[m]);
    int v = int(treap.size()) - 1;

    treap[v].l = build_balanced(values, l, m);
    treap[v].r = build_balanced(values, m + 1, r);

    upd_cnt(v);
    return v;
}

int rebuild(int tr) {
    vector<int> values;
    values.reserve(cnt(tr));

    collect_values(tr, values);

    treap.clear();
    treap.emplace_back();

    return build_balanced(values, 0, int(values.size()));
}

void solve() {
    int n;
    cin >> n;

    vector<int> a(n);
    for (int i = 0; i < n; i++) {
        cin >> a[i];
    }

    vector<int> ans(n);

    treap.reserve((size_t)((1 << 25) * 1.5));

    int tr = 0;

    for (int i = 0; i < MX; i++) {
        treap.emplace_back(i);
        tr = merge(tr, int(treap.size()) - 1);
    }

    int changed_iterations = 0;

    for (int i = n - 1; i >= 0; i--) {
        tr = change(a[i], tr);
        ans[i] = find_first(tr);

        changed_iterations++;

        if (changed_iterations % REBUILD_EVERY == 0) {
            tr = rebuild(tr);
        }
    }

    for (int i = n - 1; i >= 0; i--) {
        cout << ans[i] << ' ';
    }
}

#endif

    ios_base::sync_with_stdio(false);

    int tests = 1;
    // cin >> tests;

}
```
