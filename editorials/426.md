## 425B - Sereja and Table 
Note, that if we have two arrays *x*[1..*n*], 0 ≤ *x*<sub>*i*</sub> ≤ 1 and *y*[1..*m*], 0 ≤ *y*<sub>*i*</sub> ≤ 1, then described matrix can be showed as next one: *a*<sub>*i*, *j*</sub> = *x*<sub>*i*</sub> *xor* *y*<sub>*j*</sub>.
If *n* ≤ *k*, then we can backtrack array *x* and using greedy find best *y*. Otherwise there will be atleast one *i*, such that we will not change any cell in row number *i*. So we can simply bruteforce some row and use it like *x*. Then we use greedy and find *y*. From all possible rows we choose most optimal. Such row will be as number of mistakes is lower then number of rows, so it isn't possible to have atleast one mistake in each row.

Greedy means next algorithm: for every element of *y* we will look, will it be better to choose it like 0 or 1. To find better choise, we will count number of different bits in *x* and current(lets it be *j*) column. If number of different if lower then count of same cells we will set *y*<sub>*j*</sub> = 0, otherwise *y*<sub>*j*</sub> = 1.

## 425E - Sereja and Sets
First, lets look at *F*(*S*). First, we sort all intervals by second coordinte and then go by them in sorted order. And if current interval don't intersected with last taken to the optimal set, we get our current to the set.

Our solution will be based on this greedy. Solution of the problem is next dynamic:
1). number of position of second coordinte of interval
2). number of intervals in good set
3). second coordinate of last taken interval to the optimal set

How should we make transfers? Lets note that when we know *dp*<sub>*i*, *count*, *last*</sub> we can change *last* by *i*, or not change at all. Lets look what happens in every case. In first case *last* is changed by *i*, so we should take to optimal set atleast one of the inervals: [*last* + 1, *i*], [*last* + 2, *i*], ..., [*i*, *i*], number of such intervals *i* - *last*, number of ways to get at least one of them is 2<sup>*i* - *last*</sup> - 1. All other intervals: [1, *i*], [2, *i*], ..., [*last*, *i*] we could get as we wish, so we have 2<sup>*last*</sup> ways. So total number of transfers from *dp*<sub>*i*, *count*, *last*</sub> to *dp*<sub>*i* + 1, *count* + 1, *i*</sub> is (2<sup>*i* - *last*</sup> - 1)·(2<sup>*last*</sup>). If we count number of transfers from *dp*<sub>*i*, *count*, *last*</sub> to *dp*<sub>*i* + 1, *count*, *last*</sub>, we can simply use number 2<sup>*last*</sup>(as described early).

Also we shouldn't forget about trivial case *dp*<sub>*i*, 0, 0</sub>.

So now we have quite easy solution.
