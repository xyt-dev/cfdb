## 2199A - Game

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

There are several ways to solve this problem.

The most straightforward approach is to iterate through how many points Alice and Bob will score in the last round and check who will win.

A simpler solution is to consider only the scenario where Alice scores $0$ points and Bob scores $k$ points in the last round.

However, it is actually sufficient to check that Alice is ahead of Bob by at least $k$ points based on the results of the first two rounds. If her lead is less than $k$, then Bob will surpass her if he scores $k$ points while she scores $0$. But if Alice has scored at least $k$ points more than Bob in total over the two rounds, then she has won the first two rounds; and even if Bob surpasses her by $k$ points in the third round, Alice will still win.

Thus, it is enough to verify that $a_1 + a_2 - b_1 - b_2 \ge k$.


**Solution (BledDest)**
```kotlin
fun main() {
 val t = readLine()!!.toInt()
 repeat(t) {
 val k = readLine()!!.toInt()
 val (a1, b1) = readLine()!!.split(" ").map { it.toInt() }
 val (a2, b2) = readLine()!!.split(" ").map { it.toInt() }
 println(if (a1 - b1 + a2 - b2 >= k) "NO" else "YES")
 }
}
```

## 2199B - Two Towers

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

Using only the first type of operations, we can achieve the goal in $(c - a) + (d - b)$ actions. However, we can "save" $1$ action for each use of the second type of operation. Thus, it is advantageous to use as many operations of the second type as possible. The earliest we can start these operations is when both towers are $\max(a,b)$ high, and the latest is when both are $\min(c,d) - 1$ high. Therefore, the number of operations of the second type is at most $\min(c, d) - \max(a, b)$ (or $0$ if this value is negative). Then the minimum number of operations is $(c - a) + (d - b) - \max(0, \min(c, d) - \max(a, b))$.

 
**Solution (Neon)**
```kotlin
fun main() = repeat(readln().toInt()) {
    var (a, b, c, d) = readln().split(" ").map { it.toInt() }
    if (a > b) a = b.also { b = a }
    if (c > d) c = d.also { d = c }
    println(d - a - maxOf(0, b - c))
}
```

## 2199C - Minesweeper

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

Let there be two mines, one in column $i$ and the other in column $j$. If $|i-j| \le 2$ (that is, the mines are in the same column, in adjacent columns, or one column apart), then at least one cell will be adjacent to both of these mines; this means that there must also be a mine in that cell. It can be shown that this will ultimately lead to the entire field being filled with mines. Therefore, in the answer, the column numbers where the mines are located must differ by at least $3$, and there cannot be two mines in the same column.

If one mine is placed in a column, it will increase the number of free cells adjacent to the mines by $5$, except when it is in the first or last column (in which case the number of free cells adjacent to the mines will only increase by $3$). Moreover, no more than two mines can increase the number of these cells by $3$ (one in the first column and one in the last column). Therefore, for an answer to exist, $k$ must be expressible as $k = 5m$, $k = 5m + 3$, or $k = 5m + 6$, where $m$ is a non-negative integer. If such a representation exists for some $k$, it is unique (due to different remainders modulo $5$). We will find such a representation, placing $m$ blocks of $3$ columns, each containing a mine, and if necessary, we will add $2$ columns to the left and/or right with a mine in the first/last column.

The case $k=1$ needs to be considered separately


**Solution (Neon)**

```kotlin
}

 }

 pos.add(n - 2)

 }
 if (k % 5 == 3) {
 n += 2
 pos.add(n - 1)
 k -= 3
 }
 printAns(if (k == 0) n else 0, pos)
}
```

## 2199D - Two Arrays

Idea: [Roms](<https://codeforces.com/profile/Roms>), preparation: [Roms](<https://codeforces.com/profile/Roms>)
 
**Tutorial**

The first observation is as follows: if it is possible to make two arrays identical, then we can subsequently apply the same operations to them until their sizes become equal to $1$. Therefore, let's check if there exists some number $x$ to which both arrays can be transformed.

Let's try to understand what this $x$ could be for each array. If the array already has length $1$, then the only element of this array is the only possible value for $x$.

Otherwise, let's determine which elements of the array can be $x$ and which cannot. The first and last elements cannot be $x$, since in order to reduce the size to $1$, each element must participate in at least one operation; but as soon as we use the minimum or maximum in an operation, they will be removed.

Let's prove that any other element, except for the first or last, can be the only remaining one. Suppose we want to leave only the $i$-th element in the end. If there are an equal number of elements on the left and right, we can use all elements in one operation, and the $i$-th will remain as a result. If, for example, there are more elements on the left, we can choose any $3$ elements from the left and remove $2$ of them. Since the parity of the number of elements on the left and right of $i$ is the same, we can perform this operation until the number of elements on the left and right of $i$ is equal. Thus, we can leave the $i$-th element as the last one.

Now we know how to determine for each array all the elements that can be the only remaining ones. Let $a'$ be the array of all elements to which we can transform $a$ ($b'$ is defined similarly). To solve the problem, it is now sufficient to check that there is at least one element that belongs to both $a'$ and $b'$. We can iterate through all elements of $a'$ and check using binary search if this element exists in $b'$; or we can convert both arrays to a Set and call the intersect method.

 
**Solution (Roms)**
```kotlin
import java.util.StringTokenizer

fun main() {
    val t = readLine()!!.toInt()
    repeat(t) {
        val st = StringTokenizer(readLine())
        st.nextToken()
        st.nextToken()

        val a = readLine()!!.split(" ").map { it.toInt() }
        val b = readLine()!!.split(" ").map { it.toInt() }

        val aTrimmed =
            if (a.size > 1) a.subList(1, a.size - 1) else a
        val bTrimmed =
            if (b.size > 1) b.subList(1, b.size - 1) else b

        val ok = aTrimmed.toSet().intersect(bTrimmed.toSet()).isNotEmpty()
        println(if (ok) "Yes" else "No")
    }
}
```

## 2199E - Supersequence

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

Let's try to understand what the array $b$ might look like. To construct the shortest array in which $a$ appears as a subsequence, we can use the following process:

- set $b_1 = a_1$;
- add as few elements as possible so that the next one can be $a_2$. If $a_1 \lt a_2$, then each subsequent element should be greater than the previous one by $1$. If $a_1 \gt a_2$, then each subsequent element should be less than the previous one by $1$. If $a_1 = a_2$, we can place either $a_1 + 1$ or $a_1 - 1$ between them;
- similarly go from $a_2$ to $a_3$;
- and so on.

Thus, the number of elements that will be between the occurrences of $a_i$ and $a_{i+1}$ in the array $b$ can be easily determined: if they are equal, then there is $1$ element between them; otherwise, there are $|a_i - a_{i+1}| - 1$ elements between them. This allows us to determine the position of each element $a_i$ in the array $b$.

Consider the elements between the occurrences of $a_i$ and $a_{i+1}$. If these two numbers are equal, we cannot uniquely determine the element between them — it could be either $a_i + 1$ or $a_i - 1$. However, if they are different, all elements between them are uniquely determined, and knowing $a_i$, $a_{i+1}$, and the index of the element in the block between them makes it easy to reconstruct the element itself.

Thus, to answer each query, we need to know which block the element at position $x_i$ belongs to (or, possibly, whether it is an occurrence of one of the elements in the array $a$). If we list the starting positions of each block in the array, we can determine which block $x_i$ belongs to using binary search. This gives us a solution in $O(n + q \log n)$.


**Solution (Neon)**
```kotlin
import kotlin.math.abs

fun main() {
 val (n, q) = readln().split(" ").map { it.toInt() }
 val a = readln().split(" ").map { it.toInt() }
 val xs = readln().split(" ").map { it.toLong() }
 val bl = IntArray(2 * n - 1) { 1 }
 for (i in 1 until n) {
 if (a[i] != a[i - 1]) bl[2 * i - 1] = abs(a[i] - a[i - 1]) - 1
 }
 val s = bl.scan(0L) { x, y -> x + y }

 fun getVal(x : Long) : Int {
 if (x > s.last()) return -1
 val i = s.binarySearch { if (it < x) -1 else 1 }.inv() - 1
 val j = i / 2
 if (i % 2 == 0) return a[j]
 if (a[j] == a[j + 1]) return 0
 val d = (a[j + 1] - a[j]) / abs(a[j + 1] - a[j])
 return a[j] + d * (x - s[i]).toInt()
 }

 println(xs.map { getVal(it) }.joinToString(" "))
}
```

## 2199F - Self-Produced Sequences

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

First, let's understand what self-produced sequences look like. Consider the first non-zero element; the sum of the elements to the right should be equal to this element (since the sum on the left is $0$). Similarly, for the last non-zero element, the sum of the elements to the left of it should be equal to this element (since the sum on the right is $0$). This implies that the only possible case when both of the above conditions are met is when there are exactly $2$ non-zero elements in the sequence and they are equal. Now, let's determine where the zero elements can be placed. Clearly, zeros cannot be between non-zero elements because both the left and right sums are greater than $0$. However, they can be in any other positions, either before or after the non-zero elements. Thus, we have determined that self-produced sequences have the form: $[0, \dots, 0]$ or $[0, \dots, 0, x, x, 0, \dots, 0]$, where $x \gt 0$.

Next, let's understand how to calculate the number of such subsequences in the array $a$. Let $pref_i$ be the number of $0$s before position $i$, and $suf_i$ be the number of $0$s after position $i$. Sequences consisting solely of zeros are straightforward to count: there are $2^{tot}$ (where $tot$ is the total number of $0$s) such sequences. For sequences with two non-zero elements, fix two indices $i$ and $j$ such that $i \lt j$ and $a_i = a_j$. There are $pref_i$ zeros to the left of $i$, so the total number of ways to place these zeros is $2^{pref_i}$. Similarly, for $suf_j$ zeros to the right, there are $2^{suf_j}$ ways. Therefore, for a fixed pair $(i,j)$, the number of subsequences is $2^{pref_i} 2^{suf_j}$.

However, iterating through all pairs of $(i, j)$ would be inefficient. Instead, let's iterate over $j$ maintaining $s_x$ — the sum of $2^{pref_i}$ for all $i \lt j$ where $a_i = x$. For the current $j$, we can increase the answer by $s_{a_j} 2^{suf_j}$ if $a_j \ne 0$. Then, increment $s_{a_j}$ by $2^{pref_j}$. Note that since the array values can reach up to $10^9$, use an associative array (like MutableMap in Kotlin) or coordinate compression to store $s$ efficiently.

 
**Solution (Neon)**
```kotlin
const val MOD = 998244353;

fun add(x: Int, y: Int): Int {
    return ((x + y) % MOD + MOD) % MOD
}

fun mul(x: Int, y: Int): Int {
    return (x.toLong() * y % MOD).toInt()
}

fun main() = repeat(readln().toInt()) {
    val n = readln().toInt()
    val a = readln().split(" ").map { it.toInt() }
    val pw = generateSequence(1, { mul(it, 2) }).take(n + 1).toList()
    val cnt = a.scan(0) { x, y -> x + if (y == 0) 1 else 0 }
    val sum = mutableMapOf<Int, Int>()
    var ans = pw[cnt[n]]
    for (i in 0 until n) {
        if (a[i] == 0) continue
        val cur = sum.getOrDefault(a[i], 0)
        ans = add(ans, mul(cur, pw[cnt[n] - cnt[i]]))
        sum[a[i]] = add(cur, pw[cnt[i]]) 
    }
    println(ans)
}
```

## 2199G - Jammer

Idea: [adedalic](<https://codeforces.com/profile/adedalic>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)

**Tutorial**

Without loss of generality, let's assume that $n \le m$. Otherwise, we can simply "reflect" the field and the problem will remain unchanged.

Let's pay attention to two "special" paths of the robot: on one path, the robot will first go up to the limit and then to the right, while on the other path, it will go to the right to the limit and then up. It is not difficult to prove that our jammer will definitely intercept the robot if and only if it intercepts it on both these special paths.

Let's understand where to place the jammer so that it intercepts the robot on the path $(0, 0) - (0, m) - (n, m)$. For this, we need to place the jammer at a position $(x, y)$ such that either $x \le r$ (the robot will be intercepted on the segment $(0, 0) - (0, m)$), or $y \ge m - r$ (the robot will be intercepted on the segment $(0, m) - (n, m)$). Similarly, for the path $(0, 0) - (n, 0) - (n, m)$, we will get either $y \le r$ or $x \ge n - r$.

Then, let's iterate the coordinate $x$ of the jammer from $0$ to $n$ and determine all suitable coordinates $y$. What restrictions does the first path impose? If $x \le r$, then all $y \ge \left\lfloor \sqrt{r^2 - x^2} \right\rfloor + 1$ are suitable for us (we simply cannot choose points that are too close to $(0, 0)$). Otherwise (if $x \gt r$), only $y \ge m - r$ is suitable for us. Thus, the first path imposes a lower bound on possible $y$-s.

Similarly, if $n - x \le r$, then all $y \le m - 1 - \left\lfloor \sqrt{r^2 - (n - x)^2} \right\rfloor$ are suitable for us (meaning they are sufficiently far from $(n, m)$). Otherwise (if $n - x \gt r$), only $y \le r$ is suitable for us. Thus, the second path imposes an upper bound on possible $y$-s. Therefore, suitable $y$-s form some segment, and their number depends only on the length of that segment.

As a result, for each $x$ in $[0, n]$, we can count all $y$ in constant time. Thus, the complexity of the solution is $O(t \cdot n)$ (or $O(t \min(n, m))$ in general). Since $n \cdot m \le 10^9$ and $n \le m$, it follows that $n \le \sqrt{10^9}$.


**Solution (adedalic)**
```kotlin
import kotlin.math.*

fun main() {
 fun isqrt(a : Long) : Long {
 var s = max(0L, sqrt(a.toDouble()).toLong() - 2)
 while ((s + 1) * (s + 1) <= a)
 s++
 return s
 }
 repeat(readln().toInt()) {
 var (n, m, r) = readln().split(' ').map { it.toLong() }
 if (n > m)
 n = m.also { m = n }
 var ans = 0L
 for (i in 0..n) {
 val lf = if (i <= r) 1 + isqrt(r * r - i * i) else max(0L, m - r)
 val rg = if (n - i <= r) m - 1 - isqrt(r * r - (n - i) * (n - i)) else min(m, r)
 ans += max(0L, rg - lf + 1)
 }
 println(ans)
 }
}
```

## 2199H - Sum of MEX

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

To begin, let's try to solve the problem when all elements are equal to $-1$. We will calculate $ans_{x,y}$ — the number of arrays of size $y$ whose MEX is equal to $x$. For all $x, y \le k$, this can be done in $O(k^3)$: for each $x$, we will separately calculate the dynamic programming table $dp_{i,j}$ — the number of arrays of size $i$ with elements from $0$ to $n$, which contain $j$ distinct numbers from $0$ to $x-1$, but do not contain the number $x$. Then, $ans_{x,y}$ is equal to $dp_{i,x}$ for the given value of $x$.

How do we compute this dynamic programming? Clearly, $dp_{0,0} = 1$. From each state $dp_{i,x}$, there are two transitions:

- either we add an element from $0$ to $x-1$, which was not present before — there are $x-j$ ways to choose it;
- or we add an element greater than $x$ or one of the previously encountered elements — there are $n - (x - j)$ ways to choose it.

Now let's understand what to do with the elements from $0$ to $n$ that are present in the array $a$. How do we calculate the answer for a prefix of length $i$? We will write down all the numbers from $0$ to $n$ that were not among the first $i$ elements of $a$. Let these numbers be $x_0, x_1, \dots, x_m$ in increasing order. Let there be $c$ elements equal to $-1$ in the prefix of length $i$.

I claim that the number of arrays with MEX equal to $x_j$, which can be obtained from the prefix of length $i$, is exactly equal to $ans_{j,c}$: there will always be exactly $x_j - j$ distinct elements present in the prefix of length $i$ in the array $a$, so among the numbers that all $-1$ will be transformed into, there must necessarily be $j$ remaining numbers from $0$ to $x_j - 1$, and $j$ must not be present.

Moreover, we are only interested in the first $(c+1)$ values from $x_0, x_1, \dots, x_m$. We can maintain them using a mutableSet, DSU, or some other data structures. This allows us to process each prefix of the array $a$ in $c + \log n$ time.

Overall complexity: $O(k^3 + n \cdot (k + \log n))$, where $k$ is the number of elements equal to $-1$.

 
**Solution (BledDest)**
```kotlin
import java.util.*

const val MOD = 998244353

fun add(x: Int, y: Int): Int {
    var result = x + y
    while (result >= MOD) result -= MOD
    while (result < 0) result += MOD
    return result
}

fun mul(x: Int, y: Int): Int {
    return ((x.toLong() * y) % MOD).toInt()
}

fun solve() {
    val scanner = Scanner(System.`in`)
    val n = scanner.nextInt()
    val a = IntArray(n) { scanner.nextInt() }
    var k = 0
    for (i in 0 until n) if (a[i] == -1) k++
    val ans = Array(k + 1) { IntArray(k + 1) }
    
    for (mex in 0..k) {
        val dp = Array(k + 1) { IntArray(mex + 1) }
        dp[0][0] = 1
        for (i in 0 until k) {
            for (j in 0..mex) {
                if (dp[i][j] == 0) continue
                val inc = mex - j
                val same = n - inc
                if (inc > 0) {
                    dp[i + 1][j + 1] = add(dp[i + 1][j + 1], mul(inc, dp[i][j]))
                }
                dp[i + 1][j] = add(dp[i + 1][j], mul(same, dp[i][j]))
            }
        }
        for (i in 0..k) {
            ans[mex][i] = dp[i][mex]
        }
    }

    val unusedFirst = mutableSetOf<Int>()
    val unusedAll = mutableSetOf<Int>()
    for (i in 0..n) unusedAll.add(i)
    var cnt = 0
    for (i in 0 until n) {
        if (a[i] == -1) {
            cnt++
        } else {
            unusedFirst.remove(a[i])
            unusedAll.remove(a[i])
        }
        while (unusedFirst.size <= cnt) {
            unusedFirst.add(unusedAll.first())
            unusedAll.remove(unusedAll.first())
        }
        val unused = unusedFirst.toList()
        var sum = 0
        for (j in 0..cnt) {
            sum = add(sum, mul(ans[j][cnt], unused[j]))
        }
        print("$sum ")
    }
}

fun main() {
    val t = 1
    repeat(t) {
        solve()
    }
}
```

## 2199I - Strange Process

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Let $f(x)$ denote the size of the factorization of $x$ (the number of primes in the factorization, considering that some primes may have different powers). For example, $f(60) = 4$.

We also denote the minimum number of operations required to transform the number $x$ into the number $y$ as $d(x, y)$. The operations we consider are multiplication or division by a prime number. We can calculate $d(x, y)$ as follows: compute $g = gcd(x,y)$, then $d(x, y) = f(x) + f(y) - 2 \cdot f(g)$.

Let's try to understand how to determine if a certain array $b$ is achievable. If two non-zero elements $b_i$ and $b_j$ ($i \lt j$) are equal to each other, then it should be possible to transform $c_i$ into $c_j$ in no more than $j - i$ operations; in other words, $d(c_i, c_j) \le j - i$.

This allows us to write a dynamic programming state of the form $dp_{j, i_1, i_2, \dots, i_n}$, where $j$ is the number of initial elements of $b$ that we have considered, and $i_1, i_2, \dots, i_n$ are the indices of the last elements of $b$ that were equal to $1, 2, \dots, n$, respectively. Obviously, this dynamic programming has too many states. To reduce the number of states, we will use the following optimizations:

- The maximum value of $d(x, y)$ is $8$. This means that the values $i_1, i_2, \dots, i_n$ that do not exceed $(j-8)$ are not of interest to us (they do not impose any restrictions on where the corresponding number will appear next in the array $b$). We are only interested in values from $(j-7)$ to $(j-1)$;
- If we change all occurrences of one number from $1$ to $n$ to another and vice versa in an achievable array $b$, it will remain achievable. This means that the order of $i_1, i_2, \dots, i_n$ is not of interest to us.

We can transform the dynamic programming state into $dp'_{j, mask}$, where $mask$ is a binary mask of $7$ bits describing which of the values $j-1, j-2, \dots, j-7$ occur among $i_1, i_2, \dots, i_n$. In other words, the $k$-th bit of the mask describes whether there exists an $i$ such that $b_{j-k} = i$, and this is the last occurrence of $i$ among the first $j$ elements in the array $b$.

Transitions in this dynamic programming are done quite trivially:

- Either we assign $b_j = 0$ (this can always be done);
- Or we take one of those values that were not among the last $7$ elements (the number of ways to choose such a value is $n - popcnt(mask)$, where $popcnt(mask)$ is the number of set bits in the mask);
- Or we take one of those values that were among the last $7$ elements. We can iterate through when it was, check that the corresponding bit in the mask is $1$, and that we have enough operations to transform $c_{j-k}$ into $c_j$.

Thus, we obtain a solution in $O(m B 2^B)$, where $B$ is the number of last elements of the sequence that we are interested in (with $B=7$ being sufficient)


**Solution (BledDest)**
```kotlin
import kotlin.math.*
import java.util.*

const val MOD = 998244353
const val K = 7
const val A = 50

fun add(x: Int, y: Int): Int {
 var result = x + y
 while (result >= MOD) result -= MOD
 while (result < 0) result += MOD
 return result
}

fun mul(x: Int, y: Int): Int {
 return (x.toLong() * y % MOD).toInt()
}

fun gcd(x: Int, y: Int): Int {
 return if (x == 0) y else gcd(y % x, x)
}

fun solve() {
 val scanner = Scanner(System.`in`)
 val n = scanner.nextInt()
 val m = scanner.nextInt()
 val c = IntArray(m) { scanner.nextInt() }
 val dist = Array(A + 1) { IntArray(A + 1) }

 for (i in 1..A) {
 for (j in 1..A) {
 var diff = i * j / gcd(i, j) / gcd(i, j)
 for (k in 2..A) {
 while (diff % k == 0) {
 diff /= k
 dist[i][j]++
 }
 }
 }
 }

 val dp = IntArray(1 shl K)
 dp[0] = 1
 for (i in 0 until m) {
 val cur = c[i]
 val ndp = IntArray(1 shl K)
 for (j in 0 until (1 shl K)) {
 var popcount = 0
 val shifted = (j shl 1) and ((1 shl K) - 1)
 ndp[shifted] = add(ndp[shifted], dp[j])
 for (k in 0 until K) {
 if ((j shr k) and 1 == 1) popcount++
 }
 val unused = n - popcount
 if (unused > 0 && i >= dist[1][cur] - 1) {
 ndp[shifted + 1] = add(ndp[shifted + 1], mul(unused, dp[j]))
 }
 for (k in 0 until K) {
 if ((j shr k) and 1 == 0) continue
 val idx = i - k - 1
 if (idx >= 0 && dist[c[idx]][cur] > k + 1) continue
 var new_mask = shifted + 1
 if (k != K - 1) new_mask -= 1 shl (k + 1)
 ndp[new_mask] = add(ndp[new_mask], dp[j])
 }
 }
 for (k in dp.indices) {
 dp[k] = ndp[k]
 }
 }
 var ans = 0
 for (x in dp) ans = add(ans, x)
 println(ans)
}

 val t = 1
 repeat(t) {
 solve()
 }
}
```
