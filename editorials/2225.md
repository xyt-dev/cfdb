## 2225A - A Number Between Two Others

Author: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

There are several different ways to solve this problem.

Solution $1$ (brute force)

Let us iterate over $z$ among the numbers $2x, 3x, 4x, \dots, y-x$ and stop as soon as we find a suitable $z$ (or run out of numbers).

Why does this work fast? If an answer exists, it will always be found among roughly the first $50$ numbers we check. To prove this, suppose otherwise: let $y$ be divisible by the numbers $2x, 3x, \dots, 50x$; then it is divisible by $x \cdot \texttt{LCM}(2, 3, \dots, 50)$, where $\texttt{LCM}$ denotes the least common multiple. The $\texttt{LCM}$ of all numbers from $2$ to $50$ is already large enough to exceed the problem constraints. Therefore, among the first $50$ numbers there will be an answer.

Solution $2$ (number theory and/or case analysis)

Let $y = k \cdot x$. If $k \gt 2$, then $k \bmod (k-1) = 1$. Therefore, $y = kx$ is not divisible by $((k-1) \cdot x)$, and we can use $z = ((k - 1) \cdot x)$.

If $k = 2$, then there is no integer between $x$ and $kx$ that is divisible by $x$. Therefore, in this case there is no answer.

Thus, the number $z$ exists if and only if $y \ne 2 \cdot x$.


**Solution 1 (BledDest)**

```python
for i in range(t):
 x, y = map(int, input().split())
 good = False
 for z in range(x * 2, y, x):
 if y % z != 0:
 good = True
 break
 if good:
 print('YES')
 else:
 print('NO')
```

 
**Solution 2 (BledDest)**
```python

    x, y = map(int, input().split())
    print('YES' if y > 2 * x else 'NO')
```

## 2225B - Alternating String

Author: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

Let us consider, instead of the string itself, a sequence $d$ of length $|s| - 1$ such that $d_{i} = 1$ if $s_{i} = s_{i + 1}$, and $d_{i} = 0$ if $s_{i} \neq s_{i + 1}$.

In this form, our task is to make all numbers in the sequence $d$ equal to $0$.

Let us see how any operation on the string $s$ changes the sequence $d$. It can also reverse some subsegment of $d$, but the more interesting point is that we can change $0$ to $1$ or $1$ to $0$ at the ends of the subsegment if we choose neither a prefix nor a suffix. At the same time, if we choose a prefix or a suffix, then we can change at most one number in $d$.

That is, in one operation we can change at most two numbers in $d$. Therefore, if there are more than two ones in $d$, then the answer is always NO.

Let us prove that if there are at most two ones in $d$, then a sequence of operations always exists. If there is one one in $d$, then in the original string there is one pair of adjacent equal characters. Let us apply the operation to the prefix containing the first character of this pair. If the first character of the string is equal to the characters in this pair, then we perform the second step of the operation; otherwise, we skip it. This way, this pair of adjacent characters will stop being equal, and the string will become alternating.

If there are two ones in $d$, then there are two pairs of adjacent equal characters. In this case, we need to apply the operation to the substring from the second character of the left pair (inclusive) to the first character of the right pair (also inclusive). If the characters in the first pair differ from the characters in the second pair, then we make the string alternating by reversing this substring; otherwise, we also need to perform the second step of the operation (replace all characters in the substring).

Thus, the answer is YES if and only if the array $d$ contains at most two ones. In other words, the original string contains at most two pairs of adjacent equal characters. This is easy to check in $O(|s|)$.


**Solution (FelixArg)**

```cpp
#include <bits/stdc++.h>

using namespace std;

void solve() {
	string s;
	cin >> s;
	int ans = 0;
	for (int i = 0; i < (int)s.size() - 1; i++){
 ans += (s[i] == s[i + 1]);
	}
	cout << (ans <= 2 ? "YES\n" : "NO\n");
}
```

## 2225C - Red-Black Pairs

Author: [FelixArg](<https://codeforces.com/profile/FelixArg>)
 
**Tutorial**

You can think of the pairs as dominoes of size $2 \times 1$ or $1 \times 2$.

For any domino, you need to repaint at most one cell to make it monochromatic.

Let us think about what a tiling of a $2 \times n$ board with dominoes can look like. Consider the beginning of the board, that is, the first column. We can place a vertical domino in it, or, if the next column exists and is empty, we can place two horizontal dominoes.

So, any tiling consists of vertical dominoes and pairs of horizontal dominoes occupying two columns. Because of this, it is easy to write a dynamic programming solution:

- $\texttt{dp[i]}$ — the minimum number of repaints in the first $i$ columns;
- $\texttt{dp[0]} = 0$ — the initial state;
- $\texttt{dp[i + 1]} = \texttt{dp[i]} + \texttt{cost_vertical(i)}$ — the transition if we place a vertical domino in column $i$;
- $\texttt{dp[i + 2]} = \texttt{dp[i]} + \texttt{cost_horizontal(i)}$ — the transition if we place two horizontal dominoes in columns $i$ and $i + 1$.

The answer will be in $\texttt{dp[n]}$.

Therefore, the problem can be solved in $O(n)$.

Bonus: try solving the problem without dynamic programming.

 
**Solution (FelixArg)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;

#define int long long

const int INF = 1'000'000'007;

void solve(){
  int n;
  cin >> n;
  vector<string> d(2);
  cin >> d[0] >> d[1];

  vector<int> dp(n + 1, INF);
  dp[0] = 0;
  for (int i = 0; i < n; i++){
    dp[i + 1] = min(dp[i + 1], dp[i] + (d[0][i] != d[1][i]));
    if (i + 1 < n){
      dp[i + 2] = min(dp[i + 2], dp[i] + (d[0][i] != d[0][i + 1]) + (d[1][i] != d[1][i + 1]));
    }
  }

  cout << dp[n] << '\n';
}
 
signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);
 
	int t = 1;
	cin >> t;
	while(t--){
		solve();
	}
 
#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
		chrono::high_resolution_clock::now()
			- _clock_start).count() << "ms." << endl;

	return 0;
```

## 2225D - Exceptional Segments

Author: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

Let us use a standard technique that allows us to count the number of segments with the same value.

Denote

$$ \texttt{pref}_{i} = 1 \oplus 2 \oplus \cdots \oplus i $$

Then the XOR on the segment ($l, r$) is equal to

$$ \texttt{pref}_{l - 1} \oplus \texttt{pref}_{r} $$

According to the problem statement, we need to count the number of segments whose XOR is equal to $0$, which means the number of segments for which

$$ \texttt{pref}_{l - 1} = \texttt{pref}_{r} $$

and

$$ 0 \le l - 1 \lt x \le r \le n $$

Next, let us note the following fact:

$$ \texttt{pref}_{i} = \begin{cases} i, & \quad \text{if } i \bmod 4 = 0 \\ 1, & \quad \text{if } i \bmod 4 = 1 \\ i + 1, & \quad \text{if } i \bmod 4 = 2 \\ 0, & \quad \text{if } i \bmod 4 = 3 \end{cases} $$

To understand this, you can compute the first few values of $\texttt{pref}_{i}$ by hand and observe the pattern. We can prove this pattern using induction:

- $i$ up to $4$ can be checked by hand;
- if $i \bmod 4 = 0$ and $\texttt{pref}_i = i$, then $\texttt{pref}_i \oplus (i+1) = 1$ (numbers $i$ and $(i+1)$ differ only in the lowest bit). So, for $j = i+1$, $\texttt{pref}_j = 1$ and $j \bmod 4 = 1$;
- if $i \bmod 4 = 1$ and $\texttt{pref}_i = 1$, then $\texttt{pref}_i \oplus (i+1) = (i+2)$ (the lowest bit of $(i+1)$ is $0$, so $(i+1) \oplus 1 = (i + 1) + 1 = (i+2)$). So, for $j = i+1$, $\texttt{pref}_j = j+1$ and $j \bmod 4 = 2$;
- if $i \bmod 4 = 2$ and $\texttt{pref}_i = (i+1)$, then $\texttt{pref}_i \oplus (i+1) = 0$. So, for $j = i+1$, $\texttt{pref}_j = 0$ and $j \bmod 4 = 3$;
- if $i \bmod 4 = 3$ and $\texttt{pref}_i = 0$, then $\texttt{pref}_i \oplus (i+1) = (i+1)$. So, for $j = i+1$, $\texttt{pref}_j = j$ and $j \bmod 4 = 0$.

We can see that only the numbers $0$ and $1$ repeat, which means that the answer consists only of pairs

$$ \texttt{pref}_{l - 1} = \texttt{pref}_{r} = 0 \\ \texttt{pref}_{l - 1} = \texttt{pref}_{r} = 1 $$

The number of required indices for a specific value to the left or to the right of $x$ can be found by simple division, based on the pattern.

Thus, the problem can be solved in $O(1)$ for one test case.


**Solution (FelixArg)**
```cpp
#include<bits/stdc++.h>

using namespace std;

#define int long long

const int MOD = 998'244'353;

int get0(int x){
 return 1ll + (x >= 3 ? (x - 3) / 4 + 1 : 0);
}

int get1(int x){
 return (x >= 1 ? (x - 1) / 4 + 1 : 0);
}

void solve(){
	int n, x;
	cin >> n >> x;

 int l0 = get0(x - 1) % MOD;
 int r0 = (get0(n) - l0) % MOD;
	int ans = l0 * r0;

 int l1 = get1(x - 1) % MOD;
 int r1 = (get1(n) - l1) % MOD;
	ans += l1 * r1;
 ans %= MOD;

 cout << ans << '\n';
}

signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);

	int tests = 1;
	cin >> tests;
	while(tests--){
 solve();
	}

#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
 chrono::high_resolution_clock::now()
 - _clock_start).count() << "ms." << endl;
```

## 2225E - Covering Points with Circles

Author: [basalov_yurij](<https://codeforces.com/profile/basalov_yurij>)
 
**Tutorial**

The key idea for solving this problem is to use an optimal circle packing in the plane. It is known that this is the [hexagonal packing](<https://en.wikipedia.org/wiki/Circle_packing#Densest_packing>).

If circles of radius $r$ are arranged in a hexagonal packing, then they occupy approximately

$$\frac{\pi}{2 \sqrt 3} \approx 0.9069$$

of the plane's area.


![](eimages/2225_1.png)


How does this help solve the problem? The point is that there are quite many points in each test case, and they are generated inside a large rectangle. This means that if we place circles on a hexagonal lattice, then with high probability they will cover $90.6\%$ of all points.

It remains to understand how exactly to construct such a hexagonal lattice with integer coordinates and how to find the circles that will appear in the answer (since there are infinitely many circles on the lattice).

We will construct the lattice as follows: let

$$ w = 2r \\ h = \lceil \sqrt 3 r \rceil $$

then any point on the lattice is given by

$$ \begin{cases} x = x_{0} + col \cdot w + (row \bmod 2) \cdot r \\ y = y_{0} + row \cdot h \end{cases} $$

As the starting point ($x_{0}, y_{0}$), we can take a random one. Any two circles centered at different points of such a lattice do not intersect, because their centers are at distance at least $2r$ from each other.

We will search for the circles that should be included in the answer as follows: for each point from $p$, we find several nearest rows of the lattice containing some point and several nearest columns of the lattice containing some point, and then check the points at the intersections of those rows and columns.

In practice, it is enough to take the $5$ nearest rows and columns.

In this form, the solution may already get "Accepted" if you are lucky. But what if you are not lucky?

For problems like this, there is one effective method. If we fail to find a solution, then we simply try again, that is, choose another starting point ($x_{0}, y_{0}$) and build the lattice relative to it.

 
**Solution (FelixArg)**
```cpp
#include <bits/stdc++.h>
 
using namespace std;

#define int long long

mt19937 rng(chrono::high_resolution_clock().now().time_since_epoch().count());
 
void solve() {
	int n, r;
	cin >> n >> r;
	vector<pair<int, int>> p(n);
	for (int i = 0; i < n; i++){
		cin >> p[i].first >> p[i].second;
	}

	int w = 2 * r, h = ceil(sqrt(3) * r);

	auto is_in_circle = [&](int x, int y, int ox, int oy, int r){
		return (ox - x) * (ox - x) + (oy - y) * (oy - y) <= r * r;
	};

	int cov;
	vector<pair<int, int>> ans;

	do{
		ans.clear();
		cov = 0;
		
		int x0 = rng() % 100'000, y0 = rng() % 100'000;
		auto check_point = [&](int x, int y){
			int nearest_row = (y - y0) / h;
			for (int row = nearest_row - 2; row <= nearest_row + 2; row++){
				int nearest_col = (x - (x0 + (row % 2) * r)) / w;
				for (int col = nearest_col - 2; col <= nearest_col + 2; col++){
					int x_lat = x0 + col * w + (row % 2) * r;
					int y_lat = y0 + row * h;
					if (is_in_circle(x, y, x_lat, y_lat, r)){
						ans.emplace_back(x_lat, y_lat);
						cov++;
						return;
					}
				}
			}
		};

		for (int i = 0; i < n; i++){
			check_point(p[i].first, p[i].second);
		}
	} while(cov * 100 < 89 * n);

	sort(ans.begin(), ans.end());
	ans.erase(unique(ans.begin(), ans.end()), ans.end());

	cout << ans.size() << '\n';
	for (auto [x, y] : ans){
		cout << x << ' ' << y << '\n';
	}
}
 
signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);
 
	int tests = 1;
	//cin >> tests;
	while(tests--){
		solve();
	}
 
#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
		chrono::high_resolution_clock::now()
			- _clock_start).count() << "ms." << endl;
#endif
	return 0;
}
```

## 2225F - String Cutting

Author: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

First, let us prove that it is always optimal to cut the string into exactly $k$ parts. Suppose we cut it into $x \gt k$ parts; if we merge two adjacent parts, it can be shown that the $k$-th part in sorted order will not decrease.

Proof: the $k$-th minimum element of some multiset can be defined as the minimum $a$ such that the multiset contains at least $k$ elements not greater than $a$. Suppose we merge two parts of the string, $t_i$ and $t_{i+1}$; then the elements $t_i$ and $t_{i+1}$ are removed from the multiset of resulting parts, and instead a new element $t'_i = t_i + t_{i+1} \gt t_i$ is inserted. For every string $a$, the number of elements in the multiset not greater than $a$ cannot increase; therefore, the minimum value of $a$ for which the number of such elements is at least $k$ cannot decrease. Thus, we can merge any two adjacent pieces, and the answer will not become worse.

So now we always cut the string into exactly $k$ parts. When $k=1$, this means that the original string itself is the answer (if its length is at least $l$); when $k \gt 1$, we need to consider several candidates for the answer and choose the best among them.

Suppose we want to check whether the substring $t = s_{L} s_{L+1} \dots s_R$ can be the answer. Then the following conditions must hold:

- the prefix before position $L$ can be cut into strings of length at least $l$;
- the suffix after position $R$ can be cut into strings of length at least $l$;
- the prefix and suffix can be cut so that together they form exactly $(k-1)$ strings, and all these strings are lexicographically not greater than $t$.

The first and second conditions are quite easy to check — if the prefix or suffix contains more than $0$ and fewer than $l$ characters, then it cannot be cut into parts of length at least $l$. However, the third condition is much harder to check. Instead of checking it directly, we will use the fact that we are interested in the maximum suitable string $t$. This allows us to simplify the third condition by removing the requirement that the remaining parts must be lexicographically not greater than $t$ — if among the parts there is a string that is lexicographically greater than $t$, then we will also consider it as a candidate, which means that the current string $t$ cannot be the answer anyway.

This allows us to reformulate the conditions as follows:

- the prefix before position $L$ can be cut into strings of length at least $l$;
- the suffix after position $R$ can be cut into strings of length at least $l$;
- the prefix and suffix can be cut so that together they form exactly $(k-1)$ strings of length at least $l$.

For a single substring, these conditions can be checked in $O(1)$, which gives us $O(n^2)$ candidates.

The number of candidates can be reduced to $O(n)$ by using the fact that the substring from position $L$ to position $(R+1)$ is always lexicographically greater than the substring from position $L$ to position $R$. Therefore, we can iterate over the left boundary $L$ and for each of them find the maximum right boundary $R$ satisfying all conditions. This can be done with a fairly simple calculation — we need to determine how many parts can be obtained from the prefix, and this will show what the minimum suffix length must be.

Now we have $O(n)$ strings, each of which is a substring of the original string $s$, and among them we need to choose the lexicographically maximum one. Unfortunately, the constraints in the problem are too strict to use suffix structures conveniently (at least, we were unable to make a suffix array work fast enough). We suggest two solution methods:

Method 1 — hashes (FelixArg)

Build polynomial hashes for all prefixes of the string and precompute all powers of the hashing base (and possibly modular inverses for them — though this is not necessary). This allows us to check that two substrings are equal in $O(1)$.

But equality checks are not enough; we need to determine which of two substrings is greater and which is smaller. We can compute the longest common prefix of two substrings in $O(\log n)$ using binary search on its length. The next character after the longest common prefix tells us which substring is greater. Once we can compare two substrings in $O(\log n)$, we can easily find the maximum among them in $O(n \log n)$.

To avoid collision issues, we recommend using hashing with two bases/moduli.

Method 2 — z-function (BledDest)

Take some candidate answer $t$ and build the z-function for the string $t + d + s$, where $d$ is some separator character. The z-function will show the length of the longest common prefix of $t$ and each of the other candidate answers. This allows us to compare $t$ with the other candidates, and therefore split them into three sets:

- smaller than $t$;
- equal to $t$;
- greater than $t$.

If the third set is empty, then $t$ is the answer to the problem, since it is maximal. Otherwise, we are interested only in the third set, and we can continue analyzing it instead of the full list of candidates.

If we choose the candidate randomly, we will need to process $O(\log n)$ candidate answers on average (this is proved in roughly the same way as the recursion depth of randomized QuickSort or the depth of a randomized Cartesian tree). Each candidate is checked in $O(n)$, giving a total complexity of $O(n \log n)$.

```cpp
            lf = min(lf, cand[i].first);
            rg = max(rg, cand[i].first + cand[i].second);
        }
        auto p = cand[0];
        cur = s.substr(p.first, p.second) + "?" + s.substr(lf, rg - lf);
        z_function(cur);
        vector<pair<int, int>> better;
        int len = p.second;
        for(int i = 0; i < cand.size(); i++)
        {
            if(cand[i] == p) continue;
            int L = cand[i].first - lf;
            int cur_len = cand[i].second;
            int lcp = zf[len + 1 + L];
            lcp = min(lcp, cur_len);
            if(lcp == cur_len || (len > lcp && cur[L + len + 1 + lcp] <= cur[lcp]))
                continue;
            better.push_back(cand[i]); 
        }
        if(better.empty())
            return s.substr(p.first, p.second);
        else
            cand = better;
    }
    return "";
}
 
void solve()
{
    if(k * 1ll * l > n)
    {
        cout << "NO\n";
        return;
    }
    if(k == 1)
    {
        cout << "YES\n" << s << "\n";
        return;
    }
    vector<pair<int, int>> cand;
    for(int i = 0; i < n; i++)
    {
        if(i > 0 && i < l) continue;
        int lf = i / l;
        int rg = (n - i) / l;
        if(lf + rg < k) continue;
        int need_rg = max(0, k - lf - 1);
        int len = (n - need_rg * l) - i;
        if(len >= l)
            cand.push_back(make_pair(i, len));    
    }
    shuffle(cand.begin(), cand.end(), rnd);
    if(cand.empty())
    {
        cout << "NO\n";
    }
    else
    {
        cout << "YES\n" << find_best(cand) << "\n";
    }
}
```

## 2225G - Simple Problem

Author: [basalov_yurij](<https://codeforces.com/profile/basalov_yurij>)

**Tutorial**

Let $g_i$ denote the greatest common divisor of the numbers $k_1, k_2, \dots, k_i$. It is quite easy to see that if $g_m \ne 1$, then there is no answer. We claim that in the case $g_m = 1$, an answer always exists, and we will prove this using a constructive algorithm.

Let's divide all numbers into equivalence classes modulo $k_1$, that is, class $C_i$ will consist of all numbers from $0$ to $n-1$ whose remainder modulo $k_1$ is $i$. Any two numbers in the same class may stand next to each other in the answer. If there is only one class (that is, $k_1 = 1$), then we can immediately output any permutation.

Otherwise, we have several classes. We will construct the answer as follows: arrange the classes in some order, and then choose in each class a "first" and a "last" element so that they are different, while the last element of each class differs from the first element of the next class by exactly some number $k_j$. In other words, when "moving" between two neighboring classes, some $k_j$ will be added to the current number: if the current class was $C_i$, then the next class will be $C_{(i + k_j) \bmod k_1}$.

Initially, we have $k_1 = g_1$ classes, each of which will represent a separate "chain" consisting of a single class containing all elements with the same remainder modulo $g_1$. We will merge them into one chain, which we construct as follows:

Let a "chain with starting element $x$ of order $y$" (denote it by $P(x,y)$) be a chain of equivalence classes that starts with class $C_x$ and contains all classes having the same remainder as $x$ modulo $k_y$. Such chains can be formed recursively:

- $P(x,1)$ is the single class $x$;
- to construct $P(x,i)$, first build $P(x,i-1)$ and see at which element it ends (let it be $x_1$). Then build the chain $P((x_1 + k_i) \bmod k_1, i-1)$, append it to the previous one, and see at which element it ends (let it be $x_2$). Then build the chain $P((x_2 + k_i) \bmod k_1, i-1)$, append it to the previous one, and see at which element it ends, and so on. In total, we will need exactly $\frac{g_{i-1}}{g_i}$ chains of order $(i-1)$, and every two neighboring chains are connected by classes that differ by exactly $k_i$. Moreover, since $g_i$ is the greatest common divisor of $g_{i-1}$ and $k_i$, classes in lower-order chains will start repeating only after $\frac{g_{i-1}}{g_i}$ chains from the starting one, so all classes in the resulting chain will be distinct.

In this case, the chain $P(0,m)$ (not necessarily $0$, any starting element can be used) is exactly the chain containing all equivalence classes, and each next class is obtained from the previous one by adding some $k_j$. When constructing the chain $P(x,y)$, it is convenient to return not only the chain itself, but also the sequence of numbers $k_j$ that we add to obtain each next element.

Now it remains to arrange the elements inside each equivalence class in some way so that for every pair of neighboring classes, the last element of the previous class is exactly some $k_j$ less than the first element of the next class. For this, we use the restriction that each $k_j$ does not exceed $\frac{n}{3}$. This means that each class contains at least $3$ elements; moreover, if we consider the first two elements of some class (let them be called $a$ and $b$), then both are strictly less than $\frac{2n}{3}$. This means that both $a + k_j$ and $b + k_j$ will be less than $n$. If the current class starts with element $a$, we can end it with element $b$ and start the next class with element $b + k_j$; otherwise, we can end the current class with element $a$ and start the next class with element $a + k_j$.

Thus we obtain a solution in $O(n)$, although slower implementations also exist.
