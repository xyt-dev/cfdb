## 2237A - Destroying Towers

Idea: [_ja](<https://codeforces.com/profile/_ja>) Preparation: [_ja](<https://codeforces.com/profile/_ja>) & [quacksaysduck](<https://codeforces.com/profile/quacksaysduck>)

**Tutorial**

Optimally, go from left to right in that order. After this, the height of tower $i$ will be $\min(a_1, a_2, \dots, a_i)$, so the minimum sum is $a_1+\min(a_1,a_2)+\min(a_1,a_2,a_3)+\cdots$.

Time complexity: $\mathcal O(n)$


**Implementation**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
 int t;
 cin >> t;
 while (t--) {
 int n;
 cin >> n;
 int x = 10000, y = 0;
 for (int i = 0; i < n; ++i) {
 int z;
 cin >> z;
 x = min(x, z), y += x;
 }
 cout << y << '\n';
 }
 return 0;
}
```

## 2237B - Annoying the Ghost

Idea: [quacksaysduck](<https://codeforces.com/profile/quacksaysduck>) Preparation: [_ja](<https://codeforces.com/profile/_ja>) & [quacksaysduck](<https://codeforces.com/profile/quacksaysduck>) & [Boboge](<https://codeforces.com/profile/Boboge>)
 
**Tutorial**

Do a greedy algorithm. Maintain a set of $\{b_1, b_2, \ldots, b_n\}$.

Increase $a_1$ to the smallest possible value of $b_i$ in the set. This is optimal because if it is increased to $b_j \gt b_i$, then consider $m \gt 1$ such that $a_m$ is increased to $b_i$. Since $a_m \le a_1$, we may increase $a_1$ to $b_i$ and $a_m$ to $b_j$ instead.

Now remove $b_i$ from the set, and repeat with $a_2$, then $a_3$, and so on.

The cost (number of inversions) can be computed in $\mathcal O(n^2)$ (or $\mathcal O(n\log n)$ if you want to for some reason)

Time complexity: $\mathcal O(n^2)$ (or $\mathcal O(n\log n)$ if you want to for some reason).

 
**Implementation**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
    int t;
    cin >> t;
    while (t--) {
        int n;
        cin >> n;
        vector<int> a(n), c(n);
        for (int i = 0; i < n; i++) cin >> a[i];
        set<int> s;
        for (int i = 0; i < n; i++) {
            int x;
            cin >> x;
            s.insert(x);
        }
        bool y = true;
        for (int i = 0; i < n; ++i) {
            auto it = s.lower_bound(a[i]);
            if (it == s.end()) {
                y = false;
                break;
            }
            c[i] = *it;
            s.erase(it);
        }
        if (!y) {
            cout << -1 << '\n';
            continue;
        }
        int ans = 0;
        for (int i = 0; i < n; ++i) {
            for (int j = i + 1; j < n; ++j) {
                if (c[i] > c[j]) {
                    ans++;
                }
            }
        }
        cout << ans << '\n';
    }
    return 0;
}
```

## 2237C - Duck Surplus

Idea: [quacksaysduck](<https://codeforces.com/profile/quacksaysduck>) Preparation: [Boboge](<https://codeforces.com/profile/Boboge>)

**Tutorial**

It is useful to view the operation in another way. If we have two adjacent piles $x \gt y$, then after the operation

$$ (x,y)\to(y,x+y), $$

the smaller pile $y$ moves one position to the left, and the pile it passes through increases by $y$.

We claim that there is an optimal strategy that always chooses the leftmost inversion.

Indeed, operations on disjoint pairs can be swapped freely. The only nontrivial case is when we have three consecutive piles

$$ x \gt y \gt z. $$

If we first operate on the right pair, then this block eventually becomes

$$ (z,\ y+z,\ x+y+2z). $$

If we first operate on the left pair, then this block eventually becomes

$$ (z,\ y+z,\ x+y+z). $$

The second result is never worse, since the last pile is smaller by $z$. Therefore, whenever two neighboring inversions compete, processing the left one first is at least as good as processing the right one first. By repeatedly applying this exchange argument, we may assume that an optimal process always takes the leftmost inversion.

Now consider what happens under this strategy.

Suppose we have already processed the prefix $a_1,\dots,a_{i-1}$. It is sorted, and let $m$ be its largest pile. Now we append $x=a_i$.

If $m\le x$, then the whole prefix is still sorted, so the new largest pile is simply $x$.

Otherwise, $m \gt x$. Then $x$ must move left through all piles greater than $x$. In particular, it passes through the current largest pile $m$, so that pile becomes $m+x$. Every other crossed pile was at most $m$, so after adding $x$ it is at most $m+x$. Hence the new largest pile is exactly $m+x$.

Therefore the transition is:

$$ m = \begin{cases} x, & m\le x,\\ m+x, & m \gt x. \end{cases} $$

We scan the array from left to right and maintain this value $m$. The final value of $m$ is the minimum possible largest pile.

The time complexity is $O(n)$.


**Implementation**
```cpp
#include <bits/stdc++.h>

using namespace std;

using i64 = long long;

void run() {
 int n;
 cin >> n;
 vector<int> a(n);
 for (int i = 0; i < n; ++i) {
 cin >> a[i];
 }
 i64 ans = 0;
 for (int i = 0; i < n; ++i) {
 if (ans > a[i]) {
 ans += a[i];
 } else {
 ans = a[i];
 }
 }
 cout << ans << '\n';
}

int main() {
 ios_base::sync_with_stdio(false);
 cin.tie(nullptr);
 int T = 1;
 cin >> T;
 while (T--) {
 run();
 }
 return 0;
}
```

## 2237D - Fullmetal Bitchemist

Idea: [zeemanz](<https://codeforces.com/profile/zeemanz>) Preparation: [__baozii__](<https://codeforces.com/profile/__baozii__>)
 
**Tutorial**

We first characterize when a binary string is beautiful.

For a binary string $t$, define

$$ f(t)=\text{the number of }\mathtt{1}\text{s in }t-\text{the number of }\mathtt{0}\text{s in }t. $$

There are two possible operations:

- $\mathtt{00} \to \mathtt{1}$. In this case, $f$ changes from $-2$ to $1$, so it increases by $3$.
- $\mathtt{11} \to \mathtt{0}$. In this case, $f$ changes from $2$ to $-1$, so it decreases by $3$.

Therefore, one operation does not change $f(t) \bmod 3$.

If a string can be reduced to a string of length $1$, then the final value of $f$ is either $1$ or $-1$. Hence, a necessary condition is

$$ f(t) \not\equiv 0 \pmod 3. $$

Also, if a string of length greater than $1$ is alternating, then it has no two equal adjacent characters, so no operation can be applied. Therefore, it is not beautiful.

We claim that these two conditions are also sufficient.

A non-empty binary string $t$ is beautiful if and only if:

- $f(t) \not\equiv 0 \pmod 3$;
- $t$ is not an alternating string of length greater than $1$.

Now we prove the sufficiency.

First, consider the short corner cases.

If $|t|=1$, then $t$ is already reduced to length $1$, so it is beautiful.

If $|t|=2$, then $\mathtt{00}$ and $\mathtt{11}$ can be reduced to length $1$ in one operation, while $\mathtt{01}$ and $\mathtt{10}$ are alternating and cannot be operated on. This is exactly consistent with the claim.

Now suppose $|t| \gt 2$, $f(t)\not\equiv 0 \pmod 3$, and $t$ is not alternating. Then $t$ contains a maximal block of equal characters of length at least $2$.

If there is a block of length exactly $2$, we apply the operation to this block. Since the block is maximal, any neighboring character must be the opposite character, which is exactly the character inserted after the operation. Therefore, unless the whole string becomes length $1$, the new string is still not alternating.

If there is no block of length exactly $2$, then there is a block of length at least $3$. If this block has a neighboring character, we choose two equal characters near the boundary of the block. After the operation, the inserted character is equal to the character outside the block, so the new string is still not alternating.

The only remaining case is that the whole string consists of one kind of character. Let its length be $len$. Since $f(t)\not\equiv 0 \pmod 3$, $len$ is not divisible by $3$. The case $len=2$ was already handled. For $len\ge 4$, after applying one operation at one end, at least two equal adjacent characters still remain, so the new string is still not alternating.

In all cases, unless the string already becomes length $1$, we can perform one operation and keep both properties true:

- $f(t)\not\equiv 0 \pmod 3$;
- the string is not alternating.

Since each operation decreases the length by $1$, by induction the string can eventually be reduced to length $1$.

Therefore, a substring is beautiful exactly when:

- the number of $\mathtt{1}$s minus the number of $\mathtt{0}$s is not divisible by $3$;
- it is not an alternating string of length greater than $1$.

Now we count such substrings.

Define the prefix value

$$ p_i=\sum_{j=1}^{i} ([s_j=\mathtt{1}]-[s_j=\mathtt{0}]) \pmod 3. $$

For a substring $s[l..r]$,

$$ f(s[l..r]) \equiv p_r-p_{l-1} \pmod 3. $$

Thus,

$$ f(s[l..r]) \not\equiv 0 \pmod 3 $$

if and only if

$$ p_r \ne p_{l-1}. $$

We scan the string from left to right. Let $\mathtt{cnt}[0..2]$ store the number of previous prefixes with each value modulo $3$. Initially, $\mathtt{cnt}[0]=1$, corresponding to the empty prefix.

Suppose the current prefix value is $x$. Then the number of substrings ending at the current position with $f\not\equiv 0 \pmod 3$ is

$$ \mathtt{cnt}[0]+\mathtt{cnt}[1]+\mathtt{cnt}[2]-\mathtt{cnt}[x]. $$

However, among these substrings, some alternating strings of length greater than $1$ have been counted, and they must be subtracted.

Let $y$ be the length of the longest alternating suffix ending at the current position. Then all alternating substrings ending at this position have lengths

$$ 1,2,\dots,y. $$

Among them, alternating substrings of even length have the same number of $\mathtt{0}$s and $\mathtt{1}$s, so their $f$ value is $0$. They were not counted in the first place.

Alternating substrings of odd length have $f=\pm 1$, so they were counted. The length-$1$ substring is beautiful, so it should not be subtracted. Therefore, we only need to subtract alternating substrings of lengths

$$ 3,5,7,\dots. $$

The number of such substrings is

$$ \left\lfloor \frac{y-1}{2} \right\rfloor. $$

So the contribution of each position is

$$ \left\lfloor \frac{y-1}{2} \right\rfloor. $$

After processing the current position, we increase $\mathtt{cnt}[x]$ by $1$.

The value $y$ can be maintained while scanning. If the current character is different from the previous one, then the longest alternating suffix is extended by $1$. Otherwise, it is reset to $1$.

The important corner cases in the counting part are:

- Length-$1$ substrings must not be subtracted, because they are beautiful.
- Alternating substrings of even length must not be subtracted, because they were never counted by the modulo condition.
- Only alternating substrings of odd length at least $3$ should be subtracted, which is exactly what $\left\lfloor \frac{y-1}{2} \right\rfloor$ counts.

The total time complexity is $O(n)$.

 
**Implementation(python)**
```python
for _ in range(int(input())):
    n = int(input())
    a = [1, 0, 0]
    x = 0
    ans = 0
    pre = ""
    y = 0
    for c in input():
        if c == "0":
            x -= 1
        else:
            x += 1
        x %= 3
        if c == pre:
            y = 1
        else:
            y += 1
        pre = c
        ans += sum(a) - a[x]
        a[x] += 1
        ans -= (y - 1) // 2
    print(ans)
```

## 2237E - Permutation Commutation

Idea: [_ja](<https://codeforces.com/profile/_ja>) Preparation: [Boboge](<https://codeforces.com/profile/Boboge>)

**Tutorial**

The condition $a_{b_i}=b_{a_i}$ means that the completed permutation $b$ must commute with permutation $a$.

Decompose $a$ into cycles. A permutation that commutes with $a$ maps every cycle of $a$ to another cycle of the same length, preserving the cyclic shift inside the cycle. Therefore, fixed values already written in $b$ determine which cycle must map to which cycle and which shift must be used.

For every cycle of $a$, inspect the known positions in $b$. If they force two different target cycles, two different shifts, or a target cycle with a different length, the answer is impossible. Otherwise, reserve the forced target cycle.

The remaining cycles can be paired arbitrarily with unused cycles of the same length. To obtain the lexicographically smallest permutation $b$, we match the still-unmatched cycles greedily: among cycles of the same length, the cycle whose leftmost position in $a$ is smaller should be matched to the unused target cycle whose leftmost value is smaller. After all pairings are chosen, fill every missing value of $b$ using the corresponding cyclic shift.

The implementation groups cycles by length and stores unused cycles in buckets. Since each cycle and each element is processed only a constant number of times, the total complexity is $O(n)$ per test case.


**Implementation**
```cpp
#include <bits/stdc++.h>

using namespace std;

void run(int testCase) {
 int n;
 cin >> n;
 vector<int> a(n), b(n);
 for (int i = 0; i < n; ++i) {
 cin >> a[i];
 a[i]--;
 }
 for (int i = 0; i < n; ++i) {
 cin >> b[i];
 if (b[i] != -1) {
 b[i]--;
 }
 }
 vector<int> vis(n);
 for (int i = 0; i < n; ++i) {
 if (b[i] != -1 and !vis[i]) {
 int j = i;
 while (true) {
 if (vis[j]) break;
 vis[j] = 1;
 if (b[a[j]] == -1) {
 b[a[j]] = a[b[j]];
 } else if (b[a[j]] != a[b[j]]) {
 cout << "NO\n";
 return;
 }
 j = a[j];
 }
 }
 }
 vector<int> cnt(n);
 for (int i = 0; i < n; ++i) {
 if (b[i] == -1) continue;
 cnt[b[i]]++;
 }
 for (int i = 0; i < n; ++i) {
 if (cnt[i] > 1) {
 cout << "NO\n";
 return;
 }
 }
 vector<int> vis1(n), vis2(n);
 vector<vector<int>> cycle1(n + 1), cycle2(n + 1);
 for (int i = 0; i < n; ++i) {
 if (b[i] == -1 and !vis1[i]) {
 int j = i, len = 0;
 while (!vis1[j]) {
 vis1[j] = 1;
 len++;
 j = a[j];
 }
 cycle1[len].push_back(i);
 }
 }
 for (int i = 0; i < n; ++i) {
 if (cnt[i] == 0 and !vis2[i]) {
 int j = i, len = 0;
 while (!vis2[j]) {
 vis2[j] = 1;
 len++;
 j = a[j];

 }

 while (b[x] == -1) {
 b[x] = y;
 x = a[x];
 y = a[y];
 }
 }
 }
 cout << "YES\n";
 for (int i = 0; i < n; ++i) {
 cout << b[i] + 1 << " \n"[i == n - 1];
 }
}
```

## 2237F - Paint the Array

Idea: [StarSilk](<https://codeforces.com/profile/StarSilk>) Preparation: [StarSilk](<https://codeforces.com/profile/StarSilk>) & [Sugar_fan](<https://codeforces.com/profile/Sugar_fan>)
 
**Tutorial**

Conclusion:

An array can be obtained by painting if and only if it satisfies $a_1 = 1$, $a_n = m$, and for every pair of adjacent elements $(a_i, a_{i+1})$, at least one of the following three conditions holds:

- $a_i = m$;
- $a_{i+1} = 1$;
- $a_{i+1} = a_i + 1$.

Proof:

Necessity:

First, $a_1 = 1$ is clearly necessary, because only $1$ can be painted at the position $a_1$. Similarly, we must have $a_n = m$.

Now consider any adjacent pair $a_i$ and $a_{i+1}$. If they are obtained in the same painting operation, then condition 3 clearly holds. Otherwise, they are obtained in different painting operations. If $a_i$ is painted later, then in order not to overwrite $a_{i+1}$, $a_i$ must be the last element of its painted segment, so $a_i = m$. If $a_{i+1}$ is painted later, then similarly $a_{i+1}$ must be the first element of its painted segment, so $a_{i+1} = 1$. Therefore, at least one of the three conditions above must hold.

Sufficiency:

Contract all maximal consecutive positions that belong to the same painting operation into continuous segments. Process these segments from left to right. If the current segment contains $1$, insert its painting operation after all previously performed painting operations, so that it overwrites all painting operations that occurred in the prefix. Otherwise, since the last position of the already constructed prefix must be $m$, we no longer need this operation to overwrite any previous content. Therefore, insert this painting operation before all previously performed painting operations, so that it will be overwritten by the operations in the prefix. In this way, we can always construct a valid sequence of painting operations that produces the final array.

Next, consider computing the answer with dynamic programming from left to right. Equivalently, we want to maximize the number of positions that do not need to be modified. Let $dp_i$ denote the maximum number of unchanged positions when the last unchanged position is $i$.

If the DP value at position $i$ can be transferred to position $j$ where $i \lt j$, then one of the following three conditions must hold:

- $a_j - a_i = j - i$, meaning that positions $i$ and $j$ are in the same painting operation.
- $m - a_i \lt j - i$, meaning that $j$ lies outside the right boundary of the painting segment containing position $i$.
- $a_j - 1 \lt j - i$, meaning that $i$ lies outside the left boundary of the painting segment containing position $j$.

For transition $1$, we can use buckets to maintain the DP values for each type of painting operation. For transition $2$, one position can update all positions in a suffix. For transition $3$, one position can transition from all positions in a prefix. Therefore, transitions $2$ and $3$ can be optimized using prefix maxima.

The total time complexity is $O(n)$.

 
**Implementation**
```cpp
#include<bits/stdc++.h>

using namespace std;
int a[500000], pref[500001], suf[500001], dpvl[500001], inf = 1000000000;

int main() {
    ios::sync_with_stdio(false), cin.tie(0);
    int T, n, m, i, c;
    for (cin >> T; T > 0; T--) {
        cin >> n >> m;
        for (i = 0; i < n; i++) {
            cin >> a[i];
            a[i]--;
        }
        for (i = 0; i <= n; i++) {
            pref[i] = -inf;
            suf[i] = -inf;
            dpvl[i] = -inf;
        }
        pref[0] = 0;
        for (i = 0; i < n; i++) {
            c = suf[i];
            if (i - a[i] >= 0) {
                c = max(c, dpvl[i - a[i]]);
                c = max(c, pref[i - a[i]]);
            }
            c++;
            pref[i + 1] = max(pref[i], c);
            suf[i + 1] = max(suf[i + 1], suf[i]);
            if (i - a[i] >= 0)dpvl[i - a[i]] = max(dpvl[i - a[i]], c);
            if (i - a[i] + m <= n)suf[i - a[i] + m] = max(suf[i - a[i] + m], c);
        }
        cout << n - max(suf[n], 0) << '\n';
    }
    return 0;
}
```

## 2237G - Send GCDs

Idea: [_ja](<https://codeforces.com/profile/_ja>) Preparation: [Boboge](<https://codeforces.com/profile/Boboge>)

**Tutorial**

We want to encode the original array $a$ into another array $b$, so that in the second run we can recover every value of $a$ using only gcd queries.

The key observation is the following. Consider a prime number $p$, and let $p^k$ be the largest power of $p$ such that $p^k \le 10^6$. If we query

$$ \gcd(p^k, x), $$

then the result gives exactly the power of $p$ appearing in the prime factorization of $x$.

Therefore, if a number only contains some small primes in its prime factorization, we can recover this number by querying it against the largest powers of those small primes.

In the implementation, we take the first $110$ primes. For each such prime $p$, we put the largest power $p^k \le 10^6$ into the beginning of array $b$. These values will be used as "basis" numbers for gcd queries.

Now consider all positive integers not larger than $10^6$ whose largest prime factor is among the first $110$ primes. By sieving and checking locally, there are at least $2^{18}$ such integers. We take the first $2^{18}$ of them and store them in an array $v$. Then each index from $0$ to $2^{18}-1$ can be represented by one such smooth number.

Since every $a_i \le 10^6$, each $a_i$ can be represented as a $20$-bit binary number. We concatenate all these binary representations into one long binary string. Then we split this string into blocks of length $18$, padding zeros at the end if necessary.

For each $18$-bit block, suppose its value is $x$. We append $v_x$ to array $b$. Thus, every encoded number in $b$ represents $18$ bits of information.

In the second run, the first $110$ positions of $b$ are known to be the prime-power basis numbers. For every later position $i$, we recover its actual value as follows.

Let this value be $y$. Since $y$ is composed only of the first $110$ primes, we query

$$ \gcd(y, p_j^{k_j}) $$

for every one of the $110$ stored prime powers. Each query returns the contribution of one prime in the factorization of $y$. Multiplying all these gcd values together gives back $y$ itself.

After recovering $y$, we find its index in $v$. This index is exactly the original $18$-bit block. Hence we can recover the whole binary string, and then split it back into $20$-bit blocks to obtain all values of $a$.

The construction of $b$ is non-adaptive. In the first run, we only build the array $b$. In the second run, the query strategy is fixed: for each encoded block, query it with all $110$ prime-power basis numbers.

Let $A = 10^6$ and $P = 110$. The preprocessing complexity depends on the sieve implementation: it is $O(A \log \log A)$ with a standard sieve, or $O(A)$ with a linear sieve. After preprocessing, the first run takes $O(n)$ time. The length of $b$ is

$$ P + \left\lceil \frac{20n}{18} \right\rceil, $$

up to possible small constant differences depending on the implementation. The second run uses

$$ P \cdot \left\lceil \frac{20n}{18} \right\rceil $$

gcd queries, and the remaining decoding work has the same order.


**Implementation**

```cpp
 max_p[1] = 1;

 if (max_p[i] == 0) {
 ps.push_back(i);
 for (int j = i; j <= N; j += i) {
 max_p[j] = i;
 }
 }
 }
 ps.resize(P);

 int x = p;
 while (x * p <= N) x *= p;
 pks.push_back(x);
 }

 if (max_p[i] <= ps.back()) {
 v.push_back(i);
 }
 }

}

 }

 now *= 2;
 now += bits[i + j];
 }

 }

}
```

## 2237H - Slime and Queries

Idea: [StarSilk](<https://codeforces.com/profile/StarSilk>) Preparation: [StarSilk](<https://codeforces.com/profile/StarSilk>) & [Sugar_fan](<https://codeforces.com/profile/Sugar_fan>)
 
**Tutorial**

First, assign a core to the slime. Initially, the core can be placed at any slime node. Each query can be seen as moving the core to the target node. If the node that the core moves to is already inside the slime, the cost is $0$. Otherwise, we need to pay cost $1$ to move one slime node there.

Consider the following greedy strategy. For each query, we move the core directly to the target node. However, when we need to remove a node, we do not know which node is optimal to remove, so we do not delete any node immediately. Instead, after each query, we mark all nodes that may currently be slime nodes, and only record that exactly $m$ of them are real slime nodes.

Later, when we need to move the core to some node, we first check all marks on this node. For every mark, we check whether the number of remaining nodes that can still be slime nodes is positive. If all of them still have remaining capacity, then we can determine that this node currently really contains a slime node. We decrease the target count of all marks on this node by $1$, and remove all marks from this node. Otherwise, we have to pay cost $1$ to move some other slime node here, and we also remove all marks from this node.

Let $c_i$ be the number of remaining undetermined slime nodes for the $i$-th mark, in chronological order. Since the set of marks owned by any node is always a suffix of all current marks, if $c_i \gt c_{i+1}$, then the $i$-th mark cannot actually be used more than $c_{i+1}$ times. Therefore, we can take suffix minima over $c$, that is,

$$ c_i = \min(c_i, c_{i+1}, c_{i+2}, \dots). $$

Then define

$$ d_i = c_i - c_{i-1}, $$

where $c_0 = 0$. If the earliest mark on a node is $x$, then checking this node is equivalent to finding the largest $i \le x$ such that $d_i \gt 0$, and decreasing $d_i$ by $1$. If no such $d_i$ exists, then we must pay cost $1$.

Now we prove the correctness of the greedy strategy. First, it is never better to avoid moving the core directly to the target node and instead visit some off-path node in advance to save future movement. This is because we still have to visit the target node eventually; changing the order to visit the target first and then visit that off-path node is no worse. Second, whenever we can determine that the current node contains a slime node, we should do it immediately. Each unit of some $d_i$ can save at most one unit of cost, so once it can be used to save a cost, we should use it. Keeping it for later cannot bring any extra benefit.

We can maintain this process using std::set and heavy-light decomposition. Each time the core passes through a path, after HLD decomposition, this path becomes $O(\log n)$ intervals.

Define the color of a node as the index of the earliest mark on this node. We use a set to maintain all maximal continuous segments with the same color. Then assigning a new mark to a tree path becomes range color assignment on several intervals. Before assigning the new color, we extract all continuous color segments inside these intervals. The total number of such extracted segments is amortized $O(n \log n)$, where we regard $n$ and $q$ as the same order.

For each color segment, we check all its nodes together and determine whether they can save cost $1$. We use another set to maintain all positions with $d_i \gt 0$. For a color segment whose color is $x$, we repeatedly find the largest position $i \le x$ with $d_i \gt 0$, and match it with as many nodes in this segment as possible. If no such position exists, then those nodes must contribute cost $1$.

Each matching operation either consumes all remaining value of one position with $d_i \gt 0$, or consumes all remaining nodes in the current continuous segment. Also, a new position with $d_i \gt 0$ only appears after a query, when we add a new mark to all nodes. Therefore, the total number of matching operations is also amortized $O(n \log n)$.

In conclusion, the total number of accesses to the sets is amortized $O(n \log n)$, and each access costs an extra logarithmic factor. Therefore, the total time complexity is $O(n \log^2 n)$.

## 2237I1 - DBFS Order (Easy Version)

First, define the distance $d_i$ of a node as the number of nodes colored $1$ on the path from this node to the root. Then the generated DBFS order is equivalent to sorting all nodes by increasing $d$ as the first key, and by increasing DFS order as the second key.

If we cut all edges between a node colored $1$ and its parent, the tree is divided into several connected components. Whenever we take the root of a connected component from the queue, the following process is equivalent to running a DFS inside this component using only a stack. The nodes inside the component are inserted into the DBFS order by increasing DFS order, and all children colored $1$ whose parent is inside this component are inserted into the queue by increasing DFS order.

Now contract each connected component into a single node. On the contracted tree, DBFS is exactly a BFS. A BFS order is equivalent to sorting first by depth $d$, and then by DFS order. Therefore, for nodes inside the same connected component, the one with smaller DFS order appears earlier in the DBFS order. For nodes in different connected components, we first compare the value $d$ of their component roots; the smaller one appears earlier. If the values of $d$ are equal, the one with smaller DFS order appears earlier. Hence, the DBFS order is exactly the order obtained by sorting all nodes by increasing $d$, and then by increasing DFS order.

Now consider all nodes with $d \ge x$. In the tree, they must form several subtrees. Next, consider all nodes with $d \ge x+1$. If these nodes are exactly a suffix of all nodes with $d \ge x$ when sorted by DFS order, then we can change all nodes colored $1$ with $d=x+1$ into color $0$. This decreases $d$ by $1$ for all nodes with $d \ge x+1$. Since these nodes already appear after all other nodes with $d=x$ in DFS order, removing their advantage in $d$ does not change the DBFS order.

Conversely, if the nodes with $d \ge x+1$ are not exactly a suffix of the nodes with $d \ge x$, then there is an inversion between nodes with $d=x$ and nodes with $d \ge x+1$ in DFS order. More precisely, the minimum DFS order among nodes with $d \ge x+1$ is smaller than the maximum DFS order among nodes with $d=x$. The node with the minimum DFS order among nodes with $d \ge x+1$ must have $d=x+1$ and be colored $1$. Since both its DFS order and its $d$ are minimum among those nodes, it must appear at the front of the $d \ge x+1$ part in the DBFS order. Meanwhile, the node with maximum DFS order among nodes with $d=x$ appears at the end of the $d=x$ part. This creates a DFS-order inversion between the nodes with $d=x$ and the nodes with $d \ge x+1$. Therefore, from the DBFS order, we can uniquely infer the set of nodes with $d \ge x+1$, and hence obtain all nodes colored $1$ with $d=x+1$.

If the nodes with $d \ge x+1$ are exactly a suffix of the nodes with $d \ge x$ in DFS order, we call all nodes colored $1$ with $d=x+1$ a bad chain.

From the discussion above, if a $0/1$ assignment has no bad chain, then it uniquely corresponds to one DBFS order. If a $0/1$ assignment has a bad chain, we can repeatedly find a bad chain and change all nodes on this bad chain from color $1$ to color $0$, without changing the DBFS order, until the assignment has no bad chain. Therefore, the final answer is equal to the number of $0/1$ assignments with no bad chain.

Next, consider the structure of a bad chain. The nodes with $d \ge x$ form several subtrees in the tree. The root of the rightmost such subtree must already be colored $1$, and its distance can only be exactly $x$. Therefore, if the nodes with $d \ge x+1$ are to form a suffix, they can only appear inside the rightmost subtree among the nodes with $d \ge x$. All other such subtrees must be filled entirely with color $0$.

Inside the rightmost subtree, take the node with the minimum DFS order on the bad chain. Starting from this node and repeatedly jumping to its parent, all nodes in the subtrees of its left siblings must be colored $0$, while all nodes in its right siblings must be colored $1$ and belong to this bad chain. All ancestors reached during this upward process must also be colored $0$, until we reach the root of this subtree.

After forming this bad chain inside the subtree root, we continue jumping upward from this root. For every such ancestor, the maximum depth inside the subtrees of its left siblings must be at most $x$, because all other subtrees with depth $x$ cannot contain any node colored $1$. The maximum depth inside the subtrees of its right siblings must be strictly less than $x$, because there cannot be any subtree of depth $x$ on its right.

We solve the problem using DP and inclusion-exclusion. Let $dp_{\ast,t,h}$ denote the number of assignments inside the subtree of node $t$ such that the maximum $d$ among nodes colored $1$ differs from the distance of $t$ by $h$, without considering whether a bad chain exists. Let $dpc_{\ast,t,h}$ denote the number of assignments inside the subtree of node $t$ where we force the deepest bad chain, and the difference between its distance and the distance of $t$ is $h$.

We only need to consider the deepest bad chain. If a shallower bad chain is not destroyed during the process of merging siblings above it because some sibling subtree is too deep, then a deeper bad chain will certainly not be destroyed either.

The extra dimension $\ast$ represents the current state of the subtree. There are three possible states:

- the root of the subtree is colored $0$;
- the root of the subtree is colored $1$;
- the subtree is currently generating a bad chain, which still needs to be merged with sibling subtrees later. In this state, all nodes in left sibling subtrees must be colored $0$, while all nodes in right sibling subtrees must be colored $1$.

Using the structural properties of bad chains described above, we merge the DP arrays of all children of a node. Then we enumerate whether the current node is colored $0$ or $1$, decide whether a bad chain is generated inside the subtree, and maintain all possible distances $h$.

Since $h$ is at most the size of the subtree, we can merge the arrays by a brute-force tree-knapsack style transition. For the root node $1$, the answer is the number of all assignments minus the number of assignments containing at least one bad chain. Note that when we force a bad chain to be generated, we also need to subtract the assignments that contain a deeper bad chain, because the forced bad chain must be the deepest one.

The total time complexity is $O(n^2)$.

## 2237I2 - DBFS Order (Hard Version)

In I2, some positions are forced to be colored $1$. Therefore, unlike in I1, we cannot simply change all nodes on bad chains from $1$ to $0$. We need another way to represent all DBFS orders that can be generated.

Consider a $0/1$ coloring. We define the essential distance of a node as follows: first, force all nodes colored $1$ on all bad chains to become $0$, even if some of these nodes are forced to be $1$; then count the number of nodes colored $1$ on the path from this node to the root. By the conclusion of I1, if two colorings have different essential distances at some node, then they must generate different DBFS orders. Otherwise, if all nodes have the same essential distance, then they must generate the same DBFS order.

For a bad chain, we call the part before the chain in DFS order the upper side of this bad chain, and the part after the chain in DFS order the lower side. A bad chain must satisfy the following two properties:

- There must be no node forced to be $0$ on the bad chain.
- On the upper side of the bad chain, except for the root of the subtree, there must be no node forced to be $1$.

Using these two properties, we can extract all potential bad chains inside a subtree. Due to property 2, among these potential bad chains, only nodes belonging to the lowest bad chain may be forced to be $1$. Moreover, from lower chains to upper chains, the length of their common suffix with the lowest bad chain is monotonically non-increasing, and the number of forced $1$ nodes on the chain is also monotonically non-increasing.

Conclusion 1: If two bad chains contain exactly the same set of forced $1$ nodes, then replacing the lower bad chain with the upper bad chain does not change the DBFS order. This is because the part covered by the upper chain must completely contain the part covered by the lower chain.

Conclusion 2: Excluding bad chains with no forced $1$ nodes, if two bad chains do not contain exactly the same set of forced $1$ nodes, then the DBFS orders generated by colorings containing these two bad chains must be different.

Proof of Conclusion 2: Find a forced $1$ node $u$ that lies on the lower bad chain $l_1$ but not on the upper bad chain $l_2$, and a forced $1$ node $v$ that lies on both bad chains. Let $t$ be the ancestor of $u$ on $l_2$. In the coloring corresponding to $l_1$, nodes $u$ and $t$ must have the same essential distance.

In the coloring corresponding to $l_2$, consider the path from $t$ to $u$, excluding $t$ but including $u$. The node colored $1$ closest to $t$ on this path must exist, because $u$ is forced to be $1$. This node cannot lie on a bad chain: the branch from $t$ toward $u$ is not the rightmost branch relevant to $l_2$, because there is another forced $1$ node $v$ further to the right. By the structural characterization from I1, such a node colored $1$ cannot belong to the bad chain. Therefore, $u$ and $t$ must have different essential distances. Hence, the two cases generate different DBFS orders.

Conclusion 3: Excluding bad chains with no forced $1$ nodes, a coloring with a bad chain and a coloring without a bad chain must generate different DBFS orders.

Proof of Conclusion 3: Take any forced $1$ node on the bad chain. In the coloring with the bad chain, this node has the same essential distance as the root of the subtree. In a coloring without the bad chain, since this node is forced to be $1$, it cannot have the same essential distance as the subtree root. Therefore, the two cases generate different DBFS orders.

If a bad chain contains no forced $1$ node, or if it contains exactly the same set of forced $1$ nodes as the nearest bad chain above it, then we call it a second-order bad chain. Then the number of essentially different DBFS orders is equal to the number of $0/1$ colorings with no second-order bad chain. This is because any two different colorings without second-order bad chains generate different DBFS orders.

Proof: Find the first layer from top to bottom where the two colorings differ. It must fall into one of the following cases: two different non-bad chains, which have already been proved in I1 to generate different DBFS orders; one is a bad chain and the other is not, which has been proved by Conclusion 3; or both are bad chains but they contain different sets of forced $1$ nodes, which has been proved by Conclusion 2. Therefore, such a coloring uniquely corresponds to one DBFS order.

On the other hand, if a coloring contains a second-order bad chain, we can take any such chain. If it contains no forced $1$ node, we simply remove this bad chain. Otherwise, we replace it with the highest bad chain above it that contains the same set of forced $1$ nodes. This operation removes the second-order bad chain without changing the DBFS order.

Therefore, the number of essentially different DBFS orders is equal to the number of colorings with no second-order bad chain.

Inside a subtree, except for the topmost bad chain, whether every other bad chain is a second-order bad chain is already determined. Hence, we can follow the DP idea from I1 to count the number of $0/1$ colorings with no second-order bad chain.

Based on the DP of I1, we separately maintain the DP values for the topmost chain and the DP values for configurations that already contain some determined second-order bad chain. Later, after determining whether the topmost chain is really a second-order bad chain, we either discard the DP value of the topmost chain, or move it into the second-order-bad-chain part.

The total time complexity is $O(n^2)$.
