We could deal with this by digits.

Because *lowbit*(*x*) is taking out the lowest 1 of the number *x*, we can enumerate the number of the lowest zero.

Then, if we enumerate *x* as the number of zero, we enumerate *a* as well, which *a* × 2<sup>*x*</sup> is no more than *limit* and *a* is odd. We can find out that *lowbit*(*a* × 2<sup>*x*</sup>) = 2<sup>*x*</sup>.

In this order, we would find out that the *lowbit*() we are considering is monotonically decresing.

Because for every two number *x*, *y*, *lowbit*(*x*) is a divisor of *lowbit*(*y*) or *lowbit*(*y*) is a divisor of *lowbit*(*x*).

We can solve it by greedy. When we enumerate *x* by descending order, we check whether 2<sup>*x*</sup> is no more than *sum*, and check whether there is such *a*. We minus 2<sup>*x*</sup> from *sum* if *x* and *a* exist.

If at last *sum* is not equal to 0, then it must be an impossible test.

Why? Because if we don't choose a number whose *lowbit* = 2<sup>*x*</sup>, then we shouldn't choose two numbers whose *lowbit* = 2<sup>*x* - 1</sup>. (Otherwise we can replace these two numbers with one number)

If we choose one number whose *lowbit* = 2<sup>*x* - 1</sup>, then we can choose at most one number whose *lowbit* = 2<sup>*x* - 2</sup>, at most one number whose *lowbit* = 2<sup>*x* - 3</sup> and so on. So the total sum of them is less than 2<sup>*x*</sup> and we can't merge them into *sum*.

If we don't choose one number whose *lowbit* = 2<sup>*x* - 1</sup>, then it's just the same as we don't choose one number whose *lowbit* = 2<sup>*x*</sup>.

So the total time complexity is *O*(*limit*).
## 437C - The Child and Toy
The best way to delete all n nodes is deleting them in decreasing order of their value.

Proof:

Consider each edge (*x*, *y*), it will contribute to the total cost *v*<sub>*x*</sub> or *v*<sub>*y*</sub> when it is deleted.

If we delete the vertices in decreasing order, then it will contribute only *min*(*v*<sub>*x*</sub>, *v*<sub>*y*</sub>), so the total costs is the lowest.

## 437E - The Child and Polygon
In this problem, you are asked to count the triangulations of a simple polygon.

First we label the vertex of polygon from 0 to *n* - 1.

Then we let *f*[*i*][*j*] be the number of triangulations from vertex *i* to vertex *j*. (Suppose there is no other vertices and there is an edge between *i* and *j*)

If the line segment (*i*, *j*) cross with the original polygon or is outside the polygon, *f*[*i*][*j*] is just 0. We can check it in *O*(*n*) time.
