## 2158A - Suspension

**Hint 1**

Each red card immediately suspends a player. What is the best way to use $r$ red cards to maximize the number of distinct suspended players?


**Hint 2**

A player is suspended after receiving 2 yellow cards. With $y$ yellow cards, what is the maximum number of players you can suspend using only yellows?


**Hint 3**

If you add the maximum suspensions from red cards and yellow cards, can this total ever exceed $n$? What should happen with extra cards in that case?


**Tutorial**

To determine the maximum number of players suspended, we adopt a greedy approach. The goal is to distribute the available cards to trigger the suspension condition for as many distinct players as possible.

- Red Cards: Since a single red card causes an immediate suspension, the most efficient use is to assign each red card to a unique player. Therefore, $r$ red cards can suspend exactly $r$ players.
- Yellow Cards: A player requires $2$ yellow cards to be suspended. To maximize the number of suspensions derived from yellow cards, we group them into pairs. The number of players that can be suspended using yellow cards is the integer division of $y$ by 2, denoted as $\lfloor \frac{y}{2} \rfloor$.

Combining these two, the total potential number of suspensions is $r + \lfloor \frac{y}{2} \rfloor$. However, it is impossible to suspend more players than the total number of players $n$ present in the game. If the theoretical sum is greater than $n$, the surplus cards can simply be distributed to players who are already being suspended (e.g., giving a yellow card to a player before they receive a red), effectively wasting the extra cards. Thus, the answer is constrained by $n$. Hence, the final answer is $\min\left(n, \ r + \left\lfloor \frac{y}{2} \right\rfloor\right)$.

Time Complexity: $O(1)$ per test case.


**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

void solve(){
 int n,y,r;
 cin >> n;
 cin >> y >> r;
 cout << min(n,r+y/2) << "\n";
}

int main(){
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 cout.tie(0);
 int t;
 cin >> t;
 while(t--){
 solve();
 }
}
```

## 2158B - Split
 
**Hint 1**

Does the contribution of an element depend on its exact split $(u, v)$, or only on whether $u$ and $v$ are **odd** or **even**?

 
**Hint 2**

If every distinct element contributed its maximum possible amount, what would be the upper bound of the answer?

 
**Hint 3**

Elements with frequency of the form $4k+2$ can be split as $(2k+1,\,2k+1)$, creating $0$ size imbalance. Elements with frequency of the form $4k$ can be split as $(2k-1,\,2k+1)$, creating $2$ size imbalance.

 
**Hint 4**

The number of elements with odd total frequency is always even. How can these elements help correct any size imbalance?

 
**Hint 5**

In which situation does the size imbalance become impossible to fix, making the upper bound unreachable?

 
**Hint 6**

Consider the case when the number of distinct elements with frequency of the form $4k$ is **odd**. What happens if there exists **at least one** element with odd frequency? What happens if there are **no** elements with odd frequency?

 
**Tutorial**

Given a subsequence of size $2n$, we must split it into two subsequences $p$ and $q$ of size $n$ each. For any value with total frequency $cnt$, let $u$ and $v$ be its occurrences in $p$ and $q$, respectively, with $u+v=cnt$. The contribution of this value is $$ (u \bmod 2) + (v \bmod 2), $$ so it can be $0$, $1$, or $2$.

Classify the distinct values as follows: $$ x = \#\{cnt \text{ odd}\}, \qquad y = \#\{cnt \equiv 2 \ (\text{mod }4)\}, \qquad z = \#\{cnt \equiv 0 \ (\text{mod }4)\}. $$

The theoretical maximum possible score is $$ x + 2y + 2z. $$

For values with odd $cnt$, exactly one of $u$ or $v$ must be odd, so the contribution is always $1$. For $cnt = 4k+2$, choosing $u = v = 2k+1$ gives contribution $2$ and keeps the sizes balanced. For $cnt = 4k$, one of the splits with contribution $2$ is $(u,v) = (2k+1,\,2k-1)$, which creates a size imbalance of $\pm 2$.

If $z$ is even, these imbalances cancel. If $x \gt 0$, we can fix any remaining imbalance using one odd-frequency value — without affecting the score. Thus, whenever $x \gt 0$ or $z$ is even, the theoretical maximum is achievable: $$ x + 2y + 2z. $$

Now consider the case $x=0$ and $z$ odd. All frequencies are even. To get contribution $2$ from a value with $cnt = 4k+2$, the odd split gives size difference $0 \pmod{4}$. For $cnt = 4k$, any odd split gives size difference $2 \pmod{4}$. Summing these over all values: $$ \sum_i (u_i - v_i) \equiv 2z \pmod{4}. $$ Since $z$ is odd, this is congruent to $2$, contradicting $|p| = |q|$. Thus one value must contribute $0$ instead of $2$, reducing the total by $2$.

Therefore, when $x=0$ and $z$ odd, the maximum score is $$ x + 2y + 2z - 2. $$

Hence the final answer is $$ \begin{cases} x + 2y + 2z, & \text{if } x \gt 0 \text{ or } z \text{ is even},\\[6pt] x + 2y + 2z - 2, & \text{if } x=0 \text{ and } z \text{ is odd}. \end{cases} $$

Time complexity is $O(n)$ per test case.

 
**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

void solve(){
    int n;
    cin >> n;
    vector<int> a(2*n);
    for(int i = 0;i < 2*n;i++){
        cin >> a[i];
    }

    vector<int> cnt(2*n+1);
    for(auto &x : a)cnt[x]++;

    int x = 0,y = 0,z = 0;
    for(int i = 1;i <= 2*n;i++){
        if(cnt[i] == 0)continue; 
        if(cnt[i]&1)x++;         //odd elements
        else if(cnt[i]%4)y++;    //element of form 4*k + 2
        else z++;                //element of form 4*k 
    }

    int ans = x+2*y+2*z;
    if((z&1) && x == 0)ans -= 2; 
    cout << ans << "\n";
}

int main(){
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    int t;
    cin >> t;
    while(t--){
        solve();
    }
}
```

## 2158C - Annoying Game

**Hint 1**

If Alice makes a move and Bob immediately performs the opposite move on the same index (and vice versa), what happens to the array?


**Hint 2**

How does the parity of $k$ affect who makes the last move and therefore who can enforce the final uncancelled change?


**Hint 3**

Using the cancellation idea, can the entire game be reduced to a simpler one with exactly $k \bmod 2$ effective moves?


**Hint 4**

If Alice changes $a_i$, only subarrays containing $i$ can improve. What are the maximum-sum subarrays that **end at $i$** and **start at $i$**, and how can combining them give the best subarray passing through $i$?


**Tutorial**

Let $S(a)$ denote the maximum non-empty subarray sum of array $a$. We determine the final score by analyzing the game based on the parity of $k$, assuming optimal play from both Alice and Bob.

First, consider the case where $k$ is even. Bob has a strategy to ensure the final score is at most the initial $S(a)$. Since Bob plays the even-numbered turns, he can adopt a cancellation strategy. Immediately after Alice modifies an index $i$ by adding $b_i$, Bob can modify the same index $i$ by subtracting $b_i$. This ensures that after every pair of turns, the array is restored to the state it was in before Alice's turn. After $k$ turns, the array is identical to the initial array. Thus, Bob forces the result $\le S(a_{\text{initial}})$.

We must verify if Bob can force the score lower, or if Alice can guarantee at least $S(a_{\text{initial}})$. Alice adopts the following strategy: Let the subarray $[l, r]$ be the subarray yielding the initial maximum sum. Alice identifies an index $p$ such that $l \le p \le r$ and $b_p$ is the maximum value among all $b$ in that range. In her first turn, Alice adds $b_p$ to $a_p$. For all subsequent turns, Alice adopts the cancellation strategy against Bob: if Bob modifies index $x$, Alice immediately modifies index $x$ in her next turn to restore it.

This strategy ensures that just before Bob's very last move (turn $k$), the array has exactly one modification: $a_p$ is increased by $b_p$. Bob must now make a move to minimize the score. To reduce the sum of the subarray $[l, r]$, Bob must choose an index $q$ within the range $[l, r]$ and subtract $b_q$. The new sum becomes $S(a_{\text{initial}}) + b_p - b_q$. Since Alice chose $p$ such that $b_p$ is maximal in that range, $b_p \ge b_q$. Consequently, $S(a_{\text{initial}}) + b_p - b_q \ge S(a_{\text{initial}})$. Bob is forced to choose $q=p$ to simply undo Alice's first move; otherwise, the score remains strictly greater than $S(a_{\text{initial}})$. Thus, for even $k$, the final score is exactly $S(a_{\text{initial}})$.

Next, consider the case where $k$ is odd. Alice has a strategy to maximize the result of a single independent move. She performs her desired modification on turn 1. For any subsequent move by Bob, Alice uses her next turn to cancel it. Since Alice makes the last move (turn $k$), she ensures all of Bob's actions are neutralized. Conversely, Bob can prevent Alice from achieving anything more than a single move by canceling Alice's actions during the first $k-1$ turns. The game reduces to Alice making exactly one move $a_i \leftarrow a_i + b_i$ to maximize $S(a)$.

To solve this efficiently, we use prefix and suffix maximums. Let $L[i]$ be the maximum sum of a non-empty subarray ending at $i$, and $R[i]$ be the maximum sum of a non-empty subarray starting at $i$. If Alice modifies index $i$, the maximum sum passing through $i$ is the sum of the maximum prefix ending at $i$ and the maximum suffix starting at $i$, adjusted for modified value. Since both $L[i]$ and $R[i]$ include the original $a_i$, we subtract $a_i$ once to avoid double counting, then add $b_i$ (denoting Alice modification). The final answer is the maximum of the initial score and the best possible modified sum:

$$ \max_{1 \le i \le n} (L[i] + R[i] - a_i + b_i) $$


**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

void solve(){
 int n,k;
 cin >> n >> k;
 vector<int> a(n),b(n);
 for(int i = 0;i < n;i++)cin >> a[i];
 for(int i = 0;i < n;i++)cin >> b[i];
 k &= 1; //It can be reduced as 0/1 move game

 vector<long long> L(n); //maximum sum non empty subarray ending at each position
 for(int i = 0;i < n;i++){
 L[i] = (i && L[i-1]>0 ? L[i-1] : 0ll) + a[i];
 }

 vector<long long> R(n); //maximum sum non empty subarray starting at each position
 for(int i = n-1;i >= 0;i--){
 R[i] = (i+1<n && R[i+1]>0 ? R[i+1] : 0ll) + a[i];
 }

 if(k == 0){
 long long ans = *max_element(L.begin(),L.end());
 cout << ans << "\n";
 }
 else{
 long long ans = LONG_MIN;
 for(int i = 0;i < n;i++){
 ans = max(ans,L[i]+R[i]-a[i]+b[i]);
 }
 cout << ans << "\n";
 }
}

int main(){
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 cout.tie(0);
 int t;
 cin >> t;
 while(t--){
 solve();
 }
}
```

## 2158D - Palindrome Flipping
 
**Hint 1**

Instead of directly transforming $s$ into $t$, is it enough to know how to transform any string into an intermediate string?

 
**Hint 2**

If you know how to turn any string into $0^n$ in at most $n$ operations, how can you use that to transform $s$ into $t$ in at most $2n$ operations?

 
**Hint 3**

If there is at least one position $p$ with $s_p = s_{p+1}$. Can you grow a block of equal bits starting from $[p, p+1]$?

 
**Hint 4**

How do you ensure such a position $p$ in strictly alternating string after exactly one operation?

 
**Hint 5**

When trying to grow the block to the right (or left), what happens if the next bit is equal to the block's boundary bit?
What if it is different? Can you use flipping a palindromic block (all equal bits) to force the boundary to match the next bit?

 
**Tutorial**

We use $1$-based indexing and assume $n\ge 4$. An allowed operation chooses $1\le l \lt r\le n$ such that $s_{l,r}$ is a palindrome, and flips all its bits. To transform $s$ into $t$, it is enough to show that any string can be converted to $0^n$ using at most $n$ operations. Indeed, if we find a sequence of operations turning $s$ into $0^n$ and a (possibly different) sequence turning $t$ into $0^n$, then by performing the second sequence in reverse order starting from $0^n$, we obtain $t$. Thus the total number of operations needed to convert $s$ into $t$ is at most twice the number needed to convert a single string into $0^n$.

We therefore focus on reducing an arbitrary string $s$ to $0^n$ using at most $n$ operations. If $s$ is alternating, then since $n\ge 4$, the substring $s_{2,4}$ is either $010$ or $101$, hence a palindrome. Flipping $s_{2,4}$ changes $s_2$ while leaving $s_1$ unchanged, so afterwards $s_1=s_2$. Thus in at most one step the string becomes non-alternating.

Now assume $s$ is non-alternating. Let $p$ be the smallest index with $s_p=s_{p+1}$, and initialize a block of equal bits as $L=p$, $R=p+1$. We now expand this block until it covers the entire string.

Consider the right boundary. If $R \lt n$, then:

1. If $s_{R+1}=s_R$, we simply extend the block by setting $R:=R+1$.

2. If $s_{R+1}\ne s_R$, then $s_{L,R}$ is a palindrome (all bits in the block are equal). Flipping $s_{L,R}$ toggles every bit in the block but keeps them equal, and also toggles $s_R$ while leaving $s_{R+1}$ unchanged. Thus afterwards $s_R=s_{R+1}$, and the block expands to $R:=R+1$.

A symmetric step expands the block to the left whenever $L \gt 1$. Each operation increases the size of the block by exactly $1$. After at most $n-1$ such expansions, the block covers all positions, so the string is constant.

If the resulting string is $0^n$, we are done. If it is $1^n$, then $s_{1,n}$ is itself a palindrome, and flipping it once produces $0^n$. Thus at most $n$ operations always suffice to reach $0^n$.

 
**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

vector<array<int,2>> reduce(string &s){
    int n = s.size();
    vector<array<int,2>> op;

    int p = -1; // position p such that two consecutive characters are same
    for(int i = 0;i < n-1;i++){
        if(s[i] == s[i+1])p = i;
    }
    if(p == -1){ // string is alternating
        op.push_back({0,2}); // substring of first three character must be palindrome
        s[0] ^= 1;s[1] ^= 1;
        p = 2;
    }

    char value = s[p+1];
    int L = p,R = p+1; // We maintain [L,R] such that all position in it have the same value

    while(R+1 < n){
        if(s[R+1] != value)op.push_back({L,R});
        R++;value = s[R];
    }

    while(L){
        if(s[L-1] != value)op.push_back({L,R});
        L--;value = s[L];
    }

    if(value == '1')op.push_back({0,n-1}); // We want to make all zeroes

    return op;
}

void solve(){
    int n;
    cin >> n;
    string s,t;
    cin >> s >> t;

    auto operation_s = reduce(s); // operations to reduce s to all zeroes
    auto operation_t = reduce(t); // operations to reduce t to all zeroes

    reverse(operation_t.begin(),operation_t.end());

    int moves = operation_s.size() + operation_t.size();
    cout << moves << "\n";
    for(auto &[x,y] : operation_s)cout << x+1 << " " << y+1 << "\n";
    for(auto &[x,y] : operation_t)cout << x+1 << " " << y+1 << "\n";

}

int main(){
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    cout.tie(0);
    int t;
    cin >> t;
    while(t--){
        solve();
    }
}
```

## 2158E - Sink

**Hint 1**

How would you solve the problem if every value in the grid was distinct?


**Hint 2**

When some cells have the same value, is it natural to treat a connected component of equal valued cells as a single group?
For such a group, how can you decide whether this entire group **needs** a hole?


**Hint 3**

After a single query (decreasing the value of one cell), can the beauty increase by more than 1?
How many groups from previous grid can stop needing a hole because they now have a strictly smaller neighbour?


**Hint 4**

How can you model the evolution of the grid as a graph, where edges reflect either adjacency in the grid or "time adjacency" between different versions of the same cell?


**Hint 5**

If a cell receives $k$ decreasing updates over all queries, can you model it as a chain of $k+1$ nodes (one per value over time)?
How does connecting each new node to the latest versions of its neighbours help you maintain connected components of equal values efficiently?


**Tutorial**

We maintain the grid using a graphical representation of each cell. Initially, for every cell $(i,j)$ we create one node storing its initial value $a_{i,j}$. Later, whenever a query decreases the value of a cell, we create a new node representing the updated value of that cell. Thus each cell is represented by a sequence of nodes created over time.

For every newly created node, we define its neighbours as follows. It has up to four neighbours corresponding to the latest created nodes of its grid-adjacent cells, and it also has a neighbour equal to the immediately previous node created for the same cell (if such a node exists). Therefore each node has at most five neighbours.

We define a group to be the connected component in this node-graph consisting of nodes that all have the same value, using adjacency defined exactly as above. That is, a group is a maximal set of nodes of equal value where every node is reachable from every other using only edges between equal-valued neighbours. We maintain these groups using a disjoint-set union structure over all created nodes.

A group of value $v$ is declared to be important if no node in this group has any neighbour with strictly smaller value than $v$. If a group is not a sink, then it is covered by some neighbour of smaller value and does not require a hole. The beauty of the grid is therefore the number of important groups.

Since queries only decrease values, the behaviour of the structure is very local. When a query decreases the value of cell $(i,j)$ to $v'$, we create a new node storing $v'$ and connect it to its at most five neighbours as described earlier. This new node may merge with some of its equal-valued neighbours, forming the new group that contains the updated cell.

Only the groups touching this new node can possibly change their status as important. There are two kinds of potential changes:

1. The new group containing the updated node might change from being non-important to an important group if, after the update, it no longer has any strictly smaller neighbour.

2. Any neighbouring group, whose value is now strictly larger than $v'$, may change from important to non-important because the updated node becomes a strictly smaller neighbour.

These checks are straightforward to perform because they involve only the few neighbours of the newly created node. Thus each update requires only constant work apart from the DSU merges.

After creating the initial $n m$ nodes, and after processing each query, we count the groups that are important under the current node graph. This count is exactly the beauty of the grid at that moment.

Time complexity is $O((n m + q)\cdot \alpha(n m + q))$, where $\alpha$ is the inverse-Ackermann function.


**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

const int N = 400005;
int parent[N],siz[N],important[N],val[N];

void make_set(int v,int x) {
 parent[v] = v;siz[v] = 1;important[v] = 1;val[v] = x;
}

int find_set(int v) {
 if (v == parent[v])return v;
 return parent[v] = find_set(parent[v]);
}

void union_sets(int a, int b) {
 a = find_set(a);
 b = find_set(b);
 if (a != b) {
 if (siz[a] < siz[b])swap(a, b);
 parent[b] = a;
 siz[a] += siz[b];
 important[a] = min(important[a],important[b]);
 }
}

int n,m;

vector<array<int,2>> neighbours(int r,int c){
 vector<array<int,2>> v;
 if(r)v.push_back({r-1,c});
 if(r+1 < n)v.push_back({r+1,c});
 if(c)v.push_back({r,c-1});
 if(c+1 < m)v.push_back({r,c+1});
 return v;
}

void solve()
{
 cin >> n >> m;
 vector<vector<int>> a(n,vector<int>(m)); // latest value of a given cell
 vector<vector<int>> ls(n,vector<int>(m)); // latest node created for a given cell
 for(int i = 0;i < n;i++){
 for(int j = 0;j < m;j++){
 cin >> a[i][j];
 ls[i][j] = m*i+j;
 }
 }

 for(int i = 0;i < n;i++){
 for(int j = 0;j < m;j++){
 make_set(m*i+j,a[i][j]);
 for(auto &[p,q] : neighbours(i,j)){
 if(a[p][q] < a[i][j])important[m*i+j] = 0;
 }
 }
 }

 for(int i = 0;i < n;i++){
 for(int j = 0;j < m;j++){
 for(auto &[p,q] : neighbours(i,j)){
 if(a[p][q] == a[i][j])union_sets(m*i+j,m*p+q);
 }
 }
 }

 int ans = 0;
 for(int i = 0;i < n;i++){
 for(int j = 0;j < m;j++){
 if(parent[m*i+j] == m*i+j)ans+=important[m*i+j];
 }
 }

 cout << ans << "\n";

 int q;
 cin >> q;
 int nd = n*m;

 for(int i = 0;i < q;i++){
 int r,c,x;
 cin >> r >> c >> x;
 r--;c--;
 x = a[r][c] - x;
 set<int> s;

 int mn = INT_MAX;
 for(auto &[p,q] : neighbours(r,c)){
 s.insert(find_set(ls[p][q]));
 mn = min(mn,a[p][q]);
 }
 s.insert(find_set(ls[r][c]));

 for(auto &y : s){
 ans -= important[y];
 }

 for(auto &y : s){
 if(val[y] > x)important[y] = 0;
 }

 make_set(nd,x);
 if(mn < x)important[nd] = 0;
 else important[nd] = 1;


 for(auto &y : s){
 if(val[y] == x){
 union_sets(y,nd);
 }
 }

 a[r][c] = x;
 ls[r][c] = nd++;

 s.clear();
 for(auto &[p,q] : neighbours(r,c)){
 s.insert(find_set(ls[p][q]));
 }
 s.insert(find_set(ls[r][c]));

 for(auto &y : s){
 ans += important[y];
 }

 cout << ans << "\n";
 }

}

signed main(){
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 cout.tie(0);
 int t;
 cin >> t;
 while(t--)
 solve();
 return 0;
}
```

[2158F2 - Distinct GCDs (Hard Version)](<https://codeforces.com/contest/2158/problem/F2>) Idea & Solution: [koderkushy](<https://codeforces.com/profile/koderkushy>)
 
**Tutorial**

## 2158F2 - Различные НОДы (сложная версия)

Say we are using $k$ distinct elements denoted by $X = \{x_1,x_2,\dots,x_k\}$. What is the maximum length of an integer sequence $a$ such that $\forall i$ $a_i \in X$ and GCDs of pairwise adjacent elements of $a$ are all distinct?

Construct an undirected complete graph with $X$ as the set of vertices and label the edge between $x_i$ and $x_j$ with $\gcd(x_i, x_j)$ for all valid $i,j$ (loops with $i=j$ too). If all the edge labels are distinct, an upper bound to the above question is the length of the longest path in this graph that visits any edge at most once.

For odd $k$, it is possible to visit all $\frac{k(k+1)}{2}$ edges and such a path is called an [Eulerian tour](<https://en.wikipedia.org/wiki/Eulerian_path>). No graph with other than zero or two odd-degree vertices can have an Euler tour as only the first and last nodes of the path may have odd degrees (and none if they coincide). Thus, for even $k$ we need to flip the degree parity of at least $k-2$ vertices. The optimal way to do that is by deleting a [matching](<https://en.wikipedia.org/wiki/Matching_(graph_theory)>) of size $\frac{k-2}{2}$. Thus the maximum length of such a path is

$$\frac{k(k+1)}{2}−\frac{k-2}{2}=\frac{k^2}{2}+1$$

Constructing an Eulerian tour has a simple solution described [here](<https://cp-algorithms.com/graph/euler_path.html>)

Now, it remains to find $X$ such that the edge labels are all distinct, i.e., $\gcd(x_i,x_j)$ are all pairwise distinct for all unordered pairs $(i,j)$ and $x_i \leq 10^{18}$. For the easy version of the problem, $x_i = 2^{i-1} \cdot 3^{k-i}$ will suffice. For the hard version, we can improve by extending the above to higher dimensions as

$$x_{i + j\cdot M} = 2^{i+j} \cdot 3^{i} \cdot 5^{M-1-i} \cdot 7^j \cdot 11^{M-1-j} \text{ }\forall 0\leq i,j \lt M$$

Set $M=10$ to get $|X|=100$ that allows us to construct $a$ with over $5000$ integers.

 
**Solution (Python)**
```python
from copy import deepcopy

def get_nums(k: int=10):
    nums = [
        2**(i + j) * 3**i * 5**j * 7**(k-1-i) * 11**(k-1-j)
        for i in range(k) for j in range(k)
    ]

    return nums

def eulerian_paths(max_k: int = 100):
    paths = [[], [0, 0], [1,1,0,0]]

    for k in range(3, max_k + 1):
        path = deepcopy(paths[k - 2])
        x, y = k-2, k-1

        if k % 2:
            path.extend([x, x, y, y])
            for j in range(1, x, 2):
                path.extend([j, x, j+1, y])
            path.append(0)
        else:
            path.extend([x, x, 1, y, y])
            for j in range(2, x, 2):
```

```cpp
 a *= a, p >>= 1;
 }
 return res;
```
