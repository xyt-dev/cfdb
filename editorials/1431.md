## 1431A - Selling Hamburgers

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The main idea is that $m$ should be equal to one of the values $a_i$ (because if it is different from all of the $a_i$, then we can increase it by $1$, and the answer becomes greater). So, we need to iterate on the value of $m$ from the array $a_i$, and for every such value, calculate the answer. The solution can be implemented in $O(n^2)$ or in $O(n \log n)$.

Note that the values in the input and the output may be large, so you have to use $64$-bit data types to solve this problem.


**Solution (elizarov)**
```kotlin
fun main() {
 repeat(readLine()!!.toInt()) {
 val n = readLine()!!.toInt()
 val a = readLine()!!.split(" ").map { it.toLong() }
 val answer = a.sortedDescending().withIndex().maxOf { (it.index + 1) * it.value }
 println(answer)
 }
}
```

## 1431B - Polycarp and the Language of Gods

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [awoo](<https://codeforces.com/profile/awoo>)
 
**Tutorial**

Underline every letter 'w', so that it can't be mistaken with 'vv'. The string splits into segments of letters 'v'. Out of each pair of consecutive letters 'v' at least one should be underlined. So for the minimum amount you can underline either all the odd positions of the segment or all the even ones. Thus, if the length of the segment is $len$, then $\lfloor \frac{len}{2} \rfloor$ underlined letters is enough.

Overall complexity: $O(n)$ per testcase.

 
**Solution (elizarov)**
```kotlin
fun main() {
    repeat(readLine()!!.toInt()) {
        val s = readLine()!!
        val answer = s.count { it == 'w' } + s.split("w").sumOf { it.length / 2 }
        println(answer)
    }
}
```

## 1431C - Black Friday

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>) and [awoo](<https://codeforces.com/profile/awoo>)

**Tutorial**

Let's consider the most optimal set of items of some fixed size $x$. We want the cheapest items to be as expensive as possible, so it's easy to see that taking $x$ most expensive items overall works the best.

The other observation that makes it easier to code is that you only have to consider such $x$ that are multiples of $k$. If you take some $x$ that is not multiple of $k$, then you will only make $\lfloor \frac x k \rfloor$ cheapest items cheaper compared to the nearest multiple below it.

So the solution is to iterate over multiples of $k$ and choose the best answer of them.

Overall complexity: $O(n^2)$ per testcase.


**Solution (elizarov)**
```kotlin
fun main() {
 repeat(readLine()!!.toInt()) {
 val (n, k) = readLine()!!.split(" ").map { it.toInt() }
 val p = readLine()!!.split(" ").map { it.toInt() }
 val answer = (1..n / k).maxOf { d ->
 val m = d * k
 p.subList(n - m, n - m + d).sum()
 }
 println(answer)
 }
}
```

## 1431D - Used Markers

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

Suppose, we used $k$ markers. It means that there were $k - 1$ indices $1 \lt i_1 \lt i_2 \lt \dots \lt i_{k - 1} \le n$ such that the $ord_{i_j}$ lecturer asks for a replacement. Since the $ord_{i_j}$ lecturer asks for a replacement, it means that from the last replacement at least $a_{i_j}$ lecturers gave a lecture. In other words, $i_{j - 1} + a_{i_j} \le i_j$ and $1 + a_{i_1} \le i_1$.

As a result, we get that $1 + a_{i_1} + a_{i_2} + \dots + a_{i_{k-1}} \le i_{k-1} \le n$ or $a_{i_1} + a_{i_2} + \dots + a_{i_{k-1}} \lt n$. We can understand that to get $k$ as big as possible we need to make $a_{i_1} + \dots + a_{i_{k - 1}}$ as small as possible. So it's optimal to take $k$ minima possible $a_i$-s.

If we always take several minima possible $a_i$-s then if we sort all $a_i$ we can just find the maximum prefix such that its sum is lower than $n$. It will be the answer, but we still need to restore the order.

To restore order $ord$ we can choose these $k$ minima $a_i$-s and place all other $a_i$ between them that there will be exactly $a_{i_j} - 1$ lecturers between the $i_{j - 1}$ and $i_j$ lecturers, $a_{i_1}$ lecturers before the $i_1$-th lecturer, and all other lecturers after the $i_{k - 1}$-th.

 
**Solution (elizarov)**
```kotlin
fun main() {
    repeat(readLine()!!.toInt()) {
        val n = readLine()!!.toInt()
        val a = readLine()!!.split(" ").map { it.toInt() }
            .withIndex().sortedBy { it.value }
        var i = 0
        var j = n - 1
        val answer = ArrayList<Int>(n)
        var bc = 0
        while (i <= j) {
            if (bc >= a[i].value) {
                answer += a[i++].index
                bc = 1
            } else {
                answer += a[j--].index
                bc++
            }
        }
        println(answer.joinToString(" ") { (it + 1).toString() })
    }
}
```

## 1431E - Chess Match

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

There are two possible solutions to this problem: one in $O(n^2)$, another one in $O(n \log n \log A)$. Both solutions are based on the fact that one of the cyclic shifts of the array $[1, 2, 3, \dots, n]$ is the optimal answer.

Beginning of the proof

Suppose there are $k$ players from the first team that are weaker than their opponents. Then it's always optimal to choose $k$ first players as the ones that are weaker than their opponents, and $n - k$ last players as the ones that are not weaker than their opponents (if that's not the case, we can swap two players that violate this constraint, and the answer won't become worse).

The same applies to the second team: $k$ last players will be stronger than their opponents, and $n - k$ first players will not be stronger (the proof is similar here).

Okay, now we have to pair $k$ first players from the first team with $k$ last players from the second team, assuming that the players from the first team lose. It's easy to see that if we want to maximize the minimum of $b_{p_i} - a_i$, then we need to set $p_1 = n - k + 1$, $p_2 = n - k + 2$, ..., $p_k = n$ (if this order is violated, we can swap two adjacent values in $p$, and the answer won't become worse). The same applies to $n - k$ last players from the first team and $n - k$ first players from the second team.

End of the proof

Now, the easy solution is just to try all cyclic shifts as the answer. It was enough to get AC, but it can be improved to $O(n \log n \log A)$ as follows with binary search on the answer. To check that we can make the answer at least $m$, we can use the fact that when we increase $k$, the value of $\min\limits_{i = 1}^{k} b_{n - k + i} - a_i$ decreases, and the value of $\min\limits_{i = 1}^{n - k} a_{k + i} - b_i$ increases. We can find the last $k$ for which $\min\limits_{i = 1}^{k} b_{n - k + i} - a_i \ge m$ and the first $k$ for which $\min\limits_{i = 1}^{n - k} a_{k + i} - b_i \ge m$ using another binary search, and that way, check that the answer is at least $m$.


**Solution (Ne0n25)**
```kotlin
fun main() = repeat(readLine()!!.toInt()) {
	val n = readLine()!!.toInt()
	val a = readLine()!!.split(" ").map { it.toInt() }
	val b = readLine()!!.split(" ").map { it.toInt() }

	var ans = -1
	var ans_shift = -1
	for (shift in 0 until n) {
 var res = 1e9.toInt()
 for(i in 0 until n)
 res = Math.min(res, Math.abs(a[i] - b[(i + shift) % n]))
 if (res > ans) {
 ans = res
 ans_shift = shift
 }
	}

	println(IntArray(n) { (it + ans_shift) % n + 1 }.joinToString(" "))
}
```

## 1431F - Neural Network Problem

Idea: [vovuh](<https://codeforces.com/profile/vovuh>), preparation: [vovuh](<https://codeforces.com/profile/vovuh>)
 
**Tutorial**

Binary search is pretty obvious even from the problem statement. Let's fix the maximum sum of the block $sum$. Now we have to check if we can remove at most $k$ elements to obtain some array where each block has the sum at most $sum$.

To check it, let's implement the following greedy solution: go from left to right and maintain the priority queue of $x$ minimums. Suppose we are at the position $i$ now. Add the current element $a_i$ to the priority queue and remove the biggest element from it while its size is greater than $x$ or the sum is greater than $sum$. If the size of the queue is $x$ it also means that its sum is not greater than $sum$. Let's end the current block here (just clear the queue) and start a new one from the next position. In general, we are trying to complete the block as soon as possible. It is always optimal because the earlier we end the block — the more blocks we can create (the fewer elements we have to remove). After processing all elements, let's check if the number of elements removed is not greater than $k$.

Time complexity: $O(n \log^2{n})$.

 
**Solution (vovuh)**
```kotlin
import java.util.*

fun main() {
    val (n, k, x) = readLine()!!.split(" ").map { it.toInt() }
    val a = readLine()!!.split(" ").map { it.toInt() }
    var l = 0L
    var r = 10L * 1000 * 1000 * 1000
    var res = -1L

    fun can(sum : Long) : Boolean {
        var cursum = 0L
        var need = 0
        var cur = PriorityQueue<Int>(compareBy<Int> { -it })
        for (i in 0 until n) {
            cursum += a[i]
            cur.add(a[i])
            while (cur.size > x || cursum > sum) {
                cursum -= cur.first()
                cur.remove()
                need += 1
            }
            if (cur.size == x) {
                cursum = 0L
                cur.clear()
            }
        }
        return need <= k
    }

    while (l <= r) {
        val mid = (l + r) / 2
        if (can(mid)) {
            res = mid
            r = mid - 1
        } else {
            l = mid + 1
        }
    }
    println(res)
}
```

## 1431G - Number Deletion Game

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

The key observation is that Bob should always remove the minimum integer that is greater than $a$ on his turn (proving that formally is a bit complicated, but it works). So, if we sort the array $a$, after Alice removes the number $a_i$, Bob removes the number that was after $a_i$.

So, if we sort the array $a$, should we find $k$ non-intersecting pairs $(a_i, a_{i + 1})$ such that the sum of $a_{i + 1} - a_i$ is maximum possible? Unfortunately, this is suboptimal because when an element is deleted, the numeration of other elements changes. For example, if $n = 4$, $a = [1, 2, 3, 4]$, the optimal plan for Alice is:

- erase $2$, so Bob is forced to erase $3$;
- erase $1$, so Bob is forced to erase $4$.

How to handle these renumerations? Suppose Alice has deleted the number $a_i$ from the original sorted array, and Bob has deleted the number $a_{i + 1}$. Then, if Alice deletes $a_{i - 1}$, Bob is forced to delete $a_{i + 2}$, and so on. Thus, in $x$ turns, Alice may delete the left half of some segment of length $2x$, and force Bob to delete the right half of this segment.

It can be modeled with the following dynamic programming solution: let $dp_{i, j}$ be the maximum answer if Alice considered the first $i$ numbers and deleted $j$ of them (and Bob deleted $j$ of them as well). We can either skip the following number, transitioning from $dp_{i, j}$ to $dp_{i + 1, j}$, or delete some segment of length $2x$, transitioning from $dp_{i, j}$ to $dp_{i + 2x, j + x}$ (while adding $\sum\limits_{c = i + x}^{i + 2x - 1} a_c - \sum\limits_{c = i}^{i + x - 1} a_c$ to the value of dynamic programming). These sum queries can be performed with prefix sums in $O(1)$, so overall this solution runs in $O(n k^2)$.


**Solution (Ne0n25)**
```kotlin
fun main() {
	val (n, k) = readLine()!!.split(' ').map { it.toInt() }
	val a =	readLine()!!.split(" ").map { it.toInt() }.sorted()

	val p = IntArray(n + 1) { 0 }
	for (i in 0 until n) p[i + 1] = p[i] + a[i]

	val dp = Array(n + 1) { IntArray(k + 1) { -1 } }

 dp[0][0] = 0
 for (i in 0 until n) {
 for (j in 0 until k + 1) {
 if (dp[i][j] < 0)
 continue
 dp[i + 1][j] = Math.max(dp[i + 1][j], dp[i][j])
 val maxx = Math.min(k - j, (n - i) / 2)
 for (x in 1..maxx)
 dp[i + 2 * x][j + x] = Math.max(dp[i + 2 * x][j + x], dp[i][j] + p[i + 2 * x] - p[i + x] - p[i + x] + p[i])
 }
 }

 println(dp[n][k])
}
```

## 1431H - Rogue-like Game

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

While Marina is playing the game, there will be at most $n + m$ events when she unlocks something. Let's sort all unlockables by the required score.

After Marina has unlocked something, it is quite obvious that she has to play runs with the best combination of species and class she has already unlocked, until she unlocks something else. Since the number of unlockables is at most $n + m$, Marina needs to consider only at most $n + m$ different combinations — only the best combinations available between two "unlocking" events are needed.

So, the solution consists of two parts:

- find at most $n + m$ combinations we need to consider (these are the best combinations before each "unlocking" event);
- then iterate on one of these combinations that we will boost by reading a guide, and solve the problem with $n + m$ combinations, one of which is already boosted, greedily in $O(n + m)$ or $O((n + m) \log (n + m))$.

The complexity of the model solution is $O((n + m)^2 \log (n + m))$.

 
**Solution (Ne0n25)**
```kotlin
fun main() {
	val (n, m, k) = readLine()!!.split(" ").map { it.toInt() }	
	val a = readLine()!!.split(" ").map { it.toLong() }
	val b = readLine()!!.split(" ").map { it.toLong() }
	val c = Array(n) { readLine()!!.split(" ").map { it.toLong() } }
	
	val ev = Array(n + m) {
		if (it < n)
			longArrayOf(a[it], 1L, it.toLong())
		else
			longArrayOf(b[it - n], 0L, (it - n).toLong())
	}
	
	ev.sortWith(compareBy({ it[0] }))
	
	val vals = LongArray(n + m) { 0 }
	
	for (e in 0 until n + m) {
		if (ev[e][1] == 1L) {
			val i = ev[e][2].toInt()
			vals[e] = b.indices.filter { b[it] <= ev[e][0] }.map { c[i][it] }.max()!!
		} else {
			val j = ev[e][2].toInt()
			vals[e] = a.indices.filter { a[it] <= ev[e][0] }.map { c[it][j] }.max()!!
		}
	}
	
	var ans = 1e18.toLong()
	
	for (bonus in 1 until n + m) {
		vals[bonus] += k.toLong()
		var (res, cur, mx) = LongArray(3) { 0 }
		var i = 0
		while (true) {
			while (i < n + m && ev[i][0] <= cur) {
				mx = Math.max(mx, vals[i])
				++i;
			}
			if (i == n + m) break
			val need = (ev[i][0] - cur + mx - 1) / mx
			res += need
			cur += need * mx
		}
		ans = Math.min(ans, res)
		vals[bonus] -= k.toLong()
	}

	println(ans)
}
```

## 1431I - Cyclic Shifts

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

There are several solutions to the problem, even unexpected ones, like trie merging. But let's describe the author's solution.

Let's suppose to make the string query $t$ appear we made $k$ cyclic shifts of suffixes $1 \lt i_1 \lt i_2 \lt \dots \lt i_k \le m$. It equivalent to building $t$ as concatenation of substrings $s_{r_1}[1 \dots i_1 - 1]$ from some row $r_1$, $s_{r_2}[i_1 \dots i_2 - 1]$ from other row $r_2$ and so on.

Let's define a string on row $r$ starting from column $c$ as $s_{r,c}$ and character on row $r$ and column $c$ as $ch_{r,c}$.

It's not hard to prove that there is a greedy strategy: at first, you should find such row $r_1$ that $s_{r_1, 1}$ and $t$ has the maximum common prefix (let's name its length as $l_1$). Then we "cut" this prefix from $t$ and find $r_2$ that $s_{r_2, 1 + l_1}$ and $t$ has the maximum common prefix and so on. If we found the whole string $t$ then the answer is the number of segments minus one, otherwise, it's impossible to build $t$.

The question is how to find these common prefixes. To do it, we can sort all $s_{r, c}$ in each column $c$ lexicographically in the following way:

- if $c = m$, then $s_{r,c} = ch_{r, c}$, and we can sort strings manually;
- otherwise, we know that $s_{r,c} = ch_{r,c} + s_{r, c + 1}$, so we assign to $s_{r,c}$ a pair $(ch_{r,c}, \text{index of $s_{r, c + 1}$ in lexicographical order})$ and we can sort these pairs instead.
 In total, complexity of sorting is $O(nm \log(n))$.
Now, for starting column $c$ we need to find the longest common prefix of $t$ and any $s_{i, c}$. Since we already sorted $s_{i, c}$, we know that all strings starting from character $t_1$ form a segment in it and we can binary search its left and right border $[l_1, r_1]$. Then all strings starting from two characters $t_1 t_2$ form a subsegment $[l_2, r_2] \subseteq [l_1, r_1]$, so we can binary search $l_2$ and $r_2$ inside segment $[l_1, r_1]$.

In other words, we can binary search the first character $t_1$ in all rows, then binary search the second character $t_2$ inside the segment $[l_1, r_1]$ and so on while the segment is not empty. In total, we make $O(m)$ binary searches per query $t$ with total complexity $O(m \log(n))$.

The total complexity is $O((n + q)m \log(n))$.


**Solution (Ne0n25)**
```kotlin
import java.io.PrintWriter

fun main() {
	val (n, m, q) = readLine()!!.split(' ').map { it.toInt() }
	val s = Array(n) { readLine()!! }
	val c = Array(m + 1) { IntArray(n) { 0 } }
	val rc = Array(m + 1) { IntArray(n) { 0 } }

	for (j in m - 1 downTo 0) {
 val cur = Array(n) { intArrayOf(s[it][j].toInt(), c[j + 1][it], it) }
 cur.sortWith(compareBy({it[0]}, {it[1]}))
 for (i in 0 until n) rc[j][i] = cur[i][2]
 c[j][cur[0][2]] = 0
 for (i in 1 until n) {
 val add = if (cur[i][0] == cur[i - 1][0] && cur[i][1] == cur[i - 1][1]) 0 else 1
 c[j][cur[i][2]] = c[j][cur[i - 1][2]] + add
 }
	}

	val writer = PrintWriter(System.out)

	repeat(q) {
 val t = readLine()!!
 var ans = 0
 var j = 0
 while (j < m) {
 var (nj, L, R) = intArrayOf(j, 0, n - 1)
 while (nj < m) {
 var (l1, r1, nL) = intArrayOf(L, R, R + 1)
 while (l1 <= r1) {
 val mid = (l1 + r1) / 2
 if (s[rc[j][mid]][nj] >= t[nj]) {
 nL = mid
 r1 = mid - 1
 } else {
 l1 = mid + 1
 }
 }

 var (l2, r2, nR) = intArrayOf(nL, R, nL - 1)
 while (l2 <= r2) {
 val mid = (l2 + r2) / 2
 if (s[rc[j][mid]][nj] <= t[nj]) {
 nR = mid
 l2 = mid + 1
 } else {
 r2 = mid - 1
 }
 }

 if (nL > nR)
 break

 L = nL
 R = nR
 ++nj
 }

 if (j == nj) {
 ans = 0
 break
 }

 ans += 1
 j = nj
 }

 writer.println(ans - 1)
	}

	writer.close()
}
```

## 1431J - Zero-XOR Array

Idea: [Neon](<https://codeforces.com/profile/Neon>), preparation: [Neon](<https://codeforces.com/profile/Neon>) and [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

Let's reformulate our problem as the following: we need to choose $n-1$ elements $b_i$ such that $a_i \le b_i \le a_{i + 1}$ and $b_1 \oplus \dots \oplus b_{n - 1} = a_1 \oplus \dots \oplus a_n$. We can solve this problem from the most significant bit to the least significant bit.

On each bit level $pw$, for each $b_i$ we have a segment of possible values $[l, r]$. Let's define the $pw$-th bit of a value $x$ as $x(pw)$. If the $l(pw) = r(pw)$, we have no choice for $b_i$ and segment $[l, r]$ doesn't change. Otherwise, $l(pw) = 0$ and $r(pw) = 1$. And we have two choices:

- if we choose $b_i(pw) = 0$ then the left border $l$ doesn't change, but the right border $r$ becomes $2^{pw} - 1$ (it's not exactly $2^{pw} - 1$, but since we iterate $pw$ in descending order we can ignore all bits higher than $pw$);
- if we choose $b_i(pw) = 1$ them the right border $r$ doesn't change, but the left border $l$ becomes $0$ (we also ignore all bits higher than $pw$).

As a result, we can note that the left border is either initial $a_i$ or $0$ and the right border is either initial $a_{i + 1}$ or $2^{pw} - 1$. It leads us to the bitmask dynamic programming with $4$ states for each $b_i$. But even with a broken profile technique, it will be something like $O(4^n n \cdot B)$ where $B$ is the number of bits. So let's look further.

Note, that if we meet the state where the left segment is $0$ and the right is $2^{pw} - 1$ then this situation is special since we can choose any possible combination of other values of $b_j$ and counter it with exactly one number in $[0, 2^{pw} - 1]$ such that XOR of all $b_i$ will be exactly $a_1 \oplus \dots \oplus a_n$. So, if we meet this state in at least one $b_i$ we can explicitly calculate the answer as the product of all segments $[l, r]$ except this one.

From the other side, if the left border became $0$ (or the right became $2^{pw} - 1$) it will persist later and the state will change only to $[0, 2^{pw} - 1]$ when we choose the opposite step. For example, if for the $b_i$ we at first chose to set $0$ (and met the state $[l, 2^{pw} - 1]$) and if after that we choose more $0$, the state won't change. Only after choosing $1$ we'll meet the state $[0, 2^{pw} - 1]$.

In other words, we can for each $b_i$ choose: will we set several $0$-s and then $1$, or several $1$-s and then $0$. And that's only $2^{n - 1}$ states. Now for each such mask, let's iterate over the first bit-level $pw$ where we choose to make an opposite step (so on the next level we'll get the special situation). To calculate the answer for this $pw$ we can find for each $b_i$ the segment $[l, r]$ which will be uniquely determined by the mask, and calculate $dp[n][2][2]$, where $dp[pos][parity][flag]$ is the number of ways to choose $b_i$ from the whole segment $[l, r]$ on prefix of length $pos$ with XOR of $b_i(pw)$ equal to $parity$ and $flag$ is true if at least one $b_i(pw)$ was chosen in opposite to the mask way.

The answer for level $pw$ (total sum of all special cases on the next level) is equal to $dp[n][(a_1 \oplus \dots \oplus a_n)(pw)][1] \cdot 2^{-pw}$ (since we exclude length of the segment of one $[0, 2^{pw} - 1]$).

In total, the complexity of the solution is $O(2^n B \cdot n)$, but it needs a very careful implementation since we should set at least one $0$ before $1$ and handle situations where we have no actual choice since $l(pw) = r(pw)$.

 
**Solution (Ne0n25)**
```kotlin
fun main() {
	val MOD = 998244353
	
	fun add(x : Int, y : Int) : Int {
		return x + y - if (x + y < MOD) 0 else MOD	
	}
	
	fun mul(x : Int, y : Int) : Int {
		return (1L * x * y % MOD).toInt()
	}
	
	val inv = IntArray(60) { 0 }.also { it[0] = 1; it[1] = (MOD + 1) / 2 }
	for (i in 2 until 60) {
		inv[i] = mul(inv[i - 1], inv[1])
	}
	
	val n = readLine()!!.toInt()
	val a =	readLine()!!.split(" ").map { it.toLong() }
	val target = a.fold(0.toLong()) { res, it -> res xor it }
	val dp = Array(n) { Array(2) { IntArray(2) { 0 } } }
	
	var ans = 0
	
	val m = 1 shl (n - 1)
	for (mask in 0 until m) {
		val cur = Array(n - 1) { longArrayOf(a[it], a[it + 1]) }
		val used = BooleanArray(n - 1) { false }
		
		for (pw in 59 downTo 0) {
			for (i in 0 until n)
				for (cnt in 0 until 2)
					for (fl in 0 until 2)
						dp[i][cnt][fl] = 0
			dp[0][0][0] = 1
			for (i in 0 until n - 1) {
				for (cnt in 0 until 2) {
					for (fl in 0 until 2) {
						if (dp[i][cnt][fl] == 0)
							continue
						val (l, r) = cur[i]
						if ((l shr pw) == (r shr pw)) {
							if (!used[i] && ((mask shr i) and 1) == 1)
								continue
							val c = (l shr pw).toInt()
							val len = (cur[i][1] - cur[i][0] + 1)
							dp[i + 1][cnt xor c][fl] = add(dp[i + 1][cnt xor c][fl], mul((len % MOD).toInt(), dp[i][cnt][fl]))
						} else for (c in 0 until 2) {
							if (!used[i] && (c != (mask shr i) and 1))
								continue
							val nl = if (c == 1) 0L else l
							var nr = if (c == 1) r - (1L shl pw) else (1L shl pw) - 1
							val len = nr - nl + 1
							val nfl = if (len == (1L shl pw) && (c != ((mask shr i) and 1))) 1 else 0
							dp[i + 1][cnt xor c][fl or nfl] = add(dp[i + 1][cnt xor c][fl or nfl], mul((len % MOD).toInt(), dp[i][cnt][fl]))
						}
					}
				}
			}
			
			var cnt = ((target shr pw) and 1).toInt()
			ans = add(ans, mul(dp[n - 1][cnt][1], inv[pw]))
			if (pw == 0) 
				ans = add(ans, dp[n - 1][cnt][0])
			
			for (i in 0 until n - 1) {
				val (l, r) = cur[i]
				if ((l shr pw) == (r shr pw)) {
					val c = (l shr pw)
					cnt = cnt xor c.toInt()
					cur[i][0] -= c shl pw
					cur[i][1] -= c shl pw
				} else {
					used[i] = true
					val c = (mask shr i) and 1
					cnt = cnt xor c.toInt()
					cur[i][0] = if (c == 1) 0 else cur[i][0]
					cur[i][1] = if (c == 1) cur[i][1] - (1L shl pw) else (1L shl pw) - 1
				}
			}
			
			if (cnt != 0)
				break
		}
	}
	
	println(ans)
}
```
