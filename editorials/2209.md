## 2209A - Flip Flops


- Idea: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Solution: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Editorial: [OtterZ](<https://codeforces.com/profile/OtterZ>)

**Solution**

It's sure that OtterZ will kill as many monsters as he can. To make use of flip flops, OtterZ will keep throwing flip flops if he has flip flops left and the monsters' combat power is strictly weaker ($c \gt a_i$).

A simple algorithm can be $\mathcal{O}(Tn^2)$; if you want to make it faster, you can consider that the weakest monster that remains is always the one that can be killed if there are still some monsters that can be killed, then sort all the monsters and kill them one by one. This leads to a faster algorithm in $\mathcal{O}(Tn\log n)$.


**Code (C++)**
```cpp
#include<bits/stdc++.h>
using namespace std;
int n,a[109],k;
long long C;
int main(){
	int t;
	scanf("%d",&t);
	while(t--){
 scanf("%d %lld %d",&n,&C,&k);
 for(int i = 1; i <= n; i ++){
 scanf("%d",&a[i]);
 }
 sort(a + 1,a + n + 1);
 for(int i = 1; i <= n; i ++){
 if(a[i] > C)
 break;
 int o = min(1ll * k,C - a[i]);
 k -= o;
 C += a[i] + o;
 }
 printf("%lld\n",C);
	}
}
```

## 2209B - Array
 

- Idea: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Solution: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Editorial: [OtterZ](<https://codeforces.com/profile/OtterZ>)
  
**Solution**

As $|a_i - k| \gt |a_j - k|$ leads to $k \lt \frac{a_i + a_j}{2}, a_i \gt a_j$ or $k \gt \frac{a_i + a_j}{2}, a_i \lt a_j$. It is clear that we should choose $k$ to be either much larger than the maximum value or much smaller than the minimum value.

Then we need to compute:

$f1_i = \sum_{j = i + 1}^n[a_i \gt a_j],f2_i = \sum_{j = i + 1}^n[a_i \lt a_j]$

Which can be done using bruteforce in $\mathcal{O}(n^2)$ or Fenwick tree in $\mathcal{O}(n\log n)$.

## 2209C - Find the Zero
 

- Idea: [__baozii__](<https://codeforces.com/profile/__baozii__>)

- Solution: [__baozii__](<https://codeforces.com/profile/__baozii__>)

- Editorial: [__baozii__](<https://codeforces.com/profile/__baozii__>)
  
**Solution**

Firstly, the specific values of integers greater than $0$ do not matter as the only case where $a_i=a_j$ is when both $a_i$ and $a_j$ are zero.

Consider the following strategy:

- For every pair $(2i-1,2i)$ such that $1 \le i \le n$, we query $(2i-1,2i)$. If any pair is equal, we are done. This phase uses at most $n$ queries.
- Otherwise, since the array contains exactly $n$ zeroes, there must be exactly one zero in every pair. We now query if $(1,3)$ and $(1,4)$. Similarly, if any of them returns $1$, we are done. Otherwise, $a_1$ must be non-zero, which implies that $a_2$ must be zero. This phase uses at most $2$ queries.

The above strategy is correct, but it uses $n+2$ queries rather than $n+1$. Are any of the queries redundant?

In fact, yes. We actually do not need to query $(1,2)$ at all! To prove this fact, we shall do some casework. Since at any point in time, we are done if we receive a $1$ from the judge, we can assume that all queries have returned a $0$:

- $a_1\ne 0$, $a_2 \ne 0$: This implies that there are $n$ zeroes among the remaining $2n-2$ elements. By the pigeonhole principle, there must be at least one pair $(2i-1,2i)$ such that $a_{2i-1}=a_{2i}=0$. However, this is impossible as all queries have returned $0$.
- $a_1=0$, $a_2\ne 0$: This implies that $a_3\ne 0$ and $a_4\ne 0$, as we queried $(1,3)$ and $(1,4)$. Following the same argument as the first case, there are $n-1$ zeroes among the remaining $2n-4$ elements, which is impossible.

This only leaves the case where $a_2=0$. Thus, the strategy above is still correct even if we do not query $(1,2)$, and we have solved the problem in $n+1$ queries.

## 2209D - Ghostfires


- Idea: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Solution: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Editorial: [OtterZ](<https://codeforces.com/profile/OtterZ>)

**Solution**

The sequence of colors of the ghostfires has a special feature:

When three continuous ghostfires with different colors, the color of the next one must be equal to the second one.

Using the feature, it can be proven that the task is the same as pairing two ghostfires with different colors; then it's valid to add just a single ball. This means that it's valid to select a set of balls $S$ if none of the number of balls of a color is above $\lceil {\frac{|S|}{2}} \rceil$.

To construct the answer, make the balls into several pairs in which the two balls in a pair are different and at most one single ball. An easy way is to choose the two colors with the most remaining balls all the time. Then what to do is to put the single ghostfire first,then the three types of pairs,remember to choose the pairs with the same color ghostfires as the first ghostfire to avoid getting wrong on case $r = g = b = 2$, which can be done in $\mathcal{O}(r + g + b)$.

## 2209E - A Trivial String Problem
 

- Idea: [__baozii__](<https://codeforces.com/profile/__baozii__>)

- Solution: [__baozii__](<https://codeforces.com/profile/__baozii__>)

- Editorial: [__baozii__](<https://codeforces.com/profile/__baozii__>)
  
**Solution**

Firstly, some basic knowledge we need for the solution:

- A border of a string $s$ is a non-empty string $t$ such that $|t| \lt |s|$, and $t$ is simultaneously a prefix and a suffix of $s$. For example, both $\texttt{a}$ and $\texttt{aba}$ are borders of $\texttt{abacaba}$; $\texttt{aaa}$ is a border of $\texttt{aaaa}$. If a string does not have any borders, we call it unbordered; otherwise, we call it bordered. For example, $\texttt{abaabb}$ is unbordered.
- If $c$ is a border of $b$, and $b$ is a border of $a$, then $c$ is a border of $a$. This can be easily derived from the definition of borders.
- Consider all borders of a string $s$. Let them be $b_1,b_2,\ldots,b_k$ when sorted in increasing order of their lengths. Then for every $1 \le i \lt k$, $b_i$ is a border of $b_{i+1}$.

Now, we will derive the solution step by step. A partition will be referred to as optimal if it contains the most number of substrings.

Lemma 1. For a string $s$, it is either unbordered, or its shortest border is unbordered.

Proof. Suppose $s$ is bordered, and its shortest border $t$ is also bordered. Then, there exists a border $w$ of $t$, which will also be a border of $s$, contradicting the fact that $t$ is the shortest border of $s$.

Lemma 2. For a string $s$, there exists one and only one partition of $s$ into its unbordered prefixes.

Proof. We shall prove by induction. Let a possible partition be $s=t_1+t_2+\ldots+t_k$. Consider two cases:

- If $s$ is unbordered, the only possible partition is $s$ itself. This is because the last substring, $t_k$, must either be $s$ or a border of $s$ (prefix by definition of partition, suffix by being the last substring).
- Otherwise, since $t_k$ is an unbordered border of $s$, it is the shortest border of $s$. Thus, the last substring of the partition is fixed. This reduces the problem to partitioning $t_1+t_2+\ldots+t_{k-1}$.

Corollary 3. The unique partition of $s$ into its unbordered prefixes can be obtained by iteratively trimming the shortest border of $s$ until $s$ is unbordered.

Lemma 4. In an optimal partition of $s$ into its prefixes (not necessarily unbordered), all substrings must be unbordered.

Proof. If any $t_i$ in the partition of $s$ is bordered, we can partition it further into the unbordered prefixes of $t_i$, which will also be unbordered prefixes of $s$.

Theorem. The unique optimal partition of $s$ into its prefixes can be obtained by iteratively trimming the shortest border of $s$ until $s$ is unbordered.

Proof. All substrings in the optimal partition are unbordered (Lemma 4) $\to$ There exists a unique partition into unbordered prefixes (Lemma 2) $\to$ This partition can be obtained by iteratively trimming the shortest border (Corollary 3).

Now we will discuss how to implement this algorithm efficiently. Notice that the constraints allow a $O(nq)$ solution, so we can treat each query independently. Thus, we will discuss how to solve the problem for a single string $s$.

Firstly, compute the $\pi$ array of $s$ using KMP, where $\pi_i$ is the length of the longest border of $s[1..i]$. However, instead of the longest border, we need the shortest one. Let $b_i$ be the length of the shortest border of $s[1..i]$, or $0$ if no border exists. $b$ can also be easily computed by a simple linear scan:

$$b_i= \begin{cases} 0& \pi_i=0 \\ \pi_i & \pi_{\pi_i}=0 \\ b_{\pi_i} & \text{otherwise} \end{cases} $$

Lastly, the $f$ value of all prefixes of $s$ can be computed by another linear scan. Let $dp_i=f(s[1..i])$:

$$dp_i= \begin{cases} 1 & b_i = 0 \\ dp_{i-b_i}+1 & \text{otherwise} \end{cases} $$

As such, we have solved the problem in $O(nq)$ time.

 
**Code (Python)**
```python
import sys
input = lambda: sys.stdin.readline().strip()
def work(s):
    n = len(s)
    p = [0] * n
    b = [0] * n
    for i in range(1, n):
        j = p[i - 1]
        while j and s[i] != s[j]:
            j = p[j - 1]
        if s[i] == s[j]:
            j += 1
        p[i] = j
        if j == 0:
            b[i] = 0
        elif p[j - 1] == 0:
            b[i] = j
        else:
            b[i] = b[j - 1]
    ans = 0
    for i in range(n):
        p[i] = 0
        p[i] = p[i - b[i]] + 1
        ans += p[i]
    return ans

for _ in range(int(input())):
    n, q = map(int, input().split())
    s = input()
    for _ in range(q):
        l, r = map(int, input().split())
        print(work(s[l - 1:r]))
```

## 2209F - Dynamic Values And Maximum Sum


- Idea: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Solution: [OtterZ](<https://codeforces.com/profile/OtterZ>)

- Editorial: [OtterZ](<https://codeforces.com/profile/OtterZ>)

**Solution**

It can be observed that the values become fixed after the first operation because all the values were transformed to the leaf nodes. Therefore, we can use a DFS starting from the node you choose in the first operation and apply a greedy strategy for the remaining days.

Set any node as the root when DFS. The difference in values between choosing a node and its parent involves only two changes(the value in the node will be added and set to $0$ first and the value in the node of the father node will be transformed), which allows an $\mathcal{O}(n \log n)$ rerooting solution.

My way to get the sum of the first $k - 1$ values is to use a set. Bruteforce on the answer one of the nodes and then use a pointer to save the $k-1$-th value. When a value larger than or the same as the value that the pointer pointed to is deleted or added, the updation is simple.
