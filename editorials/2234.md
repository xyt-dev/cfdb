## 2234A - Euclid, Sequence and Two Numbers

Idea: [FairyWinx](<https://codeforces.com/profile/FairyWinx>)

**Hint 1**

Note that $(a_i \bmod a_{i + 1}) \lt a_{i + 1}$.


**Hint 2**

$a_{i + 2} = (a_i \bmod a_{i + 1}) \lt a_{i + 1}$ and $a_2 \le a_1$ mean that the sequence $a$ must be non-increasing. On the other hand, there is only one permutation of the sequence $b$ that can be non-increasing.


**Solution**

Note that any Euclid algorithm sequence is non-increasing: $a_2 = y \le x = a_1$, and for $i \ge 2$, $a_{i + 1} = (a_{i - 1} \bmod a_i) \le a_i$.

Then the only permutation of $b$ that can be a Euclid algorithm sequence is $b$ sorted in non-increasing order.

We sort $b$ in non-increasing order and check whether the resulting sequence is a Euclid algorithm sequence, i.e., we check whether for each $1 \leq i \leq k - 2$ the condition $a_{i + 2} = (a_i \bmod a_{i + 1})$ is satisfied.

```python
 a.sort()
 a = a[::-1]

 for i in range(2, n):
 if a[i] != a[i - 2] % a[i - 1]:
 print(-1)
 valid = False
 break
 if valid:
 print(a[0], a[1])
```

```cpp
    }

        cout << -1 << "\n";
    }
```

## 2234B - Palindrome, Twelve and Two Terms

Idea: [Fakewave](<https://codeforces.com/profile/Fakewave>)

**Solution**

Let us notice that all remainders modulo $12$, except $10$, are palindromes. And for remainder $10$, the number $22$ is a palindrome. So let us make the following construction:

- If $n$ modulo $12$ has remainder $10$, then take $a = 22$ and $b = n - 22$. Then $b$ is obviously divisible by $12$, and $a$ is a palindrome.
- Otherwise, take as $a$ the remainder of $n$ modulo $12$, and as $b$ the number $n - a$.

This construction works for all $n$, except $10$, and for $10$ it can be shown by brute force that no suitable pairs exist.


**Code (Python)**

```python
 print(n % 12, n - (n % 12))
```

## 2234C - Vessels, Heights and Two Versions (Easy Version)

Idea: [yanb0](<https://codeforces.com/profile/yanb0>)

**Hint**

Intuitively, the farther a vessel from the empty one, the more water there can be. Fix the empty vessel and try to explicitly find the formula for the maximum possible water height in each of the other vessels.


**Solution**

[Further, all indices and intervals will be taken modulo $n$.]

Fix the empty vessel as vessel $l$. Let's see what is the largest volume that vessel $i$ can contain for $i \ne l$. $w_i \le \max(w_{i-1}, h_{i-1})$, otherwise an obvious contradiction with the condition follows. Thus, $w_i \le \max(h_l, h_{l+1}, \ldots, h_{i-1})$. Similarly, $w_i \le \max(h_{l-1}, h_{l-2}, \ldots, h_i)$. It is easy to see that if for all $w_i$ we take the maximum value $w_i = \min(\max(h_l, h_{l+1}, \ldots, h_{i-1}), \max(h_{l-1}, h_{l-2}, \ldots, h_i))$ allowed by these conditions, then $w$ will satisfy the conditions, and therefore the sum $\min(\max(h_l, h_{l+1}, \ldots, h_{i-1}), \max(h_{l-1}, h_{l-2}, \ldots, h_i))$ over all $i \ne l$ will be the maximum capacity when vessel $l$ is empty.

The prefix maxima on each side can be calculated in $\mathcal{O}(n)$ for each $l$, and the total time complexity is $\mathcal{O}(n^2)$.


**Code (Python)**

```python
 ans.append(sum(w))

```

## 2234D - XOR, Expression and Two Binary Numbers

Idea: [Fakewave](<https://codeforces.com/profile/Fakewave>)

**Hint 1.1**

Let $A = a_1$, $B = a_{2^k + 1}$, $C = A \oplus B$.

Try to write out some values of $a$, for example, for $k = 3$.


**Hint 1.2**

$A \oplus B = C$, $B \oplus C = A$, $C \oplus A = B$.


**Hint 1.3**

Let's see how $a$ changes step by step:


- `a = [A, ?, ?, ?, ?, ?, ?, ?, B]`;

- `a = [A, ?, ?, ?, C, ?, ?, ?, B]`;

- `a = [A, ?, B, ?, C, ?, A, ?, B]`;

- `a = [A, C, B, A, C, B, A, C, B]`.

Try to notice and prove a pattern.


**Solution 1**

Let the first number be $A$ and the last number be $B$. Then all numbers will be either $A$, $B$, or $C = A\oplus B$. This is true because it is easy to show by induction that for each assignment, we take the XOR of one of the three pairs $(A, B)$, $(B, C)$, or $(C, A)$, and $A\oplus B = C$, $B\oplus C = A$, and $C\oplus A = B$.

It remains to note the following fact: if elements have equal remainders modulo $3$, then they are equal. In other words: all numbers of the form $a_{3i}$ are the same, all numbers of the form $a_{3i+1}$ are the same, and all numbers of the form $a_{3i+2}$ are the same.

Proof: We will show that each binary number $A, B, C$ can be assigned its own remainder modulo $3$. Let us associate $1$ with $A$, $B$ — $(2^k + 1) \bmod 3$, and $C$ — $(2^{k-1}+ 1) \bmod 3$ (it is easy to verify that all three remainders are distinct). Then suppose we are at the $t$th step of the process, and before it it is true that each filled row contains a corresponding binary number from $A, B, C$. It suffices to show that after this step the correspondence remains true. To do this, it is enough to understand that $\frac{p_{j}+p_{j+1}}{2} \neq p_j$ and $\frac{p_{j}+p_{j+1}}{2} \neq p_{j+1}$ modulo $3$ (this is equivalent to $p_j \neq p_{j+1}$, which can also be fixed as an invariant), since then this remainder is equal to the one that is not among $a_{p_j}$ and $a_{p_{j+1}}$, and therefore corresponds to the remaining number that is obtained by applying the XOR operation to the numbers $a_{p_j}$ and $a_{p_{j+1}}$.

Now it remains to count the number of occurrences of each of the numbers $A, B, C$ in $a$ and understand how many times they appear in the table (and this is done with simple formulas).

**Hint 2.3**

For every pair of bits $(x, y)$, count the number of positions $h$ for which the $h$-th bits of $a_1$ and $a_{2^k+1}$ are $x$ and $y$ respectively. Continue recursively.

 
**Hint 2.4**

Use caching.

 
**Solution 2**

Let the answer for the problem where $a_1 = A$, $a_{2^k+1} = B$ and $k = l$ be $F(l, A, B)$.

Then, as we write a value $A \oplus B$ in the middle of the array on the first step and then continue recursively, like for $k = l - 1$, $F(l, A, B) = F(l - 1, A, A \oplus B) + F(l - 1, A \oplus B, B) - [\text{product of the } 0 \text{ and } 1 \text{ bit counts for } A \oplus B]$.

Referring to the proof in Solution 1 that each $a_i \in [A, B, C]$, for each $l$ the function's value must be calculated for different pairs of $(A, B)$ at most $6$ times, thus, if we use a map for caching the answer of $F$, we will make not more than $6k$ calls to it, which makes the time complexity $\mathcal{O}(n + k \log k)$.

## 2234E - Vlad, Misha and Two Arrays

Idea: [Fakewave](<https://codeforces.com/profile/Fakewave>)

**Hint 1.1**

Looking only at the array $a$, how to deduce the index $i$ for which $p_i = 1$, i.e. the minimum of $p$?


**Hint 1.2**

Try to come up with a recursive solution that works in $\mathcal{O}(n^2)$.


**Solution 1 (yanb0)**

First, we will present a solution in $\mathcal{O}(n^2)$, then we will show how to optimize it to $\mathcal{O}(n \log n)$.

Let's recursively find the number of ways to arrange a set of $r - l + 1$ distinct numbers in $p$ positions on the interval $[l, r]$, — provided that the elements of $p$ immediately to the left and right of the interval (if they exist) are already given and strictly less than the numbers we are currently distributing — starting with $[1, n]$ and $n$ numbers ($1, 2, \ldots, n$):

1. If the interval consists of a single element ($l = r$) or is empty, there is obviously exactly one way. Otherwise:

2. Find *any* index $l \le i \le r$ for which $a_i = (i - l + 1)(r - i + 1)$. Clearly, $p_i$ must be the minimum element among $p_l, p_{l + 1}, \ldots, p_r$ in this and only this case. If no such index exists, there is no suitable permutation.

3. Recursively find the answers (the number of ways to arrange a fixed subset of elements) on the intervals $[l, i - 1]$ and $[i + 1, r]$, and denote them by $k_L$ and $k_R$, respectively.

4. We find the answer as $k_L \cdot k_R \cdot \binom{r - l}{i - l}$. This number is the answer, since $p_i$ must be minimal on the interval and is uniquely determined, while the remaining numbers can be distributed across the two intervals $[l, i - 1]$ and $[i + 1, r]$ in any way, preserving the invariant. For each of the $\binom{r - l}{i - l}$ distributions on the intervals $[l, i - 1]$ and $[i + 1, r]$, there will be exactly $k_L$ and $k_R$ solutions, respectively, that are independent of one another.

It is clear that in a literal implementation, the algorithm above will run in $\mathcal{O}(n^2)$ time in the worst case, but the following optimization can be applied: since it suffices to find any single index on the interval $[l, r]$ for which $a_i = (i - l + 1)(r - i + 1)$, let's check this condition for the indices $[l, r]$ in the following order: $l, r, l + 1, r - 1, l + 2, r - 2, \ldots$. We will prove that with this optimization, the algorithm will run in $\mathcal{O}(n \log n)$ time.

Let the algorithm run in $T(n)$ for a segment of length $n$. Then, if we consider $k$ — the distance from the boundary of the segment to the nearest element satisfying the condition — we obtain the following recurrence relation:

$$T(n) \le \max\Bigg{(}\mathcal{O}(n), \max_{0 \le k \le \frac{n - 1}{2}}\Big{\{}\mathcal{O}(k) + T(k) + T(n - k - 1)\Big{\}}\Bigg{)}$$

(If no index satisfies the condition, $T(n) = \mathcal{O}(n)$.) By induction, we see that $T(n) \le \mathcal{O}(n \log n)$.


**Code (C++)**
```cpp
#include <bits/stdc++.h>

#define int long long

using namespace std;

const int Mod = 1e9 + 7, Max = 5e5 + 10;

vector<int> fact(Max), ifact(Max);

int binpow(int b, int p) {
 if (p == 0) return 1;
 if (p % 2 == 0) return binpow((b * b) % Mod, p / 2);
 return (binpow(b, p - 1) * b) % Mod;
}

int C(int n, int k) {
 return (fact[n] * ((ifact[k] * ifact[n - k]) % Mod)) % Mod;
}

int rec(int l, int r, vector<int> &b) {
 if (r < l) {
 return 1;
 }
 if (l == r) {
 return (b[l] == 1 ? 1 : 0);
 }
 for (int d = 0; d < r - l + 1; d++) {
 int i = d + l;
 if ((i - l + 1) * (r - i + 1) == b[i]) {
 return (((rec(l, i - 1, b) * rec(i + 1, r, b)) % Mod) * C(r - l, i - l)) % Mod;
 }
 i = r - d;
 if ((i - l + 1) * (r - i + 1) == b[i]) {
 return (((rec(l, i - 1, b) * rec(i + 1, r, b)) % Mod) * C(r - l, i - l)) % Mod;
 }
 }
 return 0;
}

void solve() {
 int n;
 cin >> n;
 vector<int> b(n);
 for (int i = 0; i < n; i++) cin >> b[i];

 int s = accumulate(b.begin(), b.end(), 0ll);
 if (s != n * (n + 1) / 2) {
 cout << "0\n";
 return;
 }

 cout << rec(0, n - 1, b) << "\n";
}

signed main() {
 ios_base::sync_with_stdio(0); cin.tie(0);

 fact[0] = 1;
 for (int i = 1; i < Max; i++) {
 fact[i] = (fact[i - 1] * i) % Mod;
 }
 for (int i = 0; i < Max; i++) {
 ifact[i] = binpow(fact[i], Mod - 2);
 }

 int t;
 cin >> t;
 while (t--) {
 solve();
 }
}
```

## 2234F - Vessels, Heights and Two Versions (Hard Version)

Idea: [yanb0](<https://codeforces.com/profile/yanb0>)
 
**Hint 1**

Read the solution of C. Try to calculate the answer when the empty vessel is vessel $1$, then somehow change it quickly when moving the empty vessel to be vessel $2$, $3$, etc.

 
**Hint 2**

Consider the highest vessel connection.

 
**Hint 3**

You do not need any advanced data structures. Use a stack.

 
**Solution**

[Here, all indices and intervals will be taken modulo $n$.]

Fix the empty vessel as vessel $l$. Let's see what is the largest volume that vessel $i$ can contain for $i \ne l$. $w_i \le \max(w_{i-1}, h_{i-1})$, otherwise an obvious contradiction with the condition follows. Thus, $w_i \le \max(h_l, h_{l+1}, \ldots, h_{i-1})$. Similarly, $w_i \le \max(h_{l-1}, h_{l-2}, \ldots, h_i)$. It is easy to see that if for all $w_i$ we take the maximum value $w_i = \min(\max(h_l, h_{l+1}, \ldots, h_{i-1}), \max(h_{l-1}, h_{l-2}, \ldots, h_i))$ allowed by these conditions, then $w$ will satisfy the conditions, and therefore the sum $\min(\max(h_l, h_{l+1}, \ldots, h_{i-1}), \max(h_{l-1}, h_{l-2}, \ldots, h_i))$ over all $i \ne l$ will be the maximum capacity when vessel $l$ is empty.

Let $h_t$ be one of the maximal elements of $h$. Then we note that $\max(h_l, h_{l+1}, \ldots, h_{i-1}) = h_t \ge \max(h_{l-1}, h_{l-2}, \ldots, h_i)$ if $t$ is on the interval $(l, i)$, i.e., $i$ is on the interval $(t, l)$, and hence $w_i = \max(h_{l-1}, h_{l-2}, \ldots, h_i)$; similarly, for $i$ on $(l, t)$, $w_i = \max(h_l, h_{l+1}, \ldots, h_{i-1})$. Thus, we only need to know the sum $\max(h_{l-1}, h_{l-2}, \ldots, h_i)$ over all $i$ on $(t, l)$ and the symmetric sum on the other side. We will show how to precompute the first of these sums for all $l$; the second will be calculated similarly.

To reiterate, we have an array $a_1 = h_t, a_2 = h_{t+1}, \ldots, a_n = h_{t-1}$. For each $l$, we need to find the sum $\max(h_i, h_{i+1}, \ldots, h_{l-1})$ of suffix maxima on the interval over all $i$ on $[1, l - 1]$. This can be done by traversing the array from left to right and maintaining a stack of suffix maxima with their counts: when we consider the next number $h_{l-1}$, we invalidate all smaller suffix maxima from the top of the stack, increasing the required sum by $c(h_{l-1} - m)$, where $c$ is the number of suffix maxima being removed, and $m$ is its value, since all these suffix maxima now change their value from $m$ to $h_{l-1}$.

Total time complexity: $\mathcal{O}(n)$.

 
**Code (Python)**
```python
INF = float("inf")
 
tt = int(input())
for tc in range(tt):
    n = int(input())
    h = list(map(int, input().split()))
    t = 0
    for i in range(n):
        if h[i] > h[t]:
            t = i
    
    ls = [0 for i in range(n)]
    rs = [0 for i in range(n)]
 
    sm = [(INF, 0)]
    for ti in range(1, n):
        i = (ti + t) % n
        s = ls[i] + h[i]
        c = 1
        while sm[-1][0] <= h[i]:
            s += sm[-1][1] * (h[i] - sm[-1][0])
            c += sm[-1][1]
            sm.pop()
        sm.append((h[i], c))
        ls[(i + 1) % n] = s
    
    sm = [(INF, 0)]
    for ti in range(1, n):
        i = (t + n - ti) % n
        s = rs[(i + 1) % n] + h[i]
        c = 1
        while sm[-1][0] <= h[i]:
            s += sm[-1][1] * (h[i] - sm[-1][0])
            c += sm[-1][1]
            sm.pop()
        sm.append((h[i], c))
        rs[i] = s
    
    ans = [ls[i] + rs[i] for i in range(n)]
    print(*ans)
```

## 2234G - Stripe, Token and Two Players

Idea: [yanb0](<https://codeforces.com/profile/yanb0>)
 
**Hint 1**

Think of a $\mathcal{O}(n^3)$ solution.

 
**Answer to Hint 1**

DP. For each pair $(cell, strength)$ you can find whether the player that makes the move from the position wins if the game is played optimally.

 
**Hint 2**

There are not many losing positions in this game. Why?

 
**Answer to Hint 2**

The number of losing positions $(i, k)$ for a fixed $k$ with $i \le n$ is no more than $\big\lceil \frac{n}{k + 1} \big\rceil$, since if position $(i, k)$ is a losing position, then all positions $(i + 1, k), (i + 2, k), \ldots, (i + k, k)$ must be winning if they exist. Then the total number of losing positions $(i, k)$ with $i \le n$ is no more than $\mathcal{O}(n \log n)$.

 
**Hint 3**

Try to iterate over cell number $i$ from $n$ to $1$ and explicitly find all losing positions.

 
**Hint 4**

You need to think of a data structure to optimize the solution to $\mathcal{O}(n \log^2 n)$.

 
**Solution**

We'll denote the state of the game where a chip is on cell $i$ and has strength $k$ before using bonuses as $(i, k)$. We need to determine whether position $(1, 1)$ is a winning position.

Note that the number of losing positions $(i, k)$ for a fixed $k$ with $i \le n$ is no more than $\big\lceil \frac{n}{k + 1} \big\rceil$, since if position $(i, k)$ is a losing position, then all positions $(i + 1, k), (i + 2, k), \ldots, (i + k, k)$ must be winning if they exist. Then the total number of losing positions $(i, k)$ with $i \le n$ is no more than $\mathcal{O}(n \log n)$.

We will iterate over cell number $i$ from $n$ to $1$ and explicitly find all losing positions.

Let's maintain a set $S$ containing all $k$ for which there is no losing position $(j, k)$, where $i \lt j \le i + k$. This can be done using a priority queue, adding the event "no more losing positions with strength $k$ on the interval $[i + 1, i + k]$" to position $i - k - 1$ when position $(i, k)$ is losing. (Also, this event addition is done initially for positions $(n + 1, 0), (n + 1, 1), \ldots, (n + 1, n)$, since they are all losing positions, and the strength can be limited to being not more than $n$ without changing the game.) The total number of such events added to the queue will be no more than $\mathcal{O}(n \log n)$ (based on the number of losing positions), which means there will be no more than $\mathcal{O}(n \log n)$ queries to the queue, since in each cell we will only read and delete events related to it. Note that only when we read such an event do we add one element to $S$, and the number of additions to $S$ is also no more than $\mathcal{O}(n \log n)$.

We will find losing positions for cell $i$ as follows: a position $(i, k)$ is a losing position if and only if, for all $0 \le d \le a_i$, there are no losing positions among positions $(j, k + d)$ for $j \in [i + 1, i + k + d]$, i.e., if and only if $S$ contains all $k, k + 1, \ldots, k + a_i$. To quickly find such $k$, we use the following data structure (we will call it a *block container*):

There is a set $s$ of natural numbers, initially empty. All numbers in $s$ will be on the interval $[1, n]$, and all operations are guaranteed to be valid (for example, a number already contained in $s$ will not be asked to be added there). A block container can:
 

- add a number $x$ to $s$ in $\mathcal{O}(\log n)$;

- find the length of the longest segment of consecutive numbers in $s$ in $\mathcal{O}(1)$;

- find any longest segment of consecutive numbers in $s$ and remove its smallest element from $s$ in $\mathcal{O}(\log n)$.
  
**How to implement a block container**

If written in C++, a container of blocks can be implemented, for example, using two `std::set`s storing the same set of blocks (segments) of consecutive numbers in $s$ (numbers adjacent to the edges of a block must not be in $s$; for example, for $s = {1, 5, 3, 2, 6}$, the set of blocks will be ${[1, 3], [5, 6]}$). The first `std::set` will sort the blocks by their left boundary, and the second by length.
 

- When adding a number $x$ to $s$, the container adds a new block $[x, x]$, and then, using the first `std::set`, it finds whether some segments need to be merged with the new one (i.e., whether there are two blocks whose boundaries are adjacent numbers), and, if so, merges them. The container merges segments by removing the old pair of segments from both `std::set`s and adding the merged segment back to each `std::set`.

- To find the longest segment, the container simply accesses the second `std::set`.

- To remove the left element of the segment found above, the container removes the segment from both `std::set`s, increments its left bound by $1$, and, if the segment is still non-empty, adds it back to each `std::set`.
 
The code can be written similarly in other languages, if there's a built-in `set` that supports custom sorting and finding the smallest element. Alternatively, a segment tree can be written on a boolean array of length $n$, reflecting the presence/absence ($1$/$0$) of numbers in $s$, storing at a node the boundaries of the longest subsegment of the segment of the node consisting of consecutive 1s.

Now, let's show how to quickly find the required $k$. We'll store $S$ in a container of blocks. If the length of some block in $S$ is greater than $a_i$ and equals $l + a_i$, the $l$ smallest elements of this block will be losing strengths for cell $i$ — this determines all losing strengths for cell $i$ and only them. Then let's simply remove the smallest element of the longest block while its length is greater than $a_i$ — obviously, and all the removed numbers will be all the losing strengths for cell $i$. The number of requests to the block container for finding and removing when considering cell $i$ is then $1$ more than the number of losing positions $(i, k)$, that is, in total over all cells, no more than $\mathcal{O}(n \log n)$. The number of requests to the block container for adding, as we showed earlier, is also not more than $\mathcal{O}(n \log n)$.

That is, for each cell, we first process the events coming from the priority queue, load the new elements into the $S$ block container, then find the losing positions, and finally add new events for the next cells to the priority queue. This means we get every losing position in the process; all that remains is to check whether position $(1, 1)$ is a losing position.

This results in $\mathcal{O}(n \log^2 n)$ for requests to the priority queue, $\mathcal{O}(n \log^2 n)$ for requests to the block container, and a total asymptotic complexity of $\mathcal{O}(n \log^2 n)$.
