## 2146A - Equal Occurrences

**Hint 1**

Let's focus on the number of occurrences of each element: let $c_i$ be the number of time that element $i$ occurs in the array. To keep a subsequence is to decrease each $c_i$ by a non-negative integer. We need to make all the non-zero elements in $c$ the same while maximizing the sum of $c$.


**Hint 2**

For each integer $x$: suppose the value of all non-zero elements in $c$ is $x$, what is the length of the longest subsequence?

**Answer**

For those $c_i \lt x$, we decrease it to $0$; for those $c_i\ge x$, we decrease it to $x$.


**Tutorial**

Let $c_i$ be the number of occurrences of element $i$ in the array. Let the final number of occurrences of each number be $x$. For integers $i$ such that $c_i\ge x$, we should keep $x$ occurrences of $i$; for those $c_i \lt x$, we should keep no occurrences of $i$. Thus, the length of the subsequence will be the number of $i$ such that $c_i\ge x$ times $x$.

Since $0\le x\le n$, you can simulate all possible $x$ and calculate the answer.

If you sort $c_i$ in decreasing order, you can observe that the answer is $\max_{1\le i\le n}c_i\cdot i$. That's because when $x=c_i$, there are at least $i$ elements that occur at least $c_i$ times.

The time complexity is $O(n)$ or $O(n\log n)$ or $O(n^2)$.


**Implementation**

By [Caylex](<https://codeforces.com/profile/Caylex>).

```python
def solve():
 n = int(input())
 ls = list(map(int, input().split()))
 a = [0] * n
 for x in ls:
 a[x - 1] += 1
 a = sorted(a)
 s = sum(a)
 ans = s
 for i in range(n):
 ans = min(ans, s - (n - i) * a[i])
 print(n - ans)
 return

for _ in range(t):
 solve()
```

## 2146B - Merging the Sets
 
**Hint 1**

How to check if there is at least one way to choose the sets?
 
**Answer**

Obviously, we should choose all the sets.

 
**Hint 2**

How to greedily find two more solutions to choose the sets?
 
**Answer**

We should choose all the sets but one.

 
**Tutorial**

First, all the numbers should occur in at least one given set, or there will be no solutions. And so choosing all the sets is a possible solution.

Then, we can always try to choose $n-1$ sets. If there are at least two ways to choose $n-1$ sets to cover all the numbers, the answer is "Yes". Otherwise, there should be no way to choose less than $n-1$ sets to cover all the numbers (suppose not, then there should be at least two ways to choose $n-1$ sets), so the answer is "No".

We can use a bucket to store the number of occurrences of each element. When trying not to choose the $i$-th set, just iterate over the set $S_i$, delete the number of occurrences of elements in $S_i$, and it's easy to check if any element of the bucket turns into zero.

The time complexity is $O(n+m+\sum l_i)$.

 
**Implementation**

By [Caylex](<https://codeforces.com/profile/Caylex>).

```python
def solve():
    n, m = map(int, input().split())
    cnt = [0] * m
    t = 0
    v = []
    for i in range(n):
        v.append([])
        inp = list(map(int, input().split()))
        l = inp[0]
        for j in range(1, l + 1):
            x = inp[j]
            x -= 1
            t += not cnt[x]
            cnt[x] += 1
            v[i].append(x)
    ans = t == m
    for i in range(n):
        for x in v[i]:
            cnt[x] -= 1
            t -= not cnt[x]
        ans += t == m
        for x in v[i]:
            t += not cnt[x]
            cnt[x] += 1
    print("YES" if ans >= 3 else "NO")
    return

t = int(input())
for _ in range(t):
    solve()
```

## 2146C - Wrong Binary Search

**Hint 1**

How to check if an element $x$ is stable? For an element $p_i$, we only care about whether $p_i \lt x$, $p_i=x$ or $p_i \gt x$.


**Hint 2**

If an element is not stable, we can choose $m$ correctly in the first step to exclude $x$ from interval $[l,r]$.


**Tutorial**

Let's consider checking if the value $x$ is stable:

- Let's denote the elements $ \lt x$ as $-1$, $=x$ as $0$ and $ \gt x$ as $1$. This turns the permutation into an array of $x-1$ times of $-1$s, one $0$, and the rest are $1$. For example, for permutation $[3,5,1,4,2]$ and element $x=4$, let the new array be $[-1,1,-1,0,-1]$. It can be proved that doing binary search on element $0$ on this array is the same as doing binary search on element $x$ in the permutation.
- One necessary condition is that all the $-1$s occur before the $0$. Otherwise, if we choose $m$ as the position of $-1$ at first, $a_m \lt x$ will be judged, and then $l$ becomes $m+1$, where element $x$ will be outside the range.
- Similarly, all the $1$s should occur after the $0$. Otherwise, we can choose $m$ as the position of that $1$ at first.
- We can prove that the two conditions above are sufficient. That is because the array of $-1,0,1$ is already sorted, and you can always find the correct position of $0$ on a sorted array.

In all, the condition that element $x$ is stable is that: $a_x=x$, and $a_i \lt x$ if and only if $i \lt x$, and $a_i \gt x$ if and only if $i \gt x$.

Consider constructing a permutation. If $s_i=\tt 0$, we can construct anything that does not satisfy the conditions above, such as $[2,3,\dots,n,1],[n,n-1,n-2,\dots,2,1]$. Note that $n$ should not be $1$.

The positions that $s_i=\tt 1$ must be filled with $p_i=i$. For each segment of $\tt 0$ (an interval $[l,r]$ that is filled with all $\tt{0}$ and $l-1$ and $r+1$ are either boundary or $\tt 1$), we still need to fill the values $[l,r]$ into the indices $p_l,\dots,p_r$. Similar as the case when all $s_i=\tt{0}$, we can simply reverse or cyclic shift the subsegment $[l,r]$. There's no solution if $l=r$ here.

The time complexity is $O(n)$.

## 2146D1 - Max Sum OR (Easy Version)

Try a few cases or guess by the samples that the answer is always $n(n+1)$.

Actually, $x~|~y=(x+y)-(x\&y)\le x+y$. So the clear upper bound of $\sum_i(a_i~|~b_i)$ is $\sum a_i+b_i=n(n+1)$. Let's construct the array $a$ as follows to prove that the upper bound can always be reached:

- Our target is to make $a_i\&b_i=0$ for every $i$. Let the indices be $0\sim n$.
- Let $k$ be the smallest integer such that $2^k \gt n$. Clearly $0\le 2^{k}-1-n\le n$, otherwise $k$ can be smaller. Let $a_i=2^k-1-i$ for integers $i\in[2^k-1-n,n]$. Clearly $a_i\&i=0$. Then delete the suffix and let $n$ become $2^k-2-n$. Continue the process until $n$ becomes $-1$ (That is, when $n=2^{k}-1$, let's reverse the array and end the process).
- It can be seen that $n$ decreases by at least one each time, so the process always ends.

For example, the construction for $[l,r]=[0,10]$ is: $[0,2,1,4,3,10,9,8,7,6,5]$.

The time complexity is $O(n)$.

 
**Implementation**

By [Caylex](<https://codeforces.com/profile/Caylex>).

```python
def solve():
    l, r = map(int, input().split())
    pw = 1
    ans = 0
    while pw < r:
        pw = pw << 1 | 1
    s = set()
    for i in range(l, r + 1):
        s.add(i)
    a = [0] * (r + 1)
    for i in range(r, l - 1, -1):
        while pw - i not in s:
            pw >>= 1
        a[i] = pw - i
        ans += i | a[i]
        s.remove(pw - i)
    print(ans)
    print(*a[l : r + 1])
    return
```

**Hint 1**

Let's consider from the highest bits to the lowest bits. If the highest bits of $l$ and $r$ are the same, we can just ignore this bit and go on to a lower bit. We can still try to pair integers $x$ and $y$ by letting $a_x=y,a_y=x$.

**Hint 3**

In D1, it is optimal to pair $x$ with $2^k-1-x$. Here, for interval $[l,r]$ and integer $t$ defined in Hint2, it is optimal to pair $x$ with $2t-1-x$.


**Tutorial**

## 2146D2 - Max Sum OR (Hard Version)

The answer won't simply be $(r-l+1)(r+l)$. However, if you consider the $30$ bits separately, this will be the correct upper bound of the answer.

Let the indices be $[l,r]$. Let $l^x$ denote the $x$-th bit of non-negative integer $l$. Let's construct from the highest bit to the lowest:

- Let $x$ be the highest bit such that $l^x\neq r^x$. For the higher bits, they clearly don't affect the results. Now $l^x=0$ and $r^x=1$. Let $t$ be the smallest integer that $[l\le t\le r]$ and $t^i=0$ for $i \lt x$. That is, $t$ is $r$ when the bits lower than $x$ are changed to $0$. For example, when $l=9=(1001)_2,r=13=(1101)_2$, here $x=2$ and $t=12=(1100)_2$. We can see that when the sum of two paired integers is $2t-1$, it always seems optimal. Here are two cases:
- When $t-l\le r-t+1$, that is, the length of the left part that $l\le i \lt t$ is smaller than the length of the right part that $t\le i\le r$. We can pair each number $x$ in the left part with $a_x=2t-1-x$ in the right part. That is, reverse the interval $[l,2t-1-l]$ and turn the interval into $[2t-l,r]$. Here, for all the paired integers $(x,2t-1-x)$, ignoring the bits higher than $x$, the bitwise and of them is zero, which is clearly optimal.
- Similarly, when $t-l \gt r-t+1$, that is, the length of the left part is greater than the length of the right part. We can pair each number $x$ in the right part with $a_x=2t-1-x$ in the left part. That is, reverse the interval $[2t-1-r,r]$ and turn the interval into $[l,2t-2-r]$. Here, for all the paired integers $(x,2t-1-x)$, ignoring the bits higher than $x$, the bitwise and of them is zero, which is clearly optimal.
- Continue the process until the interval $[l,r]$ becomes empty. You can feel from the process or prove by separating each bit to prove that the constructed array above is optimal.

Here is an example when $l=3,r=9$:

- $x=3$ and $t=8$. The left part is $[3,4,5,6,7]$ and the right part is $[8,9]$. Let $7,6$ be paired with $8,9$ in the order: $a_6=9,a_7=8,a_8=7,a_9=6$. Now the interval becomes $[3,4,5]$ with $l=3,r=5$.
- $x=2$ and $t=4$. The left part is $[3]$ and the right part is $[4,5]$. Let $3$ be paired with $4$: $a_3=4,a_4=3$. Now the interval becomes $[5]$ with $l=r=5$. Let's simply let $a_5=5$. So the constructed array is $[4,3,5,9,8,7,6]$.

Here are some other examples for you to understand better: $[4,7]:[7,6,5,4]$, $[11,16]:[12,11,14,13,16,15]$.

The time complexity is $O(n)$.

**Another solution using greedy on trie**

It turns out that we can solve it greedily from the lowest bit to the highest bit. For each element in $[l,r]$, let's reverse its binary representation and insert it into a 01-trie. Then for each index $i$, we can do `dfs` on the trie while trying to keep every bit different with $i$. Formally, each step we try to go to the opposite side of each bit of $i$, and go on the other side if that subtree is empty.

We can prove that this gives the same construction with the other method constructing from the higher bits. You can read the implementation for better understanding.

## 2146E - Yet Another MEX Problem

**Hint 1**

For an array $b$ and an integer $x$ that **does not appear in** $b$, let $g(b,x)$ be the number of elements in $b$ that is greater than $x$. Then the weight of $b$ equals to $g(b,\rm{mex}(b))$. However, when $x\neq \rm{mex}(b)$, what will happen to $g(b,x)$?

**Answer**

The value of $g(b,x)$ is always smaller than or equal to $g(b,\rm{mex}(b))$, because when $x$ **does not appear in** $b$, letting $x=\rm{mex}(b)$ is optimal to maximize $g(b,x)$.


**Hint 2**

For a fixed right endpoint $r$, let's enumerate over all the $x$ and maximize $g(a[l\dots r],x)$ while keeping $x$ no occurred in $a[l\dots r]$. It's clear that the value is maximized for $x$ if $l$ equals the last occurrence of $x$ plus $1$.


**Hint 3**

Use a segment tree to maintain the answer for each $x$.


**Tutorial**

Let's calculate the weight of an array without calculating its mex: For each integer $x$ that does not occur in the array, calculate the number of elements $a_i \gt x$ and compare it to the answer. Note that we have weakened the conditions from $x$ being the mex to $x$ not occurring. This will not change the answer because the answer is always maximized when $x$ is equal to the mex.

Then, to calculate $\max_{1\le l\le r}w(l,r)$, we can iterate over all integers $x$ that $0\le x\le n$, find its last occurrence $p$ ($p=0$ if it never occurred), and use this $x$ to calculate $w(p+1,r)$ and compare it to the answer. That is, the number of integers $i$ that $p \lt i\le r$ and $a_p \gt x$.

Let's iterate over all integers $r$ and use a segment tree to maintain the answer $b_x$ for each $x$. Initially $b_x=0$. When you add $1$ to $r$ and add a new integer $a_r$ to the array, we should set $b_{a_r}=0$ and then increase $b_i$ by $1$ for $0\le i \lt a_r$. And then the maximum of array $b$ will be the answer.

The time complexity is $O(n\log n)$.

## 2146F - Bubble Sort
 
**Hint 1**

Let's focus on bubble sort first. For an element $p_x$, how many rounds does it take to make all the numbers before the position small than $p_x$?
 
**Answer**

Count the number of integers $i$ such that $i \lt x$ and $p_i \gt p_x$. In one round of bubble sort, exactly one of that sort of element will be moved to the right of $p_x$.

 
**Hint 2**

Try to count something else instead of permutations $p$. Can you come up with an $O(n^2)$ dynamic programming method?

 
**Hint 3**

The number of restrictions is small ($m\le 1000$). Can we decrease the number of states from $O(n^2)$ to $O(nm)$ and $O(m^2)$? How to calculate the coefficients then?

 
**Tutorial**

Let's simulate the process of bubble sort. For an element $a_x$, one necessary condition of the array being sorted is: for all $1\le i \lt x$, $a_i \lt a_x$. And if the condition is held for all $x$, the array will be sorted.

Let's consider the elements $a_i$ such that $1\le i \lt x$ and $a_i \gt a_x$. In one round of bubble sort, the largest element before $a_x$ will occur on the position $a_{x-1}$, and then swapped with $a_x$. So the number of such elements $a_i$ (before and greater than $a_x$) will decrease by exactly one. Let $c_x$ be the number of $i$ such that $1\le i \lt x$ and $a_i \gt a_x$ before the sorting, we can see that $\text{sort}(a)=\max_{i}c_i$. Moreover, $b_i$ in the statement equals $\text{sort}([a_1,a_2,\dots,a_i])=\max_{1\le j\le i} c_j$, which is the prefix maximum of $c$.

Let $a$ be a permutation. From the definition of array $c$, we can see that $0\le c_i\le i-1$, and the number of possible array $c$ is exactly $n!$. We can prove by construction that array $c$ and permutation $a$ form a bijection. Let's just count the number of arrays $c$ such that: $0\le c_i \lt i$, $\max_{i=1}^{l}c_i\le k$ and $\max_{i=1}^{r+1}c_i\gt k$.

Here is an $O(n^2)$ dynamic programming method: Let $f_{i,j}$ be the number of ways to fill the first $i$ elements of $c$, and the current maximum is $j$. We can use prefix sum to optimize it to $O(n^2)$.

We need to notice that the number of restrictions is small ($m\le 1000$). There're only $2m$ points that have restrictions. Let the $2m$ points split the array of length $n$ into $O(m)$ intervals, and we can each time fill a whole interval. Similarly, the range of values can be split into $O(m)$ intervals. Let $g_{i,j}$ be the number of ways to fill the first $i$ intervals and the current maximum is in the $j$-th interval.

There are two types of transitions:

- $g_{i-1,j}\times co\rightarrow g_{i,j}$. The coefficient here refers to: for the numbers in the $i$-th interval, the maximum does not exceed the upper bound of the $j$-th value interval. Let's call the coefficient $\text{calc}(l,r,t)$, where $l,r$ represents the index interval and $t$ represents the upper bound of the value.
- $g_{i-1,j}\times co\rightarrow g_{i,k}$. Here, $j \lt k$. Here, for the numbers in the $i$-th interval, the maximum is exactly in the $j$-th value interval (call it $[v_l,v_r]$). The coefficient is $\text{calc}(l,r,v_r)-\text{calc}(l,r,v_l-1)$.

So we need to calculate $\text{calc}(l,r,t)$: fill the $l$-th to the $r$-th element of $c$ such that $0\le c_i \lt i$ and $\max_{i\in[l,r]}c_i\le t$. Here $0\le c_i\le \min(i-1,t)$. There's a prefix that $i-1\le t$, $0\le c_i\le i-1$, and the coefficient can be calculated using factorials and inverse of factorials. For the suffix part that $i-1 \gt t$, then $0\le c_i\le t$, and this can be calculated using quick pow.

The time complexity is $O(m^2\log n)$. The $\log$ refers to quick pow.

Proof for permutation $a$ and array $c$ form a bijection:

- Given a permutation $a$, you can uniquely determine array $c$.
- Given array $c$, let's recover the permutation $a$ from back to front: There're $c_n$ numbers in all that are greater than $a_n$, so $a_n=n-c_n$, and then delete $a_n$ from the possible values. Similarly, when you have determined a suffix, you should find the $(c_i+1)$-th greatest number in those you have not used.
