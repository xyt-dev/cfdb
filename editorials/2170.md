## 2170A - Maximum Neighborhood

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

Because the matrix is small enough, you can iterate over each cell $(i, j)$ and its neighbors: $(i - 1, j)$, $(i + 1, j)$, $(i, j - 1)$, and $(i, j + 1)$ (don't forget to check if these cells exists). This allows you to calculate the cost for each cell.

However, there are solutions which don't need to consider the whole matrix. We can show that the only four cells we have to consider are $(n, n)$, $(n-1, n)$, $(n, n-1)$ and $(n-1, n-1)$ — the two rightmost cells in the last two rows. For every other cell, the cost of the cell below it or to the right of it will be strictly greater. This allows us to check only four cells.

In fact, we can also show that for $n \ge 5$, the cell $(n-1, n-1)$ is the optimal one, and its cost can be calculated using a simple formula. And the answers for $n \lt 5$ are given in the problem statement.


**Solution 1 (Neon)**
```cpp
#include <bits/stdc++.h>

using namespace std;

int dx[] = {-1, 0, 1, 0};
int dy[] = {0, -1, 0, 1};

int main() {
 int t;
 cin >> t;
 while (t--) {
 int n;
 cin >> n;
 auto get = [&](int x, int y) {
 if (x >= 0 && x < n && y >= 0 && y < n) return x * n + y + 1;
 return 0;
 };
 int ans = 0;
 for (int i = 0; i < n; ++i) {
 for (int j = 0; j < n; ++j) {
 int cur = get(i, j);
 for (int d = 0; d < 4; ++d) cur += get(i + dx[d], j + dy[d]);
 ans = max(ans, cur);
 }
 }
 cout << ans << '\n';
 }
}
```

 
**Solution 2 (Neon)**
```cpp
#include <bits/stdc++.h>

    else if (n > 4) ans = 5 * n * n - 5 * n - 5;
    cout << ans << '\n';
  }
```

## 2170B - Addition on a Segment

Idea: [FelixArg](<https://codeforces.com/profile/FelixArg>)

**Tutorial**

Let's count the number of non-zero elements in the array $c$, as well as the sum of its elements $s$. If $s - c \ge n - 1$, then the answer is $c$; otherwise, the answer is the largest $c'$ such that $0 \lt c' \lt c$ and $s - c' \ge n - 1$.

Such a $c'$ can be found by simple enumeration or calculated using the formula:

$$ c' = \min \left( c, s - n + 1 \right)$$

The first bound in the formula is quite obvious: if an element is equal to $0$, then no operation has changed it, and therefore the longest segment could not be longer than $c$.

The second bound is a bit trickier. Each operation is a segment of length $L = r_{i} - l_{i} + 1$ on which we add $1$ to all its elements. In total, across all operations, we have added $s = L_{1} + L_{2} + \dots + L_{n}$. The longest segment among all operations is $c'$, then:

- one segment has length $c'$;
- the other segments have length of at least $1$ according to the problem statement.

This means:

$$s \ge c' + 1 + \dots + 1$$

$$s \ge c' + (n - 1)$$

$$c' \le s - n + 1$$


**Solution (FelixArg)**
```cpp
#include<bits/stdc++.h>
using namespace std;

#define int long long

void solve(){
 int n;
 cin >> n;
 vector<int> a(n);
 for (int i = 0; i < n; i++){
 cin >> a[i];
 }

 int sum = 0;
 int cnt_one = 0;

 for (int i = 0; i < n; i++){
 if (a[i] > 0){
 cnt_one++;
 }
 sum += a[i];
 }

 int sum2 = sum - cnt_one;
 int sub = n - 1 - sum2;

 cout << cnt_one - max(0ll, sub) << '\n';
}

signed main()
{

#endif

 }

#ifdef FELIX

 chrono::high_resolution_clock::now()
 - _clock_start).count() << "ms." << endl;
#endif
 return 0;
}
```

## 2170C - Quotient and Remainder

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

Suppose we want to remove a pair of numbers $q_i$ and $r_j$. We need to determine the minimum $x$ required for this. Since $x \bmod y = r_i$, then $y \gt r_i$, or $y \ge r_j + 1$. We also know that $\left\lfloor \frac{x}{y} \right\rfloor = q_i$, thus $x = y \cdot \left\lfloor \frac{x}{y} \right\rfloor + (x \bmod y) = y \cdot q_i + r_j \ge (r_j + 1) \cdot q_i + r_j$.

Notice that if we take $x = q_i (r_j + 1) + r_j$ and $y = r_j + 1$, then this pair $x$ and $y$ indeed works for us. Therefore, we can remove the pair of elements $(q_i, r_j)$ if and only if $q_i (r_j + 1) + r_j \le k$.

Thus, our task is to form the largest number of pairs $(q_i, r_j)$ such that $q_i (r_j + 1) + r_j = (q_i + 1)(r_j + 1) - 1 \le k$. Since if we can form $c$ pairs, we can also form $c - 1$ pairs, we can apply binary search on the answer.

Now our task is to determine whether we can form exactly $c$ pairs. Since our constraint is an upper limit on the product, it is always optimal to take the $c$ smallest $q_i$ and pair them with the $c$ smallest $r_j$. Therefore, let's sort the arrays $q$ and $r$ in ascending order — then our task is to pair prefix of $q$ with prefix of $r$ of length $c$.

Next, we need to show that it is always optimal to pair the smallest $q_i$ with the largest $r_j$, that is, $q_1$ with $r_c$, $q_2$ with $r_{c-1}$, $q_3$ with $r_{c-2}$, and so on. To prove this, we will show that $q_1$ is optimal to pair with $r_c$.

By contradiction: suppose that in the optimal answer, the pairs $(q_1, r_y)$ and $(q_x, r_c)$ are formed. We know that $q_1 \le q_x$ and $r_y \le r_c$. Also, since the pairs exist, it means that $(q_1 + 1)(r_y + 1) - 1 \le k$ and $(q_x + 1)(r_c + 1) - 1 \le k$. We will prove that we can swap the elements in the pairs and construct $(q_1, r_c)$ and $(q_x, r_y)$:

- $(q_1, r_c)$: $(q_1 + 1)(r_c + 1) - 1 \le (q_x + 1)(r_c + 1) - 1 \le k$;
- $(q_x, r_y)$: $(q_x + 1)(r_y + 1) - 1 \le (q_x + 1)(r_c + 1) - 1 \le k$.
 Thus, it is always optimal to pair $q_1$ with $r_c$ and so on. Therefore, it is sufficient to check that if for all pairs $(q_i + 1)(r_{c - i + 1} + 1) - 1 \le k$, then $c$ pairs can be formed; otherwise, they cannot.
Thus, the solution works in $O(n \log{n})$ time due to sorting and binary search.

 
**Solution (adedalic)**
```cpp
#include<bits/stdc++.h>
 
using namespace std;
 
#define fore(i, l, r) for(int i = int(l); i < int(r); i++)
#define sz(a) int((a).size())
 
typedef long long li;
 
template<class A> ostream& operator <<(ostream& out, const vector<A> &v) {
    fore(i, 0, sz(v)) {
        if(i) out << " ";
        out << v[i];
    }
    return out;
}
 
const int INF = int(1e9);
const li INF64 = li(1e18);
 
inline void solve() {
    int n; li k;
    cin >> n >> k;
    vector<int> q(n), r(n);
    fore (i, 0, n)
        cin >> q[i];
    fore (i, 0, n)
        cin >> r[i];
    
    sort(q.begin(), q.end());
    sort(r.begin(), r.end());
 
    auto check = [&](int cnt) {
        fore (i, 0, cnt) {
            if (li(q[i] + 1) * (r[cnt - 1 - i] + 1) - 1 > k)
                return false;
        }
        return true;
    };
 
    int lf = 0, rg = n + 1;
    while (rg - lf > 1) {
        int mid = (lf + rg) >> 1;
        if (check(mid))
            lf = mid;
        else
            rg = mid;
    }
    cout << lf << endl;
}
 
int main() {
#ifdef _DEBUG
    freopen("input.txt", "r", stdin);
    int tt = clock();
#endif
    ios_base::sync_with_stdio(false);
    cin.tie(0), cout.tie(0);
    cout << fixed << setprecision(15);
    
    int t = 1; cin >> t;
    while (t--) {
        solve();
        
#ifdef _DEBUG
        cerr << "TIME = " << clock() - tt << endl;
        tt = clock();
#endif
    }
    return 0;
}
```

## 2170D - Almost Roman

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

First, let's try to solve it with only one query. Which characters should we use, and where do we put them?

Greedy idea: let's use the maximum possible number of Is, then the maximum possible number of Vs, and only then use Xs. It's because if we replace any I with V, it increases the value by at least $3$, and if we replace any V with X, it increases the value by exactly $5$.

Okay, now we know which characters in which quantities we use. Now, let's choose their ordering in such a way that the number of pairs "IV" and "IX" is the maximum possible. V and X differ only in their costs, so let's replace every X (both in the original string and in characters we will use in the query) with V, and add the number of replaced characters times $5$ to the answer.

Now imagine the following process. We replace every question mark with I and evaluate the string. But if we have too few Is in a query, we should change some of Is to Vs. When we change an I to a V, one of the following three things can happen:

- we either increase the number of pairs "IV" by $1$;
- or we don't change it;
- or we decrease it by $1$.

Obviously, we want to make as many changes that increase the number of such pairs as we can, then as many changes that keep it as it is as we can, and only then apply changes that decrease it. Let's calculate two variables inc and same — the maximum number of changes of the first and the second type we can make.

Every segment of question marks is independent of each other. Suppose a segment is isolated; then the number of increasing changes is its length divided by $2$ (because it is the maximum number of pairs we can have), and the number of changes of the second type is its length modulo $2$ (because if it has even length, every character I we replace after making the pairs breaks one pair, and if it has odd length, we can transform an "IIV" pattern into an "IVV" pattern).

However, if there is an I before the segment or a V after it, they can also participate in forming pairs, so each of them increases its length by $1$. V after the segment also reduces the number of increasing operations by $1$, because we initially already have one pair "IV".

And that's about it: calculate the length of each segment of question marks, use it to calculate the values of inc and same. Then replace all question marks by Is to calculate the value of the string in the perfect case (when we have enough Is to replace), then use inc and same to find out how many replacements I $\rightarrow$ V increase or keep the number of pairs "IV". Processing queries also becomes easy if we know these values.


**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

int cost(char c)
{
 if(c == 'I') return 1;
 return 5;
}

int eval(string s)
{
 int n = s.size();
 int ans = 0;
 for(int i = 0; i < n; i++)
 if(s[i] == 'I' && i + 1 < n && s[i + 1] == 'V')
 ans--;
 else ans += cost(s[i]);
 return ans;
}

void solve()
{
 int n, q;
 cin >> n >> q;
 string s;
 cin >> s;
 int ans = 0;
 for(int i = 0; i < n; i++)
 {
 if(s[i] == 'X')
 {
 s[i] = 'V';
 ans += 5;
 }
 }
 int inc = 0;
 int same = 0;
 int qcount = 0;
 for(int i = 0; i < n; i++)
 {
 if(s[i] != '?') continue;
 int r = i;
 while(r < n && s[r] == '?') r++;
 int len = r - i;
 if(i > 0 && s[i - 1] == 'I') len++;
 if(r < n && s[r] == 'V')
 {
 inc--;
 len++;
 }
 inc += len / 2;
 same += len % 2;
 qcount += (r - i);
 i = r - 1;
 }
 for(int i = 0; i < n; i++)
 if(s[i] == '?') s[i] = 'I';
 ans += eval(s);
 for(int i = 0; i < q; i++)
 {
 int a, b, c;
 cin >> a >> b >> c;
 int used_v = max(0, min(b, qcount - c));
 int used_x = max(0, qcount - c - b);
 int cur = ans;
 cur += used_v * 4 + used_x * 9;
 int rep = used_v + used_x;
 cur -= min(inc, rep) * 2;
 rep -= (inc + same);
 cur += max(0, rep) * 2;
 cout << cur << "\n";
 }
}

int main()
{
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 int t;
 cin >> t;
 for(int i = 0; i < t; i++)
 solve();
}
```

## 2170E - Binary Strings and Blocks

Idea: [Roms](<https://codeforces.com/profile/Roms>)
 
**Tutorial**

First, let's try to simplify the definition of beautiful strings. If a string has only $1$ block, then by removing that block, we will definitely end up with $0$ blocks. However, if there is more than one block in the string, removing one of the outer blocks decreases the number of blocks by $1$, while removing a block between two other blocks decreases the number of blocks by $2$ (those two blocks merge). If there are $2$ blocks in the string, we always end up with $1$, and if there are more than $2$, both options are available, so we can achieve any parity.

This actually means that a string is beautiful if and only if it contains more than one block (in other words, a string is not beautiful if and only if all its characters are the same).

Now our problem becomes the following: we need to count the number of binary strings in which both characters are present in every subsegment $[l_i, r_i]$. There are several approaches to solving this problem; in my opinion, the simplest is as follows:

Let $dp_i$ be the number of binary strings of length $i$ for which the characters in positions $i-1$ and $i$ differ (that is, $i$ is the position of the last difference between the characters), and the constraints on all segments ending to the left of $i$ are satisfied. Let's try to understand how to calculate $dp_i$ knowing the previous values $dp_j$. If some segment $[l, r]$ is contained within $[j, i-1]$, then all characters in it will be the same. Therefore, we need to sum only those $dp_j$ such that no segment $[l, r]$ is fully contained within the segment $[j, i-1]$.

Let's somehow find the minimum suitable $j$ for each position $i$ (obviously, all larger $j$ will also be suitable). After that, we will simply need to perform a range sum query, for which we can use either a Fenwick tree or prefix sums (which should be built in parallel to our dynamic programming).

How do we find such a position $j$ for $i$? Let's find the maximum left boundary of the segment ending at each right boundary $r$. However, this is not quite what we need, because the segment can end not only at exactly $i-1$, but also before $i-1$. But we can build prefix maxima for these values, so for each right boundary $r$, we will know the maximum left boundary for all segments ending no later than $r$, which is what we need.

Now let's understand how to calculate the answer based on this dynamic programming. In my opinion, the simplest way is to "extend" our string by $1$ character and say that the character in position $n$ must differ from the previous one. Thus, $dp_n$ will contain the number of strings of length $n+1$ for which all conditions are satisfied and the last two characters differ. By removing the last character, we obtain the number of strings of length $n$ for which all constraints are met. Therefore, the answer will be exactly $dp_n$.

Thus, we have obtained a solution in $O(n \log n)$ or $O(n)$ depending on how we perform the range sum query.

 
**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>
 
using namespace std;
 
const int INF = 1e9;
const int MOD = 998244353;
 
int add(int x, int y)
{
    x += y;
    while(x >= MOD) x -= MOD;
    while(x < 0) x += MOD;
    return x;
}
 
void solve()
{
    int n, m;
    cin >> n >> m;
    vector<int> max_left(n + 1, -1);
    for(int i = 0; i < m; i++)
    {
        int l, r;
        cin >> l >> r;
        --l;
        --r;
        max_left[r] = max(max_left[r], l);
    }
    for(int i = 1; i <= n; i++)
        max_left[i] = max(max_left[i], max_left[i - 1]);
    vector<int> dp(n + 1);
    vector<int> prefsum(n + 2);
    dp[0] = 2;
    prefsum[1] = 2;
    for(int i = 1; i <= n; i++)
    {
        int j = max_left[i - 1] + 1;
        dp[i] = add(prefsum[i], -prefsum[j]);
        prefsum[i + 1] = add(prefsum[i], dp[i]);
    }
    cout << dp[n] << "\n";
}
 
int main()
{
    ios_base::sync_with_stdio(0);
    cin.tie(0);
    int t;
    cin >> t;
    for(int i = 0; i < t; i++) solve();
}
```

## 2170F - Build XOR on a Segment

Idea: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

This looks like a problem that requires linear algebra and XOR bases. However, we only need one fact from linear algebra: the size of the XOR base does not exceed the number of bits in the integers we are working with, so the answer to each query does not exceed $B = 12$.

Let's try to write a dynamic programming solution: $dp[l,r,x,y]$ — can we form the number $x$ in the interval $[l, r)$ using $y$ elements (the value of the dynamic programming will be $1$ if it is possible, or $0$ if it is not). For now, we won't go into detail about how this dynamic programming is implemented; we just need to understand that it exists and that we can compute the answer to each query as follows: we need to find the minimum $y$ such $dp[l,r,x,y] = 1$.

This dynamic programming has the following property: if $dp[l,r,x,y] = 1$, then $dp[l-1,r,x,y] = 1$, because we can use all the same elements in the segment $[l-1,r]$. Therefore, for each triple $(r,x,y)$, there exists a maximum value of $l$ such that $dp[l,r,x,y] = 1$. This means we can move this state of the dynamic programming to its value: we will obtain a new dynamic programming $dp'[r,x,y]$ — the maximum $l$ such that we can form the number $x$ out of $y$ elements in the interval $[l, r)$. It is also easy to answer queries based on this: to answer a query, we need the minimum $y$ for which $dp'[r,x,y] \ge l$.

Let's try to understand how to compute this dynamic programming. We initialize $dp[0,0,0] = \infty$, and for all other states we set $-\infty$. How do the values of dp change when transitioning from the $i$-th layer to the $(i+1)$-th layer? First, we can set that $dp'_{i+1} = dp'_i$ for all pairs $(x,y)$ (all subsets available with the right boundary $i$ remain available with the right boundary $i+1$), and then we will try to "improve" it using the new element.

How can the new element $a_i$ "improve" the values of the dynamic programming? For some $(x,y)$, there may be a way to form $x$ using $y$ elements with a more optimal left boundary. Firstly, the way to form $a_i$ using $1$ element will definitely improve, so we can assign $dp'[i+1,a_i,1] = i$. Secondly, we can take some set that is reachable for the right boundary $i$ and add the element $a_i$ to it; that is, we transition from $dp'[i,x,y]$ to $dp'[i+1, x \oplus a_i, y+1]$. The minimum index of the number that we will use in such a set will still be $dp'[i,x,y]$, because the new number $a_i$ has a higher index than all the previous numbers we have used. Therefore, if there is a way to form $x$ using $y$ elements with the right boundary $i$ and the left boundary $dp'[i,x,y]$, we can form $dp'[i+1, x \oplus a_i, y+1]$ with the same left boundary.

This dynamic programming has a complexity of $O(n \cdot B \cdot 2^B)$, which is quite fast but does not fit into memory limits. To fix this, let's group all queries according to their right boundaries, and store only two (or even only one!) layer of dynamic programming, moving the right boundary and answering all queries for the current right boundary. This will reduce memory usage to $O(B \cdot 2^B)$, which fits within the constraints.


**Solution (BledDest)**
```cpp
#include<bits/stdc++.h>

using namespace std;

const int B = 13;
const int M = (1 << (B - 1));
const int INF = 1e9;

int dp[B][M];

void upd(int& a, int b)
{
 if(a < b) a = b;
}

int main()
{
 ios_base::sync_with_stdio(0);
 cin.tie(0);
 int n;
 cin >> n;
 vector<int> a(n);
 for(int i = 0; i < n; i++) cin >> a[i];
 vector<vector<int>> id(n);
 int q;
 cin >> q;
 vector<int> l(q), x(q);
 for(int i = 0; i < q; i++)
 {
 int r;
 cin >> l[i] >> r >> x[i];
 --l[i];
 --r;
 id[r].push_back(i);
 }

 for(int i = 0; i < B; i++)
 for(int j = 0; j < M; j++)
 dp[i][j] = -INF;
 dp[0][0] = INF;
 vector<int> ans(q, 0);
 for(int i = 0; i < n; i++)
 {
 int val = a[i];
 upd(dp[1][val], i);
 for(int j = 1; j < B - 1; j++)
 {
 for(int k = 1; k < M; k++)
 {
 upd(dp[j + 1][k ^ val], dp[j][k]);
 }
 }
 for(auto qr : id[i])
 {
 int cur = x[qr];
 for(int j = B - 1; j >= 0; j--)
 if(dp[j][cur] >= l[qr])
 ans[qr] = j;
 }
 }

 for(int i = 0; i < q; i++)
 cout << ans[i] << " ";
 cout << endl;
}
```
