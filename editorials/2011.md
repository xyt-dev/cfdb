## 2011A - Problem Solving

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

If we want to determine that Jane's skill is $x$, then there should be a problem of difficulty $x$ which she solved, and a problem of difficulty $x+1$ which she didn't. Since the only problem she didn't solve has difficulty $d_n$, then if $x$ is unique, it should be equal to $d_n-1$.

So, let's check if there exists a problem of difficulty $d_n - 1$ which Jane solved. This can be done in a multitude of ways; the model solution uses the functions dropLast to form a version of the given array without the last element, and contains to check if the resulting array contains the value we need.


**Solution (Neon)**
```kotlin
fun main() = repeat(readln().toInt()) {
 readln().toInt()
 val a = readln().split(" ").map { it.toInt() }
 println(if (a.dropLast(1).contains(a.last() - 1)) a.last() - 1 else "Ambiguous")
}
```

## 2011B - Shuffle

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)
 
**Tutorial**

First of all, $1$ divides every other number, so there should be no elements to the left of $1$, and any element can be to the right of $1$.

If we exclude $1$ from numbers we consider, then for every pair of integers $x$ and $(x+1)$, $(x+1)$ is not divisible by $x$. So, we can always put $x$ after $(x+1)$, if $x$ is at least $2$.

This allows us to form an easy construction: $[1, n, n-1, n-2, \dots, 2]$. To form a list of all integers from $n$ to $2$, you can use the function downTo; then, you should concatenate the array consisting of only integer $1$ with the resulting list.

 
**Solution (Neon)**
```kotlin
fun main() = repeat(readln().toInt()) {
  val n = readln().toInt()
  println((listOf(1) + (n downTo 2)).joinToString(" "))
}
```

## 2011C - Split the Expression

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [BledDest](<https://codeforces.com/profile/BledDest>)

**Tutorial**

This problem is much easier to implement in Kotlin than in, for example, C++.

First of all, since every expression contains one + sign, the number of expressions should be equal to the number of + signs. Furthermore, we can find the positions to split the given expression: in every block of digits except for the first and the last block, we need to choose a "cut" that leaves both parts of the block non-empty.

After we've chosen our "cut" positions, the sum of all expressions is just the sum of all integers we obtained. So, for every block (except for the first block and the last block), we have to split it so that the sum of two parts is the maximum possible. This can be done in two ways: either iterate on the position of the cut in a block, or check two options: make the left part a single digit, or the right part a single digit.

To split the given string into blocks of digits, you can use the method split("+"). The method toLong() will also be very helpful to convert blocks of digits into numbers (32-bit integers are not enough in this problem).


**Solution (Neon)**
```kotlin
fun main() = repeat(readln().toInt()) {
 val a = readln().split("+")
 val ans = a.foldIndexed(0L) { i, res, s ->
 res + if (i == 0 || i == a.size - 1)
 s.toLong()
 else
 (1 until s.length).maxOf { s.take(it).toLong() + s.drop(it).toLong() }
 }
 println(ans)
}
```

## 2011D - Among Wolves

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [adedalic](<https://codeforces.com/profile/adedalic>)
 
**Tutorial**

In order to solve this task, let's analyze all cases. You can:

- Eradicate all wolves. It will cost you $h \cdot (\text{number of wolves})$.
- Ignore wolves and dig trenches around your sheep. Since all cells around the sheep are empty, it will cost you $3 \cdot b$ in the general case.
- Dig trenches and eradicate some wolves.
 Let's look at the third case closely. If you plan to dig a trench – you have to dig trenches in at least two cells; otherwise, the trench will be pointless. But if you dig two trenches, why not dig them to the left or to the right of the sheep?
Since the field has only two rows, digging two trenches to the left (right) of the sheep is enough to block all wolves to the left (right) of the sheep. So, you only need to eradicate wolves to the right (left) of the sheep.

In other words, the third case falls into only two options:

- Block the left side with two trenches and eradicate all wolves on the right side. It will cost $2 \cdot b + h \cdot (\text{wolves on the right})$.
- Block the right side with two trenches and eradicate all wolves on the left side. It will cost $2 \cdot b + h \cdot (\text{wolves on the left})$.

In total, you need to locate a column of the sheep, count the number of wolves on the left, wolves on the right, and choose a minimum among all $4$ cases.

It turns out that you don't even need to handle a case when the sheep is on the first or last column: in such case, case $2$ with ignoring wolves will be counted in case $3$ automatically.

 
**Solution (adedalic)**
```kotlin
fun main() {
    repeat(readln().toInt()) {
        val (n, h, b) = readln().split(' ').map { it.toLong() }
        val grid = Array(2) { readln() }
        val sheepColumn = grid[0].indices.find { grid[0][it] == 'S' || grid[1][it] == 'S' }!!
        val wolvesLeft = (0..1).sumOf { grid[it].take(sheepColumn).count { it == 'W' } }
        val wolvesRight = (0..1).sumOf { grid[it].substring(sheepColumn).count { it == 'W' } }

        val ans = minOf(
            (wolvesLeft + wolvesRight) * h,
            wolvesLeft * h + 2 * b,
            wolvesRight * h + 2 * b,
            3 * b
        )
        println(ans)
    }
}
```

## 2011E - Rock-Paper-Scissors Bot

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

First of all, let's map the characters R, P and S to integers from $0$ to $2$ so that we can get who wins by subtracting them. For example, if we map R to $0$, P to $1$ and S to $2$, then between two moves $x$ and $y$, we can check who beats whom: if $(y - x) \equiv 1 (\mod 3)$, then $y$ beats $x$, and if $(y - x) \equiv 2 (\mod 3)$, then $x$ beats $y$. This is an easy way to get which move beats which, and we can also obtain the move which beats move $x$ by computing $(x+1) \bmod 3$ (or the move which is beaten by $x$ as $(x+2) \bmod 3$).

Now, let us consider the string of bot's moves. We will try to "expand" it to the left and/or right so that it meets the conditions from the statement. If its length is denoted by $n$, then the results of $n-1$ rounds are determined by this string (all rounds except for the last round, since we can play anything we want in the last round, but our moves in all other rounds are described by bot's moves in the next rounds). Let's calculate how many rounds from these $n-1$ rounds we win. Also, we can consider that we win in the last round, since we can play anything we want.

If our score is not big enough, we can "fix" it by appending additional characters to the right end of the bot's string. We can always choose such a character to increase our score by $1$. For example, if the last character in the bot's string is R, then if we use P in the last round, the bot will respond with S in the next round (and we can use R to beat it). So, if the last character is R, we append S; if the last character is S, we append P, and so on — and it increases our score by $1$ every time we append one character. We don't even have to actually append characters, we can simply calculate the number of characters we need so that our score is higher.

However, there is still one problem to solve: what if the bot's string does not begin with R? Then we must append several characters at the beginning.

One possible solution to this issue does as follows: choose a small constant $K$, consider all strings of no more than $K$ characters that begin with R, and try to append them to the beginning of the given string $s$; then consider only the possibility of appending characters to the right end of the string we got. Let's prove that $K=2$ is enough (and also design a simpler solution):

- if the starting character in the bot's string is R, then there is no issue;
- if the starting character in the bot's string is S, it means we played a P in the previous move. Let's add R to the start of the bot's string and play P in the first round; this both increases our score by $1$ and "fixes" the issue;
- but if the starting character in the bot's string is P, it gets a bit trickier. We can either add R to the beginning right away, but this means we played R in the first round, so we got a tie (we increased the length by $1$, but the score is still the same). But sometimes it's better to add RS in the beginning of bot's string — this will increase our score by $2$.

This way, we get a solution working in $O(n)$: try to add R or RS to the beginning of the bot's string if it does not begin with R, and calculate the minimum number of rounds we need to add at the end.


**Solution (Neon)**
```kotlin
const val INF = 1e9.toInt()
const val vars = "RPS"

fun main() = repeat(readln().toInt()) {
 val a = readln().map { vars.indexOf(it) }

 fun calc(a : List<Int>) : Int {
 if (a[0] != 0) return INF
 val balance = a.zipWithNext().fold(0) { s, (x, y) ->
 s + (if (x == y) 1 else 0) - (if ((x + 2) % 3 == y) 1 else 0)
 }
 return a.size + maxOf(balance, 0)
 }

 println(minOf(
 calc(a),
 calc(listOf(0) + a),
 calc(listOf(0, 2) + a)
 ))
}
```

## 2011F - Good Subarray

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

Let's calculate the array $\mathit{prev}_i$ — the nearest element to the left of $i$ that can add the $i$-th element during the execution of the algorithm (i.e., the nearest value to the left among $(a_i-1)$, $a_i$, and $(a_i+1)$).

Note that a subarray $[l, r]$ is good if there is no index $j$ such that $l \lt j \le r$, and $\mathit{prev}_j \lt l$. It follows that for a fixed left boundary $l$, we need to find the minimum $j$ for which the above conditions hold, and then the answer can be increased by $(j - l)$, since $r \in [l, j)$ are good.

Using that fact, we can iterate over the left boundary of the segment $l$ from right to left. And maintain a stack of all indices $j$ such that $j \gt l$ and $\mathit{prev}_j \lt l$. If the value at the top of the stack no longer satisfies this condition when moving to the next value of $l$, it can be removed (since the condition doesn't hold for all next $l$ either). After that, the top of the stack contains the minimum $j$, that allows us to update the answer (if the stack is empty, any right boundary is good). After that, it is sufficient to push the index $l$ onto the stack and move to the next value.

Thus, we have obtained a solution that works in $O(n)$.

 
**Solution (Neon)**
```kotlin
fun main() = repeat(readln().toInt()) {  
  val n = readln().toInt()
  val a = readln().split(" ").map { it.toInt() - 1 }
  
  val prev = IntArray(n + 1) { -1 }
  val pos = IntArray(n) { -1 } 
  
  for (i in 0 until n) {
    for (j in a[i]-1..a[i]+1) {
      if (0 <= j && j < n) {
        prev[i] = maxOf(prev[i], pos[j])
      }
    }
    pos[a[i]] = i
  }
  
  val st = mutableListOf(n)
  var ans = 0L
  for (i in (n - 1) downTo 0) {
    while (st.size > 0 && prev[st.last()] >= i) {
      st.removeLast()
    }
    ans += st.last() - i
    st.add(i)
  }
  
  println(ans)
}
```

## 2011G - Removal of a Permutation

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)

**Tutorial**

Consider each pair of adjacent elements. Either $p_i \lt p_{i+1}$ (and then an operation of first type "triggers" this pair, deleting the lesser element from it), or $p_i \gt p_{i+1}$ (and then an operation of second type "triggers" this pair). So, if we denote the number of elements deleted by the first operation as $x$ and the number of elements deleted by the second operation as $y$, then $x + y = n - 1$. This means that $\max(x, y) \ge \frac{n-1}{2}$.

If every time we choose an operation which deletes more elements, we will make about $\log_2 n$ operations in total. So, the answer is bounded by something like $18$. However, this way to delete everything might not be the fastest for all elements.

Let's iterate on the sequence of operations we make: it must be a sequence of at most $\log_2 n$ operations, so there are $O(n)$ such sequences and each of them is analyzed in $O(n \log n)$. Looks like $O(n^2 \log n)$, right?

Here comes the magic: if you consider all these sequences of operations not longer than $18$ recursively, with a function like rec(step, p) (where $step$ is the current recursion depth, and $p$ is the current state of the array), it works in $O(n \log n)$. Why? Obviously, one operation is made in $O(m)$, where $m$ is the current size of the array $p$. However, we can bound the total size of all arrays $p$ on a single recursion level as $O(n)$ as follows.

Recall that if we denote the number of elements deleted by the first operation as $x$ and the number of elements deleted by the second operation as $y$, then $x + y = n - 1$ (where $n$ is the current size of the array). This means that if we ignore one element from each array, then we can think in similar style to "every element appears on each recursion level exactly once" (this is not exactly right, but works very similarly). If you want a more formal proof, then we can say that the total size of all calls on depth $x$ is equal to the total size of all calls on depth $x-1$, plus the number of calls on depth $x-1$. So, on level $0$, there is one call and total size of calls is $n$; on level $1$, there are two calls and the total size of calls is $n+1$, and so on — on level $\log_2 n$, we get $2^{\log_2 n}$ calls with total size of $O(n)$.

Shortly, the solution can be boiled down to something like "make a recursive search over all sequences of operations, limit the recursion depth by $\log_2 n$, and it works in $O(n \log n)$".


**Solution (Neon)**
```kotlin
const val LOG = 19

fun main() = repeat(readln().toInt()) {
 val n = readln().toInt()
 val p = readln().split(" ").map { it.toInt() - 1 }
 val ans = IntArray(n - 1) { n }

 fun rec(step: Int, p: List<Int>) {
 if (p.size == 1 || step == LOG) return
 for (cur in listOf(p, p.reversed())) {
 val (a, b) = cur.zipWithNext().partition { (x, y) -> x < y }
 a.forEach { (x, _) -> ans[x] = minOf(ans[x], step) }
 rec(step + 1, b.map { (x, _) -> x} + cur.last())
 }
 }

 rec(1, p)

 println(ans.joinToString(" "))
}
```

## 2011H - Strange Matrix

Idea: [BledDest](<https://codeforces.com/profile/BledDest>), preparation: [Neon](<https://codeforces.com/profile/Neon>)
 
**Tutorial**

Note that the problem can be solved bit by bit. It remains to determine for each row whether XOR needs to be performed or not.

Consider two rows of the matrix and the definition of a strange matrix for them. The first condition means that there are no $k$ indices where this bit is $1$ in both rows. The second condition means that there are no $k$ indices where this bit is $0$ in both rows.

Notice that if we apply XOR to both rows, that doesn't affect the fulfillment of the strangeness conditions. Also, note that applying XOR only to the first row is equivalent (in terms of their "strangeness") to applying XOR only to the second row.

Thus, for each pair of rows, there are $4$ possible situations:

- XOR can be applied in any way;
- XOR needs to be applied only to one;
- XOR needs to be applied to both or not applied at all;
- the "strangeness" condition is never fulfilled.

If there is a pair of rows for which the last situation occurs, then the answer to the problem is $-1$.

Each pair of rows is constrained by conditions $2$ and $3$. They must be either in different groups (regarding the need to XOR) or in the same group.

This brings us to the bipartite coloring problem. Let's create a graph with $n$ vertices, connecting pairs of type $2$ with edges of length $1$, and pairs of type $3$ with edges of length $0$. It remains to check that each connected component is bipartite (if it is not, then the answer to the problem is $-1$). After coloring the components, we must choose the color with fewer vertices and XOR all given rows.

 
**Solution (Neon)**
```kotlin
const val INF = 1e9.toInt()
const val B = 5

fun main() = repeat(readln().toInt()) {
  val (n, m, k) = readInts()
  val a = Array(n) { readInts() }
  
  var ans = 0
  
  for (bit in 0 until B) {
    val g = Array(n) { ArrayList<Pair<Int, Int>>() }
    for (i in 0 until n) {
      for (j in 0 until i) {
        val cnt = IntArray(4) { 0 }
        for (x in 0 until m) {
          val f = (a[i][x] shr bit) and 1
          val s = (a[j][x] shr bit) and 1
          ++cnt[f * 2 + s];
        }
        val f1 = (cnt[0] < k && cnt[3] < k)
        val f2 = (cnt[1] < k && cnt[2] < k)
        if (f1 != f2) {
          g[i].add(j to if (f2) 1 else 0)
          g[j].add(i to if (f2) 1 else 0)
        } else if (!f1) {
          return@repeat println("-1")
        }
      }
    }
    
    val color = IntArray(n) { -1 }
    val cnt = IntArray(2) { 0 }
    var ok = true
    
    fun dfs(v: Int, c: Int) {
      color[v] = c
      ++cnt[c]
      for ((u, d) in g[v]) {
        if (color[u] != -1) {
          if ((c xor d) != color[u]) {
            ok = false
          }
        } else {
          dfs(u, c xor d)
        }
      }
    }
    
    for (v in 0 until n) {
      if (color[v] != -1) continue
      cnt.fill(0)
      dfs(v, 0)
      if (!ok) return@repeat println("-1")
      ans += cnt.min() shl bit
    }
  }
  
  println(maxOf(0, ans))
}

fun readInts() = readln().split(" ").map { it.toInt() }
```

## 2011I - Stack and Queue

Idea: [shnirelman](<https://codeforces.com/profile/shnirelman>), preparation: [awoo](<https://codeforces.com/profile/awoo>)

**Tutorial**

Consider the time intervals for a certain patient at both doctors. Let these be $[l_1; l_1 + a_i)$ and $[l_2; l_2 + a_i)$. How can we check if the configuration is good? For each patient, we need to ensure that these intervals do not overlap.

Then it makes sense to take the following step. Let's change the order of computation. Instead of checking the validity for all patients at each moment of time, let's find the moments of time when the intervals for each patient overlap.

First, let's forget about queries of the third type. Suppose patients can only be added to a queue or a stack.

Here we can get this idea. The moments of time when the intervals of a certain patient overlap are consecutive, thus forming a segment of queries. Suppose a patient arrives earlier in the queue than in the stack. When he arrives in the queue, his interval $[l_1; l_1 + a_i)$ is defined, and no later queries will affect this interval. Then he arrives in the stack, and his interval in the stack becomes $[0; a_i)$. As more people arrive in the stack, his second interval will move further to the right. Accordingly, at some point, it will start overlapping with the first interval, and then it will be to the right of it and will never overlap again. The analysis for the case when the patient arrives in the stack earlier is similar.

Thus, we can solve the problem using binary search. We will collect all queries of the second type into a separate array and build a prefix sum on it. For each patient, we will find the first moment of time when his second interval starts overlapping with the first. Then we will find the last such moment of time. We will say that between these queries, the answer is "NO". This can be done using a difference array. Suppose we have to say "NO" for the segment from $l$ to $r$. We will increase $\mathit{dt}_l$ by $1$, decrease $\mathit{dt}_{r+1}$ by $1$, and collect the prefix sum over the array $\mathit{dt}$. Now all values from $l$ to $r$ inclusive are equal to $1$, while the others are equal to $0$. First, we will perform the additions and subtractions for all patients, then we will collect the prefix sum once at the end and output "YES" if $\mathit{dt}_i$ is equal to $0$ and "NO" otherwise.

Let's bring the queries of the third type back. What if such monotonicity still holds? Let's check. If the third query is applied to a patient, then one of his intervals is still undefined, so there is nothing to analyze. However, such movement affects the intervals of other patients. Since he leaves the queue, the intervals of patients in the queue after him move left by $a_i$. And since they are placed somewhere in the stack, the intervals of patients in the stack after him move right by $a_i$. Thus, the relative positioning of the intervals is still monotonic.

Great, so we can still apply binary search. However, it is not so straightforward to do now.

We will use the technique of parallel binary search. For each patient, we will store the boundaries of his binary search. At each iteration, we will simulate all queries and learn to ask at certain moments what intervals the patient has. For each patient, let's ask at the middle point of his binary search boundaries and save the new boundaries for the next iteration. If patients are stored in increasing order of their middle point, we can simulate queries with two pointers.

How to ask for the segments? We will create a data structure that maintains the prefix sum of patients in the queue and in the stack. When a patient arrives in the queue, let's add him to the structure for the queue, as well as create an empty spot for him in the stack and add $0$ to the stack. He will occupy this spot when the third type query is applied to him. When a patient arrives in the stack, we simply add him to the structure for the stack. When the third type query occurs, we will assign $0$ to his spot in the queue in the structure for the queue, and assign $a_i$ to the occupied spot in the stack in the structure for the stack. Now we can query both intervals in $O(\log n)$ using a mass sum query. For such queries, we can use a BIT.

Thus, we will perform $O(\log n)$ iterations of the external parallel binary search. Inside the iteration, we will apply all $n$ queries and ask for each patient once. Therefore, one iteration takes $O(n \log n)$.

Overall complexity: $O(n \log^2 n)$.

Alternatively, we can write parallel binary search using the "divide and conquer" approach. We will write a function $\mathit{calc(l, r, ids)}$ that maintains the indices of patients whose binary search boundaries take values $[l; r)$.

Upon entering the function, we will maintain the invariant that queries from $0$ to $l$ (not inclusive) have already been applied. The process is as follows. Let $\displaystyle m = \lfloor\frac{l + r}{2}\rfloor$. We will apply queries from $l$ to $m$ (not inclusive) in the same way as in the first solution. Then we will go through the patients from the list $\mathit{ids}$ and make a query for their intervals. Based on the results of the query, we will understand the new boundaries of the binary search. Accordingly, we will distribute patients into those who go into the recursive call $[l; m)$ and those who go into $[m; r)$. Then we will solve the problem recursively on $[m; r)$ (since queries from $0$ to $m$ are now applied). After that, we will roll back the changes made by applying queries from $l$ to $m$. Finally, we will solve the problem recursively on $[l; m)$.

Overall complexity: $O(n \log^2 n)$.


**Solution (awoo)**

class Query(val t: Int, val x: Int)

class BIT(val mx: Int) {
    val f = LongArray(mx) { 0L }
    
    fun upd_pr(pos: Int, x: Int) {
        var i = pos
        while (i < mx) {
            f[i] = f[i] + x
            i = i or (i + 1)
        }
    }

    fun get_pr(pos: Int) : Long {
        var res = 0L
        var i = pos
        while (i >= 0) {
            res += f[i]
            i = (i and (i + 1)) - 1
        }
        return res
    }

    fun upd_su(pos: Int, x: Int) {
        var i = pos
        while (i >= 0) {
            f[i] = f[i] + x
            i = (i and (i + 1)) - 1
        }
    }

    fun get_su(pos: Int) : Long {
        var res = 0L
        var i = pos
        while (i < mx) {
            res += f[i]
            i = i or (i + 1)
        }
        return res
    }
}

fun main() {
    val n = readLine()!!.toInt()
    val a = readLine()!!.split(" ").map { it.toInt() }
    val q = Array(n) { Query(-1, -1) }
    for (i in 0 until n) {
        val (t, x) = readLine()!!.split(" ").map { it.toInt() }
        q[i] = Query(t, x - 1)
    }
    val fq = BIT(n)
    val fs = BIT(n)
    
    val d = IntArray(n + 1) { 0 }
    val posq = IntArray(n) { -1 }
    val poss = IntArray(n) { -1 }
    val sv = IntArray(n) { -1 }
    var cntq = 0
    var cnts = 0
    
    fun calc(l: Int, r: Int, coef: Int, all: ArrayList<Int>) {
        if (l == r - 1) {
            d[l] += all.size * coef
            return
        }
        
        val m = (l + r) / 2
        
        val who_chg = ArrayList<Int>()
        val idx_chg = ArrayList<Int>()
        val val_chg = ArrayList<Int>()
        val chq = ArrayList<Pair<Int, Int>>()
        val chs = ArrayList<Pair<Int, Int>>()
        
        for (i in l until m) {
            val x = q[i].x
            if (q[i].t == 1) {
                who_chg.add(0)
                idx_chg.add(x)
                val_chg.add(posq[x])
                posq[x] = cntq
                who_chg.add(2)
                idx_chg.add(x)
                val_chg.add(sv[x])
                sv[x] = cnts
                cntq += 1
                cnts += 1
                chq.add(Pair(posq[x], -a[x]))
                fq.upd_pr(posq[x], a[x])
            }
            else if (q[i].t == 2){
                who_chg.add(1)
                idx_chg.add(x)
                val_chg.add(poss[x])
                poss[x] = cnts
                cnts += 1
                chs.add(Pair(poss[x], -a[x]))
                fs.upd_su(poss[x], a[x])
            }
            else{
                chq.add(Pair(posq[x], a[x]))
                fq.upd_pr(posq[x], -a[x])
                who_chg.add(0)
                idx_chg.add(x)
                val_chg.add(posq[x])
                posq[x] = -1
                who_chg.add(1)
                idx_chg.add(x)
                val_chg.add(poss[x])
                poss[x] = sv[x]
                who_chg.add(2)
                idx_chg.add(x)
                val_chg.add(sv[x])
                sv[x] = -1
                chs.add(Pair(poss[x], -a[x]))
                fs.upd_su(poss[x], a[x])
            }
        }
    
        val tol = ArrayList<Int>()
        val tor = ArrayList<Int>()

            val ts = fs.get_su(poss[x] + 1)
            var ok = true
            if (coef == 1) {
                ok = tq - a[x] >= ts
            }
            else {
                ok = tq + a[x] > ts
            }
            if (ok) {
                tor.add(x)
            }
            else {
                tol.add(x)
            }
        }
    
        calc(m, r, coef, tor)
        
        who_chg.reverse()
        idx_chg.reverse()
        val_chg.reverse()
        
        for (i in 0 until who_chg.size) {
            if (who_chg[i] == 0) {
                posq[idx_chg[i]] = val_chg[i]
            }
            else if (who_chg[i] == 1) {
                poss[idx_chg[i]] = val_chg[i]
            }
            else {
                sv[idx_chg[i]] = val_chg[i]
            }
        }
        
        for (i in l until m) {
            if (q[i].t == 1) {
                cntq -= 1
                cnts -= 1
            }
            else if (q[i].t == 2){
                cnts -= 1
            }

            fq.upd_pr(it.first, it.second)
        }
        for (it in chs) {
            fs.upd_su(it.first, it.second)
        }
        
        calc(l, m, coef, tol)
    }
    
    val all = ArrayList<Int>()

        all.add(i)

        d[i + 1] += d[i]
    }

    println(res.take(res.size - 1).joinToString(separator = "\n"))
}
