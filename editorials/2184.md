## 2184A - Social Experiment

Idea: [fstilus](<https://codeforces.com/profile/fstilus>); developer: [fstilus](<https://codeforces.com/profile/fstilus>)

**Hint**

How many people can be in one civilization?

**Answer**

Any non-negative number of people, except for the number $1$.




First, let's find out how many people can be in one civilization. Note that there can be $0$, $2$, or $3$ people in it. If we add any number of groups of two people to a group of $2$, we can obtain any even number of people. The same can be done with a group of $3$ people; thus, we can achieve any odd number of people, except for the number $1$. That is, a civilization can be of any non-negative size, except for $1$.

This means that if we split $n$ into two civilizations as evenly as possible (to $\frac{n}{2}$ if $n$ is even or to $\frac{n-1}{2}$ and $\frac{n+1}{2}$ if $n$ is odd), and neither of the sizes equals $1$, then such a partition is achievable. Note that the size $1$ in such a division is only reached when $n$ is equal to $2$ or $3$. Therefore, if $n \le 3$, the answer is $n$; otherwise, the answer is $n \mod 2$.


**Solution**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
 int t;
 cin >> t;

 while (t--) {
 int n;
 cin >> n;
 if (n == 2) cout << "2\n";
 if (n == 3) cout << "3\n";
 if (n >= 4) cout << n % 2 << '\n';
 }

 return 0;
}
```

## 2184B - Hourglass

Idea: [fstilus](<https://codeforces.com/profile/fstilus>); developer: [fstilus](<https://codeforces.com/profile/fstilus>)
 
**Hint**

How many minutes of sand will remain in the upper half of the hourglass immediately after the second flip?
 
**Answer**

$s$ minutes.

 
**

For now, we will not consider $m$. Let's note two cases:

- If $s \gt k$, then in the first $k$ minutes, $k$ minutes of sand will fall out, and there will be $s-k$ minutes of sand left in the upper half of the hourglass. After the first flip, there will be $k$ minutes of sand on top. This means that in the first $2 \cdot k$ minutes, there will be nothing left in the upper half. From this, we can conclude that every $2 \cdot k$ minutes, the amount of sand in the upper half will be the same.
- If $s \le k$, then in the first $k$ minutes, all $s$ minutes of sand will fall out, and there will be nothing left in the upper half. From this, we can conclude that every $k$ minutes, the amount of sand in the upper half will be the same.

Now let's return to $m$. We will consider both cases:

- If $s \gt k$, replace the value of $m$ with $m \mod {2 \cdot k}$. If $0 \le m \le k-1$, then there will be $s - m$ minutes of sand left in the upper half, and if $k \le m \le 2\cdot k - 1$, then there will be $k - (m - k)$ minutes of sand left in the upper half.
- If $s \le k$, replace the value of $m$ with $m \mod {k}$. If $0 \le m \lt s$, then there will be $s - m$ minutes of sand left in the upper half; otherwise, there will be $0$ minutes of sand left.

 
**Solution**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
int main() {
    int t;
    cin >> t;
    
    while (t--) {
        int s, k, m;
        cin >> s >> k >> m;
        
        if (s <= k) cout << max(0, s - m % k) << '\n';
	else cout << (((m % (2 * k)) < k) ? s - m % k : k - m % k) << '\n';
    }
    
    return 0;
}
```

## 2184C - Huge Pile

Idea: [Friendiks](<https://codeforces.com/profile/Friendiks>); developer: [fstilus](<https://codeforces.com/profile/fstilus>)

**Hint 1**

Why is brute force ineffective? How can it be improved?

**Answer**

Because the same numbers are visited multiple times.


**Hint 2**

How many distinct values can be obtained starting from the number $n$?

**Answer**

$O(\log n)$.




Let's construct a decision tree starting from the number $n$: from each vertex $x$, edges lead to $\lfloor \frac{x}{2} \rfloor$ and $\lceil \frac{x}{2} \rceil$. The process stops at the values $0$ and $1$, since $k \ge 1$.

It is claimed that the number of distinct values in such a tree is small. Let the $i$-th layer of the tree be the set of vertices located at depth $i$ from the root, where the number $n$ is located. Let the minimum value on the $i$-th layer be $l_i$, and the maximum be $r_i$. Then $l_0 = r_0 = n$.

Note that for the next layer, the following estimates hold: $l_{i+1} \ge \lfloor \frac{l_i}{2} \rfloor \ge \frac{l_i-1}{2}$ and $r_{i+1} \le \lceil \frac{r_i}{2} \rceil \le \frac{r_i+1}{2}$.

Let's estimate the number of integers on the $(i+1)$-th layer using the difference $r_{i+1} - l_{i+1} + 1$: $$r_{i+1} - l_{i+1} + 1 \le \frac{r_i + 1}{2} - \frac{l_i - 1}{2} + 1 = \frac{r_i - l_i}{2} + 2$$

Let $d_i = r_i - l_i + 1$ be the number of values in the range on layer $i$. Then $d_{i+1} \le \frac{d_i - 1}{2} + 2$. Let's analyze this relation:

1. If $d_i = 1$, then $d_{i+1} \le 0.5 \cdot 0 + 2 = 2$.

2. If $d_i = 2$, then $d_{i+1} \le 0.5 \cdot 1 + 2 = 2.5 \Rightarrow d_{i+1} \le 2$ (since the number is an integer).

Thus, if a layer had no more than $2$ distinct values, then the next layer will also have no more than 2. Since there is only one value ($n$) on the zero layer, there will be no more than two distinct numbers on each subsequent layer.

There will be $O(\log n)$ layers in the tree in total, which means the total number of distinct vertices will be $O(\log n)$.

To solve the problem, it is sufficient to find the minimum depth $i$ at which the number $k$ occurs among the vertices of the $i$-th layer. This can be done either by iterating through the layers and constructing the values for the current layer based on the previous one, or by using recursion with memoization (storing results for each number $x$).


**Solution**
```cpp
#include <bits/stdc++.h>

using namespace std;

int main() {
 int t;
 cin >> t;

 while (t--) {
 int n, k;
 cin >> n >> k;

 int l = n, r = n;
 int cnt = 0;
 while (r != 1) {
 if (l <= k && k <= r) break;
 l = l / 2;
 r = r / 2 + r % 2;
 cnt++;
 }
 if (l <= k && k <= r) cout << cnt << '\n';
 else cout << -1 << '\n';
 }

 return 0;
}
```

## 2184D - Unfair Game

Idea: [Friendiks](<https://codeforces.com/profile/Friendiks>); developer: [Friendiks](<https://codeforces.com/profile/Friendiks>)
 
**Hint 1**

Alice's winning strategy is related to bits.

 
**Hint 2**

Alice's optimal number of moves depends only on the most significant bit and the number of set bits.

 
**Hint 3**

The number $n$ is a power of two, which means if you subtract $1$, any subset of bits of $n-1$ will not exceed $n-1$.

 
**

Notice that it is optimal for Alice to act as follows: if the number is even, divide it by $2$; if it is odd, subtract $1$. It can be shown that there is no strategy that allows the game to end faster.

Based on this tactic, let us analyze what happens to the binary representation of the number $n$. If the number is even, its binary representation ends in $0$, and dividing by $2$ simply removes this zero. If the number is odd, the last one in the binary representation turns into $0$ upon subtraction, after which it is removed by dividing by $2$. Thus, each zero bit (except for leading zeros) requires $1$ operation (division), while each unit bit, except for the unit corresponding to the most significant bit, requires $2$ operations (subtraction + division). The unit corresponding to the most significant bit will eventually become the last bit when the number equals $1$, and then one final subtraction will finish the game.

Consequently, starting from the number $a$, Alice needs to perform $maxBit(a) + cntBit(a)$ operations, where $maxBit(a)$ is the index of the most significant bit of the number $a$ (using zero-based indexing), and $cntBit(a)$ is the number of set bits in $a$.

Now we need to learn how to count the number of such $1 \le a \le n$ (where $n = 2^d$) for which $maxBit(a) + cntBit(a) \gt k$.

- Consider the numbers $1 \le a \lt n$. For them, $maxBit$ can take values from $0$ to $d-1$.
- Iterate through the values of $maxBit$ from $0$ to $d-1$, and then iterate through $cntBit$ from $1$ to $maxBit+1$.
- If the condition $maxBit + cntBit \gt k$ holds for the current pair, we need to add the number of ways to form such a number to the answer. Since the position of the most significant bit ($maxBit$) is already fixed, we only need to choose $cntBit-1$ units in the remaining $maxBit$ positions. The number of such ways equals $\dbinom{maxBit}{cntBit-1}$.

Separately check the number $n = 2^d$. For it, $maxBit(n) = d$ and $cntBit(n) = 1$. If $d + 1 \gt k$, add $1$ to the total answer.

For implementation, it is convenient to use the fact that $\dbinom{n}{k} = \dbinom{n-1}{k-1} + \dbinom{n-1}{k}$. This allows us to precompute all values of $\dbinom{n}{k}$ for $0 \le k \le n \le 30$ in advance.

 
**Solution**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
int c_n_k[31][31];

int main() {
    for (int i = 0; i < 30; ++i) {
        for (int j = 0; j < 30; ++j) {
            if (i < j) c_n_k[i][j] = 0;
            else if (j == 0) c_n_k[i][j] = 1;
            else c_n_k[i][j] = c_n_k[i - 1][j] + c_n_k[i - 1][j - 1];
        }
    }

    int t;
    cin >> t;

    while (t--) {
        int n, k;
        cin >> n >> k;

        int d = 0;
        while (n % 2 == 0) {
            n /= 2;
            ++d;
        }

        int ans = 0;
        for (int max_bit = 0; max_bit < d; ++max_bit) {
            for (int cnt_bit = 1; cnt_bit <= max_bit + 1; ++cnt_bit) {
                if (max_bit + cnt_bit <= k) continue;
                ans += c_n_k[max_bit][cnt_bit - 1];
            }
        }

        if (d + 1 > k) ++ans;
        cout << ans << "\n";
    }

    return 0;
}
```

## 2184E - Exquisite Array

Idea: [fstilus](<https://codeforces.com/profile/fstilus>); developer: [fstilus](<https://codeforces.com/profile/fstilus>)

**Hint 1**

If some array is $k$-exquisite, then any of its subsegments of length at least $2$ is also $k$-exquisite.


**Hint 2**

If $k_1 \gt k_2$ and some array is $k_1$-exquisite, then it is also $k_2$-exquisite.


**Hint 3**

If some array of length $m$ is $k$-exquisite, how many $k$-exquisite subsegments does it have?

**Answer**

$\frac{m \cdot (m - 1)}{2}$.


**Hint 4**

For a fixed $k$, come up with a way to divide the entire original permutation into segments, each of which is either $k$-exquisite or of length $1$, so that you can use the formula from the previous hint.


**Hint 5**

How to transition from the segmentation for $k+1$ to the segmentation for $k$?

**Answer**

You need to find all positions where the difference between the elements of the permutation equals $k$, and merge the corresponding segments.


**Hint 6**

Determine how the answer changes with each merging of two segments.




It is not difficult to see that if $k_1 \gt k_2$ and some subsegment is $k_1$-exquisite, then any of its subsegments of length at least $2$ is also $k_1$-exquisite, and they are $k_2$-exquisite as well. This means that we can iterate $k$ from $n-1$ to $1$ (since the absolute difference between adjacent elements of the permutation can only take values from the interval $[1; n-1]$).

For each possible value of $k$, we will remember all positions where the absolute difference between adjacent elements of the permutation equals $k$.

Initially, we will divide the entire permutation into segments consisting of a single element. We will iterate $k$ from $n-1$ to $1$. After each subsequent step with a fixed $k$, these segments will represent a partition into $k$-exquisite segments and segments of length $1$, such that there is no $k$-exquisite subsegment that is not entirely part of one of the segments in the partition. This can be achieved by maintaining the minimum absolute difference between adjacent elements of each segment to be at least $k$. For a fixed $k$, we will consider all positions where the absolute difference between adjacent elements of the permutation equals $k$, and we will merge the corresponding segments.

After we have performed all actions in this algorithm for a fixed $k$ and obtained the partition $segs$, the number of $k$-exquisite subsegments can be found using the formula $\sum_{seg \in segs} \frac{len(seg) \cdot (len(seg) - 1)}{2}$, where $len(seg)$ is the number of elements in the segment $seg$. Instead of recalculating this sum from scratch for each $k$, we will maintain this sum from previous steps of the algorithm, and when merging two segments, we will subtract the corresponding fractions of these two segments from the sum, and then add the corresponding fraction of the resulting segment.

Merging segments can be done using a DSU, or built-in data structures like set, or any other method you are familiar with. The overall complexity of the solution will be $O(n \cdot f(n))$, where $f(n)$ is the asymptotic complexity of merging two segments using the chosen method.


**Solution**
```cpp
#include <bits/stdc++.h>

using namespace std;

vector <int> parent;
vector <int> rnk;
vector <int> sz;

void make_set(int v) {
 parent[v] = v;
 rnk[v] = 0;
 sz[v] = 1;
}

int find_set(int v) {
 if (v == parent[v])
 return v;
 return parent[v] = find_set(parent[v]);
}

void union_sets(int a, int b) {
 a = find_set(a);
 b = find_set(b);
 if (a != b) {
 if (rnk[a] < rnk[b])
 swap (a, b);
 parent[b] = a;
 if (rnk[a] == rnk[b])
 ++rnk[a];
 sz[a] += sz[b];
 }
}

long long cnt(int x) {
 x = find_set(x);
 return (long long)sz[x] * (sz[x] - 1) / 2;
}

int main() {
 int t;
 cin >> t;

 while (t--) {
 int n;
 cin >> n;

 map <int, vector <int>> m;
 int pr;
 for (int i = 0; i < n; i++) {
 int a;
 cin >> a;
 if (i > 0)
 m[abs(a - pr)].push_back(i);
 pr = a;
 }

 parent.resize(n);
 rnk.resize(n);
 sz.resize(n);
 for (int i = 0; i < n; i++) make_set(i);

 vector <long long> ans;
 long long cur = 0;
 for (int i = n - 1; i > 0; i--) {
 for (auto y : m[i]) {
 cur -= cnt(y);
 cur -= cnt(y - 1);
 union_sets(y, y - 1);
 cur += cnt(y);
 }
 ans.push_back(cur);
 }

 reverse(ans.begin(), ans.end());
 for (auto x : ans) cout << x << ' ';
 cout << '\n';

 parent.clear();
 rnk.clear();
 sz.clear();
 }

 return 0;
}
```

## 2184F - Cherry Tree

Idea: [gravitsapa](<https://codeforces.com/profile/gravitsapa>); developer: [gravitsapa](<https://codeforces.com/profile/gravitsapa>)
 
**Hints for the first method**

**Hint 1**

Come up with a dynamic programming array $dp[u][k]$ with $O(n^2)$ states, where $u$ is the vertex number, $k$ is an additional parameter, and $dp[u][k]$ indicates whether it is possible to collect all the cherries in the subtree of vertex $u$ given that the additional parameter equals $k$.
 
**Answer**

You can use an additional parameter equal to the number of vertices in the subtree of vertex $u$ that were shaken.

 
**Hint 2**

The parameter $k$ should be considered modulo $3$. Thus, the number of states in the dynamic programming becomes $O(n)$.

 
**Hint 3**

Where will the answer to the problem be located?
 
**Answer**

The answer to the problem is located in $dp[1][0]$.

 
**Hint 4**

What will be the base case for the dynamic programming?
 
**Answer**

If vertex $u$ is a leaf, then $dp[u][0] = False, dp[u][1] = True, dp[u][2] = False$.

 
**Hint 5**

To recalculate the dynamic programming $dp[u]$, two cases need to be considered: whether vertex $u$ was shaken or not. If vertex $u$ was shaken, then it is obviously the only vertex in the entire subtree that was shaken.

 
**Hint 6**

If vertex $u$ was not shaken, then it is necessary to collect cherries in each of its children independently. The information on how this can be done for child $v$ is stored in $dp[v]$.

 
**Hint 7**

To recalculate $dp[u]$ through its children, dynamic programming needs to be used again.

 
**Hints for the second method**

**Hint 1**

Initially, we will only shake the root vertex. Then we will take some vertex that needs to be shaken and replace it with its children. This way, we can obtain any correct solution.

 
**Hint 2**

During this process, the number of selected vertices changes depending on the number of children of the vertex being replaced. Only the number of children modulo $3$ matters.

 
**Hint 3**

For each vertex that is not a leaf, we can record the number of its children modulo $3$ and find a pattern between the answer and these numbers.

 
**

First method: dynamic programming on subtrees.

We will calculate the dynamic programming array $dp[u][i]$ — whether it is possible to collect all the cherries in the subtree of vertex $u$, if the number of vertices shaken in the subtree of $u$ is congruent to $i$ modulo $3$.

Base case of the dynamic programming: if vertex $u$ is a leaf, then $dp[u][0] = False, dp[u][1] = True, dp[u][2] = False$.

Dynamic programming transition: if vertex $u$ is not a leaf, there are two cases:

- Vertex $u$ is not shaken. Then we consider all the children of vertex $u$ in order. We will maintain $dp_{son}[j]$ — whether it is possible to collect all the cherries in the considered children, if the number of vertices shaken in the subtrees of the considered children is congruent to $j$ modulo $3$. Initially, $dp_{son}[0] = True, dp_{son}[1] = False, dp_{son}[2] = False$.When considering a new child $v$, we have the dynamic programming $dp_{son}[j]$ and know $dp[v][i]$. Based on these two dynamics, we want to obtain a new state of the dynamic programming $dp_{son}^{new}[k]$. If we shook $j$ vertices in the already considered children, and shook $i$ vertices in the new child, then in total we shook $k = (i + j) \mod 3$ vertices. Therefore, the transition is:
```python
for i in 0, 1, 2:
 for j in 0, 1, 2:
 if dp[v][i] and dp_son[j]:
 dp_son_new[(i + j) % 3] = True
```
After considering all the children, we assign $dp[u] = dp_{son}$.
-  If vertex $u$ is shaken, then none of its descendants are shaken. In this case, $dp[u][0] = False, dp[u][1] = True, dp[u][2] = False$.

Since either of the two cases is possible, we can calculate the dynamics from the first case and set $dp[u][1] = True$.

The answer to the problem will lie in $dp[1][0]$.

Second method: analytical solution.

Any set of vertices that need to be shaken can be constructed as follows. Initially, we add only the root of the tree to the desired set. Then we can perform the following operations as many times as we want: we choose some vertex that is not a leaf to shake, and replace it with its children. It is easy to see that such operations always keep the set of chosen vertices valid, and that any suitable set can be obtained through such operations.

Now let's write a number $a[u]$ from 0 to 2 on each vertex $u$ according to the following rules: 

-  If the vertex is a leaf, we write 0 on it. 
-  If the vertex has $c \gt 0$ children, we write the number $(c - 1) \mod 3$ on it. 
 These numbers have the following meaning: if we perform the operation of replacing vertex $u$ with its children, the size of the desired set will change by $a[u]$ modulo $3$.
Now let's focus only on the vertices $u$ for which $a[u] \neq 0$. We note the following fact: if there are two vertices $u, v$ that are not ancestor and descendant of each other, and at the same time $a[u] \neq 0, a[v] \neq 0$, then the answer to the problem is "yes".

Proof: let's perform operations wherever possible, without reaching vertices $u$ and $v$. Let the size of the desired set modulo $3$ become $S$. If $S = 0$, then we have found what we wanted. Otherwise, if $a[u] = 3 - S$ or $a[v] = 3 - S$, we will perform the operation with the corresponding vertex, and the size $S$ will become a multiple of $3$. If this is not the case, then $S = a[u] = a[v]$. In this case, we will perform the operation with both vertices, and the size $S$ will become a multiple of $3$.

Thus, for the answer to be "no", it is necessary that all "non-zero" vertices lie on the same path to the root. Moreover, the highest of them $u$ must have $a[u] = 1$, otherwise, by performing the operation only on it, we will make the size of the desired set a multiple of $3$. Similarly, the next vertex on the path must have $a[u] = 2$. And so on.

We obtain the following solution: the answer to the problem is "no" if and only if all "non-zero" vertices lie on the same path to the root, and their values alternate as $1, 2, 1, 2, \ldots$ This condition can be checked with a single DFS run.

 
**Solution 1**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
const int MAXN = 200001;

int n;
vector <int> graph[MAXN];
vector <bool> dp[MAXN];

void merge_dp(vector <bool>& lhs, vector <bool>& rhs, vector <bool>& result) {
    for (int i = 0; i < 3; ++i) {
        if (!lhs[i]) continue;
        for (int j = 0; j < 3; ++j) {
            if (!rhs[j]) continue;
            result[(i + j) % 3] = true;
        }
    }
}

void dfs(int u, int p) {
    vector <int> child;

    for (auto v : graph[u]) if (v != p) {
        dfs(v, u);
        child.push_back(v);
    }

    dp[u].resize(3);

    if (!child.empty()) {
        dp[u][0] = true;
        for (auto v : child) {
            vector <bool> result(3, false);
 
            merge_dp(dp[u], dp[v], result);
            dp[u] = result;
        }
    }

    dp[u][1] = true;
}

signed main() {
    ios::sync_with_stdio(false);
    cin.tie(0);

    int t;
    cin >> t;
    while (t--) {
        cin >> n;
        for (int i = 1; i <= n; ++i) {
            graph[i].clear();
            dp[i].clear();
        }
        for (int i = 0; i < n - 1; ++i) {
            int u, v;
            cin >> u >> v;
            graph[u].push_back(v);
            graph[v].push_back(u);
        }

        dfs(1, -1);

        cout << (dp[1][0] ? "YES" : "NO") << '\n';
    }

    return 0;
}
```


**Solution 2**
```cpp
#include <bits/stdc++.h>

using namespace std;

const int MAXN = 200001;

int n;
vector <int> graph[MAXN];
bool ans;

int dfs(int u, int p) {
 vector <int> child;
 int cnt = 0;

 for (auto v : graph[u]) if (v != p) {
 cnt++;
 auto t = dfs(v, u);
 if (t != 0) {
 child.push_back(t);
 }
 }

 if (child.size() > 1) {
 ans = true;
 return 0;
 }

 int type = cnt == 0 ? 0 : (cnt + 2) % 3;
 vector <int> ord;
 if (type) {
 ord.push_back(type);
 }
 if (!child.empty()) {
 ord.push_back(child[0]);
 }
 if (ord.size() == 2 && ord[0] + ord[1] != 3) {
 ans = true;
 return 0;
 }
 if (ord.size() >= 1) return ord[0];
 return 0;
}

signed main() {
 ios::sync_with_stdio(false);
 cin.tie(0);

 int t;
 cin >> t;

 while (t--) {
 cin >> n;
 for (int i = 1; i <= n; ++i) {
```

## 2184G - Nastiness of Segments

Idea: [Friendiks](<https://codeforces.com/profile/Friendiks>); developer: [Friendiks](<https://codeforces.com/profile/Friendiks>)
 
**Hint 1**

Fix $L$ and $R$ and define functions of integer $d$: $f(d) = d$, $g(d) = \min(a_L, \dots, a_{L+d})$, where $0 \le d \le R-L$. What can be said about these functions?
 
**Answer**

$f(d)$ is increasing, $g(d)$ is non-increasing.

 
**Hint 2**

How many times can the problem condition be satisfied if expressed through $f$ and $g$?
 
**Answer**

The condition is equivalent to the intersection of $f(d)$ and $g(d)$, meaning there is at most one suitable point.

 
**Hint 3**

Since the function $h(d) = f(d) - g(d)$ is monotonic, the only candidate for the intersection point is the minimum $d$ such that $h(d) \ge 0$ (or $f(d) \ge g(d)$).

 
**Hint 4**

Segment tree.

 
**

Fix the left boundary $l$. Consider two functions of $d \in [0, r-l]$:

- $f(d) = d$ — strictly increases.
- $g(d) = \min(a_l, a_{l+1}, \ldots, a_{l+d})$ — is non-increasing.

The problem condition is equivalent to finding $d$ such that $f(d) = g(d)$. Since one function strictly increases and the other is non-increasing, they can have at most one intersection point on the integers. Consequently, the sought value for the segment does not exceed $1$.

To find this point, note: if a solution exists, it is the minimum $d$ such that $f(d) \ge g(d)$. The difference $h(d) = f(d) - g(d)$ is monotonic, so we can apply binary search.

To solve, we use binary search and a segment tree. We search for the minimum $d$ with binary search, calculating $\min$ on the segment $[l,\ l+d]$ using the segment tree at each iteration. Complexity: $O(n + q \log^2 n)$. To get rid of the squared logarithm, we use a descent on the segment tree. We start from the root and at each step determine whether the intersection point can be in the left child. To do this, we check if the sign of the function $h(c_l)$ is not equal to the sign of the function $h(c_r)$, where $[c_l,\ c_r]$ is the segment covered by the left child. If the signs are equal, then the sought point lies in the right child. This allows finding $d$ in $O(\log n)$.

Final complexity: $O(n + q \log n)$.

 
**Solution**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
const int MAXN = 2e5 + 7;

int a[MAXN], st[4 * MAXN];

void build(int v, int l, int r) {
    if (l + 1 == r) {
        st[v] = a[l];
        return;
    }
    int m = (r + l) / 2;
    build(v * 2 + 1, l, m);
    build(v * 2 + 2, m, r);
    st[v] = min(st[v * 2 + 1], st[v * 2 + 2]);
}

void upd(int v, int l, int r, int i, int x) {
    if (i < l || r <= i) return;
    if (l + 1 == r) {
        a[i] = x;
        st[v] = x;
        return;
    }
    int m = (r + l) / 2;
    upd(v * 2 + 1, l, m, i, x);
    upd(v * 2 + 2, m, r, i, x);
    st[v] = min(st[v * 2 + 1], st[v * 2 + 2]);
}

int getMin(int v, int l, int r, int lq, int rq) {
    if (rq <= l || r <= lq) return (int) 1e6;
    if (lq <= l && r <= rq) return st[v];
    int m = (r + l) / 2;
    return min(getMin(v * 2 + 1, l, m, lq, rq), getMin(v * 2 + 2, m, r, lq, rq));
}

int ans, currMn;

void findInter(int v, int l, int r, int lq, int rq) {
    if (rq <= l || r <= lq || ans != (int) 1e6) return;
    if (lq <= l && r <= rq && min(currMn, st[v]) > r - lq - 1) {
        currMn = min(currMn, st[v]);
        return;
    }
    if (l + 1 == r) {
        ans = l;
        return;
    }
    int m = (r + l) / 2;
    findInter(v * 2 + 1, l, m, lq, rq);
    findInter(v * 2 + 2, m, r, lq, rq);
}

int main() {
    int t;
    cin >> t;

    while (t--) {
        int n, q;
        cin >> n >> q;
        for (int i = 0; i < n; ++i) cin >> a[i];

        build(0, 0, n);
        while (q--) {
            int idx;
            cin >> idx;

            if (idx == 1) {
                int i, x;
                cin >> i >> x;
                upd(0, 0, n, i - 1, x);
            } else {
                int l, r;
                cin >> l >> r;
                l--;

                if (getMin(0, 0, n, l, r) > r - l) {
                    cout << "0\n";
                    continue;
                }

                ans = currMn = (int) 1e6;
                findInter(0, 0, n, l, r);
                cout << (ans != (int) 1e6 && getMin(0, 0, n, l, ans + 1) == ans - l) << "\n";
            }
        }
    }

    return 0;
}
```
