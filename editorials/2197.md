## 2197A - Friendly Numbers

**Tutorial**

To solve this problem, it is sufficient to explicitly check that the number $i$ meets the condition for all $i$ from $x$ to $x + 83$. To verify this, we need to explicitly calculate $i - d(i)$. Now let's prove this.

Notice that numbers greater than $2 \cdot 10^9$ definitely do not suit us, since the sum of the digits of the number $2 \cdot 10^9 + y \cdot 10^9$ does not exceed $9 \cdot 9 + 2 + y = 83 + y$, while the value of $i$ in this case will be at least $(2 + y) \cdot 10^9$, which obviously cannot be suitable.

Thus, the maximum sum of the numbers we are interested in does not exceed $83$, which means that checking is relevant between $x$ and $x + 83$


**Solution**
```python
t = int(input())

 s = str(n)
 sum = 0
 for j in s:

 return sum

 for i in range(n, n + 200):
 if i - dig_sum(i) == n:
 ans += 1
 print(ans)
```

## 2196A - Game with a Fraction

**Tutorial**

The solution is very simple, it is necessary to check that:

- $p \lt q$
- $\texttt{min}(\frac{p}{2}, \frac{q}{3}) \ge q - p$

If both conditions are met, then Bob wins, otherwise, Alice wins.

The first condition is quite obvious, if it is not met, then Alice will always decrease $q$ if possible, leading to $p \ge q$, so the fraction will always be either $ \gt \frac{2}{3}$ or $= 0$ (after all moves).

The second condition states that no matter what move Alice makes, there is always a move for Bob that maintains the original difference $q - p$. There will be a moment during the game when $p = 2 \cdot \texttt{min}(\frac{p}{2}, \frac{q}{3})$, because $2 \cdot \texttt{min}(\frac{p}{2}, \frac{q}{3}) \le p$, and at that moment, with such a difference, the fraction will exactly equal $\frac{2}{3}$.

The solution works in $O(1)$


**Solution**

```cpp
	}
}
```

## 2196B - Another Problem about Beautiful Pairs
 
**Tutorial**

Consider the following solution:

For each $i$, we will check all possible candidates $j$ that can form beautiful pairs. To do this, we will iterate through such $j = i + k \cdot a_{i}$, where $k \gt 0$.

This solution works slowly for small $a_{i}$. Let's try to speed it up using square root decomposition. We will introduce a parameter $B$ and will iterate through candidates for $i$ in different ways depending on whether $a_{i} \lt B$ or $a_{i} \ge B$:

- If $a_{i} \ge B$, we will iterate through candidates in both directions from $i$ (not just forward), meaning for each such $i$, the set of candidates will be $i + k \cdot a_{i}$, where $k$ is any integer;
- If $a_{i} \lt B$, we will also iterate through candidates only forward, but we will introduce an additional restriction on $k$, namely $k \lt B$.

Let's estimate the maximum possible number of candidates for these two cases:

- In the first case, for all such $i$ where $a_{i} \ge B$, it is $\frac{n}{B}$, since we move in steps of $B$;
- In the second case, it is clear that there are no more than $B$ candidates, as we have introduced such a restriction ourselves.

If we choose $B = \lceil\sqrt{n}\rceil$, then the number of candidates for each case is no more than $\lceil\sqrt{n}\rceil$, so the entire algorithm solves the problem in $O(n\sqrt{n})$.

Let's think about why such an algorithm will be correct. Consider the cases of a beautiful pair $(i, j)$, depending on the values of $a_{i}$ and $a_{j}$:

- If $a_{i} \lt B$ and $a_{j} \lt B$, then the pair will be counted when we iterate through candidates for $i$;
- If $a_{i} \ge B$ and $a_{j} \lt B$, then the pair will be counted when we iterate through candidates for $j$;
- If $a_{i} \lt B$ and $a_{j} \ge B$, then the pair will be counted when we iterate through candidates for $j$;

Note that there is no case where $a_{i} \ge B$ and $a_{j} \ge B$, since we chose $B = \lceil\sqrt{n}\rceil$, which means that in such a pair $a_{i} \cdot a_{j} \ge n$, and the maximum value of $j - i = n - 1$.

Therefore, our algorithm is correct

 
**Solution**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
#define int long long
 
const int SQ = 500;
 
void solve(){
  int n;
  cin >> n;
  vector<int> a(n);
  for (int i = 0; i < n; i++){
    cin >> a[i];
  }
 
  int ans = 0;
 
  for (int i = 0; i < n; i++){
    if (a[i] >= SQ){
      for (int j = 1; i + a[i] * j < n; j++){
        if (a[i + a[i] * j] == j){
          ans++;
        }
      }
      for (int j = 1; i - a[i] * j >= 0; j++){
        if (a[i - a[i] * j] == j){
          ans++;
        }
      }
    }
    else{
      for (int j = 1; i + a[i] * j < n && j < SQ; j++){
        if (a[i + a[i] * j] == j){
          ans++;
        }
      }
    }
  }
 
  cout << ans << '\n';
}
 
signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);
 
	int t = 1;
	cin >> t;
	while(t--){
		solve();
	}
 
#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
		chrono::high_resolution_clock::now()
			- _clock_start).count() << "ms." << endl;
#endif
	return 0;
}
```

## 2196C1 - Interactive Graph (Simple Version)

Let's solve the problem using binary search. For each edge, there exists a path that consists solely of that edge, so let's simply find that path and remember that this edge is in our graph. Initially, we set the boundaries $l = 0$ and $r = 2^{30}$ and will search for the first path consisting of $1$ edge that starts at vertex $1$. Once we find it, we will add the corresponding edge to the answer. After that, we continue searching for the next path of one edge that starts at vertex $1$ with a new binary search, taking into account that all paths starting from the first found edge are no longer of interest to us. When two edges are known, we will ignore all paths that start on them, and so on. Ultimately, we will find all edges from vertex $1$ (the last binary search will not find an edge from vertex $1$). After this, we will continue searching for all edges from vertex $2$, $3$, and so on.

As a result, we will need $\log A \cdot (n + m)$ queries. Since $A = 2^{30}$, this fits well within the query limits of the problem


**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

#define int long long

const int INF = 1'000'000'007;

vector<int> ask(int k){
	cout << "? " << k << endl;
	int l;
	cin >> l;
	if (l == -1){
 exit(0);
	}
	vector<int> res(l);
	for (int i = 0; i < l; i++){
 cin >> res[i];
	}
	return res;
}

void solve(){
	int n;
	cin >> n;

	vector<pair<int, int>> edges;

	for (int i = 0; i < n; i++){
 int prev = -1;
 while(1){
 int l = 1, r = (1 << 30);
 while(l <= r){
 int m = l + (r - l) / 2;
 auto path = ask(m);
 if (!path.empty() && path[0] < i + 1){
 l = m + 1;
 continue;
 }
 if (path.empty() || path[0] > i + 1 || (path.size() > 1 && path[1] > prev)){
 r = m - 1;
 }
 else{
 l = m + 1;
 }
 }

 auto path = ask(l);
 if (path.size() > 1){
 edges.emplace_back(path[0], path[1]);
 prev = path[1];
 }
 else{
 break;
 }
 }
	}

	cout << "! " << edges.size() << endl;
	for (auto [u, v] : edges){
 cout << u << ' ' << v << endl;
	}
}

signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);

 solve();
```

## 2196C2 - Interactive Graph (Hard Version)

Let's start asking for paths in order starting from $2$, since path $1$ consists of a single vertex $1$. If we ask for paths one by one (that is, each subsequent one), then during our questioning, the path will change in one of two ways:

- a vertex has been added to the previous path;
- a suffix of vertices has been removed from the previous path and a new one has been added.

Note that when the second point occurs, for all the vertices that are removed from the suffix, we can determine the number of paths that start from this vertex and end at some other vertex, let's denote this as $C_v$. Therefore, if at some point we visit a vertex for the second time, we can immediately skip these $C_v$ paths and move on to the next one in lexicographic order. Thus, for each query, we either learn about one edge or move to another connected component, so we need exactly $n + m$ questions

 
**Solution**
```cpp
#include<bits/stdc++.h>
 
using namespace std;
 
vector<int> ask(int k){
	cout << "? " << k << endl;
	int cnt;
	cin >> cnt;
	vector<int> res(cnt);
	for (int i = 0; i < cnt; i++){
		cin >> res[i];
		res[i]--;
	}
	return res;
}
 
void solve(){
	int n;
	cin >> n;
 
	int m = 0;
	vector<vector<int>> g(n);
	vector<int> cnt(n, -1);
 
	function<void(int)> calc = [&](int v){
		if (cnt[v] != -1){
			return;
		}
		cnt[v] = 1;
		for (int to : g[v]){
			calc(to);
			cnt[v] += cnt[to];
		}
	};
 
	vector<int> prev = {0};
	int k = 2;
 
	while(1){
		auto cur = ask(k);
		if (cur.size() == 0){
			break;
		}
		int com_pref = 0;
		for (int i = 0; i < min(prev.size(), cur.size()); i++){
			if (prev[i] != cur[i]){
				break;
			}
			com_pref++;
		}
		if (prev.size() > com_pref){
			calc(prev[com_pref]);
		}
 
		if (com_pref > 0){
			g[cur[com_pref - 1]].push_back(cur[com_pref]);
			m++;
		}
		if (cnt[cur[com_pref]] == -1){
			k++;
		}
		else{
			k += cnt[cur[com_pref]];
		}
		prev = cur;
	}
 
	cout << "! " << m << endl;
	for (int i = 0; i < n; i++){
		for (int to : g[i]){
			cout << i + 1 << ' ' << to + 1 << endl;
		}
	}
}
 
signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);
 
	int tests = 1;
	cin >> tests;
	for (int test = 0; test < tests; test++){
		solve();
	}
#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
		chrono::high_resolution_clock::now()
			- _clock_start).count() << "ms." << endl;
#endif
	return 0;
}
```

## 2196D - Double Bracket Sequence

**Tutorial**

The problem has a fairly simple solution with a time complexity of $O(|s|^{3})$ using dynamic programming of the form $\texttt{dp}[i][bal_1][bal_2]$—the minimum number of changes required after processing the first $i$ characters, where the balance of the subsequence of round brackets is $bal_1$, and the balance of the subsequence of square brackets is $bal_2$. The transitions are quite trivial (from each state, we try to process the next bracket by either changing it or not changing it).

However, this solution does not help when the constraints are $|s| \lt = 10^{6}$ (though it is useful for stress testing).

Another solution suggests using a greedy approach. Ultimately, each bracket must have a pair, and for each pair, either $0$, $1$, or $2$ actions are needed to make the pair correct. For example, for the pair "()", $0$ actions are needed; for the pair "[)", $1$ action is needed; and for the pair "][", $2$ actions are needed. Let's assume we have optimally paired the brackets (such that this pairing achieves the minimum number of actions); then an important observation is that there can be at most one pair that requires $2$ actions, because otherwise, we could form pairs differently, which would not worsen the answer.

We would also like to maximize the number of pairs that require $0$ actions. The simplest way to do this is to find a subsequence of round brackets that forms the longest valid parentheses subsequence (LPS), and do the same for square brackets. The remaining brackets that do not belong to any LPS will form pairs that require either $1$ or $2$ actions. Here, we need to check whether there will be that one pair that requires $2$ actions or not. It turns out that it is sufficient to check that the remaining brackets form a sequence where closing brackets come first, followed by opening brackets, with an odd number of closing and opening brackets, for example:

"))]))[[("

Here, the opening brackets ($5$ in total) come first, followed by the closing brackets ($3$ in total), and for such a sequence, there will be a pair that requires $2$ actions.

In any other case, there will be no pairs requiring $2$ actions.

This solution works in $O(|s|)$


**Solution**
```cpp
#include<bits/stdc++.h>
using namespace std;

#define int long long

const int INF = 1'000'000'007;

void solve(){
	int n;
	cin >> n;
	string s;
	cin >> s;

	vector<int> stay(n);

	auto delete_cbs = [&](char open, char close){
 vector<int> st;
 for (int i = 0; i < n; i++){
 if (s[i] == close){
 if (!st.empty() && s[st.back()] == open){
 st.pop_back();
 }
 else{
 st.push_back(i);
 }
 }
 else if (s[i] == open){
 st.push_back(i);
 }
 }
 for (int x : st){
 stay[x] = 1;
 }
	};

	delete_cbs('(', ')');
	delete_cbs('[', ']');

	int last_open = 0;
	int cnt_open = 0, cnt_close = 0;
	int ans = 1;

	for (int i = 0; i < n; i++){
 if (!stay[i]){
 continue;
 }
 if (s[i] == '(' || s[i] == '['){
 cnt_open++;
 last_open = 1;
 }
 else{
 cnt_close++;
 if (last_open){
 ans = 0;
 }
 last_open = 0;
 }
	}
	if (cnt_open % 2 == 0 || cnt_close % 2 == 0){
 ans = 0;
	}
	ans += (cnt_open + cnt_close) / 2;
	cout << ans << '\n';
}

signed main()
{
#ifdef FELIX
	auto _clock_start = chrono::high_resolution_clock::now();
#endif
	ios_base::sync_with_stdio(false);
	cin.tie(0);
	cout.tie(0);

	int t = 1;
	cin >> t;
	while(t--){
 solve();
	}

#ifdef FELIX
	cerr << "Executed in " << chrono::duration_cast<chrono::milliseconds>(
 chrono::high_resolution_clock::now()
 - _clock_start).count() << "ms." << endl;
#endif
	return 0;
}
```

## 2196E1 - Fuzzy Concatenation (Easy Version)

The following greedy algorithm works: we will find the longest prefix of the string $t$ such that this prefix is contained in $s$ as a substring (possibly with one character replaced), and then remove this prefix from $t$ and repeat until $t$ is empty. The number of such "pieces" will be the answer. This greediness is correct because if we take a prefix of shorter length, the next piece can only decrease in size, not increase.

Now we need to learn how to quickly solve the following problem:

For a fixed number $l$, find the maximum $r$ such that there exists a number $i$ and a string $c$, for which the string $t_l t_{l + 1} \ldots t_{i - 1} c t_{i + 1} \ldots t_{r}$ is a substring of the string $s$.

Solving this problem involves using root optimization. Let $B$ be the constant we chose for our root. Let $d$ denote $r - l + 1$ for optimal $i, c$ (in other words, how many characters we processed in one iteration of the greedy algorithm). We want to handle the case $d \lt B$ in $O(d)$ time.

Let's store the hash of each substring of the string $s$ of length at most $B$, where we have removed one of the elements. There are a total of $O(n \cdot B^2)$ such segments. Thus, for fixed $i, d$, where $d \lt B$, we can check in $O(1)$ time whether a given string is a substring of $s$ by verifying that the hash of the string without the character $c$ is in the set of precomputed hashes. This allows us to solve the case when $d \lt B$ in $O(d^2)$ time. We can iterate $i$ from $l$ to the maximum accumulated length and increase the optimal $d$ by exactly $1$ if we find this substring for the given $i$. Smaller $r$ values are not of interest to us. Overall, this part of the solution works in $O(m \cdot B)$ time, as we increase $r$ no more than $m$ times in total, and each check works in $d$ time, since there are at most $B$ interesting values of $i$ in each iteration.

If $d \geq B$, we can explicitly iterate over the starting point of the substring in the string $s$. Let's denote this starting point of the substring as $j$. Let $d_1$ be $\operatorname{lcp}(s_j \ldots s_n, t_l \ldots t_m)$. Then for a fixed starting point $j$, we can add at most $d_1 + 1 + \operatorname{lcp}(s_{j + d_1 + 1} \ldots s_n, t_{l + d_1 + 1} \ldots t_m)$. The $\operatorname{lcp}$ can be easily computed in $O(1)$ time using a suffix array for the string $s\text{\#}t$. Thus, this part of the solution works in at most $O(\frac{n \cdot m}{B})$ time, as this search algorithm will be run no more than $\frac{m}{B}$ times, and the iteration itself works in $O(n)$ time.

The asymptotic complexity of the solution is $O(n \cdot B^2 + \frac{n \cdot m}{B} + m \cdot B)$. With $B=50$, this solution should fit well within the problem's constraints.

There is also a solution that runs in $26 \cdot m \cdot \log^2(n + m) + \log(n) \cdot (n + m)$, which is based on a complete solution but uses hashes

## 2196E2 - Fuzzy Concatenation (Hard version)

The following greedy algorithm works: we will find the longest prefix of the string $t$ such that this prefix is contained in $s$ as a substring (possibly with one character replaced) and then remove this prefix from $t$ and repeat until $t$ is empty. The number of such "pieces" will be the answer. This greediness is correct because if we take a prefix of shorter length, the next piece can only decrease in size, not increase.

To efficiently find the longest prefix, we will use the following algorithm:

We will start from the beginning of the prefix and try to change the current character to some character from the alphabet, and then attempt to find the LCP of the string $t$ with the modified character and some suffix of the string $s$. Let $f(t', pos)$ denote the time to find such an LCP if a character in the string is changed at position $pos$ to some character from the alphabet; then the time complexity of the entire algorithm can be estimated as $O(|t| \cdot \sum_{i = 1}^{|t|} f(t', i))$.

We will use a suffix array. We will construct it for the string $s + "\#" + t$, and also compute the LCP for this array. Additionally, we will compute the reverse array $sa\_rev$: that is, such that $sa\_rev[i]$ contains the position of the suffix of length $i$ in the suffix array $sa$.

Let $t_{suff}$ be the suffix of the original $t$, where we need to search for the maximum "piece". Also, let $t_{suff, ps}$ be the suffix of the original $t$, in which one character was changed at position $ps$.

In the suffix array, there are two classes of suffixes: for $s$ and for $t$. We will separate the positions of all suffixes for $s$ into a separate array. Now let's search for our maximum "piece" in $t_{suff, ps}$. We will perform a binary search on the suffix array to determine where the position of the string $t_{suff, ps}$ would be in it if we wanted to insert $t_{suff, ps}$ into the suffix array constructed solely from $s$.

Next, we need to understand how the check for this binary search will look. Suppose we want to check during the binary search whether the position after $sa_i$ is the position we need; let $sa_{j}$ and $sa_{k}$ be the positions of the nearest suffixes to the left and right that belong to $s$. We need to check that $sa_{j} \le t_{suff, ps} \le sa_{k}$. It seems that comparing such strings cannot be done faster than $\log$, but since we do not have arbitrary strings, we can do the following:

We will find the LCP of $sa_{j}$ and $t_{suff}$ (we can do this because $sa$ is constructed from all suffixes of $s$ and $t$, and we can find the LCP of any two arbitrary suffixes in the suffix array in $O(1)$). If this LCP is greater than $ps$ for the current $t_{suff, ps}$, then we know the relationship between the strings $sa_{j}$ and $t_{suff, ps}$ (greater, less, or equal). If the LCP is less, we will check that the corresponding character of $sa_{j}$ at position $ps$ is equal to the corresponding character in $t_{suff, ps}$ (if it is not equal, we again know the relationship between the strings).

If it turns out to be equal, we need to compare the strings $sa_{sa\_rev_{sa_{j} + ps}}$ and $t_{suff + ps}$. This can also be done in $O(1)$ by looking at their positions in the suffix array $sa$.

After we have found the required position in the suffix using binary search, we can similarly calculate the maximum LCP of $t_{suff, ps}$ and the substring of $s$ also in $O(1)$.

Thus, $f(t', pos)$ can be estimated as $O(\log (|s| + |t|) \cdot k)$, where $k$ is the size of the alphabet.

Therefore, the problem can be solved in $O(|t| \cdot \log (|s| + |t|) \cdot k)$

 
**Solution**
```cpp
#include <bits/stdc++.h>
 
using namespace std;
 
template <typename T>
struct SparseTable{
	int n, r;
	vector<vector<T>> t;
	void build(vector<T> &a) {
		n = a.size();
		r = 32 - __builtin_clz(n);
		t.resize(r, vector<T>(n + 1));
		for(int i = 1; i <= n; ++i) t[0][i] = a[i - 1];
		for(int k = 1; k < r; ++k) {
			for(int i = 1; i + (1 << k) - 1 <= n; ++i) {
				t[k][i] = f(t[k - 1][i], t[k - 1][i + (1 << (k - 1))]);
			}
		}
	}
 
	T query(int l, int r) {
		int k = 31 - __builtin_clz(r - l + 1);
		return f(t[k][l], t[k][r - (1 << k) + 1]);
	}
 
	inline T f(T x, T y){
		return min(x, y);
	}
};
 
struct SuffixArray{
    int n;
    vector<int> sa;
    vector<int> lcp;
 
    vector<int> _s;
    vector<int> _inv_sa;
    SparseTable<int> _st_lcp;
 
    SuffixArray(){}
 
    void build(const string& s){
        _s.assign(s.size(), 0);
        for (int i = 0; i < s.size(); i++){
            _s[i] = s[i];
        }
        _build(_s);
        _build_lcp_array();
        _st_lcp.build(lcp);
    }
 
    void build(const vector<int>& s){
        _s.assign(s.size(), 0);
        for (int i = 0; i < s.size(); i++){
            _s[i] = s[i];
        }
        _build(_s);
        _build_lcp_array();
        _st_lcp.build(lcp);
    }
 
    void _build(const vector<int>& s){
        map<int, int> mp;
        for (int ch : s){
            mp[ch] = 0;
        }
        int cc = 1;
        for (auto& [key, val]: mp){
            val = cc++;
        }
 
        n = s.size() + 1;
        vector<int> c(n);
        sa.assign(n, 0);
 
        for (int i = 0; i < s.size(); i++){
            c[i] = mp[s[i]];
            sa[i] = i;
        }
        c[n - 1] = 0;
        sa[n - 1] = n - 1;
 
        for (int i = 1; (i >> 1) < n; i <<= 1){
            if (i != 1){
                for (int j = 0; j < n; j++){
                    sa[j] = (sa[j] - (i >> 1) + n) % n;
                }
            }
            vector<int> cnt(n);
            for (int j = 0; j < n; j++){
                cnt[c[sa[j]]]++;
            }
            int su = 0;
            for (int j = 0; j < n; j++){
                su += cnt[j];
                cnt[j] = su - cnt[j];
            }
            vector<int> new_sa(n);
            for (int j = 0; j < n; j++){
                new_sa[cnt[c[sa[j]]]++] = sa[j];
            }
            sa.swap(new_sa);
 
            if (i != 1){
                vector<int> new_c(n);
                new_c[sa[0]] = 0;
                for (int j = 1; j < n; j++){
                    if (c[sa[j]] > c[sa[j - 1]] || c[(sa[j] + (i >> 1)) % n] > c[(sa[j - 1] + (i >> 1)) % n]){
                        new_c[sa[j]] = new_c[sa[j - 1]] + 1;
                    }
                    else{
                        new_c[sa[j]] = new_c[sa[j - 1]];
                    }
                }
                c.swap(new_c);
            }
        }
    }
 
    void _build_lcp_array(){
        lcp.assign(n - 1, 0);
        _inv_sa.assign(n, 0);
        for (int i = 0; i < n; i++){
            _inv_sa[sa[i]] = i;
        }
        for (int i = 0; i < n; i++){
            if (_inv_sa[i] == n - 1){
                continue;
            }
            lcp[_inv_sa[i]] = 0;
            if (i > 0 && _inv_sa[i - 1] != n - 1){
                lcp[_inv_sa[i]] = max(0, lcp[_inv_sa[i - 1]] - 1);
            }
 
            int len = min(n - 1 - i, n - 1 - sa[_inv_sa[i] + 1]);
            while (lcp[_inv_sa[i]] < len && _s[i + lcp[_inv_sa[i]]] == _s[sa[_inv_sa[i] + 1] + lcp[_inv_sa[i]]]){
                lcp[_inv_sa[i]]++;
            }
        }
    }
 
    int get_lcp(int i, int j){
        assert(i != j);
        i = _inv_sa[i];
        j = _inv_sa[j];
        if (i > j){
            swap(i, j);
        }
        j--;
        return _st_lcp.query(i + 1, j + 1);
    }
};
 
void solve(){
    int n, m;
    cin >> n >> m;
    string s, t;
    cin >> s >> t;
 
    string all = s + "%" + t;

    suff_array.build(all);

    };
```

## 2196F - Indivisible

**Tutorial**

First solution:

Let's start by solving the problem for odd $n$. Intuitively, if for an odd $n$ we can make all vertex degrees almost equal and as large as possible, there should be a good chance that the set of degrees will be indivisible.

We divide the sum of all degrees, $2m$, by $n$ with a remainder. Let $2m = q \cdot n + r$. $0 \le r \lt n$.

We can make the vertex degrees almost equal if they are $q, \ldots, q, q+1, \ldots, q+1$, where $q+1$ appears $r$ times, and $q$ appears $n-r$ times. A graph with such degrees can always be constructed; let's consider two cases:
- $q$ and $r$ are even numbers. Mentally arrange the vertices in a circle from $1$ to $n$, where $n$ and $1$ will also be neighboring vertices. Connect vertices $i$ and $j$ with an edge if the minimum distance between them around the circle does not exceed $\frac{q}{2}$. After this, each vertex will have a degree equal to $q$. Then we add $\frac{r}{2}$ edges between pairs of vertices $1 \lt = \gt \frac{n}{2}+1, \ldots, r \lt = \gt \frac{n}{2}+r$.
- $q$ and $r$ are odd numbers. Since $n$ is odd and $q \lt n$, it is also true that $q+1 \lt n$, which means we can construct a configuration from the first case where each vertex degree is $q+1$. After that, we remove edges $1 \lt = \gt 2, \ldots, n-r-1 \lt = \gt n-r$.

There are no other cases since $n$ is odd, and $2m = q \cdot n + r$, which means modulo two, $q + r$ equals $0$.

Let's analyze in which cases this graph will meet the problem's condition. For the condition to be violated, there must be a solution to the equation $qa + (q+1)b = m$, where $0 \leq a \leq n-r, 0 \leq b \leq r$. Additionally, we fix the condition $a+b \lt \frac{n}{2}$; this must be satisfied for one of the halves of the partition (since the total number of vertices is $n$, the smaller half has fewer than $\frac{n}{2}$ vertices when $n$ is odd). We transform the equation:

$$qa + (q+1)b = m$$

$$q(a+b) + b = m$$

$$2q(a+b) + 2b = 2m$$

$$2q(a+b) + 2b = qn + r$$

$$q(2a+2b-n) = r - 2b$$

$$q(n - 2a - 2b) = 2b - r$$

Let's take a closer look at the rewritten equation. The left side is guaranteed to be an integer $\geq q$, since $n \gt 2a+2b$.

We will show that when $r \lt q$, the equation has no solutions. When $r \lt q$, since $b \le r$, we get that $2b - r \le r$, meaning the right side of the equation $\le r$, while the left side equals $q$, and in the case $r \lt q$, such an equation is unsolvable. Thus, if $r \lt q$, we have shown that the graph satisfies the problem's condition.

Let's continue the chain of inequalities, each time weakening the inequality.

$$(q + 1) \cdot (n - 2a - 2b) = n - 2a - r$$

$$q + 1 \le n - 2a - r$$

$$q + 1 + 2a + r \le n$$

$$q + r \lt n$$

It follows that from the assumption that a solution to the equation exists, we derive the fact that $q + r \lt n$. From this, it follows that when $n \le q + r$, there is no solution to the equation, and the graph satisfies the problem's condition.

Let's consider the following strategy: while $\frac{(n-2)(n-3)}{2} \geq m$, we decrease $n$ by $2$ and reduce the problem to $(n-2, m)$, isolating two vertices of degree $0$. In the end, we will obtain a problem where $n(n-1) \ge 2m$ and $(n-2)(n-3) \lt 2m$, while $n$ is still odd.

We will show that in this case (when $n(n-1) \ge 2m$ and $(n-2)(n-3) \lt 2m$) one of the two conditions ($n \le q+r$ or $r \lt q$) will always be satisfied, except for the case when $m \in \{1, 2, 4, 6, 12\}$.

$$n(n-1) \geq 2m \gt n^2-5n+6$$

$$n-1 \geq \lfloor \frac{2m}{n} \rfloor \gt n-5+\frac{6}{n}-1$$

$$n-1 \geq q \gt n-6+\frac{6}{n}$$

Let's analyze the cases.
- $q = n-1$In this case, the graph must be complete, and for it $r=0$, thus the condition $r \lt q$ is satisfied.
- $q = n-2$If $r \lt n-2$, then $r \lt q$.If $2 \le r$, then $n \le q + r$.The extreme case where both conditions are not satisfied is $n=3$, then $m=2$.
- $q = n-3$If $r \lt n-3$, then $r \lt q$.If $3 \le r$, then $n \le q + r$.The extreme cases where both conditions are not satisfied are $n=3$, $m=1$ and $n = 5$, $m = 6$.
- $q = n-4$If $r \lt n-4$, then $r \lt q$.If $4 \le r$, then $n \le q + r$.The extreme cases where both conditions are not satisfied are $n = 7$, $m = 12$ and $n = 5$, $m = 4$.
- $q = n-5$The unweakened condition: $2m \gt n^2-5n+6$, thus $2m - qn \gt 6$, meaning $r \gt 6$. Therefore, the condition $n \le q+r$ in this case is always satisfied.

Thus, our strategy has been proven to yield an indivisible graph for odd $n$, and $m \notin \{1,2,4,6,12\}$!

By bruteforce, it is easy to show that all possible graphs with $m \in \{1,2,4,6\}$ will be divisible. For example, for $m=2$, the possible vertex degrees are either $\{1,1,1,1\}$ or $\{1,1,2\}$.

And for $m=12$, it is possible to create a graph on $6$ vertices (and for all $n \gt 6$, we can take this graph and $n-6$ isolated vertices) that satisfies the indivisibility condition, with degrees $\{3,3,3,5,5,5\}$, which is $K_6$ without three edges between the first three vertices.

Thus, the solution for odd $n$ is No for $m \in \{1,2,4,6\}$, with the case $m=12$ handled separately; otherwise, the strategy works: take the densest graph with $m$ edges and $\le n$ vertices, supplemented with isolated vertices.

Now let's solve the problem for even $n$. Immediately, we can discard a cluster of cases using the solution for odd:

- If $m \in \{1,2,4,6\}$, the answer is still no.
- If $m = 12$, the same example will work.
- If $m \le \frac{(n-1)(n-2)}{2}$, we can isolate one vertex and reduce the problem to $(n-1, m)$, and $n-1$ will be odd, thus we know that with such parameters a solution always exists.

The only remaining case: $2m \gt (n-1)(n-2)$.

Notice that in this case, if the graph has a partition of vertices into two sets with equal sum of degrees, then both of these sets must have size $\frac{n}{2}$, otherwise, the smaller set has size $\le \frac{n}{2}-1$, and thus the maximum sum of degrees of this set: $(n-1)(\frac{n}{2}-1) = (n-1)\frac{n-2}{2}$, while $m$ is strictly greater than this number.

Knowing this, we note that in this case, the condition of indivisibility for this graph is equivalent to the condition of indivisibility for the reverse graph, but with the added condition that the vertex sets must have equal size.

In the reverse graph, there will be $\frac{n(n-1)}{2} - m \lt n - 1$ edges. If $\frac{n(n-1)}{2} -m$ is not equal to $0, 1, 2, 4, 6$, we can take an indivisible reverse graph on $n-1$ vertices and $\frac{n(n-1)}{2} - m$ edges, using the construction above. Since this graph is indivisible in general form, it is also indivisible under the added condition of equal set sizes.

It remains to deal with the cases when $\frac{n(n-1)}{2} - m \in \{0,1,2,4,6\}$. Here we can recall the restriction $n \ge 12$. It turns out that for $n \ge 12$, any graph with $0,1,2,4,6$ edges is not just always divisible, but always divisible into two sets of equal size. This is true because in a regular partition, the sizes of both sets do not exceed $6$ (if we only take non-isolated vertices), thus we can take a regular partition and supplement it with isolated vertices so that both sets have size $6$. And for $n \gt 12$, we can take a pair of isolated vertices in different sets and reduce the problem to $n - 2$. Thus, in this case, there is no solution to the problem.

Second solution (thanks to [user:SomethingNew] for the alternative solution!):

Let's note/guess/suppose that the graph answer cannot have more than 3 different degrees. More precisely, it is sufficient to consider only graphs with no more than 3 different degrees to cover all possible $(n,m)$ where a solution exists.

Let's bruteforce all possible sets of degrees and use the Erdős–Gallai theorem to check whether a graph can be formed from these degrees, in $O(n \log n)$. Checking the indivisibility criterion can also be done quite quickly, given that there are no more than $3$ different degrees (they can be arranged in $O(\log n)$ knapsack items), and using a bitset.

Such a solution already works, but is obviously too slow. However, we can cleverly "tweak" the parameters of the enumeration, trying to guess the properties of the construction so that it works in terms of time.

- Enumerate the actual $n$ (without isolated vertices) in increasing order, starting from the first such that $\frac{n(n-1)}{2} \ge m$.
- Enumerate the maximum degree value only from $n$ to $n-5$.
- Honestly enumerate the number of vertices with the maximum degree, as well as the minimum degree, after which we honestly enumerate the average degree. Of course, add as many break as possible.

It is claimed that such bruteforce will run in $O(m \sqrt m \log m)$ time, as all considered values of $n$ will be $O(\sqrt m)$
